# HTML 规范文档翻译规范（html_spec.md）

> **版本**：v1.4（2026-08-26；v1.4 采纳双 AI 第六轮微调：合并命令改 find+xargs 流式（防 E2BIG）、JSON 尾逗号清洗）
> **适用**：规范原文是 HTML（如 POSIX/RFC/ISO 官网页面），产物（直译、导读）也是 HTML。
> **配套**：`md_spec.md`（markdown 中间产物场景）、`pdf_spec.md`（PDF 场景）、`spec.md`（总入口与通用机制）、`html_output_spec.md`（三兄弟 HTML 最终输出，完全适配 template.html）。
> **最终适配**：本规范产物是**官方结构的 HTML**；嵌入博客前必须按 `html_output_spec.md` 做 template 适配转换（加 h1、标题锚点外移、`&nbsp;`→空格、`<pre>`→`<pre><code class>`、表格 thead/tbody + colspan 展开、跨页链接剥文本、禁用标签映射）。
> **执行区隔**：标有 **[Agent 执行]** 或"必须/禁止/一律/上限/铁律"的条目是硬性约束；其余为背景解释。

## 1. 总体流程（HTML 场景核心）

```
curl 抓取官方 HTML（index.html）＋ md5 基线
        │
        ▼
Python DOM 解析（BeautifulSoup/html.parser）
        │
        ├─ ① 抽取块级节点文本（保留行内标签/占位符）
        ├─ ② 抽取白名单属性文本（alt/title/placeholder）
        │
        ▼
分块投递 LLM（纯文本经 base64 编码投递，LLM 不接触 HTML 结构）＋ md5 双基线闭环
        │
        ▼
LLM 解码 base64 → 翻译中文文本
        │
        ▼
Python 节点数/顺序断言 → HTML 转义 → 回填 DOM → 输出 index.html
        │
        ▼
知识卡片 → knowledge-index → 两阶段导读（HTML）
```

**核心原则：LLM 永远不直接处理原始 HTML 结构**——它只翻译"抽出来的纯文本"，HTML 的增删改由 Python 脚本完成。这是杜绝"LLM 幻觉漏掉 `</div>`、改写 href、破坏实体"的根本手段。

---

## 2. 下载与基线

1. **下载**：`curl -s -o <dir>/index.html "<官方 URL>"` 原样保存（含 head/CSS/导航）。
2. **配套资源**：`style.css`、`darkmode.js`、图片（`../images/x.gif` → `.pic/x.gif`，src 改写）。
3. **md5 基线（必须）**：`md5sum index.html > index.html.md5`——这是校验"Agent→LLM 传输无损"的唯一权威基线。
4. **[Agent 执行] 读取原文一律经 base64 通道（见 4）**，严禁 `cat`/`read` 裸读大段文本进管道；**DOM 抽取出的文本块同样经 base64 编码投递**（见 3.4），禁止裸纯文本进管道（管道实测：纯文本特定组合被替换成 `[redacted]`）。

## 3. DOM 抽取 → 翻译 → 回填（核心流程）

### 3.1 抽取规则

- **最小翻译单元 = 块级节点**（`<p>`、`<h1-h6>`、`<li>`、`<td>`、`<blockquote>` 等），**保留块内行内标签**（`<b>`、`<i>`、`<a>`、`<code>`、`<tt>`），或替换为占位符（`[LINK_1]`、`[CODE_2]`）保证语境连贯。
  - 反例（禁止）：`<p>Click <a href="...">here</a> for details.</p>` 拆成 `"Click "`、`"here"`、`" for details."` 分别翻译——LLM 无法理解语境。
- **[Agent 执行] inner_html 提取铁律**：抽取块级节点文本**必须使用能保留内部子标签的序列化方法**（如 BeautifulSoup 的 `element.encode_contents()` 或等价 inner HTML 提取），把**包含完整行内标签的字符串整块打包**投递；**严禁 `.text` / `.get_text()`**——它们会剥离 `<a>`/`<b>`/`<code>` 等行内标签（`<p>Click <a href="x">here</a></p>` 会变成 `"Click here"`），回填时官方超链接与代码样式被物理抹除。
- **白名单属性**：`<img alt>`、`<a title>`、`placeholder` 等可翻译属性，与文本节点一并提取翻译；`href`/`src`/`id`/`class` 等**属性值禁止翻译**。
- **不翻译节点**：`<script>`、`<style>`、`<code>`、`<pre>`、`<tt>` 内容（代码/程序原样保留），标记跳过。

### 3.2 表格语义保护

- **[Agent 执行]** 表格文本抽离投递给 LLM 时，**必须附带语义上下文**（所属表题、行头、列头），禁止投递无上下文的孤立文本。否则"0"可能被误译为"零"而非"退出状态 0"。
- **[Agent 执行] 投递格式（JSON 明文骨架 + 仅 payload base64）**：**严禁把整个 JSON 对象打包进 base64**（高熵结构会让 LLM 心算解码错位漏字符）；JSON 骨架保持明文，仅对**待翻译纯文本字段**做 base64：
  ```json
  {"context": "表 2-1 退出状态：列=Exit Status", "b64_payload": "<仅 text 的 base64>", "chunk_md5": "<payload 解码后的 md5>"}
  ```

### 3.3 回填规则

- **[Agent 执行]** 回填前必须对 LLM 返回的中文做 **HTML 转义**（`<` → `&lt;`、`>` → `&gt;`、`&` → `&amp;`），确保是安全的文本节点（防"小于/大于"产生非法 HTML）。
- **[Agent 执行]** 回填后必须做**节点数与顺序断言**：抽取 N 个文本节点 → 回填必须恰好 N 个且顺序一致，防止错位（脚本比对占位符序号）。
- 样式需求在单元格/文本内**一律用 HTML 标签**（`<b>`、`<i>`、`<br>`），不使用 markdown 语法。

### 3.4 分块投递（base64 + md5，禁裸纯文本）

- 大文件按块投递，**默认每块 ≤10KB 原文**；分块**按语义节点截断**（`</p>`、`</table>` 处），禁止在标签/表格/长句中间硬截断。
- **[Agent 执行] DOM 节点级重叠（禁字符重叠）**：HTML 是严格的树状结构，**禁止按字符数（100-200 字符）机械切分重叠**——会从 `<div>`/`<table>`/属性值中间撕裂标签，导致投递片段畸形、LLM 无法对齐语义、回填断言失败。分块必须以**完整闭合的块级兄弟节点**为单位截断；若需建立跨块上下文，把**上一块末尾 1-2 个完整块级节点**作为只读上下文放在当前块 prompt 头部，**严禁从任何标签/节点中间切断**。
- **[Agent 执行] 重叠节点属性剔除**：作为只读上下文附带的块级节点，**必须剔除其内部的白名单属性文本**（`alt`/`title`/`placeholder`），仅保留核心纯文本语境——防止属性文本混入下一块 Payload 流、打乱节点顺序，导致回填断言失败。
- **[Agent 执行] 节点重叠"只读不译"**：作为上下文附带的完整节点仅用于建立语义上下文，输出译文时必须显式跳过，确保各块拼接后无重复。
- **[Agent 执行] 投递通道（防遮蔽）**：抽取出的文本块**一律经 base64 编码投递，禁止裸纯文本进管道**（管道实测：纯文本特定组合被替换成 `[redacted]`；base64 完全干净）。每块操作：
  1. 工具侧把该块存为独立文件（`.chunks/0001.txt`…），`md5sum` 记录基线（A_chunk）；
  2. 投递：`base64 -w0 .chunks/0001.txt` → LLM；
  3. LLM：把收到的 base64 串**原样写回** `/tmp/verify.b64`，同时**心算解码 b64_payload** 得到可读文本（仅解码纯文本字段，不接触 JSON 骨架语法；解码结果即翻译基线）；
  4. 工具侧：`base64 -d /tmp/verify.b64 > /tmp/verify_chunk.txt && md5sum` 对比 A_chunk；
  5. 一致 → 解码内容即该块真实文本，LLM 基于它翻译；不一致 → 分块重取；
  6. **未经 md5 闭环确认的文本块一律不采信**。
- 完整闭环流程与管道实测定论见 **spec.md 4.3**（总入口，通用机制）。

### 3.5 译文输出协议（结构化回填防错位）

**[Agent 执行] 译文结构化流式返回镜像协议**：LLM 返回翻译结果时**必须镜像输入的明文 JSON 骨架结构，拒绝自由文本/裸中文输出**——否则 Python 回填脚本在流式输出错位、漏键时 `json.loads()` 直接崩溃，或节点顺序错位（Off-by-one）。

- **输出格式强制为纯 JSON 数组**（与输入节点一一对应）：
  ```json
  [ {"index": 1, "translated_text": "中文译文"}, {"index": 2, "translated_text": "..."} ]
  ```
- 工具侧回填脚本**必须利用 `index` 序号原位回填**（`node_map[item['index']].string = item['translated_text']`）与单节点逐一断言——**严禁接受任何无序号的裸文本返回**；
- `json.loads()` 失败或 `index` 对位失败时，**在该节点级别触发重试**，而不是毁掉整个文档；
- 纯文本块投递（非表格 JSON）同样适用：一批节点 → 一个 JSON 数组返回，`index` 对应投递时的节点顺序。
- **[Agent 执行] 返回 JSON 弹性去噪（防尾逗号地雷）**：LLM 流式输出长数组时存在末尾多吐尾逗号的肌肉记忆，`json.loads()` 零容忍。工具侧解析前**必须强制清洗**：`text = re.sub(r',\s*\]', ']', text)`——全局抹掉 `[... ,]` 形式的末尾冗余逗号后再 `json.loads()`。
- **参考实现**：`../tools/json_filler.py`（尾逗号清洗 + `json.loads` 容错 + index 完整性校验 + HTML 转义 + 原位回填回调 + 节点级重试信息），工具侧脚本可直接 import 使用或对照实现。

## 4. 传输完整性校验（md5 双基线闭环）

**三主体拓扑**：① 工具 = 跑在用户 WSL2 里的程序（文件与命令的唯一直实体）；② 管道 = 传输层（LLM 与 WSL2 之间唯一路径，会污染文本/毁掉二进制，base64 干净）；③ LLM = 云端模型，只能经工具间接读写文件。

**管道实测结论（写死）**：纯文本特定组合被替换成 `[redacted]`；base64 干净；md5 短哈希干净；tar.gz 二进制变乱码不可直接传 LLM。tar.gz 仅作工具侧内容容器（备份/多文件打包），不经过管道。

**[Agent 执行] 强制流程：**

1. 下载后 `md5sum index.html > index.html.md5`（基线 A）。
2. 读原文一律 base64 通道：工具按块 `dd if=index.html bs=1 skip=OFFSET count=LEN | base64 -w0` → LLM 收到 → 写回 `/tmp/verify.b64` → 工具 `base64 -d /tmp/verify.b64 > /tmp/verify.html && md5sum` 得基线 C（**文件名是 `.html`**，解码还原的是原文 HTML，MD5 必须与 A 完全相等；`.md` 是译文名，不可混用）。
   - **DOM 抽取文本块的投递走同一闭环**：基线为 `.chunks/NNN.txt` 的 md5（见 3.4），解码文件名用 `/tmp/verify_chunk.txt`。
3. A==C → 可信，作为翻译基线；不一致 → 分块逐段校验或重取。
4. 读到 `[redacted]`：md5 校验通过却仍见（极少数）才算官方遮蔽；否则一律按完整内容翻译，**不得**加译者注。
5. **未经 md5 闭环确认的内容一律不采信。**

**降级容错**：官方 HTML 内嵌 >50KB 的 DataURL 图片 → 脚本剥离转存本地；畸形表格连续 2 次验收失败 → 降级为译者注说明，不得卡死重试。

## 5. 导读与知识卡片（两阶段，解跨章死锁）

**[Agent 执行] 导读两阶段依赖锁：**

- **Phase 1（直译 + 卡片期）**：各章节子 Agent 只做：下载原文、中文直译（老二）、产出**章节知识卡片**（附录模板）；**不写导读**。
- **Map Building（地图构建）**：父 Agent 收集**全部**章节卡片，生成完整的 `knowledge-index.md`（全卷地图：章节索引 + 全局术语表 + 跨章引用关系图 + 全局概念清单）。
- **Phase 2（导读期）**：全卷地图锁死后，才允许编写老三（AI 导读）；查阅全局地图 + 按需投递被引用章节片段（base64 + md5），不凭记忆。

> 为什么两阶段：写第 1 章导读时第 4 章可能还没翻译，若此时依赖"全卷地图"会陷入先鸡后蛋。Phase 1 全部完成 → 地图完整 → Phase 2 统一开写，前向/后向引用都有据可依。

**导读标题铁律**：0. 章节自由；从 1. 起与原文编号一一对应；原文无子编号时不得自造（用无编号粗体）；细分用无编号粗体。

**知识卡片**（每章 ≤500 token）：元信息/核心概念/引入术语/交叉引用/关键规则/易错点/重要锚点。模板见附录。

## 6. 递归、并行与合并

- **递归硬约束**：派生 ≤2 层（父→子→孙，孙禁再派生）；并发 ≤4；最小片段 ≥50 行。
- **片段命名（防溢出铁律）**：`.parts/0001_xxx.html` **四位零填充前缀**（0001-9999；三位在 >1000 片段时 `1000` 排在 `100` 前导致乱序），合并 `export LC_ALL=C; find .parts/ -name "*.html" | sort | xargs cat > index.html`（`xargs` 自动分批防 E2BIG；`*.html` 全匹配无需前缀模式），防并发乱序。
- **静态快照锁**：任务启动时 spec + 术语表落盘 `.spec_snapshot.md`，递归链统一读快照，禁止热更新。
- **文件系统共享**：工具在同一 WSL2，父写盘 → 子本地读，不经 LLM 管道。
- **成本熔断**：单 Agent 轮数 ≤15（或步数 400），超限熔断。
- **[Agent 执行] 熔断落盘**：熔断挂起前，工具侧把当前进度、临时片段路径、校验哈希、错误卡点写入 `.codewhale/crash_report.json`；人类介入复工后**读 JSON 恢复状态并清理历史会话**，不依赖超长上下文记忆。

## 7. 验证清单

1. **结构完整性**：回填后 DOM 解析，标签配对完整（`<table>`/`<td>`/`<a>` 等无未闭合）；
2. **节点断言**：抽取节点数 == 回填节点数，顺序一致；
3. **残留检查**：无未翻译的英文文本节点（排除代码/`<code>`/`<pre>`）、无占位符残留（`[LINK_1]` 等）、无 `[redacted]` 误加译者注；
4. **标题一致性**：直译/导读标题与原文编号一一对应；
5. **表格逐格**：行数、列数、colspan 与官方一致；
6. **基线校验**：全程 md5 闭环记录可查。
