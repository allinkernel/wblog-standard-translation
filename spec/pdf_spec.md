# PDF 规范文档翻译规范（pdf_spec.md）

> **版本**：v1.4（2026-08-26；v1.4 采纳双 AI 第六轮微调：合并命令 find+xargs 流式、JSON 尾逗号清洗、Markdown 泄漏检查过滤 style/script 属性）
> **适用**：规范原文只有 PDF 版本（或官方以 PDF 为主发行，如 ISO 标准、IEEE 标准正式版、RFC PDF 版）。
> **不适用**：官方有 HTML 版 → 优先 `html_spec.md`（DOM 抽取→纯文本翻译→回填，格式保真度最高）；源是 markdown → `md_spec.md`。
> **配套**：`spec.md`（总入口与通用机制：三兄弟定义、触发审批、递归、成本、md5 双基线闭环、导读两阶段、知识卡片）。
> **执行区隔**：标有 **[Agent 执行]** 或"必须/禁止/一律/上限/铁律"的条目是硬性约束；其余为背景解释。

---

## 1. 总体流程

```
PDF 获取 → md5 基线
        │
        ▼
PDF → 文本提取（pdftotext / pdfplumber）＋ 章节边界（书签/TOC 识别）
        │
        ▼
文本清洗（去页眉页脚/页码/目录自身、修多列错序、识别表格区域）
        │
        ▼
按章节切分 → md5 基线 → 片段投递 LLM 直译（纯文本段对段镜像，输出 index.html）
        │
        ▼
知识卡片 → knowledge-index → 两阶段导读（通用机制见 spec.md 5.5，输出 index.html）
        │
        ▼
验证（段落/章节完整性、无遗漏）
```

**核心差异（与其他场景的本质区别）**：PDF 是**版式文档**——文本流是渲染出来的，不是结构化的。提取出的"纯文本"没有 HTML 标签、没有段落语义保证（换行≠段落），表格/代码块/列表的边界要靠启发式恢复。**质量上限取决于提取质量，提取质量必须先验证再开工。**

---

## 2. PDF 获取与基线

1. **下载**：`curl -s -o <dir>/source.pdf "<官方 URL>"`（或用户本地提供路径）。
2. **md5 基线（必须）**：`md5sum source.pdf > source.pdf.md5`——PDF 是二进制，**禁止直接传 LLM**（二进制经管道变乱码，见 spec.md 4.3 管道实测定论）。
3. 本场景 **LLM 永不接触 PDF 本身**：所有内容必须先在工具侧提取为文本，文本经 base64 + md5 闭环投递（通用机制见 spec.md 4.3）。

## 3. 文本提取（工具侧，LLM 不参与）

### 3.1 提取工具

| 工具 | 用途 | 备注 |
| --- | --- | --- |
| `pdftotext -layout source.pdf out.txt`（poppler-utils） | 保留版面布局的纯文本 | 默认首选；`-layout` 保留空格/缩进，利于恢复结构 |
| `pdfplumber`（Python） | 需要表格/坐标时 | `extract_table()` 提取表格、`extract_words()` 带坐标 |
| PDF 书签提取（`pdfinfo` / python `pypdf` 的 `outline`） | 章节边界 | 官方 PDF 通常带书签，直接映射章节号 |

### 3.2 提取后必须做的清洗（[Agent 执行]）

1. **去页眉页脚**：每页重复的标准名/章节名/页码行，正则或按坐标剔除（页眉页脚混入正文是最大污染源）。
2. **去目录页**：PDF 自带 TOC 页的条目会与正文重复，识别后整页跳过。
3. **多栏布局**：双栏 PDF 提取后文本左右交错，需按坐标（`x0`）分栏重排；若排版过于复杂无法自动修复，建议用户切换至 HTML 场景（若官方存在 HTML 版）。
4. **段落边界恢复（硬性）**：PDF 按行输出，**工具侧脚本必须把硬换行（Hard Wrap）合并为连续段落后再投递 LLM**——**单换行 = 段内拼合，双换行（空行）= 段落分隔**；严禁把"每行"当"段落"投递（否则 LLM 逐行翻译碎片化，或擅自合并段落导致段落数断言失败）。
   - **[Agent 执行] 拼段符号去噪净化**：拼合时必须自查拼接边界（前行尾/后行首），若含裸 `*`、`_`、`#`、`$` 等 Markdown/TeX 敏感触发符，**自动对其做实体转义或包 `<code>` 标签**——防"机械拼行把行首星号粘成 `text*`"触发后续 Markdown 泄漏拦截的假阳性断言。
5. **[Agent 执行] 降级中断协议（防热切换死锁）**：若抽查发现嵌入字体缺失导致大量 `□`/乱码，且换用提取工具无效——若官方存在 HTML 版：**子 Agent 禁止擅自继续或自行重载 html_spec**（fresh 上下文 + 静态快照锁下无权限切流），必须立刻把提取异常写入日志、向父 Agent 抛出标准状态码 `ERROR_FALLBACK_TO_HTML` 并终止当前进程；由**父 Agent** 统一解除快照锁、重新评估用户输入链接、切换 `html_spec.md` 流水线。用户坚持 PDF 时才降级继续。

### 3.3 章节切分

- 优先用**书签/目录**映射章节边界（章节号 → 页范围 → 文本范围）；
- 无书签时按"章节标题模式"（`^\d+(\.\d+)*\s+标题`）正则切分；
- 切分后每章一个文本文件（`<dir>/chapters/0001.txt`、`0002.txt`…），**四位数字零填充前缀命名**（0001-9999，封死超长卷 >1000 章节的排序溢出；通用机制见 spec.md 6.3）；
- 翻译完成后拼接：`export LC_ALL=C; find chapters/ -name "*.txt" | sort | xargs cat > index.html`（`xargs` 自动分批防 E2BIG；`*.txt` 全匹配无需前缀模式）；
- 每章 `md5sum` 记录基线。

### 3.4 表格与代码块

- **表格**：`pdfplumber.extract_table()` 提取为结构化行/列，投递 LLM 时**附带表题与表头语义上下文**（防"0"被误译为"零"，同 html_spec 3.2），投递格式统一为明文 JSON 骨架 + 仅 payload 走 base64（见 4 节投递通道）。
  - **[Agent 执行] 拼回前 HTML 转义**：LLM 返回的单元格译文拼回 `<td>`/`<th>` 前，**必须先做 HTML 转义**（`<`→`&lt;`、`>`→`&gt;`、`&`→`&amp;`），防译文中的"小于/大于"产生非法 HTML。
  - **[Agent 执行] 内联样式注入（防隐形表格）**：PDF 无官方 HTML 样式可继承，拼回 `<table>` 必须注入极简高兼容样式，统一声明：`<table border="1" cellspacing="0" cellpadding="5" style="border-collapse: collapse; border: 1px solid var(--border-color, #444); margin: 10px 0;">`——**严禁输出无样式裸标签**（浏览器/Pandoc 下呈现为不可读的隐形色块）。
- **代码块**：`pdftotext` 提取的代码块靠缩进识别（等宽字体区域），提取后原样保留，LLM 不译。
- 提取质量差（表格错乱/乱码）时：**降级为译者注**（"此处官方 PDF 表格提取失败，见原文 PDF 第 N 页"），不得卡死重试。

## 4. 直译（老二）

- **总原则**：语义零丢失 + 中文自然语序 + 结构镜像（段对段、条对条、层对层）——定义见 **spec.md 4.1 / 4.2**（通用），本节只列差异。
- **[Agent 执行] 交付格式（用户定稿）**：**PDF 输入同样以 HTML 输出**——直译结果统一保存为 `<dir>-translate/index.html`（html 输入 → html 输出、pdf 输入 → html 输出；**不接受 markdown 输出方案**）。文本结构用 HTML 标签表达：章节标题 `<h2>`/`<h3>`/`<h4>`、段落 `<p>`、有序列表 `<ol><li>`（**编号保留原文数字**）、无序列表 `<ul><li>`、代码块 `<pre>`、表格 `<table>`。
- **[Agent 执行] 投递通道（base64 + md5，禁裸文本）**：切分后的章节文本/片段投递 LLM **必须经 base64 编码**（禁止裸文本直接进管道，防 `[redacted]` 替换），严格执行 spec.md 4.3 的 base64 + md5 双基线校验；**结构化投递（表格上下文）统一格式**：JSON 骨架明文 + 仅待翻译纯文本字段 base64——`{"context": "明文语义提示", "b64_payload": "<仅待翻译纯文本的 base64>", "chunk_md5": "<payload 解码后的 md5>"}`（**严禁把整个 JSON 打包进 base64**，高熵结构会让 LLM 心算解码错位漏字符）。
- **[Agent 执行] 成本熔断与崩溃恢复（显式继承 spec.md 1.6）**：单 Agent 轮数 ≤15（或步数 400），超限熔断并写入 `.codewhale/crash_report.json`（当前进度、片段路径、校验哈希、错误卡点）；复工读 JSON 恢复，不依赖超长上下文。
- **[Agent 执行] 译文结构化流式返回镜像协议**：LLM 返回翻译结果**必须镜像输入的明文 JSON 骨架，拒绝自由文本/裸中文输出**——否则回填脚本在流式输出错位、漏键时 `json.loads()` 直接崩溃或节点错位。**输出强制为纯 JSON 数组**：`[ {"index": 1, "translated_text": "中文译文"}, ... ]`；工具侧必须利用 `index` 序号原位回填（表格单元格按 index 拼回 `<td>`）与单节点断言，`json.loads()` 失败或 index 对位失败时在该节点级重试，**严禁接受无序号的裸文本返回**。
- **[Agent 执行] 返回 JSON 弹性去噪（防尾逗号地雷）**：LLM 流式输出长数组时存在末尾多吐尾逗号的肌肉记忆，`json.loads()` 零容忍。工具侧解析前**必须强制清洗**：`text = re.sub(r',\s*\]', ']', text)`——全局抹掉 `[... ,]` 形式的末尾冗余逗号后再 `json.loads()`。
- **参考实现**：`../tools/json_filler.py`（尾逗号清洗 + `json.loads` 容错 + index 完整性校验 + HTML 转义 + 原位回填回调 + 节点级重试信息），表格单元格拼回 `<td>` 与直译回填均适用。
- 本场景的镜像对象是**提取后的文本结构**（无官方 HTML 标签可抄）：**段落 ↔ 段落、列表 ↔ 列表、代码块 ↔ 代码块** 一一对应即可；**项目符号/行宽/字体等纯排版不复制**（用户明确）。
- 章节编号（1. 2. 3.）与子编号（1.1、1.1.1）**必须保留原文数字**，不得重排。
- 交叉引用：原文写"见 2.3 节"→ 译文"见 2.3 节"，编号不变；有页引用（"见第 45 页"）→ 保留页码或注明"原文第 45 页"。
- 术语表与情态词规则（shall→应、may→可以、should→宜）见 **spec.md 附录 A**（通用）。
- 特殊记号（函数名、变量名、命令名、token 名）原样保留不译。

## 5. AI 导读（老三）

- 目标、语言要求、标题铁律、知识卡片两阶段机制全部见 **spec.md 5.x**（通用，标题铁律与 md_spec 第 6 节一致）。
- **交付格式**：导读结果统一保存为 HTML（`<dir>-AI-guide/index.html`），与直译同编号结构。
- **[Agent 执行] 知识卡片锚点替代（PDF 无 DOM 锚点）**：附录 C 卡片的"重要锚点"栏一律用 **"章节号/页码 + 原文独特文本特征短语"**（如 `第 3.2 节 (第 15 页) - "The order of evaluation..."`），供按需投递时 `grep`/python `find` 定位；交叉引用同样用"原文第 N 页 / 第 N 章"文字引用。

## 6. 验证清单

1. **提取质量前置验证（开工前必做）**：抽查 3-5 个章节，确认页眉页脚已清、段落边界正确、无乱码（嵌入字体缺失导致 `□`/乱码时换提取工具或降级）；
2. **章节完整性**：提取出的章节清单与官方目录一一对应（缺章 = 切分失败，先修切分再翻译）；
3. **段落对应**：译文章节数 == 原文章节数；每章段落数偏差 ≤ 容差（人工抽查）；
4. **表格/代码块**：数量与原文一致（脚本对比提取标记）；
5. **残留检查**：无未翻译英文段落（排除代码块/术语）、无 TODO/占位残留；
6. **标题一致性**：直译/导读标题编号与原文一致（官方有而译文无 = 漏节，译文有而官方无 = 自造编号）。
7. **HTML 产物校验**：直译/导读的 `.html` 用 python `html.parser` 解析，`<table>`/`<pre>`/`<ol>`/`<ul>` 标签闭合无误、无残留未转义字符。
8. **[Agent 执行] Markdown 语法泄漏拦截**：检查 HTML 文本节点无未渲染的 markdown 语法（`**`、`###`、`[text](url)`）；标题必须是 `<h2-h4>`，加粗必须是 `<b>`/`<strong>`；**解析时必须过滤 `<style>`/`<script>` 内容与各标签 `style`/`class` 属性值**——防内联样式里的 `#444`、`--border-color` 等被误判为 markdown 标题/标记的假阳性。

## 7. PDF 场景常见陷阱速查

1. **PDF 是二进制，永不直接传 LLM**（管道变乱码）；一切内容先工具侧提取为文本，文本走 base64 + md5 闭环。
2. 页眉页脚/页码混入正文是最大污染源——清洗不彻底，翻译全是垃圾输入。
3. 双栏 PDF 提取后左右交错，必须按坐标分栏重排；搞不定就建议用户提供 HTML 版。
4. 提取的"行"不是"段落"，必须先拼回段落再投递，否则 LLM 逐行翻译产生碎片化译文。
5. 嵌入字体缺失 → 乱码/`□`；先修提取再翻译，不要带病翻译。
6. 表格提取失败 → 降级译者注，不卡死重试；官方有 HTML 版时优先切换 `html_spec.md`。
7. 交叉引用无锚点，用"第 N 章 / 第 N 页"文字引用。
8. **产物是 HTML 不是 markdown**（用户定稿）：PDF 输入同样输出 index.html，结构用 HTML 标签表达。
