2.1 Shell 简介（Shell Introduction）

本节在说什么

Shell 是命令语言解释器。第 2 章整章就是这部命令语言的”语法书 + 语义书”——它同时约束三个使用方：

  1. sh 实用程序（交互式 shell 与脚本解释器）；
  2. C 语言接口 system()（把字符串交给 shell 执行）；
  3. C 语言接口 popen()（把命令的输出接到管道上）。

核心机制：七步操作流程

规范给出一份总览，shell 对每一条命令循环执行七个阶段，理解这个顺序是理解全章的地图：

  1. 读取输入：从文件、-c 字符串、标准输入或 system()/popen() 取输入。注意第一条规则里的细节：如果脚本文件第一行以 #! 开头，结果未指定（这个由内核的 shebang 机制处理，不属于 shell 语言本身）。
  2. 拆成 token：把输入字符流切成”词（word）“和”运算符（operator）“（2.3）。
  3. 解析：把 token 序列组织成简单命令（2.9.1）和复合命令（2.9.4）的语法结构（2.10）。
  4. 单词扩展：先处理 $'...' 里的反斜杠转义，再按严格顺序执行 2.6 定义的各类扩展——参数扩展、命令替换、算术扩展等。
  5. 重定向：执行重定向，并把重定向运算符和它的操作数从参数列表里移除（它们不是传给命令的参数）。
  6. 执行：依次查找函数 → 特殊内置 → 普通内置 → 可执行文件/脚本，把扩展后的字段作为位置参数 $1…$n，命令名作为特殊参数 $0。
  7. 等待与收集：同步命令等待完成并收集退出状态；异步命令（& 结尾）立即返回。

这张七步地图是理解 2.2–2.15 的骨架：后面每一节都在细化其中某一步。

2.2 引用 / 转义（Quoting）

本节在说什么

引用（quoting）的作用是”关闭”字符的特殊含义。shell 里很多字符（$、`、\、空格、*、; 等）在语法上有特殊身份，引用让你能按字面使用它们。规范给出四种引用机制，各有各的”保留”和”不保留”。

核心机制：四种引用对照

机制 写法 保留所有字面值？ 例外/特殊行为
反斜杠 \x 仅对紧跟的单个字符 后跟换行是”续行”，\ 与换行一起被删除
单引号 '...' 全部 内部不能出现单引号（无任何转义手段）
双引号 "..." 大多数 $ ` 与特定场景的 \ 仍特殊；$'...' 的引入被关闭
美元单引号 $'...' 大多数 支持 ANSI C 风格转义序列（\n、\x41、\101、\cA…）

关键机制逐个拆

反斜杠（2.2.1）——最”弱”的引用：只保一个字符。两个注意点：

  • \ + 换行 = 续行：两字符在切 token 前被一起删除，命令可以跨行书写而不产生换行 token。
  • 在单引号内 \ 是普通字符；在双引号内 \ 只有后跟 $、`、\、"、换行时才有转义意义。

单引号（2.2.2）——最”强”的引用：内部一切字面。代价：无法表示单引号本身，需要 '“’”`（关一个、开一个、引一个）这类拼接技巧。

双引号（2.2.3）——引用与扩展的平衡点：$ 和反引号仍引入扩展，但扩展结果不经过字段分割（"$var" 里的空格不会被拆词）。这是 shell 中最常用的引用。两个易错点：

  • $ 在双引号内不引入 $'...' 形式；
  • 双引号内的 "$(...)"、"${...}" 内部，双引号本身对特殊字符的处理会被”让位”——规则较细，读原文 2.2.3 的三段。

美元单引号（2.2.4）——“C 字符串”：$'...' 里可以写 \n、\t、\xNN、\ddd、\cX 等转义，用于生成控制字符/任意字节。注意 \x 后超过两个十六进制数字、或八进制值放不进一个字节时，结果是未指定/未定义。

2.3 Token 识别（Token Recognition）

本节在说什么

把输入切成 token：要么是 word（词），要么是 operator（运算符）。识别规则定义了”什么样的字符序列算一个词”。

核心机制

运算符表：| & ; ( ) < > 以及 &&、||、;;、<<、>>、<&、>&、<>、<<-、>| 等组合。运算符把输入切成多个部分；需要按字面使用这些字符时，必须引用它们。

需要引用的字符：除了运算符，$、`、\、"、'、空格、制表、换行在特定位置需要引用才能表示自身（例如想让空格成为参数的一部分，必须加引号）。

词法处理的顺序细节（规范用编号列表给出）：

  • 每条注释从 # 到行尾被丢弃（但 # 不是运算符的一部分）；
  • 别名替换在 token 分类之后进行（见 2.3.1）；
  • 换行符是 token 分隔符；
  • 引号影响”当前字符是否被引用”的状态，进而决定字符是否参与特殊识别。

这里有一条重要的整体原则：切 token 发生在任何扩展之前。$var 先被切成一个词，扩展发生在词内部——所以 $var 扩展出来的空格不会重新触发切词（那是 2.6.5 字段分割的事，用的是 IFS，不是语法空格）。

2.3.1 别名替换（Alias Substitution）

别名机制：在 token 被识别为 TOKEN 类型后，如果满足条件（token 无引用字符、是有效别名名、别名当前生效、未被更高层递归使用、能解析为命令名位置），就用别名的值替换该 token，并从别名值的开头重新开始 token 识别。

机制上的关键点：

  • 替换后如果别名值以”替换后未引用的空格/制表”结尾，shell 会继续检查下一个 token 是否也要别名替换——这就是 alias ll='ls -l' 能工作的原理（值末尾的空格让后续 token 继续被检查）；
  • 别名是否生效对保留字位置的判断：如果 token 在输入中会作为保留字出现，是否替换别名是未指定的——所以别名定义和保留字（如 if）之间有条模糊地带，规范特意留白；
  • 别名不跨 shell 调用继承，脚本里定义别名通常只在当前执行环境有效。

2.4 保留字（Reserved Words）

本节在说什么

保留字是 shell 语法结构的关键词：if then else elif fi do done case esac while until for { } ! in 等。它们在特定语法位置是保留的——注意措辞：保留字只有在语法需要它们的位置才作为保留字被识别。

核心机制

  • 保留字的识别发生在语法状态下：解析器处于”这里只能出现保留字”的状态时，匹配的 token 才被当作保留字（这正是 2.3.1 别名替换和它的相互作用点）。
  • 一个词不是保留字的情形：被引用的词（'if' 不会触发 if 语法）、以及不作为语法关键词出现的位置（echo if 中的 if 是普通参数）。
  • 保留字名单以 # 结尾的条目（如 time）历史上可带参数，具体以原文列表为准。

2.5 参数与变量（Parameters and Variables）

本节在说什么

shell 的参数（parameter） 三大家族：位置参数（$1…）、特殊参数（$0 $# $? $* $@ $- $$ $!）、Shell 变量（用户自定义 + 环境变量）。这一节定义了它们的语义。

2.5.1 位置参数（Positional Parameters）

  • 由命令调用传入：$1…$n，$0 是特殊参数（命令名/脚本名）。
  • 语法上：单数字 $n 只能到 9，多位数必须用花括号 "${10}"。
  • 位置的设定手段：set（2.26）、脚本调用、函数调用（函数内位置参数是函数自己的）。

2.5.2 特殊参数（Special Parameters）——速查表

参数 含义 关键机制
$0 命令名/脚本名 函数内是函数名；脚本内是脚本名
$# 位置参数个数
$? 上一个管道（命令）的退出状态 是管道最后一条命令的状态（见 2.9.2）
$* 所有位置参数，一个字段 双引号内 "$*" 用 IFS 首字符连接
$@ 所有位置参数，各自成字段 双引号内 "$@" 保留每个参数的边界——最常用的写法
$- 当前选项标志 如 set -x 后包含 x
$$ 当前进程 ID 子 shell 内仍是”外层”进程 ID？——不，是当前 shell 的
$! 最近后台命令的进程 ID

最容易错的两个：

  • "$@" vs "$*"："$@" 把每个参数当作独立字段（保留空参数），"$*" 合并成一个字段——脚本里传参几乎永远应该用 "$@"。
  • $? 取的是最近完成的管道的状态：false | true 的 $? 是 0（取 true）。

2.5.3 Shell 变量（Shell Variables）

  • 变量 = 名称 + 值，名称由字母、数字、下划线组成（数字不能开头）。
  • 环境变量 → Shell 变量：从环境初始化的变量自动标记为 export；变量赋值可以创建新变量。
  • export 属性：决定变量是否进入子进程环境（2.23）。
  • 只读属性（2.24）：一旦标记，不能被赋值/取消设置（但函数/变量定义可先删除再重建？——规则见 2.30）。
  • 规范对一组常用变量有默认语义约定：HOME、PATH、IFS、LANG、LC_*、PS1、PS2、PS4、ENV、PPID、PWD、OLDPWD、SHELL、MAIL、TMPDIR 等——其中 IFS（字段分割）、PATH（命令搜索）、PS1/PS2（提示符）是机制性的。

2.6 单词扩展（Word Expansions）

本节在说什么

单词扩展（word expansion） 是 shell 语义的核心：一个词在解析后、执行前，要经过七个按严格顺序执行的处理阶段。顺序本身是规范的重头戏——顺序错了，结果就错。

核心机制：七阶段扩展顺序

顺序 阶段 作用 关键点
1 波浪号展开（2.6.1） ~ → 用户主目录 ~user、~/path；赋值语境里的 ~ 也展开
2 参数扩展（2.6.2） $var、${var:-def} 等 最丰富的语法家族
3 命令替换（2.6.3） `cmd`、$(cmd) 在子 shell 环境执行
4 算术扩展（2.6.4） $((expr)) C 语言风格整数运算
5 字段分割（2.6.5） 按 IFS 切分 只有前 4 步的未引用结果才切分
6 路径名展开（2.6.6） * ? [...] → 文件名 不匹配则原样保留
7 引用消除（2.6.7） 删除引用字符 最后一步

全局规则（规范原文强调）：1–4 步”从开始到结束依次执行”；字段分割和路径名展开不作用于由 1–4 步产生的、出现在双引号内的部分。

2.6.1 波浪号展开（Tilde Expansion）

  • 词首的 ~（未引用）后跟 $HOME 或登录名 → 替换为主目录路径。
  • 赋值语境：第一个 = 之后、以及任何未引用 : 之后的 ~ 也展开（所以 PATH=~/bin:$HOME/bin 两处都展开）。

2.6.2 参数扩展（Parameter Expansion）——最丰富的语法

基本形式 ${parameter}，花括号可选（多位数位置参数、或变量名后紧跟会被当作名字一部分的字符时必须用）。

条件语法家族（基于”是否设置 + 是否为空”两个状态）：

语法 参数设置且非空 设置但为空 未设置
${p:-word} p word word
${p-word} p 空 word
${p:=word} p 赋 word 并返回 赋 word 并返回
${p=word} p p（空） 赋 word 并返回
${p:?word} p 报错退出 报错退出
${p?word} p 空 报错退出
${p:+word} word 空 空
${p+word} word word 空

带 : 的版本把”空字符串”也当作”未设置”处理——这是 : 的全部意义。

子串处理家族：${#p}（长度）、${p%pat} / ${p%%pat}（去尾）、${p#pat} / ${p##pat}（去头）、${p/pat/rep}（替换，POSIX 之外的扩展在 XSI 中）。注意 %/# 与模式匹配（2.14）配合，是路径/后缀处理的主力工具。

2.6.3 命令替换（Command Substitution）

  • 两种写法：`cmd`（传统）和 $(cmd)（现代，推荐——可嵌套、引号处理简单）。
  • 机制：在子 shell 环境中执行 cmd，把标准输出（去掉末尾换行）替换进词里。
  • 字段分割规则：不带引号的命令替换结果会经受字段分割和路径名展开；带引号（"$(cmd)"）则不。"$@" 式的例外不适用于普通命令替换。

2.6.4 算术扩展（Arithmetic Expansion）

  • $((expr))：整数表达式，语法接近 C：+ - * / %、比较、逻辑、位运算、变量名直接求值（$x 与 x 都行）、++/--、三目 ?:。
  • 变量在算术语境中按数值解释；对未定义变量按 0 处理（实现定义符号常量名等）。
  • 前缀 +/- 可选；结果按十进制输出（某些情况如 $((#x)) 是 XSI 扩展）。

2.6.5 字段分割（Field Splitting）

  • 用 IFS 的值做分隔符：空白类（空格/制表/换行，连续出现合并且开头结尾的被丢弃）与非空白类（每个出现都算一个分隔符）。
  • 只对未引用的扩展结果执行：$var（未引用）会切分，"$var"（引用）不会——这是”为什么要给变量加引号”的规范根源。
  • IFS 未设置时等价于 空格+制表+换行；IFS 为空则不切分。

2.6.6 路径名展开（Pathname Expansion）

  • * 匹配任意串（含空）、? 匹配单字符、[...] 括号表达式（可含范围 [a-z]、字符类 [[:alpha:]]、取反 [!a]）。
  • 点文件规则：文件名开头（或紧跟 /）的 . 必须显式匹配——* 不匹配隐藏文件。
  • 匹配结果按 locale 整理序列排序；无匹配时模式原样保留（不是报错！）。

2.6.7 引用消除（Quote Removal）

最后一步：把 \、'、" 这些引用字符从词中删除。执行后 shell 仍记得哪些字符曾被引用（这在 case 模式匹配等处有后续语义）。

2.7 重定向（Redirection）

本节在说什么

重定向改变命令的文件描述符的指向：从文件读、写到文件、追加、复制 fd、关闭 fd、here-document。语法是 [n]运算符 word（n 是 fd 号，默认 0/1/2 依运算符而定）。

核心机制：运算符表

运算符 含义 默认 fd
< 从文件读入 0（stdin）
> 覆盖写 1（stdout）
>> 追加写 1
>& 复制输出 fd（2>&1） 1
<& 复制输入 fd（0<&3） 0
<> 读写打开 0
<< / <<- here-document 0
>| 覆盖写（无视 noclobber） 1

关键机制：

  • 执行顺序：多个重定向从左到右求值——所以 2>&1 >file 和 >file 2>&1 语义不同（前者 stderr 先指向旧 stdout，后者都指向 file）。
  • 重定向的 word 经受波浪号/参数/命令/算术扩展和引用消除，但不做路径名展开（非交互 shell）。
  • 重定向错误是 shell 错误，可能中止 shell（非交互）——见 2.8.1。
  • n>| 用于 set -C（noclobber）生效时强制覆盖。

2.7.4 Here-Document（立即文档）

  • << 后的 word 是定界符；后续行直到单独一行”只有定界符”为止全部作为 stdin。
  • 引用定界符 = 关闭扩展：<<'EOF' 时内容完全字面；<<EOF 时内容经受参数/命令/算术扩展、命令替换。
  • <<- 删除每行前导的制表符（方便缩进书写）。
  • 多条 here-doc 按出现顺序消费输入。

2.8 退出状态与错误（Exit Status and Errors）

本节在说什么

定义两类”状态”：命令的退出状态（0=成功、非零=失败）和 shell 错误的后果（哪些错误致命、哪些可恢复）。

核心机制

2.8.1 错误的后果：

  • 语法错误（如 if 没有 then）：非交互 shell 直接退出；交互 shell 报错并继续。
  • 重定向错误、变量赋值错误（如给只读变量赋值）：按是否特殊内置区分——特殊内置的错误可能中止 shell。
  • 交互/非交互的分界线是这一节的主线。

2.8.2 命令的退出状态：

  • 0 = 成功；1–125 = 应用可用的失败码；126 = 找到但不可执行；127 = 未找到；>128 = 被信号终止（128 + 信号号是惯例）。
  • 管道（2.9.2）的退出状态 = 最后一条命令的状态（set -o pipefail 之外，POSIX 基本版不强制 pipefail）。

2.9 Shell 命令（Shell Commands）

本节在说什么

定义命令的结构层次：简单命令 → 管道 → 列表 → 复合命令 → 函数。这是执行模型的主体。

核心机制：命令层次

AND-OR 列表（&& / ||）
   └── 列表（; & 分隔）
         └── 管道（|）
               └── 简单命令 / 复合命令

2.9.1 简单命令：[赋值...] [单词...] [重定向...]。处理顺序：识别赋值/重定向 → 扩展第一个词找到命令名 → 执行重定向 → 扩展赋值 → 执行。

  • 变量赋值的归属：赋值影响当前环境还是子环境，取决于命令名是谁：特殊内置→当前环境；函数→看函数内；普通命令→子环境（只对那个命令生效）。
  • 声明型实用程序（如 export、readonly）：跟在它后面的 name=word 按赋值上下文展开（不切分、不路径名展开）。

2.9.2 管道：cmd1 | cmd2。每条命令在子 shell 中执行（POSIX 允许最后一条在当前环境实现，但语义上按子 shell 描述）；退出状态取最后一条。

2.9.3 列表：; 顺序执行、& 异步后台、&&/|| 短路（左结合，与 C 相同）。

2.9.4 复合命令：语法结构块：

结构 语法 语义要点
分组 ( list ) 子 shell 环境
分组 { list; } 当前环境（注意末尾必须 ; 或换行）
条件 if c; then ...; fi
循环 while/until 条件列表的退出状态决定
循环 for for name in words
选择 case w in pat) ...;; 模式匹配第一个命中（2.14）
双括号 [[ ... ]] XSI 扩展，非 POSIX 基本

2.9.5 函数定义命令：name() compound-command（POSIX 语法）或 function name（XSI）。函数：在当前环境执行、可递归、位置参数独立。

延伸阅读

  • 2.10 形式文法（上面所有结构的精确定义）
  • 2.13 执行环境（子 shell 是什么）

本节在说什么

核心机制

  • 2.10.1 词法约定：token 类型（WORD、IO_NUMBER、运算符）、保留字识别规则、%token 表。

2.11 作业控制（Job Control）

本节在说什么

交互式 shell 里后台作业与前台作业的管理模型：bg、fg、jobs、wait 的底层语义，以及作业与进程组、终端的关系。

核心机制

  • 作业（job）：由一个管道构成的进程组；有作业号（[1]、[2]）。
  • 控制终端：前台作业组获得终端访问；后台作业组读终端会收到 SIGTTIN，写会收到 SIGTTOU。
  • jobs -p 输出进程组 ID；wait 等待后台作业并返回其状态。
  • 实现细节留给实现：作业控制的可选性（XSI 扩展）、监控（job control）是否开启。

2.12 信号与错误处理（Signals and Error Handling）

本节在说什么

shell 如何对待信号：哪些信号默认动作、哪些被忽略、trap 的挂接点、以及”shell 等待子进程时收到信号”的行为。

核心机制

  • 信号处理与 trap（2.29）联动；交互 shell 对 SIGINT/SIGQUIT 的处理有特殊性（等待命令时收到信号，shell 行为未指定）。
  • 异步列表（&）中命令的信号处理独立于交互 shell。
  • trap 动作的执行点：命令完成、等待时、子 shell 继承规则（2.13）。

2.13 Shell 执行环境（Shell Execution Environment）

本节在说什么

定义”执行环境”这个核心抽象：shell 在什么状态下执行命令，子 shell 复制了什么、没复制什么，环境如何继承。

核心机制

执行环境包含：shell 变量（及其 export 属性）、当前工作目录、文件描述符、umask、信号 trap 设置、函数定义、别名、shell 选项、$! 等。

子 shell（subshell）环境的继承规则——三个层级：

  1. 子 shell 继承（( list )、管道成员、命令替换等）：复制父环境的所有属性，但子 shell 内的修改（变量赋值、cd、重定向）不传回父环境；未忽略的 trap 在子 shell 中重置为默认动作。
  2. 命令执行环境（执行外部命令）：只传导出变量、fd（0/1/2 及未关闭的高 fd）、umask、信号默认/忽略设置等。
  3. 函数执行环境：增加位置参数/$0 的局部化。

易错点：cd、export、umask 在子 shell 里的修改”丢失”——这是 (cd dir && cmd) 惯用法的依据；exec（2.21）则替换整个 shell。

2.14 模式匹配记号（Pattern Matching Notation）

本节在说什么

模式（pattern） 的语法与语义：*、?、[...] 括号表达式。这套记号同时服务于 case、参数扩展的 #/%、路径名展开和 [[ = ]]。

核心机制

2.14.1 单字符模式：

  • ?：匹配任意一个字符。
  • *：匹配任意（含空）字符串。
  • [...] 括号表达式：字符类 [[:alpha:]]、范围 [a-z]、取反 [!a]（在 POSIX 正则中 ^ 的角色在此用 !）。

2.14.2 多字符模式：* 的匹配规则（零或多个字符）。

2.14.3 用于文件名展开的模式——路径名特有的三条规则：

  1. / 必须显式匹配（* 不能跨目录）；
  2. 前导 . 必须显式匹配（隐藏文件规则）；
  3. 模式与文件名按当前 locale 排序比较。

与正则的差异：shell 模式不是正则！* 在正则里是”前一个字符重复”，在模式里是”任意串”；^/$ 锚点不存在；括号表达式的 ! 取反而不是 ^。这是初学者的头号混淆点。

2.15 特殊内置实用程序（Special Built-In Utilities）

本节在说什么

15 个特殊内置（官方编号 2.16–2.30）：break、colon、dot、eval、exec、exit、export、readonly、return、set、shift、times、trap、unset（加上 2.17 的 colon 共 15 个，即 break/colon/continue/dot/eval/exec/exit/export/readonly/return/set/shift/times/trap/unset）。

核心机制：特殊内置 vs 普通内置

两条区别（规范原文的要点）：

  1. 错误后果：特殊内置中的错误可能导致 shell 中止（非交互）；普通内置不会。
  2. 赋值归属：特殊内置前的变量赋值影响当前执行环境（FOO=bar set ... 里的 FOO=bar 是当前环境的）；普通内置则否。

共同点：无需 fork 外部进程，在 shell 内部实现；exec 函数族不一定能访问它们（不必提供可执行文件）。

速查表（详见 2.16–2.30）：

工具 一句话 常用场景
break / continue 退出/继续循环 循环控制
colon : 空命令（返回 0） 占位、给 if/while 填空
dot . 在当前环境执行文件 脚本”源入”（source）
eval 拼接参数为命令再执行 动态构造命令
exec 替换 shell 或仅做重定向 优化、重定向当前 shell
exit 退出 shell 设置退出码
export 标记变量进环境 导出变量
readonly 标记只读 保护变量
return 从函数/点脚本返回 函数返回值
set 设置选项/位置参数 调试开关（-x/-e）
shift 丢弃位置参数 参数解析
times 打印累计 CPU 时间 计时
trap 注册信号/EXIT 处理 清理、信号处理
unset 删除变量/函数 清理环境

2.16–2.30 特殊内置逐条速查

以下各节按官方编号对应原文。每节给出：机制要点（规范怎么说）+ 易错点。

2.16 break

  • break [n]：退出第 n 个外层循环（默认 1）。
  • “外层”的定义：词法上包含该命令的循环（同执行环境中 do-group 的 compound-list 内）。
  • 易错：n 必须是正十进制整数（对应用的要求，不是 shell 的）；n 大于循环数时用最外层；无外层循环时行为未指定。

2.17 colon（空命令）

  • : 永远返回 0，不做任何事（不处理参数、不识别 --）。
  • 用途：while :; do ...; done 死循环、给分支占位、在脚本中留注释位。

2.18 continue

  • continue [n]：回到第 n 个外层循环的顶部。
  • “外层”的定义与易错点同 2.16 break。

2.19 dot（在当前环境执行文件）

  • . file：token 化、解析、在当前环境执行文件内容（区别于脚本的子 shell 执行）。
  • file 无斜杠 → 按 PATH 搜索，但不要求可执行（读权限即可）。
  • 解析为 program 还是单个 compound_list：未指定（影响别名生效时机）。
  • 易错：找不到可读文件时，非交互 shell 中止。

2.20 eval

  • eval [argument...]：参数用空格拼接成字符串 → 重新 token 化、解析、执行。
  • 典型用途：动态构造命令（但要警惕注入风险）。
  • 不要求识别 --；参数以 - 开头时建议 eval " $cmd" 保护。

2.21 exec

  • 无操作数：只做重定向，作用于当前 shell（exec 3<file）。
  • 有操作数：用该实用程序替换当前 shell 进程（exec cmd）。
  • 失败时：非交互 shell 退出；交互 shell 只在子 shell 环境可退出。
  • 易错：exec 后的代码不会执行（进程已被替换）。

2.22 exit

  • exit [n]：退出当前执行环境。子 shell 中退出只退出子 shell。
  • n 的规则：0–255 正常状态；>256 且对应信号则”被信号终止”；非法值未指定。
  • EXIT trap：trap ... EXIT 在 shell 终止前执行（但 trap 动作里再 exit 则立即退出）。
  • 无 n 时用 $? 的当前值。

2.23 export

  • export name[=word]...：给变量标记 export 属性（进入子进程环境）；-p 打印所有导出变量。
  • 声明型实用程序：export X=$(false) 里的赋值在赋值上下文展开——所以 $? 是 0（export 成功），即使命令替换失败。
  • 输出格式 export name=value 可直接回读恢复。

2.24 readonly

  • readonly name[=word]...：标记只读（不能修改、不能 unset）。
  • 与 export 同为声明型实用程序：name=word 按赋值上下文处理。
  • 易错：只读变量在子 shell 也不能改（属性随环境继承）。

2.25 return

  • return [n]：从函数或 .（dot）脚本返回；无参数时用 $?。
  • 在函数外调用：非交互 shell 可能中止；交互 shell 行为未指定。

2.26 set

  • 三大功能：设置/取消 shell 选项（-o 选项表 14 项）、设置位置参数（set -- a b c）、设置 $1 等。
  • 常用选项：-e（errexit，命令失败即退出）、-x（xtrace，跟踪执行）、-f（noglob，关闭路径名展开）、-u（nounset，未定义变量报错）、-C（noclobber）、-v（verbose）。
  • set -- 清空位置参数；set - / set + 组合用于恢复。
  • 易错：set -e 的陷阱（条件表达式、!、函数内等上下文中的失败不触发退出）——规范列了 3 条例外，务必精读。
  • -o 选项表：allexport、braceexpand、errexit、hashall、ignoreeof、interactive-comments、monitor、noclobber、noexec、noglob、nojobcontrol、nounset、notify、onecmd、physical、pipefail（XSI）、posix、privileged、verbose、vi、xtrace 等。

2.27 shift

  • shift [n]：丢弃前 n 个位置参数（默认 1）。
  • n 必须是非负整数且 ≤ $#（超出时未指定——POSIX 定义此行为未指定，但常见实现报错）。

2.28 times

  • times：打印 shell 及其子进程的用户/系统 CPU 时间（格式 %dm%fs 等）。
  • 用于粗粒度计时。

2.29 trap

  • trap action condition...：注册对信号/EXIT 的处理；trap -p 打印当前 trap；trap - COND 恢复默认。
  • 条件名：信号名（INT、TERM…）、编号、EXIT（0）、ERR/DEBUG（非 POSIX 基本，XSI/扩展）。
  • 机制要点：
    • 非交互 shell 中，被忽略的信号在 trap 后仍被忽略；
    • 子 shell 继承 trap 但未忽略的 trap 在子 shell 重置为默认；
    • trap 动作执行时，$? 是 trap 触发前的状态；
    • 空 action（trap '' INT）= 忽略信号。
  • 易错：trap 'cmd' 0 与 trap 'cmd' EXIT 等价（0 是 EXIT）。

2.30 unset

  • unset [-fv] name...：删除变量（-v）或函数（-f）；默认变量（存在同名函数时是否也删未指定）。
  • readonly 变量不能 unset（但会移除 readonly 之外的其他属性——Issue 8 澄清）。
  • 易错：VAR=（赋空）≠ unset VAR——前者变量仍存在（“已设置但为空”），后者完全删除（“未设置”），两者在 ${var:-def} 下的行为不同（带 : 时相同，不带时不同）。
