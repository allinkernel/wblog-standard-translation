sed

名称 (NAME)

sed — 流编辑器（stream editor）

概要 (SYNOPSIS)

sed [-En] script [file...]
sed [-En] -e script [-e script]... [-f script_file]... [file...]
sed [-En] [-e script]... -f script_file [-f script_file]... [file...]

描述 (DESCRIPTION)

sed 实用程序是一个流编辑器，它应（shall）读取一个或多个文本文件，根据一个编辑命令脚本进行编辑修改，并将结果写入标准输出。该脚本应（shall）从 script 操作数字符串或 -e script 与 -f script_file 选项的选项参数组合中获取。

选项 (OPTIONS)

sed 实用程序应符合 XBD 12.2 实用程序语法准则，但 -e 和 -f 选项的呈现顺序是有意义的（is significant）。

应支持以下选项：

-E
使用扩展正则表达式匹配。将每个指定的模式视为 ERE，如 XBD 9.4 扩展正则表达式 所述。
-e script
将由 script 选项参数指定的编辑命令添加到编辑命令脚本的末尾。
-f script_file
将文件 script_file 中的编辑命令添加到编辑命令脚本的末尾。
-n
抑制默认输出（默认情况下，每行在被检查编辑后被写入标准输出）。只写入显式选择输出的行。

如果指定了任何 -e 或 -f 选项，则编辑命令脚本最初应为空。每个 -e 或 -f 选项指定的命令应按指定顺序添加到脚本中。每次添加时，如果前一次添加（若有）来自 -e 选项，则应在新的添加内容之前插入一个 <newline>（换行）。生成的脚本应具有与 script 操作数相同的属性，如操作数（OPERANDS）一节所述。

操作数 (OPERANDS)

应支持以下操作数：

file
其内容被读取和编辑的文件的路径名。如果指定了多个 file 操作数，则应按指定顺序读取命名文件，并编辑它们的拼接结果（concatenation）。如果未指定 file 操作数，则应使用标准输入。
script
用作编辑命令脚本的字符串。应用（application）不应提供违反文本文件限制的 script，但最后一个字符不必是 <newline>。

标准输入 (STDIN)

如果未指定 file 操作数，则应使用标准输入；如果 file 操作数为 '-' 且实现将 '-' 视为标准输入，也应使用标准输入。否则，不应使用标准输入。参见输入文件（INPUT FILES）一节。

输入文件 (INPUT FILES)

输入文件应为文本文件。-f 选项命名的 script_file 应由编辑命令组成。

环境变量 (ENVIRONMENT VARIABLES)

以下环境变量应影响 sed 的执行：

LANG
为未设置或为空的国际化变量提供默认值。（关于用于确定 locale 类别值的国际化变量的优先级，参见 XBD 8.2 国际化变量。）
LC_ALL
如果设置为非空字符串值，则覆盖所有其他国际化变量的值。
LC_COLLATE
确定用于正则表达式内范围（ranges）、等价类（equivalence classes）和多字符排序元素（multi-character collating elements）行为的 locale。
LC_CTYPE
确定用于将文本数据的字节序列解释为字符（例如，参数和输入文件中的单字节与多字节字符）的 locale，以及正则表达式内字符类（character classes）的行为。
LC_MESSAGES
确定应用于影响写入标准错误的诊断消息格式和内容的 locale。
NLSPATH
[XSI] 确定消息对象和消息目录的位置。

异步事件 (ASYNCHRONOUS EVENTS)

默认。

标准输出 (STDOUT)

输入文件应写入标准输出，并应用脚本中指定的编辑命令。如果指定了 -n 选项，则只有脚本选择的那些输入行应写入标准输出。

标准错误 (STDERR)

标准错误应仅用于诊断和警告消息。 ## 输出文件 (OUTPUT FILES)

输出文件应为文本文件，其格式取决于给出的编辑命令。

扩展描述 (EXTENDED DESCRIPTION)

script 应由以下形式的编辑命令组成：

[address[,address]]function

其中 function 表示 sed 中的编辑命令 列表中的单字符命令动词，后跟任何适用的参数。

命令前面可以有 <blank>（空白）字符和/或 <semicolon>（分号）字符。函数前面可以有 <blank> 字符。这些可选字符应无效果。

在默认操作中，sed 应循环地将一行输入（去掉其结尾的 <newline> 字符）追加到模式空间（pattern space）。如果在结束上一周期的 D 命令之前模式空间中已有 <newline>，则应跳过从输入读取。然后 sed 实用程序应按顺序应用所有其地址选中该模式空间的命令，直到某个命令开始下一个周期或退出。如果没有命令显式开始新周期，则在脚本末尾应将模式空间复制到标准输出（除非指定了 -n），并删除模式空间。每当模式空间被写入标准输出或命名文件时，sed 应立即在其后跟一个 <newline>。

某些编辑命令使用保持空间（hold space）来保存模式空间的全部或部分以供后续检索。模式空间和保持空间各自应能容纳至少 8192 字节。

地址 (Addresses in sed)

地址是十进制数字（跨文件累计计算输入行数）、寻址最后一行输入的 '$' 字符，或上下文地址（context address）。上下文地址具有 "/RE/" 或 "\cREc" 形式，其中 RE 是如 sed 中的正则表达式 所述的正则表达式，c 是除 <backslash>（反斜杠）或 <newline> 以外的任何字符。在 sed 上下文地址中，BRE 和 ERE 语法应扩展为支持通过转义序列转义 RE 中出现的 <slash>（斜杠）或 c 定界符（参见 XBD 9.1 正则表达式定义）。对于 "\cREc" 形式，如果由 c 指定的字符未在 XBD 9.3.3 BRE 特殊字符（若未指定 -E 选项）或 XBD 9.4.3 ERE 特殊字符（若指定了 -E）中列为特殊 BRE 字符或特殊 ERE 字符，则转义序列 <backslash>c 应被视为该字面字符；否则，转义序列 <backslash>c 被视为字面字符还是特殊字符是未指定的（unspecified）。无论哪种情况，转义序列 <backslash>c 都不应终止 RE。例如，在上下文地址 "/abc\/def/" 中，第二个 <slash> 表示其自身，因此 RE 是 "abc/def"；在 "\xabc\xdefx" 中，第二个 'x' 表示其自身，因此 RE 是 "abcxdef"。

没有地址的编辑命令应选中（select）每个模式空间。

有一个地址的编辑命令应选中每个匹配该地址的模式空间。

有两个地址的编辑命令应选中闭区间（inclusive range）：从匹配第一个地址的第一个模式空间开始，到匹配第二个地址的下一个模式空间为止。（如果第二个地址是小于或等于首次选中的行号的数字，则只应选中一行。）从所选区间后面的第一行开始，sed 应再次查找第一个地址。此后，重复该过程。在以下形式中省略任一或两个地址分量会产生未定义（undefined）的结果：

[address[,address]]

正则表达式 (Regular Expressions in sed)

sed 实用程序应支持 XBD 9. 正则表达式 中描述的 RE；默认情况下它应使用 XBD 9.3 基本正则表达式 中描述的 BRE，但如果使用 -E 选项，则应使用 XBD 9.4 扩展正则表达式 中描述的 ERE。在 sed 中，BRE 和 ERE 语法应扩展如下：

  • 在 RE 前后出现的定界符（delimiter）字符，当它出现在括号表达式（bracket expression）内时不应终止 RE，并且在括号表达式中应具有其正常含义。例如，上下文地址 "\%[%]%" 等价于 "/[%]/"，命令 "s-[0-9]--g" 等价于 "s/[0-9]//g"。

  • 转义序列 '\n' 应匹配嵌入模式空间中的 <newline>。字面 <newline> 不应在上下文地址或替换函数（substitute function）的 RE 中使用。

  • 如果 RE 为空（即未指定模式），sed 应表现得如同指定了最后一个命令（作为地址或作为替换命令的一部分）中使用的最后一个 RE。

编辑命令 (Editing Commands in sed)

在以下编辑命令列表中，每个函数允许的最大地址数由 [0addr]、[1addr] 或 [2addr] 指示，分别表示零个、一个或两个地址。

text 参数应由一行或多行组成。text 中的 <backslash> 可以用另一个 <backslash> 转义。应用应确保 text 中每个嵌入的 <newline>（即除最后一行结尾 <newline> 以外的那些）前面有一个未转义的 <backslash>。如果未转义的 <backslash> 后面紧跟除 <backslash> 或 <newline> 以外的任何字符，或紧跟脚本结尾，则行为是未指定的。

r 和 w 命令动词，以及 s 命令的 w 标志，接受 rfile（或 wfile）参数，该参数与命令动词字母或标志之间用一个或多个 <blank> 字符分隔；实现可以允许零分隔作为扩展。

rfile 参数或 wfile 参数应终止编辑命令。每个 wfile 应在处理开始前创建。实现应在脚本中支持至少十个 wfile 参数；实现支持的实际数量（大于或等于 10）是未指定的。使用 wfile 参数应导致该文件（如果不存在）被初始创建，或替换现有文件的内容。

b、r、s、t、w、y 和 : 命令动词应接受附加参数。以下概要指示哪些参数应与命令动词之间用一个 <space>（空格）分隔。

a 和 r 命令安排稍后输出的文本。为 a 命令指定的文本，以及为 r 命令指定的文件的内容，应在执行 c、D、d、N 或 n 命令时下一次尝试获取输入行之前写入标准输出，或在执行 q 命令之前写入标准输出，或在到达脚本末尾时写入标准输出。如果在到达脚本末尾时写入，且未指定 -n 选项，则文本应在将模式空间复制到标准输出之后写入。为 r 命令指定的文件的内容应以其被写入输出时为准，而不是应用 r 命令时为准。文本应按 a 和 r 命令应用于输入的顺序输出。

除 a、b、c、i、r、t、w、: 和 # 以外的编辑命令，后面可以跟一个 <semicolon>、可选的 <blank> 字符和另一个编辑命令。但是，当 s 编辑命令使用 w 标志时，以这种方式在其后跟另一个命令会产生未定义的结果。

函数前面可以有 '!' 字符，在这种情况下，如果地址未选中模式空间，则应应用该函数。'!' 字符前应接受零个或多个 <blank> 字符。'!' 字符后是否可以跟 <blank> 字符是未指定的，符合要求的应用不应在 '!' 字符后跟 <blank> 字符。

如果 label 参数（用于 b、t 或 : 命令）包含便携文件名字符集（portable filename character set）之外的字符，或者 label 超过 8 字节，则行为是未指定的。实现应支持识别为唯一的 label 参数，至少到 8 字节；实现支持的实际长度（大于或等于 8）是未指定的。超过最大支持的标签长度会导致错误还是静默截断是未指定的。

[2addr] {editing command editing command ... } : 仅当模式空间被选中时执行一组 sed 编辑命令。这组 sed 编辑命令应用花括号包围。花括号前面或后面可以有 <blank> 字符。<right-brace>（右花括号）前面应有一个 <newline> 或 <semicolon>（在 <right-brace> 前面任何可选 <blank> 字符之前）。

命令列表中的每个命令应以 \<newline\> 字符终止，或者在命令在花括号外使用时允许的情况下以 \<semicolon\> 字符终止。编辑命令前面可以有 \<blank\> 字符，但后面不应跟 \<blank\> 字符。

[1addr]a\ text : 如前所述将文本写入标准输出。

[2addr]b [label]
分支到带有 label 参数的 : 命令动词。如果未指定 label，则分支到脚本末尾。

[2addr]c\ text : 删除模式空间。使用 0 或 1 个地址，或在 2 地址区间的末尾，将 text 置于输出上。开始下一个周期。

[2addr]d
删除模式空间并开始下一个周期。
[2addr]D
如果模式空间不包含 <newline>，则删除模式空间并开始正常的新周期，如同发出了 d 命令。否则，删除模式空间从开头到第一个 <newline> 的初始段，并以所得的模式空间开始下一个周期，而不读取任何新输入。
[2addr]g
用保持空间的内容替换模式空间的内容。
[2addr]G
在模式空间后追加一个 <newline> 及保持空间的内容。
[2addr]h
用模式空间的内容替换保持空间的内容。
[2addr]H
在保持空间后追加一个 <newline> 及模式空间的内容。

[1addr]i\ text : 将 text 写入标准输出。

[2addr]l

（字母 ell。）以视觉上无歧义的形式将模式空间写入标准输出。XBD 转义序列及相关操作 中列出的字符（'\\'、'\a'、'\b'、'\f'、'\r'、'\t'、'\v'）应写成相应的转义序列；该表中的 '\n' 不适用。不在该表中的不可打印字符，其每个字节应写成一个三位八进制数字（前面加 <backslash>）（最高有效字节在前）。

长行应折叠（folded），折叠点通过写入一个 <backslash> 后跟一个 <newline> 来指示；发生折叠的长度是未指定的，但应适合输出设备。每行的结尾应用 '$' 标记。

[2addr]n

如果默认输出未被抑制，则将模式空间写入标准输出，并用下一行输入（去掉其结尾的 <newline>）替换模式空间。

如果没有下一行输入可用，n 命令动词应分支到脚本末尾并退出，而不开始新周期。

[2addr]N

将下一行输入（去掉其结尾的 <newline>）追加到模式空间，使用嵌入的 <newline> 分隔追加的材料与原始材料。注意当前行号会改变。

如果没有下一行输入可用，N 命令动词应分支到脚本末尾并退出，而不开始新周期，也不将模式空间复制到标准输出。

[2addr]p
将模式空间写入标准输出。
[2addr]P
将模式空间写到第一个 <newline> 为止的部分写入标准输出。
[1addr]q
分支到脚本末尾并退出，而不开始新周期。
[1addr]r rfile
如前所述将 rfile 的内容复制到标准输出。如果 rfile 不存在或无法读取，则应将其视为空文件，不产生错误条件。
[2addr]s/RE/replacement/flags

用替换字符串替换模式空间中 RE 的实例。除 <backslash> 或 <newline> 以外的任何字符都可以代替 <slash> 来定界 RE 和替换。在 RE 内（作为 sed 对 BRE 和 ERE 语法的扩展）和替换中，如果定界符是转义序列的第二个字符，则它不应终止 RE 或替换（参见 XBD 9.1 正则表达式定义）。如果定界符字符未在 XBD 9.3.3 BRE 特殊字符（若未指定 -E 选项）或 XBD 9.4.3 ERE 特殊字符（若指定了 -E）中列为特殊 BRE 字符或特殊 ERE 字符，则转义的定界符在 RE 中应被视为该字面字符；否则，转义的定界符被视为字面字符还是特殊字符是未指定的。同样，如果定界符字符不是 <ampersand>（'&'），则转义的定界符在替换中应被视为该字面字符；如果是 <ampersand>，则转义的定界符被视为字面字符还是特殊字符是未指定的（见下文）。

替换字符串应从头到尾扫描。替换中出现的 <ampersand>（'&'）应替换为匹配 RE 的字符串。'&' 在此上下文中的特殊含义可以通过在其前面加 <backslash> 来抑制。字符 "\n"（其中 n 是数字）应替换为相应反向引用（back-reference）表达式匹配的文本。如果相应的反向引用表达式不匹配，则字符 "\n" 应替换为空字符串。"\n"（其中 n 是此上下文中的数字）的特殊含义可以通过在其前面加 <backslash> 来抑制。对于遇到的每个其他 <backslash>，以下字符应失去其特殊含义（如果有）。

可以通过向行中替换一个 <newline> 来拆分行。应用应通过在替换中的 <newline> 前面加 <backslash> 来转义它。

未转义的 <backslash> 后面紧跟除 '&'、<backslash>、数字、<newline> 或此命令使用的定界符字符以外的任何字符的含义是未指定的。

任何用于改变后续字符默认含义的 <backslash> 应从生成的替换字符串中丢弃。即使生成的替换字符串与它所替换的字符串相同，也应认为替换已执行。

flags 的值应为以下零个或多个：

n
仅替换模式空间内找到的 RE 的第 n 次出现。
g
全局替换 RE 的所有非重叠实例，而不仅仅是第一个。如果同时指定了 g 和 n，结果是未指定的。
i
以不区分大小写（case-insensitive）的方式匹配正则表达式。
p
如果进行了替换，则将模式空间写入标准输出。
w wfile
写入。如果进行了替换，则将模式空间追加到 wfile。符合要求的应用应在 wfile 参数前加一个或多个 <blank> 字符。如果 w 标志不是多个标志值连接中的最后一个标志值，结果是未定义的。
[2addr]t [label]
测试。如果自最近一次读取输入行或执行 t 以来进行过任何替换，则分支到带有 label 的 : 命令动词。如果未指定 label，则分支到脚本末尾。
[2addr]w wfile
将模式空间追加（写入）到 wfile。
[2addr]x
交换模式空间和保持空间的内容。
[2addr]y/string1/string2/
将 string1 中字符的所有出现替换为 string2 中相应的字符。如果 string1 或 string2 中出现 <backslash> 后跟 'n'，则这两个字符应作为一个 <newline> 处理。如果（在解析任何转义序列之后）string1 和 string2 中的字符数不相等，或者 string1 中的任何字符出现多次，结果是未定义的。除 <backslash> 或 <newline> 以外的任何字符都可以代替 <slash> 来定界字符串。如果定界符不是 'n'，则在 string1 和 string2 内，如果定界符前面有一个未转义的 <backslash>，则其本身可以用作字面字符。如果 string1 或 string2 中的 <backslash> 字符被紧邻其前的未转义 <backslash> 字符转义，则这两个 <backslash> 字符应作为一个字面 <backslash> 字符处理。未转义的 <backslash> 后跟任何不是 'n'、<backslash> 或定界符字符的字符的含义是未定义的。
[0addr]:label
什么都不做。此命令带有 label，b 和 t 命令分支到该标签。
[1addr]=
将以下内容写入标准输出： 
"%d\n", <current line number>
[0addr]
忽略此空命令。
[0addr]#
忽略 '#' 及该行的其余部分（将其视为注释），唯一的例外是：如果脚本中前两个字符是 "#n"，则应抑制默认输出；这应等同于在命令行上指定 -n。 ## 退出状态 (EXIT STATUS)

应返回以下退出值：

0
成功完成。
>0
发生错误。

错误后果 (CONSEQUENCES OF ERRORS)

默认。

应用程序用法 (APPLICATION USAGE)

正则表达式匹配整个字符串，而不仅仅是单独的行，但 <newline> 在 sed RE 中由 '\n' 匹配；POSIX.1-2024 中正则表达式的一般定义不允许 <newline>。还要注意，'\n' 不能用于匹配任意输入行结尾的 <newline>；<newline> 字符作为 N 编辑命令的结果出现在模式空间中。

将特殊 RE 字符用作定界符（例如 '.' 或 '*'）并需要在 RE 中将定界符用作字面字符的应用，应将其放在括号表达式内，因为各实现之间在是否用 <backslash> 转义会移除其特殊含义方面存在差异。例如，对于上下文地址 "/\.[0-9]/"，要用 '.' 作为定界符书写，需要使用形式 "\.[.][0-9]."；"\..[0-9]." 不能为此目的可移植地使用，因为这是否等价于 "/\.[0-9]/" 或 "/.[0-9]/" 是未指定的。如果特殊 RE 字符需要在 RE 中具有其特殊含义，可移植应用不能将其用作定界符，因为转义它可能移除其特殊含义。

使用 sed 处理路径名时，建议在环境中将 LC_ALL（或至少 LC_CTYPE 和 LC_COLLATE）设置为 POSIX 或 C，因为路径名可以包含在某些 locale 中不构成有效字符的字节序列，在这种情况下实用程序的行为将是未定义的。在 POSIX locale 中，每个字节都是有效的单字节字符，因此避免了此问题。

注意，一些 sed 实现还支持 s 命令的 I 标志，作为小写 i 标志的别名。

一些 sed 实现在不符合作的环境中执行时，处理正则表达式中的 <backslash> 转义的方式与 awk 在词法 token ERE 中的处理方式类似（将 "\t" 处理为制表字符等）。这是一种兼容性扩展，但当 <backslash> 出现在括号表达式内时与本标准的要求冲突。本标准未来版本可能允许此行为，因此应用应在括号表达式中使用两个 <backslash> 字符而不是一个，以确保未来的可移植性。在符合当前标准的实现上，第二个 <backslash> 是多余的。将来（以及在当前不符合作的环境中），第一个 <backslash> 可能转义第二个。

示例 (EXAMPLES)

此 sed 脚本模拟 BSD cat -s 命令，压缩标准输入中多余的空白行。

sed -n '
# Write non-empty lines.
/./ {
    p
    d
    }
# Write a single empty line, then look for more empty lines.
/^$/    p
# Get next line, discard the held <newline> (empty line),
# and look for more empty lines.
:Empty
/^$/    {
    N
    s/.//
    b Empty
    }
# Write the non-empty line before going back to search
# for the first in a set of empty lines.
    p
'

以下 sed 命令是压缩空白行的更简单方法，尽管它与 cat -s 不完全相同，因为它会移除任何开头的空白行：

sed -n '/./,/^$/p'

原理 (RATIONALE)

POSIX.1-2024 本卷要求实现支持至少十个不同的 wfile，与许多实现上的历史实践一致。鼓励实现支持更多，但符合要求的应用不应超过此限制。

此处指定的退出状态码与 System V 中的不同。System V 对混乱的 sed 命令返回 2，但对用法消息或无法打开输入文件时返回零。标准开发者认为这是一个缺陷。

l 命令写入不可打印字符的方式被更改，以避免历史上的退格-叠印（backspace-overstrike）方法，并添加了其他实现无歧义输出的要求。有关所选格式的详细信息，参见 ed 的 RATIONALE，该格式与为 sed 选择的格式相同。

POSIX.1-2024 本卷要求实现提供至少 8192 字节的模式空间和保持空间，大于某些历史实现使用的 4000 字节空间，但小于早期提案中使用的 20480 字节限制。鼓励实现根据需要动态分配更大的模式空间和保持空间。

对命令行中接受 <blank> 和 <space> 字符的要求已比早期提案更加明确，以清楚描述历史实践，并消除对历史 sed 实用程序文本描述中出现的 “protect initial blanks [sic] and tabs from the stripping that is done on every script line” 这一短语的混淆。（并非所有实现都已知会从文本行中剥离 <blank> 字符，尽管它们都允许命令行地址前面有前导 <blank> 字符。）

对 '#' 注释的处理与 SVID 不同，SVID 只允许注释作为脚本的第一行，但这与 BSD 派生的实现一致。注释字符被视为命令，并且在接受前导 <blank> 字符方面具有相同的属性；BSD 实现历史上一直支持这一点。

早期提案要求 script_file 至少有一行非注释行。一些历史实现在不是这种情况时表现异常。标准开发者认为这是错误行为，应用开发者不应必须避免此功能。POSIX.1-2024 本卷的正确实现应允许仅由注释行组成的 script_file。

早期提案指出，如果 -e 和 -f 选项混合使用，则所有 -e 选项在任何 -f 选项之前处理。这已改为按呈现顺序处理，因为它符合历史实践并且更直观。

<backslash> 和 <newline> 字符不能用作 RE 定界符字符，因为它们永远不能被识别为结束定界符：

  • <backslash> 不行，因为如果它稍后在 RE 中未转义地出现，它要么转义后面的字符（该字符随后永远不能成为结束定界符），要么是括号表达式的一部分，而 RE 的结束定界符无法在括号表达式内部定位。

  • <newline> 不行，因为如果未转义，它会终止命令，意味着它不能成为结束定界符。

一些历史 sed 实现不支持在用作 BRE 定界符时转义 '('、')'、'{' 和 '}'，因为序列 "\(" 等仍被视为特殊，通常导致错误。本标准要求这些序列被视为字面字符。这是为了与扩展保持一致。例如，一些实现将 BRE 中的 "\s" 视为匹配空白字符，作为扩展。当 's' 用作 BRE 定界符时，它不能具有其特殊含义，以确保具有 's' 作为定界符并转义它的 sed 命令的可移植性。如果允许 "\s" 保持其特殊含义，那么进一步扩展的可能性将意味着可移植应用将无法转义除 <slash> 以外的任何定界符字符。

当默认输出被抑制时，s 命令的 p 标志的处理在 System V 和基于 BSD 的系统之间不同。在两个示例中：

echo a | sed    's/a/A/p'
echo a | sed -n 's/a/A/p'

POSIX.1-2024 本卷、BSD、System V 文档和 SVID 表明第一个示例应写入两行 A，而第二个示例应写入一行。一些 System V 系统在两个示例中都只写一次 A，因为如果未指定 -n 选项，p 标志被忽略。

这是系统之间截然不同的差异，无法通过将行为声明为未指定的折衷方案来调和。SVID/BSD/System V 文档行为被 POSIX.1-2024 本卷采纳，因为：

  1. 没有任何已知的历史系统文档描述 p 标志与 -n 选项之间的交互。

  2. 所选行为更正确，因为没有技术理由支持 p 标志与 -n 选项之间的任何交互。-n 与 p 标志之间的关系可能暗示它们只在一起使用，但这忽略了通过使用 D、d、q 或分支命令中断处理周期性的有效脚本。此类脚本依赖 p 后缀来写入模式空间，因为它们不使用脚本 “底部” 的默认输出。

  3. 因为 -n 选项使 p 标志变得不必要，任何交互只有在 sed 脚本被编写为在有和没有 -n 选项的情况下都能运行时才有用。这被认为不太可能。程序员编写 p 标志时预期它是不必要的，就更不可能了。由于该交互没有文档记录，程序员发现该交互并依赖它的可能性进一步降低。

  4. 最后，在指定行为下出错的脚本产生过多输出而不是过少输出，这更容易诊断和纠正。

使用 n 后缀的替换命令形式在早期提案中被限制为前 512 次匹配。此限制已被移除，因为没有理由让处理 {LINE_MAX} 长度行的编辑器受此限制。命令 s/a/A/2047 应能够替换一行上第 2047 次出现的 a。

b、t 和 : 命令被记录为忽略前导空白，但没有提到尾随空白。历史 sed 实现为标签 'x' 和 "x " 分配了不同的位置。这没有用处，并导致微妙的编程错误，但这是历史实践，更改它理论上可能破坏工作脚本。鼓励实现者提供警告消息，说明从未被 b 或 t 命令引用的标签、跳转到不存在的标签以及可能被截断的标签参数。

本标准的早期版本允许实现使用非八位字节，但此版本已对此进行修改。

未来方向 (FUTURE DIRECTIONS)

本标准未来版本可能允许 sed 处理正则表达式中的 <backslash> 转义，方式与 awk 在词法 token ERE 中的处理方式类似。（“类似” 而非 “相同”，因为 sed 可以使用 BRE 或 ERE，而 awk 只使用 ERE。）
