2. Shell 命令语言 (Shell Command Language)

本章包含 Shell 命令语言的定义。

翻译说明：本译文为中文直译，与英文原文（2.shell/index.md）逐段、逐条、逐层对应，结构（标题层级、有序列表、缩进、顶格标记）完全镜像原文，便于中英对照阅读。

2.1 Shell 简介 (Shell Introduction)

Shell 是一种命令语言解释器（command language interpreter）。本章描述该命令语言的语法，它被 POSIX.1-2024《系统接口》卷中定义的 sh 实用程序以及 system() 和 popen() 函数所使用。

Shell 按照以下操作总览运行。具体细节包含在本章所引用的各节中。

  1. Shell 从文件（见 sh）、-c 选项，或 POSIX.1-2024《系统接口》卷中定义的 system() 和 popen() 函数读取其输入。如果 shell 命令文件的第一行以字符 "#!" 开头，结果是未指定的（unspecified）。

  2. Shell 将输入分解为 token：单词和运算符；见 2.3 Token 识别。

  3. Shell 将输入解析为简单命令（见 2.9.1 简单命令）和复合命令（见 2.9.4 复合命令）。

  4. 对命令中的每个单词，shell 处理美元单引号（dollar-single-quotes）内的 <backslash>-转义序列（见 2.2.4 美元单引号），然后执行各种单词扩展（见 2.6 单词扩展）。在简单命令的情况下，结果通常包含一个路径名列表和将被视为命令名与参数的字段列表；见 2.9 Shell 命令。

  5. Shell 执行重定向（见 2.7 重定向），并从参数列表中移除重定向运算符及其操作数。

  6. Shell 执行函数（见 2.9.5 函数定义命令）、内置命令（见 2.15 特殊内置实用程序）、可执行文件或脚本，将参数的名称作为编号 1 到 n 的位置参数传递，并将命令名（或在脚本内函数的情况下，脚本名）作为特殊参数 0（见 2.9.1.4 命令搜索与执行）。

  7. Shell 可选地等待命令完成并收集退出状态（见 2.8.2 命令的退出状态）。

2.2 引用 / 转义 (Quoting)

引用（Quoting）用于移除某些字符或单词对 shell 的特殊含义。引用可用于：保留下一段中特殊字符的字面含义（literal meaning）、防止保留字（reserved words）被识别为保留字，以及防止在 here-document 处理过程中发生参数扩展和命令替换（见 2.7.4 Here-Document）。

如果以下字符要表示其自身，应用（application）应对其进行引用：

|  &  ;  <  >  (  )  $  `  \  "  '  <space>  <tab>  <newline>

而以下字符在特定情况下可能需要进行引用。也就是说，这些字符在 POSIX.1-2024 本卷其他地方描述的条件下有时是特殊的：

*  ?  [  ]  ^  -  !  #  ~  =  %  {  ,  }

注意： 本标准未来版本可能扩展这些字符变为特殊的条件。因此，应用在希望这些字符表示其自身时，应始终对其加引用。这不适用于 <hyphen-minus>（'-'），因为它属于便携文件名字符集（portable filename character set）。

各种引用机制包括：转义字符（escape character）、单引号（single-quotes）、双引号（double-quotes）和美元单引号（dollar-single-quotes）。here-document 代表另一种引用形式；见 2.7.4 Here-Document。

2.2.1 转义字符：反斜杠 (Escape Character (Backslash))

未被引用的 <backslash>（反斜杠）应保留其后字符的字面值，<newline>（换行符）除外。如果 <newline> 紧跟 <backslash> 之后，shell 应将其解释为续行（line continuation）。在将输入拆分为 token 之前，应移除该 <backslash> 和 <newline>。由于被转义的 <newline> 从输入中被完全移除且不被任何空白替换，它不能充当 token 分隔符。

2.2.2 单引号 (Single-Quotes)

将字符括在单引号（''）中，应保留单引号内每个字符的字面值。单引号内不能出现单引号。

2.2.3 双引号 (Double-Quotes)

将字符括在双引号（""）中，应保留双引号内所有字符的字面值，但反引号、<dollar-sign>（美元符号）和 <backslash>（反斜杠）除外，如下：

$

<dollar-sign> 保留其特殊含义：可引入参数扩展（见 2.6.2 参数扩展）、命令替换（见 2.6.3 命令替换）和算术扩展（见 2.6.4 算术扩展）；但不保留其引入美元单引号引用形式（见 2.2.4 美元单引号）的特殊含义。

双引号字符串中，凡位于 "$(" 与匹配的 ')' 之间的输入字符，都不受双引号的影响——它们构成命令；进行单词扩展时，该命令的输出将替换 "$(...)"。2.3 Token 识别中的 token 化规则应被递归应用，以找到匹配的 ')'。

对于提供子串处理（substring processing）的四种参数扩展变体（见 2.6.2 参数扩展），当扩展发生在双引号内时，从被括起的 "${" 到匹配的 '}' 之间的字符串中，任何特殊字符的处理都不受双引号影响。

对于除上述四种变体以外的参数扩展，当扩展发生在双引号内时，从被括起的 "${" 到匹配的 '}' 之间的字符串中，双引号应保留所有字符的字面值，但双引号、反引号、<dollar-sign> 和 <backslash> 除外。若该字符串中出现任何未转义的双引号字符（嵌入式命令替换中的除外），行为是未指定的（unspecified）。反引号和 <dollar-sign> 按本节所述双引号内字符的规则处理。<backslash> 同样按本节所述双引号内字符的规则处理，但附加一条：当它后跟 '}' 时，保留其作为转义字符的特殊含义——被转义的 '}' 在确定匹配的 '}' 时不会被计入（使用 2.6.2 参数扩展 中的规则）。

`

反引号保留其引入另一种形式命令替换（见 2.6.3 命令替换）的特殊含义。被引用字符串中，从初始反引号起、到下一个未被 <backslash> 前缀（转义字符已移除）的反引号为止的部分，构成命令；进行单词扩展时，该命令的输出将替换 &#34;`...`&#34;。以下任一情况产生未定义（undefined）的结果：

  • 一个在 &#34;`...`&#34; 序列内开始但未结束的引用（单引号、双引号或美元单引号）字符串

  • 一个在同一双引号字符串内开始但未结束的 &#34;`...`&#34; 序列

\

在 "$(...)" 和 "${...}" 之外，<backslash> 仅当紧跟下列字符之一时，才保留其作为转义字符（见 2.2.1 转义字符（反斜杠））的特殊含义：

$   `   \   <newline>

或紧跟一个原本会被视为特殊的双引号字符（见 2.6.4 算术扩展 和 2.7.4 Here-Document）。

当双引号用于引用参数扩展、命令替换或算术扩展时，扩展结果中所有字符的字面值都应被保留。

应用应确保：不在 "$(...)" 内、也不在 "${...}" 内的双引号，若要包含在双引号之中，必须紧跟在一个 <backslash> 之后。参数 '@' 在双引号内具有特殊含义，见 2.5.2 特殊参数。

2.2.4 美元单引号 (Dollar-Single-Quotes)

以 <dollar-sign> 紧跟单引号（$'）开头的字符序列，应保留直到未转义的结尾单引号（'）为止所有字符的字面值，但某些 <backslash>-转义序列除外，如下：

  • \" 产生 <quotation-mark>（双引号）字符，但注意 <quotation-mark> 可以不带转义地包含。

  • \' 产生 <apostrophe>（撇号/单引号）字符。

  • \\ 产生 <backslash>（反斜杠）字符。

  • \a 产生 <alert>（警告）字符。

  • \b 产生 <backspace>（退格）字符。

  • \e 产生 <ESC>（转义）字符。

  • \f 产生 <form-feed>（换页）字符。

  • \n 产生 <newline>（换行）字符。

  • \r 产生 <carriage-return>（回车）字符。

  • \t 产生 <tab>（制表）字符。

  • \v 产生 <vertical-tab>（垂直制表）字符。

  • \cX 产生 stty 实用程序 OPERANDS 节中 Values for cpio c_mode Field 表的 Value 列所列的控制字符，当 X 是同一表的 ^c 列所列字符之一时；但 \c\\ 产生 <FS> 控制字符，因为 <backslash> 字符必须被转义。

  • \xXX 产生值为十六进制数 XX（一个或多个十六进制数字）的字节。如果 \x 后跟超过两个十六进制数字，结果是未指定的。

  • \ddd 产生值为八进制数 ddd（一到三个八进制数字）的字节。

  • 未转义的 <backslash> 紧跟任何其他字符（包括 <newline>）的行为是未指定的。

在可以使用可变数量字符来指定转义序列的情况（\xXX 和 \ddd）下，转义序列应在遇到第一个不属于预期类型的字符时终止，或者对于 \ddd 序列，在达到指定的最大字符数时终止，以先发生者为准。

这些 <backslash>-转义序列应在包含美元单引号序列的单词进行单词扩展（见 2.6 单词扩展）之前立即处理（替换为它们所产生的字节或字符）。

如果 \xXX 或 \ddd 转义序列产生值为 0 的字节，那么该空字节是否包含在结果中，还是该字节及直到结尾未转义单引号之前的任何后续常规字符和转义序列被求值并丢弃，是未指定的。

如果 \ddd 指定的八进制值放不进一个字节，结果是未指定的。

如果 \e 或 \cX 转义序列指定的字符，在这些 <backslash>-转义序列被处理时，在当前 locale 中没有编码，结果是实现定义的（implementation-defined）。但实现不应将不支持的字符替换为在那种 locale 字符集中不构成有效字符的字节。

如果 <backslash>-转义序列表示单引号字符（如 \'），该序列不应终止美元单引号序列。

2.3 Token 识别 (Token Recognition)

shell 应按行读取其输入。（关于 shell 如何读取输入的细节，见 sh 的描述。）输入行的长度可以是无限的。这些行应使用两种主要模式进行解析：普通 token 识别和 here-document 处理。

当文法（见 2.10 Shell 文法）识别出一个 io_here token 后，紧跟下一个 NEWLINE token 之后的一行或多行构成 here-document 的主体，并应按照 2.7.4 Here-Document 的规则进行解析。在搜索下一个 NEWLINE token 期间识别出的任何非 NEWLINE token（包括更多的 io_here token）应被保存，以便在 here-document 解析完成后处理。如果被保存的 token 是 io_here token，对应的 here-document 应在包含前一个 here-document 结尾定界符的那一行的下一行开始。如果任何被保存的 token 包含 <newline> 字符，行为是未指定的。

当不处理 io_here 时，shell 应通过对其输入中的每个字符依次应用以下第一条适用规则，将输入分解为 token。在输入开始时，或在刚界定完前一个 token 之后，第一个（或下一个）token 应以尚未被包含在任何 token 中、且未按下述规则丢弃的第一个字符开始。token 一旦开始，输入中的零个或多个字符应被追加到该 token，直到按以下规则之一界定 token 的结束。当 token 的开始和结束都被界定时，构成该 token 的字符应恰好是输入中两个定界符之间的那些字符，包括任何引用字符。如果以下规则表明某个 token 被界定，但没有任何字符被包含进该 token，该空 token 应被丢弃。

  1. 如果识别到输入结束，当前 token（如有）应被界定。

  2. 如果前一个字符被用作运算符的一部分，且当前字符未被引用并可与前面的字符组成一个运算符，则它应被用作该（运算符）token 的一部分。

  3. 如果前一个字符被用作运算符的一部分，且当前字符不能与前面的字符组成一个运算符，则包含前一个字符的运算符应被界定。

  4. 如果当前字符是未引用的 <backslash>、单引号或双引号，或是未引用的 <dollar-sign> 单引号序列的第一个字符，它应影响直到引用文本结束为止的后续字符的引用。引用规则如 2.2 引用 所述。在 token 识别期间，不应实际执行任何替换，结果 token 应精确包含输入中从引用文本开始到结束之间出现的、未经修改的字符，包括任何嵌入或包围的引号或替换运算符。token 不应被引用字段的结束所界定。

  5. 如果当前字符是未引用的 '$' 或 '`'，shell 应从它们的引入性未引用字符序列——分别是 '$' 或 "${"、"$(" 或 '`'、以及 "$(("——识别参数扩展（2.6.2 参数扩展）、命令替换（2.6.3 命令替换）或算术扩展（2.6.4 算术扩展）的任何候选者的开始。shell 应读取足够的输入以确定要扩展的单元的结果（如所引用的各节所述）。在处理字符时，如果在替换内发现嵌套的扩展或引用实例，shell 应对所发现的构造按为其规定的方式递归处理。仅对于 "$(" 和 '`'，如果在替换内发现嵌套的 io_here token 实例，应按照 2.7.4 Here-Document 的规则解析它们；如果替换的结尾 ')' 或 '`' 出现在标记 here-document 开始的 NEWLINE token 之前，行为是未指定的。从替换开始到其结束所发现的字符（允许为识别嵌入构造所必需的任何递归）应未经修改地包含在结果 token 中，包括任何嵌入或包围的替换运算符或引号。token 不应被替换的结束所界定。

  6. 如果当前字符未被引用，且可用作新运算符的第一个字符，则当前 token（如有）应被界定。当前字符应被用作下一个（运算符）token 的开始。

  7. 如果当前字符是未引用的 <blank>，包含前一个字符的任何 token 应被界定，且当前字符应被丢弃。

  8. 如果前一个字符是单词的一部分，当前字符应被追加到该单词。

  9. 如果当前字符是 '#'，它及直到下一个 <newline>（不含）为止的所有后续字符应作为注释被丢弃。结束该行的 <newline> 不被视为注释的一部分。

  10. 当前字符被用作新单词的开始。

token 一旦被界定，就按照 2.10 Shell 文法 的要求进行分类。

在 shell 将输入解析为 program 的情况下，一旦文法（见 2.10 Shell 文法）识别出一个 complete_command，该 complete_command 应在下一个 complete_command 被 token 化和解析之前执行。

2.3.1 别名替换 (Alias Substitution)

在 token 被分类为 TOKEN 类型（见 2.10.1 Shell 文法词法约定）之后，包括（递归地）由别名替换产生的任何 token，如果以下所有条件都为真，该 TOKEN 应经受别名替换：

  • 该 TOKEN 不包含任何引用字符。

  • 该 TOKEN 是有效的别名名称（见 XBD 3.10 Alias Name）。

  • 具有该名称的别名当前生效。

  • 该 TOKEN 并未完全或（可选地）部分地源于任何更早递归级别上对同一别名的别名替换。

  • 要么该 TOKEN 因跟在某个替换值以 <blank> 结尾的别名替换之后（见下文）而被考虑进行别名替换，要么该 TOKEN 基于其自身及（如有）其前面的 token（但不考虑任何后续字符是否允许）可被解析为简单命令的命令名单词（见 2.10 Shell 文法）。

但如果该 TOKEN 满足上述条件，并且如果它出现在输入中的适当位置就会被识别为保留字（见 2.4 保留字），那么该 TOKEN 是否经受别名替换是未指定的。

当 TOKEN 经受别名替换时，别名的值应被处理，如同它是从输入中读入以代替该 TOKEN 一样，token 识别（见 2.3 Token 识别）从别名值的开始处恢复。当到达别名值的结尾时，shell 可以表现得如同在输入中、在被替换的 TOKEN 之后又读入了一个额外的 <space> 字符。如果不添加该 <space>，则在 token 识别应用于输入中紧跟该 TOKEN 之后的字符（如有）之前，当前 token 是否被界定是未指定的。

注意：

本标准未来版本可能不允许添加该 <space>。

如果替换该 TOKEN 的别名的值以替换后未被引用的 <blank> 结尾，并且可选地如果它以替换后被引用的 <blank> 结尾，shell 应检查输入中的下一个 token（如果它是 TOKEN）是否进行别名替换；此过程应持续进行，直到找到不是有效别名的 TOKEN，或某个别名值不以这样的 <blank> 结尾。

实现可以延迟对别名的更改生效，但该更改最迟应在当前正在执行的 complete_command（见 2.10 Shell 文法）完成时生效。对别名的更改不应乱序生效。实现可以提供 shell 被调用时已生效的预定义别名。

当按 POSIX.1-2024 本卷的规定使用时，别名定义不应被 shell 的单独调用或由 shell 调用的实用程序执行环境所继承；见 2.13 Shell 执行环境。

2.4 保留字 (Reserved Words)

保留字是对 shell 具有特殊含义的单词；见 2.9 Shell 命令。以下单词应被识别为保留字：


!
{
}
case


do
done
elif
else


esac
fi
for
if


in
then
until
while

这种识别应仅在没有任何字符被引用，且该单词被用作以下情形之一时发生：

  • 命令的第一个单词
  • 紧跟除 case、for 或 in 之外的一个保留字之后的第一个单词
  • case 命令中的第三个单词（此情形下只有 in 有效）
  • for 命令中的第三个单词（此情形下只有 in 和 do 有效）

见 2.10 Shell 文法 中的文法。

当在识别保留字的情形（如上所述）下使用时，以下单词可以被识别为保留字，此时结果是未指定的，但下文对 time 的描述除外：

[[]]

function

namespace

select

time

当单词 time 在以下情形下被识别为保留字：如果它不是保留字，它本应成为将执行 time 实用程序的一个简单命令（见 2.9.1.1 处理顺序）的命令名，且其执行方式不属于 time 所述结果为未指定的方式，则行为应按 time 实用程序的规定执行。

当在识别保留字的情形（如上所述）下使用时，所有最后一个字符为 <colon>（':'）的单词都是保留的；它们在这些情形下的使用产生未指定的结果。

2.5 参数与变量 (Parameters and Variables)

参数（parameter）可以用名称（name）、数字或 2.5.2 特殊参数 中列出的特殊字符之一来标识。变量（variable）是用名称标识的参数。

如果参数具有已赋的值，则称其被设置（set）（null 是有效值）。变量一旦被设置，只能通过使用 unset 特殊内置命令来取消设置。

参数可以包含任意的字节序列，空字节（null byte）除外。shell 仅在执行本标准以字符（characters）术语描述的操作时，才将它们的值作为字符处理。

2.5.1 位置参数 (Positional Parameters)

位置参数（positional parameter）是用正整数的十进制表示来标识的参数。表示位置参数的数字应始终解释为十进制值，即使存在前导零。当指定多于一位数字的位置参数时，应用应将这些数字括在花括号中（见 2.6.2 参数扩展）。

示例：

  • "$8"、"${8}"、"${08}"、"${008}" 等全部展开为第八个位置参数的值。
  • "${10}" 展开为第十个位置参数的值。
  • "$10" 展开为第一个位置参数的值后跟字符 '0'。
注意：

0 是特殊参数，不是位置参数，因此 ${00} 的展开结果是未指定的。

位置参数在 shell 被调用时（见 sh）初始赋值，在调用 shell 函数时被临时替换（见 2.9.5 函数定义命令），并可以用 set 特殊内置命令重新赋值。

2.5.2 特殊参数 (Special Parameters)

下面列出特殊参数及它们应展开成的值。这里只列出特殊参数的值；关于展开单词所涉及的所有阶段的详细汇总，见 2.6 单词扩展。

@

展开为位置参数，从 1 开始，初始为每个被设置的位置参数产生一个字段。当展开发生在将执行字段分割（field splitting）的上下文中时，任何空字段可以被丢弃，每个非空字段应按 2.6.5 字段分割 所述进一步分割。当展开发生在双引号内时，行为是未指定的，除非以下之一为真：

  • 如果该展开不在双引号内，就会按 2.6.5 字段分割 执行字段分割（无论字段分割是否会产生任何效果；例如，如果 IFS 为 null）。
  • 双引号位于 ${parameter:-word} 或 ${parameter:+word} 展开（带或不带 <colon>；见 2.6.2 参数扩展）的 word 内，而如果展开的是 parameter 而非 word，该展开本应经受字段分割。

如果这些条件之一为真，初始字段应作为单独字段保留，但如果被展开的参数嵌入在单词内，第一个字段应与原单词的开始部分连接，最后一个字段应与原单词的结尾部分连接。在所有其他上下文中，展开结果是未指定的。如果没有位置参数，'@' 的展开应生成零个字段，即使 '@' 在双引号内；但如果该展开嵌入在一个包含一个或多个展开为带引号的 null 字符串的其他部分的单词内，这些 null 字符串仍应产生一个空字段，但如果其他部分与 '@' 在同一双引号内，结果是零个字段还是一个空字段是未指定的。

*

展开为位置参数，从 1 开始，初始为每个被设置的位置参数产生一个字段。当展开发生在将执行字段分割的上下文中时，任何空字段可以被丢弃，每个非空字段应按 2.6.5 字段分割 所述进一步分割。当展开发生在不执行字段分割的上下文中时，初始字段应连接成单个字段，每个参数的值由 IFS 变量的第一个字符分隔（如果 IFS 至少包含一个字符），如果 IFS 未设置则由一个 <space> 分隔，如果 IFS 被设置为 null 字符串则无分隔。

#

展开为位置参数个数的十进制数的最短表示。命令名（参数 0）不应计入 '#' 给出的数目，因为它是特殊参数，不是位置参数。

?

展开为从当前 shell 执行环境（不是子 shell 环境）执行的、最近终止的管道（见 2.9.2 管道）的十进制退出状态（见 2.8.2 命令的退出状态）的最短表示，或者（可选地，仅当 shell 是交互式且启用了作业控制时）最近被信号停止的管道——取二者中最近者。如果该管道已终止，状态值应是其退出状态；否则，状态值应等于如果该管道被与其停止信号同号的信号终止时本应产生的退出状态。特殊参数 '?' 的值应在 shell 初始化期间设置为 0。当创建子 shell 环境时，调用 shell 环境中特殊参数 '?' 的值应在子 shell 中保留。

注意：

在 var=$(some_command); echo $? 中，输出的是 some_command 的退出状态，它在子 shell 环境中执行，但这是因为它的退出状态成为赋值命令 var=$(some_command)（见 2.9.1 简单命令）的退出状态，而这个赋值命令是最近完成的管道。对于完全由没有命令字的简单命令组成但包含一个或多个命令替换的任何管道，也是如此。（见 2.9.1 简单命令。）

-

（连字符。）展开为当前选项标志（单字母选项名连接成的字符串），按调用时、set 特殊内置命令或 shell 隐式指定的方式。"$-" 的展开中是否包含 -c 和 -s 选项是未指定的。如果 shell 是交互式的，-i 选项应包含在 "$-" 中，无论它是否在调用时指定。

$

展开为被调用 shell 的十进制进程 ID 的最短表示。在子 shell（见 2.13 Shell 执行环境）中，'$' 应展开为与当前 shell 相同的值。

!

展开为从当前 shell 执行环境执行的最近异步 AND-OR 列表（见 2.9.3.1 异步 AND-OR 列表）相关联的十进制进程 ID 的最短表示，或展开为通过使用 bg 最近恢复执行的作业控制后台作业中当前正在执行的管道的最后一个命令的十进制进程 ID 的最短表示——取二者中最近者。

0

（零。）展开为 shell 或 shell 脚本的名称。关于该名称如何派生的详细描述，见 sh。

关于 IFS 变量的描述，见 2.5.3 Shell 变量。

2.5.3 Shell 变量 (Shell Variables)

变量应从环境（如 XBD 8. 环境变量 和 POSIX.1-2024《系统接口》卷中 exec 函数所定义）初始化，并可以通过变量赋值命令赋予新值。Shell 变量应仅从具有有效名称的环境变量初始化。如果变量从环境初始化，应立即标记为导出（export）；见 export 特殊内置。新变量可以通过变量赋值、read 或 getopts 实用程序、for 循环中的 name 参数、${name=word} 展开，或实现扩展提供的其他机制来定义和初始化。

以下变量应影响 shell 的执行：

ENV

[UP]（User Portability Utilities 选项）如果系统支持 User Portability Utilities 选项，则应支持 ENV shell 变量的处理。

当且仅当调用交互式 shell 时，该变量应由 shell 经受参数扩展（见 2.6.2 参数扩展），结果值应用作文件的路径名。在读取任何交互式命令之前，shell 应对文件内容进行 token 化（见 2.3 Token 识别），将 token 解析为 program（见 2.10 Shell 文法），并在当前环境中执行结果命令。（换言之，ENV 文件的内容不被解析为单个 compound_list。这个区别很重要，因为它影响别名何时生效。）该文件不必是可执行的。如果 ENV 展开后的值不是绝对路径名，结果是未指定的。如果用户的真实和有效用户 ID 或真实和有效组 ID 不同，ENV 应被忽略。

HOME

用户主目录的路径名。HOME 的内容用于波浪号展开（见 2.6.1 波浪号展开）。

IFS

一个被视为字符列表的字符串，用于字段分割、'*' 特殊参数的展开，以及用 read 实用程序将行分割为字段。如果 IFS 的值包含任何不构成有效字符一部分的字节，字段分割、'*' 的展开以及 read 实用程序的使用结果是未指定的。

如果 IFS 未设置，它对未设置变量表现正常，但 shell 的字段分割和 read 实用程序的行分割应如同 IFS 的值为 <space><tab><newline> 那样执行；见 2.6.5 字段分割。

shell 被调用时应将 IFS 设置为 <space><tab><newline>。

LANG

为未设置或为 null 的国际化变量提供默认值。（用于确定 locale 类别的值的国际化变量的优先级，见 XBD 8.2 Internationalization Variables。）

LC_ALL

该变量的值覆盖 LC_* 变量和 LANG，如 XBD 8. 环境变量 所述。

LC_COLLATE

确定模式匹配中范围表达式、等价类和多字符整理元素的行为。

LC_CTYPE

确定文本数据的字节序列作为字符的解释（例如，单字节与多字节字符），哪些字符被定义为字母（字符类 alpha）和 <blank> 字符（字符类 blank），以及模式匹配中字符类的行为。shell 启动后更改 LC_CTYPE 的值不应影响当前 shell 执行环境或其子 shell 中 shell 命令的词法处理。调用 shell 脚本或执行 exec sh 会使新 shell 经受 LC_CTYPE 的更改。

LC_MESSAGES

确定消息应使用的语言。

LINENO

[UP] 如果系统支持 User Portability Utilities 选项，则应支持 LINENO shell 变量的处理。

由 shell 设置为一个十进制数，表示脚本或函数内执行每条命令之前的当前顺序行号（从 1 开始编号）。如果用户取消设置或重置 LINENO，该变量可能在 shell 的整个生命周期内失去其特殊含义。如果 shell 当前未在执行脚本或函数，LINENO 的值是未指定的。

NLSPATH

[XSI] 确定用于 LC_MESSAGES 处理的消息目录的位置。

PATH

一个字符串，格式如 XBD 8. 环境变量 所述，用于实现命令解释；见 2.9.1.4 命令搜索与执行。

PPID

在 shell 初始化期间由 shell 设置为其父进程 ID 的十进制值。在子 shell（见 2.13 Shell 执行环境）中，PPID 应被设置为与当前 shell 的父进程相同的值。例如，echo $PPID 和 (echo $PPID) 会产生相同的值。

PS1

[UP] 如果系统支持 User Portability Utilities 选项，则应支持 PS1 shell 变量的处理。

每次交互式 shell 准备读取命令时，该变量的值应经受参数扩展（见 2.6.2 参数扩展）和感叹号展开（见下文）。该值是否还经受命令替换（见 2.6.3 命令替换）或算术扩展（见 2.6.4 算术扩展）或两者，是未指定的。扩展后，该值应写到标准错误。

扩展应分两遍执行，第一遍的结果是第二遍的输入。其中一遍应只执行下文描述的感叹号展开。另一遍应按 2.6 单词扩展 中的规则执行其他扩展。两遍中先执行哪一遍是未指定的。

默认值应为 "$ "。对于具有特定额外实现定义特权的用户，默认值可以是另一个实现定义的值。

感叹号展开：shell 应将每个 <exclamation-mark> 字符（'!'）实例替换为将要输入的下一条命令的历史文件编号（见 Command History List）。被另一个 <exclamation-mark> 字符转义的 <exclamation-mark> 字符（即 "!!"）应展开为单个 <exclamation-mark> 字符。

PS2

[UP] 如果系统支持 User Portability Utilities 选项，则应支持 PS2 shell 变量的处理。

每次用户在交互式 shell 中、完成命令行使输入 <newline> 之前，该变量的值应经受参数扩展（见 2.6.2 参数扩展）。该值是否还经受命令替换（见 2.6.3 命令替换）或算术扩展（见 2.6.4 算术扩展）或两者，是未指定的。扩展后，该值应写到标准错误。默认值应为 "> "。

PS4

[UP] 如果系统支持 User Portability Utilities 选项，则应支持 PS4 shell 变量的处理。

当正在执行执行跟踪（set -x）时，在执行跟踪的每一行之前，该变量的值应经受参数扩展（见 2.6.2 参数扩展）。该值是否还经受命令替换（见 2.6.3 命令替换）或算术扩展（见 2.6.4 算术扩展）或两者，是未指定的。扩展后，该值应写到标准错误。默认值应为 "+ "。

PWD

由 shell 和 cd 实用程序设置。在 shell 中，该值应按如下方式从环境初始化。如果在执行时向 shell 传递了环境中 PWD 的值，该值是当前工作目录的绝对路径名，长度不超过 {PATH_MAX} 字节（包括结尾空字节），且该值不包含任何为 dot 或 dot-dot 的组件，则 shell 应将 PWD 设置为该环境值。否则，如果在执行时向 shell 传递了环境中 PWD 的值，该值是当前工作目录的绝对路径名，且该值不包含任何为 dot 或 dot-dot 的组件，则 shell 是将 PWD 设置为该环境值，还是将 PWD 设置为 pwd -P 本应输出的路径名，是未指定的。否则，sh 实用程序将 PWD 设置为 pwd -P 本应输出的路径名。在 PWD 被设置为环境值的情况下，该值可以包含引用符号链接类型文件的组件。在 PWD 被设置为 pwd -P 本应输出的路径名的情况下，如果对当前工作目录或该目录的任何父目录没有足够权限来确定该路径名是什么，PWD 的值是未指定的。对该变量的赋值可能被忽略。如果应用设置或取消设置 PWD 的值，cd 和 pwd 实用程序的行为是未指定的。

2.6 单词扩展 (Word Expansions)

本节描述对单词执行的各种扩展。并非每个单词都执行所有扩展，如下文各节及本章其他部分所述。对给定单词执行的扩展应按以下顺序执行：

  1. 波浪号展开（见 2.6.1 波浪号展开）、参数扩展（见 2.6.2 参数扩展）、命令替换（见 2.6.3 命令替换）和算术扩展（见 2.6.4 算术扩展）应从开始到结束依次执行。见 2.3 Token 识别 中的第 5 项。
  2. 应对步骤 1 生成的字段的部分执行字段分割（见 2.6.5 字段分割）。
  3. 应执行路径名展开（见 2.6.6 路径名展开），除非 set -f 生效。
  4. 引用消除（见 2.6.7 引用消除），如果执行，应始终最后执行。

发生在单个单词内的波浪号展开、参数扩展、命令替换、算术扩展和引用消除应展开为单个字段，但下文所述情况除外。shell 应仅因字段分割、路径名展开或以下情况，从单个单词创建多个字段或不创建字段：

  1. 特殊参数 '@' 和 '*' 的参数扩展（如 2.5.2 特殊参数 所述）可以从单个单词创建多个字段或不创建字段。

  2. 当展开发生在将执行字段分割的上下文中时，一个单词如果在应用任何扩展之前、其内部某处以指定顺序包含以下全部内容：

    • 一个未被引用的 <left-curly-bracket>（'{'），且其前面不是未被引用的 <dollar-sign>（'$'）
    • 一个或多个未引用的 <comma>（','）字符，或一个由两个被其他字符包围的相邻 <period>（'.'）字符组成的序列（这些其他字符也可以是 <period> 字符）
    • 一个未引用的 <right-curly-bracket>（'}'）

    则可以经受一种额外的实现定义形式的扩展，这种扩展可以从单个单词创建多个字段。这种扩展（如果支持）应在所有其他单词扩展应用之前应用。然后，其他扩展应应用于由此扩展产生的每个字段。

当本节中的扩展不是在准备执行命令的上下文中执行时，它们应在当前 shell 执行环境中进行。

当为即将执行的命令扩展单词，且该单词将是命令名或命令的参数时，扩展应在当前 shell 执行环境中进行。（要执行的命令的环境在命令单词已知之前是未知的。）

当扩展即将执行的命令中与变量赋值或重定向一起使用的单词时，扩展是在当前执行环境还是在即将执行的命令的环境中进行的，是未指定的。

'$' 字符用于引入参数扩展、命令替换或算术求值。如果一个既不在单引号内、也不被 <backslash> 转义的 '$' 紧跟一个不是 <space>、不是 <tab>、不是 <newline> 且不是以下之一的字符：

  • 数字字符
  • 特殊参数的名称之一（见 2.5.2 特殊参数）
  • 变量名的有效首字符
  • <left-curly-bracket>（'{'）
  • <left-parenthesis>
  • 单引号

则结果是未指定的。如果一个既不在单引号内、也不被 <backslash> 转义的 '$' 紧跟一个 <space>、<tab> 或 <newline>，或后面没有任何字符，则 '$' 应被视为字面字符。

2.6.1 波浪号展开 (Tilde Expansion)

"波浪号前缀（tilde-prefix）"由单词开头的未引用 <tilde>（'~'）字符，后跟单词中第一个未引用 <slash> 之前的所有字符（如果单词中没有 <slash> 则为单词中的所有字符）组成。在赋值（见 XBD 4.26 Variable Assignment）中，可以使用多个波浪号前缀：一个在单词开头（即在赋值的 <equals-sign> 之后），或一个跟随在任何未引用的 <colon> 之后，或两者。赋值中的波浪号前缀由第一个未引用的 <colon> 或 <slash> 或赋值单词的结尾终止。

如果波浪号前缀只由 <tilde> 字符组成，它应被替换为变量 HOME 的值。如果 HOME 未设置，结果是未指定的。

否则，波浪号前缀中 <tilde> 之后的字符应被视为来自用户数据库的可能登录名。如果这些字符不构成便携登录名（见 XBD 8.3 Other Environment Variables 中 LOGNAME 环境变量的描述），结果是未指定的。

注意：

由于在移除 <tilde> 以获得登录名之后，波浪号前缀不再经受进一步的单词扩展，因此以下各项的 <tilde> 之后都没有便携登录名：

~"string"
~'string'
~$var
~\/bin

原因在于登录名中存在 '"'、'\''、'$'、'\\' 和 '/' 字符。

如果波浪号前缀中 <tilde> 之后的字符构成便携登录名，波浪号前缀应被替换为与该登录名关联的初始工作目录的路径名。该路径名应如同使用 POSIX.1-2024《系统接口》卷中定义的 getpwnam() 函数那样获得。如果系统不识别该登录名，结果是未指定的。

替换波浪号前缀的路径名应被视为已被引用，以防止它被字段分割和路径名展开改变；如果 <slash> 跟随在波浪号前缀之后且该路径名以 <slash> 结尾，则替换时应省略路径名末尾的 <slash>。如果被展开的单词只由 <tilde> 字符组成，且 HOME 被设置为 null 字符串，这将产生一个空字段（而非零个字段）作为展开后的单词。

注意：

本标准未来版本可能要求：如果 <slash> 跟随在波浪号前缀之后且该路径名以 <slash> 结尾，则替换时省略路径名末尾的 <slash>。

2.6.2 参数扩展 (Parameter Expansion)

参数扩展的格式如下：

${expression}

其中 expression 由直到匹配的 '}' 为止的所有字符组成。任何被 <backslash> 转义或在引用字符串内的 '}'，以及嵌入的算术扩展、命令替换和变量扩展中的字符，在确定匹配的 '}' 时不应被检查。

参数扩展的最简单形式是：

${parameter}

应替换 parameter 的值（如有）。

参数名或符号可以括在花括号中；花括号是可选的，但对于多于一位数字的位置参数，或当 parameter 是名称且其后跟有可被解释为名称一部分的字符时，花括号是必需的。

对于不括在花括号中的参数：

  • 如果参数是名称，扩展应使用最长的有效名称（见 XBD 3.216 Name），无论该名称所表示的变量是否存在。
  • 否则，参数是单字符符号，如果该字符既不是数字也不是特殊参数之一（见 2.5.2 特殊参数），行为是未指定的。

此外，参数扩展可以使用以下格式之一进行修改。在每种需要 word 值的情况（基于 parameter 的状态，如下所述）下，word 应经受波浪号展开、参数扩展、命令替换、算术扩展和引用消除。如果不需要 word，则不应展开它。界定以下参数扩展修改的 '}' 字符应按本节前文及 2.2.3 双引号 中所述的方式确定。如果 parameter 是 '*' 或 '@'，展开结果是未指定的。

${parameter:-[word]}

使用默认值（Use Default Values）。如果 parameter 未设置或为 null，应替换 word 的展开（如果省略 word 则为空字符串）；否则，应替换 parameter 的值。

${parameter:=[word]}

赋默认值（Assign Default Values）。如果 parameter 未设置或为 null，应对 word 的展开执行引用消除，结果（如果省略 word 则为空字符串）应赋给 parameter。在所有情况下，都应替换 parameter 的最终值。只有变量（而非位置参数或特殊参数）能以这种方式被赋值。

${parameter:?[word]}

若为 null 或未设置则指示错误（Indicate Error if Null or Unset）。如果 parameter 未设置或为 null，应将 word 的展开（如果省略 word 则为指示其未设置的消息）写到标准错误，且 shell 以非零退出状态退出。否则，应替换 parameter 的值。交互式 shell 不必退出。

2.6.3 命令替换 (Command Substitution)

命令替换允许用一个或多个命令的输出替换命令本身。当命令按如下方式括起时，应发生命令替换：

$(commands)

或（反引号版本）：

`commands`

shell 应通过在子 shell 环境（见 2.13 Shell 执行环境）中执行 commands 来扩展命令替换，并将命令替换（commands 字符串的文本加上包围的 "$()" 或反引号）替换为命令的标准输出；如果输出以一个或多个编码值为 <newline> 字符的字节结尾，它们不应包含在替换中。出现在其他位置的任何此类字节应包含在替换中；但它们可能被当作字段定界符并在字段分割期间被消除，具体取决于生效的 IFS 值和引用。如果输出包含任何空字节，行为是未指定的。

在反引号风格的命令替换中，如果命令替换不在双引号内，<backslash> 应保留其字面含义，但后跟 '$'、'`' 或 <backslash> 时除外。命令替换在双引号内时 <backslash> 的处理见 2.2.3 双引号。对匹配反引号的搜索应由第一个未引用的非转义反引号满足；在此搜索期间，如果在 shell 注释、here-document、$(commands) 形式的嵌入命令替换或引用字符串中遇到非转义反引号，会产生未定义的结果。在 "`...`" 序列内开始但未结束的引用字符串产生未定义的结果。

对于 $(commands) 形式，从左括号之后到匹配的右括号为止的所有字符构成 commands 字符串。

对于反引号和 $(commands) 两种形式，commands 字符串应被 token 化（见 2.3 Token 识别）并解析（见 2.10 Shell 文法）。commands 字符串是被增量地解析并作为 program 执行（如同 shell 脚本），还是被解析为在字符串完全解析后执行的单个 compound_list，是未指定的。此外，$(commands) 形式的结尾 ')' 是否能由别名替换产生，是未指定的。对于 $(commands) 形式，任何语法正确的 program 都可以用作 commands，但以下情况除外：

  • 如果 commands 字符串只由重定向组成，结果是未指定的。
  • 如果 commands 字符串被解析为单个 compound_list，则在执行任何命令之前，commands 中的 alias 和 unalias 命令在解析期间没有效果（见 2.3.1 别名替换）。严格符合（strictly conforming）的应用应确保 commands 字符串不依赖于按 program 方式解析和执行时才会发生的别名更改的增量生效。
  • 如果结尾 ')' 不在包含命令替换的 token 中，行为是未指定的；也就是说，如果期望 ')' 由别名替换产生。

命令替换的结果不应再被处理以进行进一步的波浪号展开、参数扩展、命令替换或算术扩展。

命令替换可以嵌套。要在反引号版本中指定嵌套，应用应在内部反引号前加上 <backslash> 字符；例如：

\`commands\`

Shell 命令语言的语法对以 "$((" 开头的扩展存在歧义：它可以引入算术扩展，也可以引入以子 shell 开头的命令替换。算术扩展优先；也就是说，shell 应首先确定它是否能将该扩展解析为算术扩展，并且仅当它确定无法将该扩展解析为算术扩展时，才应将该扩展解析为命令替换。shell 在执行此确定时不必求值嵌套扩展。如果它在尚未确定无法将该扩展解析为算术扩展的情况下遇到输入结束，shell 应将该扩展视为不完整的算术扩展并报告语法错误。符合应用应确保在以子 shell 开头的命令替换中，将 "$(" 和 '(' 分隔为两个 token（即用空白分隔它们）。例如，包含单个子 shell 的命令替换可以写成：

$( (commands) )

2.6.4 算术扩展 (Arithmetic Expansion)

算术扩展提供了一种求值算术表达式并替换其值的机制。算术扩展的格式如下：

$((expression))

该表达式应被视同处于双引号内，但表达式内的双引号不被特殊处理。shell 应扩展表达式中的所有 token，以进行参数扩展、命令替换和引用消除。

接下来，shell 应将其视为算术表达式并替换表达式的值。算术表达式应按 1.1.2.1 算术精度与运算 中给出的规则处理，但以下例外：

  • 只要求有符号长整数（signed long）算术。
  • 只要求识别 ISO C 标准第 6.4.4.1 节中规定的十进制常量、八进制常量和十六进制常量。
  • 不要求 sizeof() 运算符以及前缀和后缀 "++"、"--" 运算符。
  • 不支持选择（selection）、迭代（iteration）和跳转（jump）语句。

算术表达式中对变量的所有更改在算术扩展之后都应生效，如同参数扩展 "${x=value}" 一样。

如果 shell 变量 x 包含构成有效整数常量的值（可选地包括前导 <plus-sign> 或 <hyphen-minus>），则算术扩展 "$((x))" 和 "$(($x))" 应返回相同的值。

作为扩展，shell 可以识别超出所列的算术表达式。shell 可以使用等级大于 signed long 等级的有符号整数类型。shell 可以使用实浮点（real-floating）类型代替 signed long，只要在无溢出的情况下不影响结果即可。如果表达式无效，或表达式中使用的 shell 变量的内容不被 shell 识别，则扩展失败，且 shell 应向标准错误写一条指示失败的诊断消息。

以下各节是提供信息的（informative）。

示例 (Examples)

使用算术扩展的简单示例：

# repeat a command 100 times
x=100
while [ $x -gt 0 ]
do
    command
    x=$(($x-1))
done

提供信息文本结束。

2.6.5 字段分割 (Field Splitting)

在参数扩展（2.6.2 参数扩展）、命令替换（2.6.3 命令替换）和算术扩展（2.6.4 算术扩展）之后，如果 shell 变量 IFS（见 2.5.3 Shell 变量）已设置且其值不为空，或者 IFS 未设置，shell 应扫描包含未在双引号内发生的扩展和替换结果的每个字段以进行字段分割；可以产生零个、一个或多个字段。

在本节余下部分，对扩展结果（results of an expansion）的任何引用都应解释为来自一个或多个未引用的变量或算术扩展，或未引用的命令替换的结果。

如果 IFS 变量已设置且其值为空字符串，则不应发生字段分割。但是，如果包含扩展结果的输入字段完全为空，则应将其移除。注意这发生在引用消除之前；任何包含引用字符的输入字段在此刻不可能为空。从输入中移除任何此类字段后，可能被修改的输入字段列表应成为输出。

每个输入字段应按从第一个到最后一个的顺序考虑，本节所述算法的结果导致生成输出字段，这些输出字段应保持与它们源自的输入字段相同的顺序。

不包含扩展结果的字段不应受字段分割影响，并应保持原样，只是从输入字段列表移动到输出字段列表的下一个位置。

在余下的描述中，假定字段中至少存在一个扩展结果；不再重述此假定。字段分割只会改变字段中那些部分。

就本节而言，术语 "IFS 空白（IFS white space）"用于指便携字符集（见 XBD 3.413 White Space、3.414 White-Space Byte 和 3.415 White-Space Character）中存在于 IFS 变量值中的空白字节（见 XBD 6.1 Portable Character Set）<space>、<tab> 或 <newline>，以及可能的其他空白字符。出现在 IFS 值中的其他空白字符是否也被视为 "IFS 空白"，是实现定义的。上面指定为 IFS 空白字节的三个字符，当它们出现在 IFS 值中时总是 IFS 空白，无论它们在相关 locale 中是否为空白字符。对于实现允许的其他 locale 特定空白字符，该字符是在被赋给 IFS 变量时为空白的时刻被视为 IFS 空白，还是在字段分割发生时为空白的时刻被视为 IFS 空白，是未指定的。（locale 可能在这两个事件之间发生了变化。）

如果 IFS 变量未设置，则就本节而言（但不改变变量的值），其值应被视为包含便携字符集中的三个单字节字符 <space>、<tab> 和 <newline>，它们都是 IFS 空白字符。

shell 应使用构成 IFS 变量值中字符的字节序列作为定界符。出现在 IFS 值中的 <space>、<tab> 和 <newline> 每个字符都应是单字节定界符。shell 应使用这些定界符作为字段终止符，将扩展结果以及相邻的其他字节分割为单独字段，如下所述。注意这些定界符终止一个字段；它们本身不导致新字段开始——开始新字段需要后续的、不是来自扩展结果、或不构成 IFS 空白字符的字节。

注意 shell 处理输入字段中的任意字节；不要求这些字节构成有效字符。

如果算法结果是未界定任何字段；也就是说，如果输入字段完全为空或完全由 IFS 空白组成，则结果应是零个字段（而非空字段）。

就本节而言，当说一个字段被界定时，按如下生成候选字段应成为输出字段。当算法将候选转换为输出字段时，应将其追加到当前输出字段列表。

每个包含扩展结果的字段应按顺序处理，与不包含扩展结果的字段交错，按上述方式处理，如同使用以下算法，从头到尾检查输入字段中的字节：

  • 以空候选字段和如上指定的输入开始。
  • 当被指示开始循环的下一次迭代时，这就是循环的开始。当输入（按此循环的早期迭代修改后）不为空时：

    • 考虑输入的前导剩余字节或字节序列。任何此类字节序列不应包含这样的数据：序列中的一些字节来自扩展，而另一些不是，也不包含来自多于一个扩展的结果的字节。如果该字节或字节序列是：

      1. 输入中不是来自扩展的字节（或字节序列）：

        将该字节（或序列）追加到候选，并将其从输入中移除。开始循环的下一次迭代。

      2. 输入中来自扩展且不构成 IFS 中字符的字节序列：

        将序列的第一个字节追加到候选，并将该字节从输入中移除。开始循环的下一次迭代。

      3. 输入中来自扩展且构成 IFS 空白字符的字节序列：

        将该字节序列从输入中移除，考虑新的前导输入字节序列，并重复此步骤。

      4. 输入中来自扩展且构成 IFS 中非 IFS 空白字符的字节序列：

        将该字节序列从输入中移除，但记录它被观察到。

      此时，如果候选不为空，或者在步骤 4 中看到了表示非 IFS 空白的 IFS 字符的字节序列，则称一个字段已被界定，候选应成为输出字段。

    • 清空（清除）候选，并开始循环的下一次迭代。

  • 一旦输入为空，当且仅当候选不为空时，候选应成为输出字段。

如此产生的有序输出字段列表（可能为空）应替换输入字段列表。

2.6.6 路径名展开 (Pathname Expansion)

字段分割之后，如果 set -f 未生效，结果命令行中的每个字段应使用 2.14 模式匹配记号 中描述的算法进行展开，并由 2.14.3 用于文件名展开的模式 中的规则限定。

2.6.7 引用消除 (Quote Removal)

原始单词中存在的 <dollar-sign> 单引号引用字符序列和单字符引用字符（<backslash>、单引号和双引号）应被移除，除非它们自身已被引用。注意终止 <dollar-sign> 单引号序列的单引号字符本身就是一个单字符引用字符。

注意：

引用消除之后，shell 仍会记住哪些字符曾被引用。这对于在 case 条件构造（见 2.9.4.3 Case 条件构造 和 2.14 模式匹配记号）中匹配模式等目的来说是必要的。

2.7 重定向 (Redirection)

重定向用于为当前 shell 执行环境（见 2.13 Shell 执行环境）或任何命令打开和关闭文件。重定向运算符可以与表示文件描述符的数字（见 XBD 3.141 File Descriptor）一起使用，如下所述。

重定向使用的总体格式为：

[n]redir-op word

数字 n 是可选的一位或多位十进制数，指定文件描述符编号；应用应确保它与任何前面的文本分隔，并紧接在重定向运算符 redir-op 之前（不允许有中间的 <blank> 字符）。如果 n 被引用，该数字不应被识别为重定向表达式的一部分。例如：

echo \2>a

将字符 2 写入文件 a。如果 redir-op 的任何部分被引用，则不识别任何重定向表达式。例如：

echo 2\>a

将字符 2>a 写到标准输出。可选数字、重定向运算符和 word 不应出现在提供给要执行命令（如有）的参数中。

shell 可以支持用于重定向的附加格式：

{location}redir-op word

其中 location 非空，表示可以存储整数值的位置，如 shell 变量的名称。如果支持此格式，其行为是实现定义的。

shell 重定向中支持的最大文件描述符编号是实现定义的；但所有实现都应至少支持 0 到 9（含），供应用使用。

如果重定向运算符是 "<<" 或 "<<-"，紧随重定向运算符之后的 word 应经受引用消除；是否发生任何其他扩展是未指定的。对于其他重定向运算符，紧随重定向运算符之后的 word 应经受波浪号展开、参数扩展、命令替换、算术扩展和引用消除。非交互式 shell 不应对该 word 执行路径名展开；交互式 shell 可以执行它，但如果展开会产生多个单词，则重定向是不执行路径名展开地继续，还是失败，是未指定的。

注意：

本标准未来版本可能要求在这种情况下重定向失败。

如果一个命令指定了多个重定向运算符，求值顺序是从开始到结束。

打开或创建文件失败应导致重定向失败。

2.7.1 重定向输入 (Redirecting Input)

输入重定向应导致名称由 word 展开产生的文件在指定的文件描述符上为读取而打开，如果未指定文件描述符则为标准输入。

重定向输入的一般格式为：

[n]<word

其中可选 n 表示文件描述符编号。如果省略该数字，重定向应指标准输入（文件描述符 0）。

2.7.2 重定向输出 (Redirecting Output)

重定向输出的两种一般格式为：

[n]>word
[n]>|word

其中可选 n 表示文件描述符编号。如果省略该数字，重定向应指标准输出（文件描述符 1）。

使用 '>' 格式的输出重定向，如果设置了 noclobber 选项（见 set -C 的描述），且由 word 展开命名的文件存在并且是普通文件或解析为普通文件的符号链接，则应失败；如果该文件是未解析到现存文件的符号链接，也可能失败。存在性检查、文件创建和打开操作应原子地执行，如同 POSIX.1-2024《系统接口》卷中定义的 open() 函数在设置了 O_CREAT 和 O_EXCL 标志时所做的那样，但如果文件存在且是符号链接，则除非该符号链接解析到现存的普通文件，否则打开操作不必以 [EEXIST] 失败。原子地执行这些操作确保了锁文件和唯一（通常是临时）文件的创建是可靠的，其中重要的注意事项详见 C.2.7.2 Redirecting Output。文件类型检查不必与存在性检查、文件创建和打开操作原子地执行。如果不这样，可能存在竞态条件，当重定向失败时可能导致误导性的 shell 诊断消息。更多细节见 XRAT C.2.7.2 Redirecting Output。

在所有其他情况下（未设置 noclobber、使用 '>' 的重定向不因上述原因失败，或使用 ">|" 格式的重定向），输出重定向应导致名称由 word 展开产生的文件在指定的文件描述符上为输出而打开，如果未指定则为标准输出。如果文件不存在，应将其创建为空文件；否则，应如同以 O_TRUNC 标志调用 open() 函数那样打开它。

2.7.3 追加重定向输出 (Appending Redirected Output)

追加输出重定向应导致名称由 word 展开产生的文件在指定的文件描述符上为输出而打开。该文件应如同以 O_APPEND 标志调用 POSIX.1-2024《系统接口》卷中定义的 open() 函数那样打开。如果文件不存在，应创建它。

追加重定向输出的一般格式如下：

[n]>>word

其中可选 n 表示文件描述符编号。如果省略该数字，重定向指标准输出（文件描述符 1）。

2.7.4 Here-Document

重定向运算符 "<<" 和 "<<-" 都允许将 shell 读取的后续行重定向到命令的输入。这些被重定向的行称为 "here-document"。

here-document 应被视为单个单词，从下一个 NEWLINE token 之后开始，持续到出现只包含定界符和一个 <newline>、中间没有任何 <blank> 字符的行为止。然后，如果有下一个 here-document，它开始。为了定位这个终止行，command_string 操作数（见 sh）的结尾应被视为 <newline> 字符，而 $(commands) 和 `commands` 中 commands 字符串的结尾可以被视为 <newline>。如果在未找到终止行的情况下到达输入结束，shell 应该（但不必）将此视为重定向错误。格式如下：

[n]<<word
    here-document
delimiter

其中可选 n 表示文件描述符编号。如果省略该数字，here-document 指标准输入（文件描述符 0）。该文件描述符是作为普通文件还是某种其他类型的文件打开，是未指定的。便携应用不能依赖该文件描述符是可寻址的（seekable）（见 XSH lseek()）。

如果 word 的任何部分被引用（不包括命令替换之外的双引号，如果 here-document 在命令替换内的话），定界符应通过对 word 执行引用消除来形成，且 here-document 的行不应被扩展。否则：

  • 定界符应是 word 本身。
  • 在搜索结尾定界符期间，应执行 <backslash><newline> 的移除以进行续行（见 2.2.1 转义字符（反斜杠））。（因此，紧跟在被续行移除的 <newline> 之后，不识别结尾定界符。）包含结尾定界符的行本身是否经受此续行，是未指定的。
  • 当重定向运算符被求值但已在定位 here-document 的结尾定界符之后，here-document 的所有行应被扩展，以进行参数扩展、命令替换和算术扩展。如果重定向运算符从未被求值（因为它所属的命令未被执行），则应在不执行任何扩展的情况下读取 here-document。
  • 输入中的任何 <backslash> 字符应表现得像双引号内的 <backslash>（见 2.2.3 双引号）。但双引号字符（'"'）在 here-document 内不应被特殊处理，除非该双引号出现在 "$()"、"``" 或 "${}" 内。

如果重定向运算符是 "<<-"，所有前导 <tab> 字符应从输入行中剥离（在按需执行 <backslash><newline> 续行之后），并从包含结尾定界符的行中剥离。前导 <tab> 字符的剥离应在 here-document 从 shell 输入读取时发生（因此不影响来自扩展的任何 <tab> 字符）。

如果在一行上指定了多个 "<<" 或 "<<-" 运算符，与第一个运算符关联的 here-document 应由应用首先提供，并由 shell 首先读取。

当从终端设备读取 here-document 且 shell 是交互式的，它应在读取每行输入之前，将变量 PS2 的内容（按 2.5.3 Shell 变量 所述处理）写到标准错误，直到定界符被识别。

以下各节是提供信息的（informative）。

示例 (Examples)

here-document 的示例如下：

cat <<eof1; cat <<eof2
Hi,
eof1
Helene.
eof2

提供信息文本结束。

2.7.5 复制输入文件描述符 (Duplicating an Input File Descriptor)

重定向运算符：

[n]<&word

应从一个输入文件描述符复制另一个输入文件描述符，或关闭一个。如果 word 求值为一个或多个数字，则由 n 表示的文件描述符（如果未指定 n 则为标准输入）应成为由 word 表示的文件描述符的副本；如果 word 中的数字不代表已打开的文件描述符，应发生重定向错误（见 2.8.1 Shell 错误的后果）；如果由 word 表示的文件描述符是未为输入打开的已打开文件描述符，可能发生重定向错误。如果 word 求值为 '-'，文件描述符 n（如果未指定 n 则为标准输入）应被关闭。尝试关闭未打开的文件描述符不应构成错误。如果 word 求值为其他内容，行为是未指定的。

2.7.6 复制输出文件描述符 (Duplicating an Output File Descriptor)

重定向运算符：

[n]>&word

应从一个输出文件描述符复制另一个输出文件描述符，或关闭一个。如果 word 求值为一个或多个数字，则由 n 表示的文件描述符（如果未指定 n 则为标准输出）应成为由 word 表示的文件描述符的副本；如果 word 中的数字不代表已打开的文件描述符，应发生重定向错误（见 2.8.1 Shell 错误的后果）；如果由 word 表示的文件描述符是未为输出打开的已打开文件描述符，可能发生重定向错误。如果 word 求值为 '-'，文件描述符 n（如果未指定 n 则为标准输出）被关闭。尝试关闭未打开的文件描述符不应构成错误。如果 word 求值为其他内容，行为是未指定的。

2.7.7 为读和写打开文件描述符 (Open File Descriptors for Reading and Writing)

重定向运算符：

[n]<>word

应导致名称由 word 展开产生的文件在由 n 表示的文件描述符（如果未指定 n 则为标准输入）上为读取和写入而打开。如果文件不存在，应创建它。

2.9.1.2 变量赋值 (Variable Assignments)

变量赋值应按如下方式执行：

  • 如果没有产生命令名，变量赋值应影响当前执行环境。
  • 如果命令名不是特殊内置实用程序或函数，变量赋值应为命令的执行环境导出，并且除了步骤 4 中执行的扩展的副作用外，不应影响当前执行环境。在这种情况下，以下事项是未指定的：
    • 这些赋值在步骤 4 的后续扩展中是否可见
    • 作为这些扩展的副作用而进行的变量赋值，在步骤 4 的后续扩展中、或在当前 shell 执行环境中、或两者中是否可见
  • 如果命令名是以函数形式实现的标准实用程序（见 XBD 4.25 Utility），变量赋值的效果应如同该实用程序不是以函数形式实现一样。
  • 如果命令名是特殊内置实用程序，变量赋值应在该实用程序执行之前影响当前执行环境，并在命令完成时仍然生效；如果被赋值的变量被该实用程序进一步修改，该实用程序所做的修改应持续存在。除非 set -a 选项开启（见 set），否则以下事项是未指定的：
    • 这些变量在特殊内置实用程序执行期间是否获得 export 属性
    • 因变量赋值而获得的 export 属性在特殊内置实用程序完成后是否持续存在
  • 如果命令名是不是以函数形式实现的标准实用程序的函数，变量赋值应在函数执行期间影响当前执行环境。以下事项是未指定的：
    • 变量赋值在函数完成后是否持续存在
    • 这些变量在函数执行期间是否获得 export 属性
    • 因变量赋值而获得的 export 属性在函数完成后是否持续存在（如果变量赋值在函数完成后持续存在）

如果任何变量赋值试图为当前 shell 环境中设置了 readonly 属性的变量赋一个值（无论该赋值是否在该环境中进行），应发生变量赋值错误。这些错误的后果见 2.8.1 Shell 错误的后果。

2.9.1.3 无命令名的命令 (Commands with no Command Name)

如果简单命令在单词扩展后没有命令名（见 2.9.1.1 处理顺序），任何重定向应在子 shell 环境中执行；该子 shell 环境是否与命令内命令替换所用的同一环境，是未指定的。（要影响当前执行环境，见 exec 特殊内置。）如果在当前 shell 执行环境中执行的任何重定向失败，命令应立即以大于零的退出状态失败，且 shell 应写一条指示失败的错误消息。这些失败对交互式和非交互式 shell 的后果见 2.8.1 Shell 错误的后果。

此外，如果没有命令名但命令包含命令替换，命令应以退出状态最后被获取的那个命令替换的退出状态完成。否则，命令应以零退出状态完成。

  2. 如果命令名包含至少一个 <slash>：

    2. 如果命名实用程序不存在，命令应以退出状态 127 失败，且 shell 应写一条错误消息。

2.9.2 管道 (Pipelines)

管道（pipeline）是由控制运算符 '|' 分隔的一个或多个命令的序列。对于除最后一个外的每个命令，shell 应将该命令的标准输出连接到下一个命令的标准输入，如同创建管道并将管道的写端作为命令的标准输出、管道的读端作为下一个命令的标准输入一样。

管道的格式为：

[!] command1 [ | command2 ...]

如果管道以保留字 ! 开头且 command1 是子 shell 命令，应用应确保 command1 开头的 ( 运算符与 ! 之间由一个或多个 <blank> 字符分隔。保留字 ! 后紧跟 ( 运算符的行为是未指定的。

command1 的标准输出应连接到 command2 的标准输入。命令的标准输入、标准输出或两者应被视为在命令部分的重定向运算符（见 2.7 重定向）指定的任何重定向之前由管道分配。

如果管道不在后台（见 2.9.3.1 异步 AND-OR 列表 和 2.11 作业控制），shell 应等待管道中指定的最后一个命令完成，并且也可以等待所有命令完成。

退出状态 (Exit Status)

2.9.3.4 OR 列表 (OR Lists)

控制运算符 "||" 表示 OR 列表。格式应为：

command1 [ || command2] ...

首先，应执行 command1。如果其退出状态非零，应执行 command2，依此类推，直到某个命令具有零退出状态或没有更多命令要执行。

退出状态 (Exit Status)

OR 列表的退出状态应是列表中执行的最后一个命令的退出状态。

2.9.4 复合命令 (Compound Commands)

shell 有几个编程构造称为 "复合命令（compound commands）"，它们为命令提供控制流。每个复合命令在开头有一个保留字或控制运算符，在结尾有相应的终止保留字或运算符。此外，每个复合命令后面可以跟与终止符同一行上的重定向。每个重定向应应用于复合命令内未显式覆盖该重定向的所有命令。

在下面的描述中，一些复合命令的退出状态以 compound-list（复合列表）的退出状态来表述。compound-list 的退出状态应是特殊参数 '?'（见 2.5.2 特殊参数）在执行该 compound-list 之后立即具有的值。

2.9.4.1 分组命令 (Grouping Commands)

分组命令的格式如下：

( compound-list )

在子 shell 环境中执行 compound-list；见 2.13 Shell 执行环境。影响环境的变量赋值和内置命令在列表完成后不应保持生效。

如果以 "((" 开头的字符序列在 '$' 前缀下会被 shell 解析为算术扩展，则实现将 "(("expression))" 作为算术表达式求值的扩展，可以将 "((" 视为引入算术求值而非分组命令。符合应用应确保用空白分隔两个前导 '(' 字符，以防止 shell 执行算术求值。

{ compound-list ; }

在当前进程环境中执行 compound-list。此处显示的 semicolon 是界定 } 保留字的控制运算符的一个示例。如 2.10 Shell 文法 所示，其他定界符也是可能的；<newline> 是常用的。

退出状态 (Exit Status)

分组命令的退出状态应是 compound-list 的退出状态。

2.9.4.2 for 循环 (The for Loop)

for 循环应为 items（项）列表中的每个成员执行一个命令序列。for 循环要求使用保留字 do 和 done 来界定命令序列。

for 循环的格式如下：

for name [ in [word ... ]]
do
    compound-list
done

首先，应扩展 in 之后的单词列表以生成项列表。然后，变量 name 应依次设置为每个项，并每次执行 compound-list。如果扩展没有产生任何项，则不应执行 compound-list。省略：

in word ...

应等价于：

in &#34;$@&#34;
退出状态 (Exit Status)

如果项列表中至少有一个项，for 命令的退出状态应是执行的最后一个 compound-list 的退出状态。如果没有项，退出状态应为零。

2.9.4.3 case 条件构造 (Case Conditional Construct)

条件构造 case 应执行与第一个匹配的 pattern（见 2.14 模式匹配记号）相对应的 compound-list（如有任何模式），该模式与给定单词经波浪号展开、参数扩展、命令替换、算术扩展和引用消除后产生的字符串匹配。保留字 in 应表示要匹配的模式的开始。具有相同 compound-list 的多个模式应由 '|' 符号分隔。控制运算符 ')' 终止与给定动作相对应的模式列表。被终止的模式列表和随后的 compound-list 称为 case 语句的 clause（子句）。每个 case 语句子句（除最后一个外）应以 ";;" 或 ";&" 终止。case 构造以保留字 esac（case 的反写）终止。

case 构造的格式如下：

case word in
    [[(] pattern[ | pattern] ... ) compound-list terminator] ...
    [[(] pattern[ | pattern] ... ) compound-list]
esac

其中 terminator 是 ";;" 或 ";&"，对于最后一个 compound-list 是可选的。

从 case 语句的开始到结束，每个为 compound-list 标记的 pattern 应经受波浪号展开、参数扩展、命令替换和算术扩展，这些扩展的结果应按 2.14 模式匹配记号 所述规则与 word 的扩展进行比较（该节还描述了引用模式部分的效果）。在第一次匹配之后，case 语句中不再有模式被扩展，应执行匹配子句的 compound-list。如果 case 语句子句由 ";;" 终止，不再检查进一步的子句。如果 case 语句子句由 ";&" 终止，则应按顺序执行每个后续子句的 compound-list（如有），直到到达由 ";;" 终止的子句并执行其 compound-list（如有），或 case 语句中没有进一步的子句。为 compound-list 语句标记的多个 pattern 的扩展和比较顺序是未指定的。

退出状态 (Exit Status)

如果没有匹配的模式，case 的退出状态应为零。否则，退出状态应是最后执行的子句的 compound-list 的退出状态。

2.9.4.4 if 条件构造 (The if Conditional Construct)

if 命令应执行一个 compound-list 并使用其退出状态来确定是否执行另一个 compound-list。

if 构造的格式如下：

if compound-list
then
    compound-list
[elif compound-list
then
    compound-list] ...
[else
    compound-list]
fi

应执行 if compound-list；如果其退出状态为零，应执行 then compound-list 且命令完成。否则，应依次执行每个 elif compound-list，如果其退出状态为零，应执行 then compound-list 且命令完成。否则，应执行 else compound-list。

退出状态 (Exit Status)

if 命令的退出状态应是已执行的 then 或 else compound-list 的退出状态，如果两者都未执行则为零。

注意：

尽管在确定 if 命令的退出状态时忽略 if 或 elif compound-list 的退出状态，但在执行下一个 then、elif 或 else compound-list（如有执行）期间，它可以照常通过特殊参数 '?'（见 2.5.2 特殊参数）获得。

2.9.4.5 while 循环 (The while Loop)

while 循环应持续执行一个 compound-list，只要另一个 compound-list 具有零退出状态。

while 循环的格式如下：

while compound-list-1
do
    compound-list-2
done

应执行 compound-list-1，如果它具有非零退出状态，while 命令应完成。否则，应执行 compound-list-2，并重复该过程。

退出状态 (Exit Status)

while 循环的退出状态应是执行的最后一个 compound-list-2 的退出状态，如果未执行则为零。

注意：

由于在确定 while 命令的退出状态时忽略 compound-list-1 的退出状态，除了在 compound-list-1 执行期间通过特殊参数 '?'（见 2.5.2 特殊参数）之外，无法获得导致循环退出的命令的状态，例如：

while some_command; st=$?; false; do ...

compound-list-1 的退出状态在 compound-list-2 执行期间可通过特殊参数 '?' 获得，但此时已知为零。

2.9.4.6 until 循环 (The until Loop)

until 循环应持续执行一个 compound-list，只要另一个 compound-list 具有非零退出状态。

until 循环的格式如下：

until compound-list-1
do
    compound-list-2
done

应执行 compound-list-1，如果它具有零退出状态，until 命令完成。否则，应执行 compound-list-2，并重复该过程。

退出状态 (Exit Status)

until 循环的退出状态应是执行的最后一个 compound-list-2 的退出状态，如果未执行则为零。

注意：

尽管在确定 until 命令的退出状态时忽略 compound-list-1 的退出状态，但在 compound-list-2 执行期间，它可以照常通过特殊参数 '?'（见 2.5.2 特殊参数）获得。

2.9.5 函数定义命令 (Function Definition Command)

函数（function）是用户定义的名称，用作简单命令来调用带有新位置参数的复合命令。函数用"函数定义命令（function definition command）"定义。

函数定义命令的格式如下：

fname ( ) compound-command [io-redirect ...]

函数名为 fname；应用应确保它是名称（见 XBD 3.216 Name），且不是特殊内置实用程序的名称。作为扩展，实现可以允许函数名中出现其他字符。实现应为函数和变量维护单独的名称空间。

参数 compound-command 表示复合命令，如 2.9.4 复合命令 所述。

当声明函数时，不应在 compound-command 或 io-redirect 的文本上执行 2.6 单词扩展 中的任何扩展；所有扩展应在每次调用函数时照常执行。类似地，可选的 io-redirect 重定向和 compound-command 内的任何变量赋值应在函数本身执行期间进行，而不是在函数定义时。这些操作失败对交互式和非交互式 shell 的后果见 2.8.1 Shell 错误的后果。

当执行函数时，它应具有 2.15 特殊内置实用程序 开头枚举列表第一项中为特殊内置实用程序描述的语法错误属性。

每当函数名被指定为简单命令的名称时（见 2.9.1.4 命令搜索与执行），应执行该 compound-command。命令的操作数在 compound-command 执行期间应临时成为位置参数；特殊参数 '#' 也应改变以反映操作数数量。特殊参数 0 应保持不变。当函数完成时，位置参数和特殊参数 '#' 的值应恢复为函数执行之前的值。如果在 compound-command 中执行了特殊内置 return（见 return），函数完成，执行应从函数调用之后的下一条命令恢复。

退出状态 (Exit Status)

如果函数声明成功，函数定义的退出状态应为零；否则，应大于零。函数调用的退出状态应是该函数执行的最后一个命令的退出状态。

2.10 Shell 文法 (Shell Grammar)

以下文法定义 Shell 命令语言。这种正式语法应优先于前面的文本语法描述。

2.10.1 Shell 文法词法约定 (Shell Grammar Lexical Conventions)

shell 的输入语言应首先在字符级被识别。产生的 token 应根据以下规则（按顺序应用）由其直接上下文分类。这些规则应用于确定在 token 级进行解析时经受解析的 "token" 是什么。2.3 Token 识别 中的 token 识别规则应适用。

  1. 如果 token 是运算符，应产生该运算符的 token 标识符。
  2. 如果字符串仅由数字组成，且定界字符是 '<' 或 '>' 之一，应产生 token 标识符 IO_NUMBER。
  3. 如果字符串至少包含三个字符，以 <left-curly-bracket>（'{'）开头并以 <right-curly-bracket>（'}'）结尾，且定界字符是 '<' 或 '>' 之一，可以产生 token 标识符 IO_LOCATION；如果结果不是 IO_LOCATION，应产生 token 标识符 TOKEN。
  4. 否则，应产生 token 标识符 TOKEN。

对 TOKEN 的进一步区分是上下文相关的。同一个 TOKEN 可能产生 WORD、NAME、ASSIGNMENT_WORD 或下面的保留字之一，具体取决于上下文。下面文法中的一些产生式标注了下列列表中的规则编号。当看到 TOKEN 且其中一个标注的产生式可用于归约该符号时，应应用适用的规则，将 TOKEN 的 token 标识符类型转换为：

  • 对于规则 1，所识别保留字的 token 标识符
  • 对于所有其他规则，文法中该点可接受的 token 标识符

然后应根据所应用规则产生的 token 标识符类型进行归约。当多条规则适用时，应应用编号最高的规则（该规则又可能引用另一条规则）。 （注意，除规则 7 外，token 中存在 '=' 没有影响。）

WORD token 应在相关联命令即将执行时立即对其应用单词扩展规则，而不是在命令被解析时。

2.10.2 Shell 文法规则 (Shell Grammar Rules)

  1. [命令名 (Command Name)]：

    当 TOKEN 恰好是保留字时，应产生该保留字的 token 标识符。否则，应返回 token WORD。此外，如果解析器处于任何只有保留字才可能是下一个正确 token 的状态，按上述进行。

    注意：

    因为此时引用字符（<backslash>、单引号、<quotation-mark> 和 <dollar-sign> 单引号序列）保留在 token 中，被引用的字符串不能被识别为保留字。此规则还意味着保留字仅在输入的某些位置（如 <newline> 或 <semicolon> 之后）被识别；文法假定如果意图是保留字，用户会正确界定它，并且不试图直接反映该要求。另请注意，行连接（line joining）在 token 化之前完成，如 2.2.1 转义字符（反斜杠） 所述，因此在此时被转义的 <newline> 字符已被移除。

    规则 1 在文法中没有被直接引用，但被其他规则引用，或全局适用。

  2. [重定向到或来自文件名 (Redirection to or from filename)]：

    应发生 2.7 重定向 中指定的扩展。如该节所述，只能产生一个字段（或结果未指定），且对路径名展开有额外要求。

  3. [来自 here-document 的重定向 (Redirection from here-document)]：

    应对 word 应用引用消除以确定定界符，该定界符用于找到在下一个 <newline> 之后开始的 here-document 的结尾。

  4. [case 语句终止 (Case statement termination)]：

    当 TOKEN 恰好是保留字 esac 时，应产生 esac 的 token 标识符。否则，应返回 token WORD。

  5. [for 中的 NAME]：

    当 TOKEN 满足名称的要求（见 XBD 3.216 Name）时，应产生 token 标识符 NAME。否则，应返回 token WORD。

  6. [for 和 case 的第三个单词 (Third word of for** and case)]**：

    1. [仅 case]

      当 TOKEN 恰好是保留字 in 时，应产生 in 的 token 标识符。否则，应返回 token WORD。

    2. [仅 for]

      当 TOKEN 恰好是保留字 in 或 do 时，应分别产生 in 或 do 的 token 标识符。否则，应返回 token WORD。

    （对于 a. 和 b.：如文法所示，linebreak 位于 token in 和 do 之前。如果在所示位置存在 <newline> 字符，则以这种方式处理的是它们之后的 token。）

  7. [命令名之前的赋值 (Assignment preceding command name)]：

    1. [当是第一个单词时]

      如果 TOKEN 恰好是保留字，应产生该保留字的 token 标识符。否则，应应用 7b。

    2. [不是第一个单词时]

      如果 TOKEN 包含一个未被引用的（在应用 2.3 Token 识别 的规则 4 时确定的）<equals-sign> 字符，且该字符不是嵌入的参数扩展、命令替换或算术扩展构造的一部分（在应用 2.3 Token 识别 的规则 5 时确定的）：

      • 如果 TOKEN 以 '=' 开头，应返回 token WORD。
      • 如果 TOKEN 中第一个此类 <equals-sign> 之前的所有字符构成有效名称（见 XBD 3.216 Name），应返回 token ASSIGNMENT_WORD。
      • 否则，返回 token WORD 还是 ASSIGNMENT_WORD，或以某种其他方式处理该 TOKEN，是实现定义的。

      否则，应返回 token WORD。

    如果返回的 ASSIGNMENT_WORD token 以有效名称开头，应按 2.9.1 简单命令 中的规定，将第一个 <equals-sign> 之后的值赋给该名称。如果返回的 ASSIGNMENT_WORD token 不以有效名称开头，该 token 的处理方式是未指定的。

  8. [函数中的 NAME]：

    当 TOKEN 恰好是保留字时，应产生该保留字的 token 标识符。否则，当 TOKEN 满足名称的要求时，应产生 token 标识符 NAME。否则，适用规则 7。

  9. [函数体 (Body of function)]：

    在解析此规则时，即使上述规则要求，也不应发生单词扩展和赋值。每个可能被扩展或被赋值的 TOKEN 应改为作为单个 WORD 返回，该 WORD 仅由精确等于 2.3 Token 识别 所述 token 的字符组成。

2.11 作业控制 (Job Control)

作业控制（见 XBD 3.181 Job Control）被定义为一个设施，它允许用户选择性地停止（挂起）进程的执行并在稍后继续（恢复）其执行。它由终端 I/O 驱动程序和命令解释器联合提供。shell 就是这样一种命令解释器，shell 中的作业控制由 set -m 启用（在交互式 shell 中默认启用）。本节其余部分描述 shell 提供的作业控制设施。本节中与后台作业相关的要求仅适用于作业控制后台作业。

如果 shell 有控制终端且是终端会话的控制进程，它应初始将与终端关联的前台进程组 ID 设置为其自身的进程组 ID。否则，如果它有控制终端，如果是交互式的，它应初始执行以下步骤；如果是非交互式的，可以执行：

  1. 如果其进程组是与终端关联的前台进程组，shell 应将其进程组 ID 设置为其进程 ID（如果它们尚不相等），并将与终端关联的前台进程组 ID 设置为其进程组 ID。
  2. 如果其进程组不是与终端关联的前台进程组（这将是它被作业控制 shell 作为后台作业启动的结果），shell 应通过向自身发送 SIGTTIN 信号来停止自己，或者，如果交互式，尝试从标准输入读取（如果标准输入是控制终端，则产生 SIGTTIN 信号）。如果它被停止，那么当它继续执行（在收到 SIGCONT 信号之后）时，应重复这些步骤。

随后，当前台作业正在运行时，shell 应按下文描述中所述更改与其控制终端关联的前台进程组。

当启用作业控制时，shell 在执行具有以下形式之一的列表（见 2.9.3 列表）时应创建一个或多个作业：

  • 单个异步 AND-OR 列表
  • 一个或多个顺序执行的 AND-OR 列表，后跟至多一个异步 AND-OR 列表

为作业控制之目的，包含多个异步 AND-OR 列表的列表应被视为被拆分为多个单独的列表，每个列表以异步 AND-OR 列表结尾。

当创建由单个异步 AND-OR 列表组成的作业时，它应构成一个后台作业（background job），相关联的进程 ID 应是成为进程组组长的子进程的进程 ID，shell 为执行该 AND-OR 列表而创建的所有其他进程（如有）最初具有此进程 ID 作为其进程组 ID。

对于由一个或多个顺序执行的 AND-OR 列表后跟至多一个异步 AND-OR 列表组成的列表，整个列表应构成单个前台作业（foreground job），直到顺序执行的 AND-OR 列表全部执行完毕，此时异步 AND-OR 列表（如有）应如上所述构成后台作业。

对于前台作业中的每个管道，如果管道在列表仍是前台作业时执行，构成该管道的进程集及其任何后代进程应全部在同一进程组中，除非 shell 在当前 shell 执行环境中执行管道中的某些命令，而在子 shell 环境中执行其他命令；在这种情况下，当前 shell 的进程组 ID 不必更改（如果它是会话组长则不能更改），因此其他进程共有的进程组 ID 可能与当前 shell 的进程组 ID 不同（这意味着发送到其中一个进程组的 SIGSTOP、SIGTSTP、SIGTTIN 或 SIGTTOU 信号不会导致整个管道停止）。

在执行异步 AND-OR 列表时创建的后台作业可以通过 fg 实用程序（如果支持）带入前台；在这种情况下，整个作业应成为单个前台作业。如果 shell 随后等待的进程是此前台作业的一部分且被信号停止，整个作业应成为挂起作业（suspended job），其行为应如同该进程在作业于后台运行时被停止一样。

当创建前台作业，或通过 fg 实用程序将后台作业带入前台时，如果 shell 有控制终端，它应按如下设置与终端关联的前台进程组 ID：

  • 如果作业最初是作为后台作业创建的，前台进程组 ID 应设置为 shell 执行异步 AND-OR 列表时使其成为进程组组长的那一进程的进程 ID。
  • 如果作业最初是作为前台作业创建的，则在执行作业中的每个管道时，前台进程组 ID 应按如下设置：
    • 如果 shell 自身没有在当前 shell 执行环境中执行管道中的所有命令，前台进程组 ID 应设置为执行该管道的其他进程所共有的进程组 ID（见上文）。
    • 如果管道中的所有命令都由 shell 自身在当前 shell 执行环境中执行，前台进程组 ID 应设置为 shell 的进程组 ID。

当前台作业终止或成为挂起作业（见下文）时，如果 shell 有控制终端，它应将与终端关联的前台进程组 ID 设置为 shell 的进程组 ID。

每个后台作业（无论是否挂起）都应与一个作业号和一个在当前 shell 执行环境中已知的进程 ID 相关联。当通过 fg 实用程序将后台作业带入前台时，相关联的作业号应从 shell 的后台作业列表中移除，相关联的进程 ID 应从当前 shell 执行环境中已知的进程 ID 列表中移除。

如果 shell 正在等待的进程是作为前台作业启动的前台作业的一部分，且被可捕获信号（SIGTSTP、SIGTTIN 或 SIGTTOU）停止：

  • 如果构成前台作业的列表内当前正在执行的 AND-OR 列表由单个管道组成，其中所有命令都是简单命令，shell 应创建由至少该 AND-OR 列表和同一列表中的剩余（如有）AND-OR 列表组成的挂起作业，或创建仅由该 AND-OR 列表组成的挂起作业并丢弃同一列表中的剩余（如有）AND-OR 列表。
  • 否则，shell 应创建由构成前台作业的列表内的一组命令组成的挂起作业，该组命令是未指定的，但该组应包括被停止进程所属的管道至少。前台作业中尚未完成且未包含在挂起作业中的命令应被丢弃。
注意：

尽管只有简单命令的管道保证在前台启动并随后挂起时保持完整，但可以通过在后台启动复杂 AND-OR 列表并立即将其带入前台来确保其在挂起时保持完整。例如：

command1 && command2 | { command3 || command4; } & fg

如果 shell 正在等待的进程是作为前台作业启动的前台作业的一部分，且被 SIGSTOP 信号停止，除非在交付 SIGSTOP 时 shell 正在当前 shell 执行环境中执行内置实用程序（导致 shell 自身被该信号停止），行为应按上述可捕获信号的描述进行；在后一种情况下，如果 shell 随后收到 SIGCONT 信号且有一个或多个保持停止的子进程，shell 应创建挂起作业，如同只有那些子进程被停止一样。

当因前台作业被停止而创建挂起作业时，应为其分配作业号，且交互式 shell 应写、非交互式 shell 可以写一条消息到标准错误，格式如 jobs 实用程序（不带 -l 选项）为挂起作业所述。该消息可以指示构成该作业的命令包括已完成的命令；在这种情况下，如果随后继续执行该作业，已完成命令不应被重复。如果 shell 是交互式的，它应在将终端设置更改为其读取进一步命令所需的设置之前保存这些设置。

当与后台作业关联的进程被 SIGSTOP、SIGTSTP、SIGTTIN 或 SIGTTOU 信号停止时，shell 应将该（非挂起）后台作业转换为挂起作业，且交互式 shell 应在以下时间写一条格式如 jobs 实用程序（不带 -l 选项）为挂起作业所述的消息到标准错误：

  • 如果 set -b 已启用，消息应在作业变得挂起后立即写入，或在写下一条输入提示符之前立即写入。
  • 如果 set -b 已禁用，消息应在写下一条输入提示符之前立即写入。

挂起作业的执行可以通过 fg 实用程序（如果支持）作为前台作业继续，或通过 bg 实用程序（如果支持）或向被停止进程发送 SIGCONT 信号作为（非挂起）后台作业继续。fg 和 bg 实用程序应向其停止等待状态导致 shell 挂起该作业的进程的进程组发送 SIGCONT 信号。如果 shell 有控制终端，fg 实用程序应在设置与终端关联的前台进程组 ID（见上文）之后发送 SIGCONT 信号。如果从交互式 shell 使用 fg 实用程序将从前台作业创建的挂起作业带入前台，在发送 SIGCONT 信号之前，fg 实用程序应将终端设置恢复为 shell 在作业挂起时保存的设置。

当后台作业完成或被信号终止时，交互式 shell 应在以下时间写一条消息到标准错误，格式分别如 jobs 实用程序（不带 -l 选项）为已完成或被信号终止的作业所述：

  • 如果 set -b 已启用，消息应在作业完成或被终止后立即写入。
  • 如果 set -b 已禁用，消息应在写下一条输入提示符之前立即写入。

在上面每种交互式 shell 在写下一条输入提示符之前立即写消息的情况下，非交互式 shell 也可以在以下任何时间写同样的消息：

  • 在下次前台作业终止或挂起之后
  • 在 shell 解析进一步输入之前
  • 在 shell 退出之前

2.12 信号与错误处理 (Signals and Error Handling)

如果 shell 在执行异步 AND-OR 列表时禁用作业控制（见 set -m 的描述），列表中的命令应从 shell 继承对 SIGINT 和 SIGQUIT 信号的忽略（SIG_IGN）信号动作。在所有其他情况下，shell 执行的命令应继承与 shell 从其父进程继承的相同的信号动作，除非信号动作被 trap 特殊内置（见 trap）修改。

当 shell 等待执行前台命令的实用程序完成时收到已设置 trap 的信号，与该信号关联的 trap 不应执行，直到前台命令完成之后。当 shell 通过 wait 实用程序等待异步命令完成时，收到已设置 trap 的信号应导致 wait 实用程序以退出状态 >128 立即返回，紧接着应执行与该信号关联的 trap。

如果 shell 有多个待处理的、有关联 trap 动作的信号，trap 动作的执行顺序是未指定的。

2.13 Shell 执行环境 (Shell Execution Environment)

shell 执行环境（shell execution environment）由以下内容组成：

  • 调用 shell 时继承的打开文件，加上由 exec 控制的打开文件
  • 由 cd 设置的工作目录
  • 由 umask 设置的文件创建掩码
  • 由 ulimit 设置的文件大小限制
  • 由 trap 设置的当前 trap
  • 通过变量赋值（见 set 特殊内置）设置的 shell 参数，或来自 shell 开始时继承的 POSIX.1-2024《系统接口》卷环境（见 export 特殊内置）的 shell 参数
  • Shell 函数；见 2.9.5 函数定义命令
  • 调用时或由 set 开启的选项
  • 后台作业及其关联的进程 ID，以及在作业控制禁用时为执行异步 AND-OR 列表而创建的子进程的进程 ID；这些进程 ID 共同构成"此 shell 环境已知"的进程 ID。如果实现支持非作业控制后台作业，已知进程 ID 列表和后台作业列表可以构成单个列表，尽管本标准将它们描述为分别更新。见 2.9.3.1 异步 AND-OR 列表
  • Shell 别名；见 2.3.1 别名替换

除特殊内置（见 2.15 特殊内置实用程序）外的实用程序应在由以下内容组成的单独环境中调用。这些对象的初始值应与父 shell 相同，但下文所述除外。

  • 调用 shell 时继承的打开文件、由 exec 特殊内置控制的打开文件，加上对实用程序的任何重定向指定的任何修改和添加
  • 当前工作目录
  • 文件创建掩码
  • 如果实用程序是 shell 脚本，shell 捕获的 trap 应设置为默认值，shell 忽略的 trap 应设置为被该实用程序忽略；如果实用程序不是 shell 脚本，trap 动作（默认或忽略）应映射为该实用程序的适当信号处理动作
  • 具有 export 属性的变量，以及为命令持续期间显式导出的变量，应传给实用程序环境变量
  • 调用 shell 时传入、但因名称无效而未被用于初始化 shell 变量（见 2.5.3 Shell 变量）的环境变量，是否包含在被调用实用程序的环境中，是未指定的。

shell 进程的环境不应被实用程序更改，除非实用程序描述显式规定（例如 cd 和 umask）。

子 shell 环境（subshell environment）应作为 shell 环境的副本创建，但以下情况除外：

  • 除非另有规定（见 trap），未被忽略的 trap 应设置为默认动作。
  • 如果 shell 是交互式的，子 shell 应在所有方面表现为非交互式 shell，但以下除外：
    • 特殊参数 '-' 的展开可以继续指示它是交互式的。
    • set -n 选项可以被忽略。

对子 shell 环境所做的更改不应影响 shell 环境。命令替换、用括号分组的命令以及异步 AND-OR 列表应在子 shell 环境中执行。此外，多命令管道的每个命令都在子 shell 环境中；但作为扩展，管道中的任何或所有命令可以在当前环境中执行。除非另有说明，所有其他命令应在当前 shell 环境中执行。

2.14 模式匹配记号 (Pattern Matching Notation)

本节描述的模式匹配记号用于在 shell 中指定匹配字符字符串的模式。这种记号也被一些其他实用程序（find、pax，以及可选地 make）和某些系统接口（fnmatch()、glob() 和 wordexp()）使用。历史上，模式匹配记号与 XBD 9. 正则表达式 中描述的正则表达式记号相关，但略有不同。因此，这种模式匹配记号的规则描述基于正则表达式记号的描述，并针对差异进行了修改。

如果尝试使用模式匹配记号来匹配包含一个或多个不构成有效字符一部分的字节的字符串，行为是未指定的。由于路径名可以包含此类字节，便携应用需要确保在任意路径名上执行模式匹配（或扩展）时，当前 locale 是 C 或 POSIX locale。

2.14.1 匹配单个字符的模式 (Patterns Matching a Single Character)

以下模式应匹配单个字符：普通字符（ordinary characters）、特殊模式字符（special pattern characters）和模式括号表达式（pattern bracket expressions）。模式括号表达式还应匹配单个整理元素（collating element）。

在模式或其一部分中，在可以使用 shell 引用 <backslash> 的地方，<backslash> 字符应按 2.2.1 转义字符（反斜杠） 所述转义后面的字符，无论该 <backslash> 是否在括号表达式内。（序列 "\\" 表示一个字面的 <backslash>。）

在模式或其一部分中，在不能使用 shell 引用 <backslash> 来保留原本会被视为特殊的字符的字面值的地方：

  • 不在括号表达式内的 <backslash> 字符应保留后面字符的字面值，除非后面字符位于模式中可以使用 shell 引用的部分并且是 shell 引用字符，在这种情况下行为是未指定的。
  • 仅对于 shell，括号表达式内的 <backslash> 字符是否保留后面字符的字面值，是未指定的。

引用对普通字符、shell 特殊字符和特殊模式字符的所有要求和效果应适用于此上下文中的转义，除非另有规定。（适用此情况的情形包括：路径名展开中使用的模式不在原始单词中而是由较早的扩展产生的单词扩展，或传给 find 的 -name 或 -path 主选项的参数，或当 flags 中未分别设置 FNM_NOESCAPE 或 GLOB_NOESCAPE 时传给 fnmatch() 和 glob() 函数的 pattern 参数。）

如果模式以未转义的 <backslash> 结尾，行为是未指定的。

普通字符是应匹配自身的模式。在模式或其一部分中，在可以使用 shell 引用 <backslash> 的地方，普通字符可以是受支持字符集中的任何字符，但 NUL、2.2 引用 中需要引用的特殊 shell 字符，以及下文描述的三个特殊模式字符除外。在模式或其一部分中，在不能使用 shell 引用 <backslash> 来保留原本会被视为特殊的字符的字面值的地方，普通字符可以是受支持字符集中的任何字符，但 NUL 和下文描述的三个特殊模式字符除外。匹配应基于用于编码字符的位模式，而不是字符的图形表示。如果任何字符（普通、shell 特殊或模式特殊）被引用，或用 <backslash> 转义，该模式应匹配该字符本身。应用应确保对任何原本会被视为特殊的字符加引用或转义，以便它作为普通字符被匹配。

当未被引用、未被转义且不在括号表达式内时，以下三个字符在模式的规定中应具有特殊含义：

?

<question-mark> 是应匹配任何字符的模式。

*

<asterisk> 是应匹配多个字符的模式，如 2.14.2 匹配多个字符的模式 所述。

[

如果其后的字符满足 XBD 9.3.5 RE Bracket Expression 中规定的括号表达式要求，<left-square-bracket> 应引入括号表达式，但 <exclamation-mark> 字符（'!'）应替换 <circumflex> 字符（'^'）在正则表达式记号的非匹配列表中的作用。以未引用的 <circumflex> 字符开头的括号表达式产生未指定的结果。不引入有效括号表达式的 <left-square-bracket> 应匹配该字符本身。

2.14.2 匹配多个字符的模式 (Patterns Matching Multiple Characters)

以下规则用于从匹配单个字符的模式构造匹配多个字符的模式：

  1. <asterisk>（'*'）是应匹配任何字符串（包括 null 字符串）的模式。
  2. 匹配单个字符的模式的连接是有效模式，应匹配由每个被连接的模式匹配的单个字符或整理元素的连接。
  3. 一个或多个匹配单个字符的模式与一个或多个 <asterisk> 字符的连接是有效模式。在此类模式中，每个 <asterisk> 应匹配零个或多个字符的字符串，匹配仍允许模式其余部分匹配该字符串的最大可能字符数。

2.14.3 用于文件名展开的模式 (Patterns Used for Filename Expansion)

2.14.1 匹配单个字符的模式 和 2.14.2 匹配多个字符的模式 到目前为止描述的规则，由以下适用于模式匹配记号用于文件名展开时的规则限定：

  1. 路径名中的 <slash> 字符应通过在模式中使用一个或多个 <slash> 字符显式匹配；它既不应被 <asterisk> 或 <question-mark> 特殊字符匹配，也不应被括号表达式匹配。模式中的 <slash> 字符应在括号表达式之前被识别；因此，<slash> 不能包含在用于文件名展开的模式括号表达式中。如果在找到相应的 <right-square-bracket> 之前，在未转义的 <left-square-bracket> 字符之后发现 <slash> 字符，则该开括号应被视为普通字符。例如，模式 "a[b/c]d" 不匹配诸如 abd 或 a/d 之类的路径名。它只匹配字面的 a[b/c]d 路径名。

  2. 如果文件名以 <period>（'.'）开头，该 <period> 应通过使用 <period> 作为模式的第一个字符或紧跟在 <slash> 字符之后来显式匹配。前导 <period> 不应被以下匹配：

    • <asterisk> 或 <question-mark> 特殊字符
    • 包含非匹配列表（如 "[!a]"）、范围表达式（如 "[%-0]"）或字符类表达式（如 "[[:punct:]]"）的括号表达式

    括号表达式匹配列表（如 "[.abc]"）中的显式 <period> 能否匹配文件名中的前导 <period>，是未指定的。

  3. 如果指定模式包含任何将被视为特殊的 '*'、'?' 或 '[' 字符（见 2.14.1 匹配单个字符的模式），应按适当情况对现有文件名和路径名进行匹配；如果 dot 和 dot-dot 的目录项存在，可以忽略它们。包含任何此类字符的每个组件都要求该组件所在目录的读权限。包含将被视为特殊的 <backslash> 的每个组件可能要求该组件所在目录的读权限。不包含任何将被视为特殊的 '*'、'?' 或 '[' 字符的任何组件（最后一个除外）要求搜索权限。如果这些权限被拒绝，或者如果作为目录打开或搜索路径名、或读取已打开目录的尝试因与文件系统内容相关的错误条件而失败，这不应被视为错误，路径名展开应继续，如同该路径名命名了一个已成功打开和读取或搜索的现有目录，且其中未找到匹配的目录项。对于其他错误条件，路径名展开是失败还是与权限被拒绝时同样处理，是未指定的。

    例如，给定模式：

    /foo/bar/x*/bam

    目录 / 和 foo 需要搜索权限，目录 bar 需要搜索和读权限，每个 x* 目录需要搜索权限。

    如果模式匹配任何现有文件名或路径名，该模式应被替换为这些文件名和路径名，按当前 locale 中生效的整理序列（collating sequence）排序。如果此整理序列没有对所有字符进行全序排序（见 XBD 7.3.2 LC_COLLATE），任何整理相等的文件名或路径名应进一步使用 POSIX locale 的整理序列逐字节比较。

    如果模式包含不按 XBD 9.3.5 RE Bracket Expression 引入括号表达式的开括号（'['），模式同一斜杠分隔组件内的其他未引用 '*'、'?'、'[' 或 <backslash> 字符是保留其特殊含义还是被视为普通字符，是未指定的。例如，模式 "a*[/b*" 可能匹配目录 "a*[" 中以 'b' 开头的所有文件名，也可能匹配名称以 'a' 开头以 '[' 结尾的所有目录中以 'b' 开头的所有文件名。

    如果模式不匹配任何现有文件名或路径名，模式字符串应保持不变。

    注意：

    本标准未来版本可能要求在将模式与现有文件名匹配时忽略 dot 和 dot-dot 的目录项（如果存在）。例如，展开模式 ".*" 时，结果将不包括 dot 和 dot-dot。

  4. 如果指定模式不包含任何将被视为特殊的 '*'、'?' 或 '[' 字符，模式字符串应保持不变。

2.15 特殊内置实用程序 (Special Built-In Utilities)

以下 "特殊内置（special built-in）" 实用程序应在 shell 命令语言中支持。每个命令的输出（如有）应写到标准输出，受所有命令都可能进行的正常重定向和管道限制。

术语 "内置（built-in）" 意味着无需执行单独的可执行文件，因为该实用程序在 shell 自身中实现。实现可以选择使任何实用程序成为内置；但此处描述的特殊内置实用程序在两个方面不同于常规内置实用程序：

  1. 特殊内置实用程序中的错误可能导致执行该实用程序的 shell 中止，而常规内置实用程序中的错误不应导致执行该实用程序的 shell 中止。（错误对交互式和非交互式 shell 的后果见 2.8.1 Shell 错误的后果。）如果遇到错误的特殊内置实用程序没有中止 shell，其退出值应为非零。
  2. 如 2.9.1 简单命令 所述，特殊内置实用程序调用之前的变量赋值影响当前执行环境；对于常规内置或其他实用程序则不应如此。

本节中的特殊内置实用程序不必以可通过 POSIX.1-2024《系统接口》卷定义的 exec 函数族访问的方式提供。

一些特殊内置被描述为符合 XBD 12.2 Utility Syntax Guidelines。对于那些不符合的，1.4 Utility Description Defaults 中要求将 "--" 识别为要丢弃的第一个参数的要求不适用，符合应用不应使用该参数。

2.22 exit

名称 (NAME)

exit — 使 shell 退出

概要 (SYNOPSIS)

exit [n]

描述 (DESCRIPTION)

exit 实用程序应使 shell 从其当前执行环境退出。如果当前执行环境是子 shell 环境，shell 应从子 shell 环境退出，并在调用该子 shell 环境的环境中继续；否则，shell 实用程序应终止。shell 或子 shell 的等待状态应由无符号十进制整数 n（如果指定）确定。

如果指定了 n 且其值在 0 到 255（含）之间，shell 或子 shell 的等待状态应表明它以退出状态 n 退出。如果指定了 n 且其值大于 256，对应于 shell 分配给被有效信号终止的命令的退出状态（见 2.8.2 命令的退出状态），shell 或子 shell 的等待状态应表明它被该信号终止。与该信号关联的其他动作，例如执行 trap 动作或创建 core 映像，不应由 shell 执行。

如果指定了 n 但不是无符号十进制整数，或其值为 256，或其值大于 256 但不对应于 shell 分配给被有效信号终止的命令的退出状态，shell 或子 shell 的等待状态是未指定的。

在 shell 终止之前应执行 trap 对 EXIT 的动作，但 exit 实用程序在该 trap 动作本身中被调用的情况除外，此时 shell 应立即退出。在执行 trap 对 EXIT 的动作期间设置新的 trap 对 EXIT 的动作，是否会导致该新动作在 shell 终止前被执行，是未指定的。

"export %s=%s\n", <name>, <value>

"export %s\n", <name>

如果 name 未设置。

  1. 具有值的只读变量不能被重置。
  2. 在输出时未设置的变量，如果在保存状态之后、保存的输出重新输入 shell 之前有值被赋给该变量，则不必被重置为未设置状态。

# Shells that support array assignment as an extension generally

一些实现扩展了 shell 的赋值语法（例如允许通过单个赋值填充数组），并且为了使此类扩展能在作为 export 参数的赋值中使用，这些 shell 在其文法中将 export 作为单独的 token。本标准仅允许在 shell 的输入根据标准文法包含语法错误时进行此类性质的扩展。注意，虽然 export 可以是 shell 文法中的单独 token，但它不能是保留字，因为 export 是别名替换的候选，而保留字不是（见 2.3.1 别名替换）。

名称 (NAME)

readonly — 为变量设置只读属性（set the readonly attribute for variables）

概要 (SYNOPSIS)

描述 (DESCRIPTION)

应给予其名称被指定的变量 readonly 属性。具有 readonly 属性的变量的值不能通过随后的赋值或使用 export、getopts、readonly 或 read 实用程序来更改，这些变量也不能被 unset 实用程序取消设置。如 XBD 8.1 Environment Variable Definition 所述，符合规范（conforming）的应用不应请求将某个变量标记为 readonly，如果该变量被记载为由 shell 内置实用程序操纵，因为这可能使这些实用程序无法成功完成。如果变量名后跟 =word，则该变量的值应被设置为 word。

  1. 在输出时具有值的变量没有设置 readonly 属性。

原理 (RATIONALE)

一些历史 shell 在独立的调用之间保留 readonly 属性。POSIX.1-2024 本卷允许此行为，但不要求它。

-p 选项允许可移植地访问这些值，这些值可以被保存并随后恢复，例如使用 dot 脚本。另见 export 的 RATIONALE，其中描述了无参数和 -p 输出情况以及相关示例。

一些实现扩展了 shell 的赋值语法（例如允许通过单个赋值填充数组），并且为了使此类扩展能在作为 readonly 参数的赋值中使用，这些 shell 在其文法中将 readonly 作为单独的 token。本标准仅允许在 shell 的输入根据标准文法包含语法错误时进行此类性质的扩展。注意，虽然 readonly 可以是 shell 文法中的单独 token，但它不能是保留字，因为 readonly 是别名替换的候选，而保留字不是（见 2.3.1 别名替换）。

set 特殊内置应支持 XBD 12.2 Utility Syntax Guidelines，但选项可以用前导 <hyphen-minus>（表示启用该选项）或 <plus-sign>（表示禁用该选项）来指定，除非另有规定。

-a

为所有变量赋值设置 export 属性。当此选项开启时，每当在当前 shell 执行环境中为变量赋值，都应为该变量设置 export 属性。这适用于所有形式的赋值，包括作为变量扩展或算术扩展的副作用而进行的赋值，以及作为 cd、getopts 或 read 实用程序操作结果而进行的赋值。

正如 2.9.1 简单命令 中讨论的，并非所有变量赋值都发生在当前执行环境中。当赋值发生在单独的执行环境中时，export 属性仍会为该变量设置，但这不影响当前执行环境。

-b

如果实现支持 User Portability Utilities 选项，则应支持此选项。当作业控制和 -b 都启用时，shell 应写出后台作业完成（包括被信号终止）的异步通知，并且可以写出后台作业挂起的异步通知。详见 2.11 作业控制。当作业控制被禁用时，-b 选项应不起作用。异步通知不应默认启用。

中，false 命令导致执行命令替换的子 shell 不执行 echo one 就退出；子 shell 的退出状态被忽略，shell 随后执行经过单词扩展的命令 echo two。

应用程序用法 (APPLICATION USAGE)

应用程序编写者应避免依赖函数内的 set -e。例如，在以下脚本中：

set -e
start() {
    some_server

使用 set -n 会使 shell 解析脚本的其余部分而不执行任何命令，这意味着不能使用 set +n 来撤销该效果。语法检查更常通过 sh -n script_name 进行。

示例 (EXAMPLES)

写出所有变量及其值：

set

设置 $1、$2 和 $3，并将 "$#" 设置为 3：

set c a b

打开 -x 和 -v 选项：

set -xv

取消设置所有位置参数：

set --

将 $1 设置为 x 的值，即使它以 '-' 或 '+' 开头：

set -- "$x"

将位置参数设置为 x 的展开，即使 x 展开后带有前导 '-' 或 '+'：

set -- $x

原理 (RATIONALE)

set -- 形式在 SYNOPSIS 中被特别列出，尽管这种用法已被 Utility Syntax Guidelines 隐含。对此特性的解释消除了任何关于 set -- 形式是否可能被误解为等同于不带任何选项或参数的 set 的歧义。此形式的功能取自 KornShell。在 System V 中，set -- 仅在至少有一个参数时才取消设置参数；取消设置所有参数的唯一方法是使用 shift。使用 KornShell 版本不应影响 System V 脚本，因为不应该有故意不带参数发出它的理由；如果它被发出，例如：

set -- "$@"

而实际上 "$@" 没有产生任何参数，取消设置参数将不会有任何结果。

早期提案中的 set + 形式被省略，因为它是不必要的 set 单独形式的重复，且不是广泛的历史实践。

noclobber 选项被更改，以允许 set -C 以及 set -o noclobber 选项。添加单字母版本是为了不破坏历史悠久的 "$-" 范式；见 2.5.2 特殊参数。

-e 选项的描述旨在匹配 1988 版 KornShell 的行为。

-h 选项与命令名散列（command name hashing）有关。见 hash。规范性描述故意含糊，因为此选项的工作方式因 shell 实现而异。

本标准的早期版本将 -h 规定为一种在函数被定义时定位并记住要由函数调用的实用程序的方式（实用程序通常在函数执行时被定位）。然而，这与大多数 shell 中的现有实践不符。

以下 set 选项被故意省略，理由如下：

-k

选项 -k 最初由 Bourne shell 的作者添加，以使 shell 预发布版本的用户更容易使用。在 Bourne shell 的早期版本中，必须使用构造 set name=value 来为 shell 变量赋值。-k 的问题在于其行为会影响解析，几乎排除了编写任何编译器的可能。要解释 -k 的行为，有必要描述解析算法，而它是实现定义的。例如：

set -k; echo name=value

以及：

set -k
echo name=value

的行为不同。与函数的交互甚至更复杂。更何况，-k 选项从未被需要，因为命令行本来可以重新排序。

-t

选项 -t 难以规定，且几乎从未被使用。唯一已知的用途可以用 here-document 完成。此外，ksh 与 sh 的行为不同。参考页面说它在读取并执行一条命令后退出。什么是一条命令？如果输入是 date;date，sh 执行两条 date 命令，而 ksh 只执行第一条。

曾考虑重写 set 以简化其令人困惑的语法。一个具体的建议是使用 unset 实用程序来取消设置选项，而不是使用不能 getopt() 的 +option 语法。然而，得出的结论是使用 +option 的历史实践令人满意，并且没有令人信服的理由修改如此广泛的历史实践。

-o 选项取自 KornShell 以解决用户需求。除了其普遍友好的界面外，-o 还是提供 vi 命令行编辑模式所必需的，历史实践没有为其提供单字母选项名。（虽然发明这样一个字母是可能的，但人们认识到会开发其他编辑模式，而 -o 为描述此类扩展提供了充足的名字空间。）

历史实现在 -o 选项状态报告所使用的格式上不一致。添加不带选项参数的 +o 格式，是为了允许可移植地访问那些可以保存、随后用例如 dot 脚本恢复的选项。

历史上，sh 确实跟踪 set +x 命令，但 ksh 不跟踪。

ignoreeof 设置防止在输入文件结尾字符（通常是 <control>-D）时意外登出。用户应显式执行 exit 以离开交互式 shell。

set -m 选项被添加为仅适用于 UPE（User Portability Utilities 选项），因为它主要适用于交互式使用，而非 shell 脚本应用。

异步通知能力在 1988 版 KornShell 中变得可用。要使它发生，用户必须发出命令：

trap "jobs -n" CLD

C shell 提供两个不同级别的异步通知能力。环境变量 notify 类似于 set -b 或 set -o notify 所做的。当设置时，它立即通知用户后台作业的完成。当未设置时，此能力被关闭。

另一种通知能力通过内置实用程序 notify 提供。语法是：

notify [%job ... ]

通过发出不带操作数的 notify，它使 C shell 在当前作业状态改变时异步通知用户。如果给定操作数，notify 异步告知用户指定作业的状态变化。

为了向 POSIX shell 添加异步通知，KornShell 对 trap 的扩展和 C shell 的 notify 环境变量似乎都不合适（notify 不是合适的 POSIX 环境变量名）。

set -b 选项被选为折衷方案。

内置 notify 被认为具有比简单异步通知所需更多的功能。

历史上，一些 shell 将 -u 选项应用于所有参数，包括 $@ 和 $*。标准开发者认为这是一个缺陷，因为无论是否向它们传递了任何参数，在 shell 脚本中使用 $@ 和 $* 都是正常且常见的。在未传递参数时将这些使用视为错误，会降低 -u 用于发现变量名拼写错误和未设置位置参数使用的预期价值。

未来方向 (FUTURE DIRECTIONS)

本标准的未来版本可能移除 -o nolog 选项。

2.29 trap

名称 (NAME)

trap — 捕获信号

概要 (SYNOPSIS)

trap n [condition...]

trap -p [condition...]

trap [action condition...]

描述 (DESCRIPTION)

如果未指定 -p 选项且第一个操作数是无符号十进制整数，shell 应将所有操作数视为 condition（条件），并应将每个 condition 重置为默认值。否则，如果未指定 -p 选项且有操作数，第一个操作数应被视为动作（action），其余操作数应被视为 condition。

如果 action 是 '-'，shell 应将每个 condition 重置为默认值。如果 action 为 null（""），shell 应在每个指定的 condition 出现时忽略它。否则，当相应的 condition 之一出现时，参数 action 应由 shell 读取并执行。trap 的动作应覆盖先前的动作（无论是默认动作还是显式设置的动作）。trap 动作完成后 "$?" 的值应是该 trap 动作被执行之前它所具有的值。

condition 可以是 EXIT、0（等同于 EXIT），或使用符号名称（不带 SIG 前缀）指定的信号，如 XBD 14. Headers 中定义的 <signal.h> 头文件中的信号名称表所列；例如 HUP、INT、QUIT、TERM。实现可以允许带 SIG 前缀的名称或忽略信号名称中的大小写，作为扩展。为 SIGKILL 或 SIGSTOP 设置 trap 产生未定义（undefined）的结果。

EXIT condition 应在 shell 正常终止（退出）时发生，并且可以在 shell 因传递信号（SIGKILL 除外）而异常终止时发生，该信号的 trap 动作是默认动作。

shell 执行 trap 对 EXIT 的动作所处的环境，应与在 trap 对 EXIT 的动作被执行之前、所执行的最后一条命令之后的环境完全相同。

如果 action 既不是 '-' 也不是空字符串，那么每次匹配的 condition 出现时，action 应以等同于以下方式的方式执行：

eval action

进入非交互式 shell 时被忽略的信号不能被捕获或重置，尽管尝试这样做时无需报告错误。交互式 shell 可以重置或捕获进入时被忽略的信号。对于给定的 shell，trap 应保持生效，直到用另一条 trap 命令显式更改。

当进入子 shell 时，未被忽略的 trap 应被设置为默认动作，但仅包含单个 trap 命令的命令替换的情况除外，此时 trap 不必被更改。实现可以仅使用词法分析来检查这种情况；例如，如果 `trap` 和 $( trap -- ) 不改变子 shell 中的 trap，那么诸如赋值 var=trap 然后使用 $($var) 的情况仍可能改变它们。这并不暗示 trap 命令不能在子 shell 内用于设置新的 trap。

不带操作数的 trap 命令应向标准输出写入与一组 condition 中每一个关联的命令列表；如果未指定 -p 选项，该组应仅包含不处于默认状态的 condition（包括进入非交互式 shell 时被忽略的信号）；如果指定了 -p 选项，该组应包含所有 condition，但对应于 SIGKILL 和 SIGSTOP 信号的 condition 是否包含在该组中是未指定的。如果命令在子 shell 中执行，且实现不执行上述对仅包含单个 trap 命令的命令替换的可选检查，并且自进入子 shell 以来没有执行过带操作数的 trap 命令，该列表应包含在进入子 shell 环境之前与每个 condition 关联的命令。否则，该列表应包含当前与每个 condition 关联的命令。格式应为：

"trap -- %s %s ...\n", <action>, <condition> ...

shell 应格式化输出（包括正确使用引用），使其适合作为命令重新输入 shell，以达到为输出中包含的 condition 集获得相同的捕获（trapping）结果，但如上所述在进入 shell 时被忽略的信号除外。如果该组包含对应于 SIGKILL 和 SIGSTOP 信号的 condition，当输出被重新输入 shell 时，shell 应接受它们（其中接受它们意味着它们不导致非零退出状态、诊断消息或未定义行为）。例如：

save_traps=$(trap -p)
...
eval "$save_traps"

或：

save_traps=$(trap -p INT QUIT)
trap "some command" INT QUIT
...
eval "$save_traps"

应用程序用法 (APPLICATION USAGE)

当不使用 -p 选项时，由于不带操作数的 trap 不输出用于恢复当前被设置为默认的 trap 的命令，这些 trap 需要被单独恢复。原理节展示了示例并描述了它们的缺点。

示例 (EXAMPLES)

写出所有 trap 和动作的列表：

trap

设置一个 trap，使 HOME 环境变量所指目录中的 logout 实用程序在 shell 终止时执行：

trap '"$HOME"/logout' EXIT

或：

trap '"$HOME"/logout' 0

取消 INT、QUIT、TERM 和 EXIT 上的 trap：

trap - INT QUIT TERM EXIT

原理 (RATIONALE)

实现可以允许小写信号名称作为扩展。实现也可以接受带 SIG 前缀的名称；没有已知的历史 shell 这样做。本卷 POSIX.1-2024 中的 trap 和 kill 实用程序现在在信号名称省略 SIG 前缀方面是一致的。一些 kill 实现不允许该前缀，且 kill -l 列出不带前缀的信号。

捕获 SIGKILL 或 SIGSTOP 被一些历史实现从语法上接受，但它没有效果。可移植的 POSIX 应用不能尝试捕获这些信号。

输出格式不是历史实践。由于历史 trap 命令的输出不可移植（因为数字信号值不可移植），并且必须改变以使其可移植，于是利用这个机会以 shell 脚本可以在想要时用来保存并稍后重新使用 trap 的方式格式化输出。

KornShell 使用一个 ERR trap，每当 set -e 会导致退出时它就被触发。这是作为扩展被允许的，但未被强制要求，因为其他 shell 没有使用它。

关于 EXIT trap 环境的文本使某些历史版本的交互式 shell 的行为失效，例如，这些 shell 在执行对 0 的 trap 之前关闭标准输入。例如，在某些历史交互式 shell 会话中，以下对 0 的 trap 将总是打印 "--"：

trap 'read foo; echo "-$foo-"' 0

命令：

trap 'eval " $cmd"' 0

使 shell 变量 cmd 的内容在 shell 退出时作为命令被执行。使用：

trap '$cmd' 0

如果 cmd 包含任何特殊字符（如引号或重定向），则不能正确工作。使用：

trap " $cmd" 0

也可以工作（前导的 <space> 字符防止 cmd 是十进制整数或以 '-' 开头的不太可能的情况），但它是在 trap 命令被执行时展开 cmd 变量，而不是在执行退出动作时展开。

添加 -p 选项是因为没有它，用于恢复 trap 的方法需要对使用不带操作数的 trap 保存当前 trap 时被设置为默认的 trap 进行特殊处理。一个示例是：

save_traps=$(trap)
trap "some command" INT QUIT
save_traps="trap - INT QUIT; $save_traps"
...
eval "$save_traps"

但此方法依赖于硬编码用于重置正在被设置的 trap 的命令。如果保存时 INT 或 QUIT 没有被设置为默认，它还有竞争条件（race condition），因为它先将它们设置为默认，然后恢复已保存的 trap。更通用的方法将是：

save_traps=$(trap)
...
for sig in EXIT $( kill -l )
do
    case "$sig" in
    SIGKILL | KILL | sigkill | kill | SIGSTOP | STOP | sigstop | stop)
    ;;
    *) trap - $sig
    ;;
    esac
done
eval "$save_traps"

这有相同的竞争条件，因为它先将所有（可以被设置的）trap 设置为默认，然后恢复那些先前没有被设置为默认的 trap。

历史上，一些 shell 在没有操作数时，带 -p 与不带 -p 的行为相同。本标准要求这两种情况的 condition 集不同：带 -p 时是所有 condition（可能除 SIGKILL 和 SIGSTOP 外）；不带 -p 时只是不处于默认状态的 condition。

2.30 unset

名称 (NAME)

unset — 取消设置变量和函数的值与属性

概要 (SYNOPSIS)

unset [-fv] name…

描述 (DESCRIPTION)

unset 实用程序应取消设置由 name 指定的、不具有 readonly 属性的每个变量或函数定义，并移除已被给予 name 的除 readonly 之外的任何属性（见 2.15 特殊内置实用程序 的 export 和 readonly）。

如果指定了 -v，name 指变量名，shell 应取消设置它并将其从环境中移除。只读变量不能被取消设置。

如果指定了 -f，name 指函数，shell 应取消设置该函数定义。

如果既未指定 -f 也未指定 -v，name 指变量；如果不存在该名称的变量，是否应取消设置该名称的函数（如有），是未指定的（unspecified）。

取消设置先前未设置的变量或函数不应被视为错误，且不应导致 shell 中止。

unset 特殊内置应支持 XBD 12.2 Utility Syntax Guidelines。

注意：

VARIABLE=

这不等价于对 VARIABLE 的 unset；在示例中，VARIABLE 被设置为 ""。此外，可被 unset 的变量不应被误解为包含特殊参数（见 2.5.2 特殊参数）。

示例 (EXAMPLES)

取消设置 foo 和 bar 函数：

原理 (RATIONALE)

曾考虑省略 -f 选项而采用 unfunction 实用程序，但标准制定者决定保留历史实践。

引入 -v 选项是因为 System V 历史上对变量和函数两者使用一个名称空间。当 unset 不带选项使用时，System V 历史上会取消设置函数或变量之一，并且对所指的是哪一个没有混淆。便携 POSIX 应用可以使用不带选项的 unset 来取消设置变量，但不能取消设置函数；必须使用 -f 选项。
