# 2. Shell 命令语言 (Shell Command Language)

本章包含 Shell 命令语言的规范定义。

## 2.1 Shell 简介 (Shell Introduction)

Shell 是一个命令语言解释器（Command Language Interpreter）。本章描述了 `sh` 实用程序以及 POSIX.1-2024《系统接口》卷中定义的 `system()` 和 `popen()` 函数所使用的命令语言语法。

Shell 遵循以下通用操作流程运作。具体细节详见本章对应的各小节：

1. **读取输入**：Shell 从文件（参见 `sh`）、`-c` 命令行选项或 POSIX.1-2024《系统接口》定义的 `system()` 和 `popen()` 函数中读取输入。如果 Shell 命令文件的第一行以字符 `#!` 开头，其执行结果是未指定的（Unspecified，*指标准未明确规定，由具体实现自行决定*）。
2. **词法标记化 (Tokenization)**：Shell 将输入分解为词法标记（又称“令牌”）（Tokens，*语法分析的最小独立单元*）：即单词（Words）与运算符（Operators）；参见 **2.3 词法标记识别**。
3. **语法解析 (Parsing)**：Shell 将输入解析为简单命令（Simple Commands，参见 **2.9.1**）和复合命令（Compound Commands，参见 **2.9.4**）。
4. **单词扩展 (Word Expansions)**：针对命令中的每个单词，Shell 首先处理美元单引号（`$''`）内的反斜杠转义序列（Backslash-Escape Sequences，参见 **2.2.4**），然后执行各种单词扩展（参见 **2.6**）。对于简单命令，扩展结果通常包含一组路径名（Pathnames）和字段（Fields），分别作为命令名称和参数；参见 **2.9 Shell 命令**。
5. **重定向 (Redirection)**：Shell 执行重定向（参见 **2.7**），并从参数列表中移除重定向运算符及其操作数（Operands）。
6. **命令查找与执行 (Command Execution)**：Shell 执行函数（Function）、内置命令（Built-in Utility，参见 **2.15**）、可执行文件或脚本。将实参（Arguments）名称作为编号从 $1$ 到 $n$ 的位置参数（Positional Parameters），并将命令名称（或脚本内函数的情况下的脚本名）作为特殊参数 $0$ 传递；参见 **2.9.1.4 命令搜索与执行**。
7. **收集退出状态 (Collecting Exit Status)**：Shell 可选择等待命令完成并收集其退出状态（Exit Status，*即命令执行后的返回值/错误码*）；参见 **2.8.2 命令的退出状态**。

## 2.2 引用 / 转义 (Quoting)

引用（Quoting，*通常也常被称为“转义”或“引用保护”*）用于移除某些字符或单词在 Shell 中的特殊含义。引用可用于保留特殊字符的字面含义（Literal Meaning）、防止保留字（Reserved Words）被识别为关键字，以及阻止在 Here-Document（*即“立即文档”或“嵌入式文档”*）处理过程中发生参数扩展和命令替换。

如果应用程序希望以下字符仅表示其**字面本身**，则**必须**对其进行引用：

> `|` `&` `;` `<` `>` `(` `)` `$` `"` `'` `<space>` `<tab>` `<newline>` <code>`</code> <code>\\</code>

在某些特定情况下，以下字符也可能需要被引用（即这些字符在特定条件下具有特殊含义）：

> `*` `?` `[` `]` `^` `-` `!` `#` `~` `=` `%` `{` `,` `}`

> **注**：未来的标准版本可能会扩大这些字符具有特殊含义的条件。因此，当应用程序希望它们仅代表字面本身时，**应该**始终对其进行引用。（这不适用于连字符 `-`，因为它属于可移植文件名字符集）。

不同的引用机制包括：**转义字符（Escape Character）**、**单引号（Single-Quotes）**、**双引号（Double-Quotes）** 以及 **美元单引号（Dollar-Single-Quotes）**。Here-Document 代表了引用的另一种形式；参见 **2.7.4 Here-Document**。

### 2.2.1 转义字符：反斜杠 (Escape Character: Backslash)

未被引用的反斜杠 `<backslash>` (`\`) 应当保留其后紧跟字符的字面值，**换行符 `<newline>` 除外**。

如果反斜杠后紧跟换行符 `<newline>`，Shell 应当将其解释为**续行符 (Line Continuation)**。该反斜杠和换行符将在输入被拆分为 Token 之前被**完全移除**。由于被转义的换行符被彻底从输入中删除了（且未被替换为任何空白字符），因此它**不能**作为 Token 分隔符。

### 2.2.2 单引号 (Single-Quotes)

将字符包围在单引号（`''`）中，可以保留单引号内**所有**字符的字面值。

- **注意**：单引号内部**绝对不能**出现单引号本身（*即单引号无法嵌套或转义自己*）。

### 2.2.3 双引号 (Double-Quotes)

将字符包围在双引号（`""`）中，可以保留双引号内所有字符的字面值，**但以下字符例外**：反引号 <code>\`</code> 、 美元符号 `<dollar-sign>` (`$`) 和反斜杠 `<backslash>` (`\`)。具体规则如下：

- **`$` (美元符号)**：保留其引入以下扩展的特殊含义：
  
  - 参数扩展（Parameter Expansion，如 `$VAR` / `${VAR}`）
  - 命令替换（Command Substitution，如 `$(cmd)`）
  - 算术扩展（Arithmetic Expansion，如 `$((1+1))`）
  - **但**在双引号内部，`$` **不再保留**引入美元单引号（`$''`）引用的特殊含义。
  - 封闭在 `$(` 和匹配的 `)` 之间的字符不受双引号影响，而是定义其输出将替换 `$(...)` 的命令。
  - 对于提供子字符串处理的四种参数扩展（如 `${var#pattern}` 等），在 `${` 到对应 `}` 之间的双引号对特殊字符的处理**无影响**。
- **<code>`</code>反引号** ：保留其引入传统格式命令替换（Command Substitution，如 ``cmd``）的特殊含义。从起始反引号到下一个未被反斜杠转义的反引号之间的部分定义被执行的命令。
- **`\` (反斜杠)**：在 `$(...)` 和 `${...}` 之外，反斜杠**仅在**紧跟以下字符时才保留其作为转义字符（Escape Character）的特殊含义：   

  - > `$` `\` `<newline>` `"` <code>`</code>

  - 如果反斜杠后面跟的是其他字符，则反斜杠失去了转义作用，会被当作普通字面字符输出。
- **`@` (特殊参数)**：在双引号内部，`$@` 具有特殊展开含义（扩展为多个独立的单词，保留各自参数边界）。

### 2.2.4 美元单引号 (Dollar-Single-Quotes: `$''`)

以美元符号紧跟单引号（`$''`）开头的字符序列，将保留所有字符的字面值，直至遇到未被转义的结尾单引号 `'`。**但支持以下反斜杠转义序列 (Backslash-Escape Sequences)**：

| **转义序列** | **产生的字符/字节**          | **术语与含义解释**                                       |
| ------------ | ---------------------------- | -------------------------------------------------------- |
| `\"`         | 双引号 `"`                   | Double-Quote                                             |
| `\'`         | 单引号 `'`                   | Apostrophe / Single-Quote                                |
| `\\`         | 反斜杠 `\`                   | Backslash                                                |
| `\a`         | 警报音/响铃                  | Alert (BEL, 响铃信号)                                    |
| `\b`         | 退格符                       | Backspace                                                |
| `\e`         | 转义符                       | Escape (ESC 字符, ASCII 27)                              |
| `\f`         | 换页符                       | Form-Feed                                                |
| `\n`         | 换行符                       | Newline                                                  |
| `\r`         | 回车符                       | Carriage-Return                                          |
| `\t`         | 水平制表符                   | Horizontal Tab                                           |
| `\v`         | 垂直制表符                   | Vertical Tab                                             |
| `\cX`        | 控制字符 (Control Character) | 表示 Ctrl+X 对应的控制字符（如 `\cA` 为 ASCII 1/Ctrl-A） |
| `\xXX`       | 十六进制字节                 | 1 到 2 位十六进制数指定的字节值                          |
| `\ddd`       | 八进制字节                   | 1 到 3 位八进制数指定的字节值                            |

**详细规定**：

- 如果 `\xXX` 或 `\ddd` 产生的值为 `0`（Null Byte，空字符），其是否包含在结果中由实现决定（Unspecified）。
- 该 `$''` 转义序列的解析处理，紧接在单词扩展（Word Expansions）之前完成。
- 如果转义序列表示单引号（如 `\'`），该序列**不会**终止美元单引号的闭合。

## 2.3 词法标记识别 (Token Recognition)

Shell 应当以**行 (Lines)** 为单位读取输入，输入行可以是无限长度的。输入行将通过两种主要模式进行语法解析：**普通 Token 识别** 与 **Here-Document 处理**。

### 语法解析流转规则（按优先级顺序应用）：

1. **输入结束 (End of Input)**：若识别到输入末尾，当前 Token（如果有）即被界定终止。
2. **运算符拼接 (Operator Continuation)**：若上一个字符属于某个运算符（Operator，如 `>` 或 `|`），且当前字符未被引用，且能与之前的字符组合成更长的运算符（如 `>>` 或 `||`），则当前字符被归入该运算符 Token。
3. **运算符终止 (Operator Delimitation)**：若上一个字符属于运算符，而当前字符无法与其构成合法运算符，则之前包含上一字符的运算符 Token 被界定终止。
4. **引用处理 (Quoting Start)**：若当前字符是未引用的 `\`、`'`、`"` 或 `$'` 序列的首字符，它将影响后续字符的引用状态，直到被引用的文本结束。在此期间**不进行实际的变量/命令替换**，Token 原始保留这些字符。
5. **保留字与特殊标识符识别**：
   - 若 Shell 正在寻找命令名称，并且 Token 未被引用且属于 Shell 保留字（Reserved Word，如 `if`、`while`、`for`、`fi` 等），则该 Token 被识别为保留字。
   - 若 Token 是合法的变量名格式（NAME）且紧跟 `=`，则被判定为赋值语句（Assignment）。

## 2.4 参数与变量 (Parameters and Variables)

参数（Parameter）是存储值的实体。在 Shell 中，参数可以是**位置参数**、**特殊参数**，或者是**变量**。

### 2.4.1 位置参数 (Positional Parameters)

位置参数是由数字（$0$ 除外）标识的参数。

- 当 Shell 启动、执行脚本或调用函数时，它会将传入的实参按顺序赋值给位置参数 $1, 2, 3 \dots n$。
- 如果数字大于 9，必须使用大括号括起来，例如 `${10}`。
- 可以通过内置命令 `set` 重新设置位置参数，或通过 `shift` 命令对位置参数进行左移（丢弃第一个，后面的依次前移）。

### 2.4.2 特殊参数 (Special Parameters)

特殊参数由单个特殊字符标识，其值由 Shell 自动维护，**不能**由用户直接赋值：

| **特殊参数** | **名称/含义** | **简要解释与行为细节**                                       |
| ------------ | ------------- | ------------------------------------------------------------ |
| `\*`     | 位置参数列表  | 扩展为从 $1$ 开始的所有位置参数。在双引号内（`"$*"`）时，整个列表会拼成长为一个单词，参数间由 `IFS` 变量的首字符分隔。 |
| `@`      | 位置参数数组  | 扩展为从 $1$ 开始的所有位置参数。在双引号内（`"$@"`）时，每个位置参数会保留各自的边界，扩展为**独立的多个单词**（如 `"$1" "$2" ...`）。如果没有位置参数，则扩展为空。 |
| `#`      | 参数个数      | 扩展为位置参数的总个数（十进制数字）。                       |
| `?`      | 退出状态      | 扩展为上一个执行命令的**退出状态码 (Exit Status)**。         |
| `-$`     | 当前标志位    | 扩展为当前 Shell 启动或通过 `set` 设定的所有选项标志（Option Flags）。 |
| `$`      | 进程 ID (PID) | 扩展为当前 Shell 的进程 ID。在子 Shell 中，它依然返回**父级主 Shell** 的 PID。 |
| `!`      | 后台 PID      | 扩展为最近一个被异步（后台，如 `cmd &`）执行的命令的进程 ID。 |
| `0`      | 脚本/命令名   | 扩展为 Shell 或脚本本身的名称。                              |

### 2.4.3 变量 (Variables)

变量是由名称（Name，*必须以字母或下划线开头，后跟字母、数字或下划线*）标识的参数。

- **赋值格式**：`name=value`。如果在赋值时不提供 `value`，则变量会被设为**空字符串 (Null String)**。
- **常用内置环境变量**：
  - `IFS`：Internal Field Separator（内部字段分隔符），用于单词拆分（Word Splitting）。默认值为 `<space><tab><newline>`。
  - `PATH`：命令搜索路径，由冒号 `:` 分隔的一组目录。
  - `HOME`：用户的家目录，波浪号扩展（`~`）的默认目标。
  - `PPID`：父进程 ID（Parent Process ID）。

## 2.5 单词扩展 (Word Expansions)

在 Shell 执行简单命令时，输入的单词（Words）会按照固定顺序经历以下**七种扩展机制**（扩展完成后才会发起命令调用）：

```
[原始 Token 单词]
       │
       ▼
 1. 波浪号扩展 (Tilde Expansion: ~)
       │
       ▼
 2. 参数扩展 (Parameter Expansion: ${VAR})
 3. 命令替换 (Command Substitution: $(cmd))
 4. 算术扩展 (Arithmetic Expansion: $((1+1)))
       │ (2,3,4 在扫描中同时进行)
       ▼
 5. 单词拆分 (Word Splitting) —— 基于 IFS
       │
       ▼
 6. 路径名扩展 / 通配符匹配 (Pathname Expansion / Globbing: *.txt)
       │
       ▼
 7. 引号移除 (Quote Removal) —— 剔除内部转义用引号
       │
       ▼
[最终参数列表并交付执行]
```

### 2.5.1 参数扩展形态速查表 (Parameter Expansion Syntax)

除了最基础的 `$VAR` 或 `${VAR}` 外，POSIX 标准定义了如下条件扩展形态（用于安全处理空值/未定义变量）：

| **语法格式**             | **规则描述（若 VAR 未设置或为 Null）**  | **规则描述（若 VAR 已设置且非 Null）** |
| ------------------------ | --------------------------------------- | -------------------------------------- |
| `${parameter:-word}` | 扩展为 `word` 的值                      | 扩展为 `${parameter}` 的值             |
| `${parameter:=word}` | 将 `word` 赋值给 `parameter` 并扩展该值 | 扩展为 `${parameter}` 的值             |
| `${parameter:?word}` | 将 `word` 输出到标准错误并**终止脚本**  | 扩展为 `${parameter}` 的值             |
| `${parameter:+word}` | 扩展为**空**                            | 扩展为 `word` 的值                     |

> **注**：若省略上述语法中的冒号 `:`（例如 `${parameter-word}`），则仅当变量**完全未设置 (Unset)** 时触发规则；若变量已设置但为空字符串（Null），则依然保留空字符串。

#### 模式匹配裁剪语法 (Pattern Removal)：

- `${parameter#pattern}`：从开头裁剪**最短**匹配 `pattern` 的前缀。
- `${parameter##pattern}`：从开头裁剪**最长**匹配 `pattern` 的前缀。
- `${parameter%pattern}`：从结尾裁剪**最短**匹配 `pattern` 的后缀。
- `${parameter%%pattern}`：从结尾裁剪**最长**匹配 `pattern` 的后缀。

## 2.6 重定向 (Redirection)

重定向用于改变命令的标准输入 (stdin, FD 0)、标准输出 (stdout, FD 1) 或标准错误 (stderr, FD 2)。

### 2.6.1 常用重定向运算符

- `<` **(输入重定向)**：将文件作为标准输入 (`0< file`)。
- `>` **(输出重定向)**：将标准输出覆盖写入文件 (`1> file`)。如果设置了 `set -o noclobber`，防止意外覆盖已存在的文件。
- `>>` **(追加输出)**：将标准输出追加到文件末尾。
- `>&` **/** `<&` **(文件描述符复制 / Duplicating FD)**：
  - `2>&1`：将 stderr (FD 2) 重定向到 stdout (FD 1) 当前指向的位置。
- `<>` **(读写打开)**：以可读可写方式打开文件（通常配合 FD 使用，如 `3<>file`）。

### 2.6.2 Here-Document (`<<`) 与 Here-String

Here-Document（立即文档）用于将多行文本块直接作为命令的输入：


```bash
command << EOF
Line 1: $VAR 将会被扩展
Line 2
EOF
```

- **语法细节**：
  1. 若定界符（如 `EOF`）**未被任何引号包裹**，文档体内的 `$VAR`、`$(cmd)` 和 `\` 将进行扩展。
  2. 若定界符**带引号**（如 `'EOF'` 或 `"EOF"`），文档体内的所有字符均当作**纯字面值 (Literal)** 处理，不发生任何扩展。
  3. 若使用 `<<-EOF` 格式，文档每行开头的 **Tab 制表符**（`<tab>`）将被自动剥离（*常用于脚本缩进美化*）。

## 2.7 Shell 命令类型 (Shell Commands)

Shell 解析完成后，将其划分为以下四类层级的命令结构：

### 1. 简单命令 (Simple Commands)

由可选的变量赋值（如 `LANG=C`）、可选的重定向符号，以及以空白符分隔的命令名和参数组成的序列。退出状态即该命令本身的返回值。

### 2. 管道 (Pipelines)

通过 `|` 连接的一个或多个命令序列。

- 语法：`[!] command1 | command2`
- `command1` 的标准输出通过管道作为 `command2` 的标准输入。
- 前缀 `!` 表示对整条管道最后的退出状态进行**逻辑非 (Logical NOT)** 取反。

### 3. 命令列表 (Lists)

通过 `;`、`&`、`&&` 或 `||` 连接的管道序列：

- `cmd1 && cmd2` **(AND-List)**：仅当 `cmd1` 返回成功 (exit status 0) 时，才执行 `cmd2`。
- `cmd1 || cmd2` **(OR-List)**：仅当 `cmd1` 返回失败 (exit status 非 0) 时，才执行 `cmd2`。
- `cmd &` **(Asynchronous List)**：在后台异步子 Shell 中执行该命令，当前 Shell 不等待其结束。
- `cmd ;` **(Sequential List)**：按顺序串行执行命令。

### 4. 复合命令 (Compound Commands)

控制 Shell 执行流程的封闭结构：

- **括号组合** `( compound-list )`：在**独立子 Shell (Subshell)** 环境中执行内部命令（内部对变量的修改不影响当前 Shell）。

- **大括号组合** `{ compound-list; }`：在**当前 Shell** 环境中执行内部命令（注意末尾必须有分号或换行，且 `{` 后须有空格）。

- `for` **循环**：


  ```bash
  for var in item1 item2; do
      command
  done
  ```

- **`case` 条件选择**：


  ```bash
  case "$var" in
      pattern1) command ;;
      pattern2|pattern3) command ;;
      *) default_command ;;
  esac
  ```

- **`if` / `while` / `until` 条件分支与循环**。

## 2.8 特殊内置命令 (Special Built-In Utilities)

POSIX 定义了一组“特殊内置命令”（Special Built-Ins）。它们直接在 Shell 进程内部执行，且**其执行失败会导致非交互式脚本立即退出**，变量赋值在命令结束后依然持续有效：

> `break` | `: (colon)` | `continue` | `. (dot / source)` | `eval` | `exec` | `exit` | `export` | `readonly` | `return` | `set` | `shift` | `times` | `trap` | `unset`

## 核心专有名词总结

| **英文原词**             | **中文标准译名**      | **术语原理解析**                                             |
| ------------------------ | --------------------- | ------------------------------------------------------------ |
| **Subshell**             | 子 Shell              | 派生出的子进程 Shell，拥有父进程的副本，但在其中修改变量/更改目录不会影响父 Shell。 |
| **Word Splitting**       | 单词拆分              | 变量扩展后，Shell 根据 `IFS` 字符（如空格）将单个文本段切割为多个独立参数的过程。 |
| **Pathname Expansion**   | 路径名扩展 (Globbing) | 使用通配符（`*`, `?`, `[...]`）匹配文件系统中的真实路径的过程。 |
| **File Descriptor (FD)** | 文件描述符            | 内核暴露给进程用于访问文件或 Standard I/O 管道的整数索引（如 0/1/2）。 |
| **Noclobber**            | 防误覆盖标志          | Shell 选项（`set -C` / `set -o noclobber`），防止 `>` 重定向意外擦除现有文件内容。 |
