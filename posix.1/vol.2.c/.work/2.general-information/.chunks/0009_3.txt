[h5_00971] [A1105][/A1105]SCHED_OTHER
[p_00972] Conforming implementations shall include one scheduling policy identified as SCHED_OTHER (which may execute identically with either the FIFO or round robin scheduling policy). The effect of scheduling threads with the SCHED_OTHER policy in a system in which other threads are executing under SCHED_FIFO, SCHED_RR, [S1106][[A1107]SS[/A1107]][/S1106] [IMG1108] &nbsp;or SCHED_SPORADIC [IMG1109] is implementation-defined.
[p_00973] This policy is defined to allow strictly conforming applications to be able to indicate in a portable manner that they no longer need a realtime scheduling policy.
[p_00974] For threads executing under this policy, the implementation shall use only priorities within the range returned by the [A1110][I1111]sched_get_priority_max[/I1111]()[/A1110] and [A1112][I1113]sched_get_priority_min[/I1113]()[/A1112] functions when SCHED_OTHER is provided as the parameter.
[h4_00975] [A1114][/A1114]2.8.5 Clocks and Timers
[p_00976] The [A1115][I1116]&lt;time.h&gt;[/I1116][/A1115] header defines the types and manifest constants used by the timing facility.
[h5_00977] [A1117][/A1117]Time Value Specification Structures
[p_00978] Many of the timing facility functions accept or return time value specifications. A time value structure [B1118]timespec[/B1118] specifies a single time value and includes at least the following members:
[td_00979] ctx="行 1: [B1119]time_t[/B1119]" [B1119]time_t[/B1119]
[td_00980] ctx="列头: Member Name" [I1120]tv_sec[/I1120]
[td_00981] ctx="列头: Description" Seconds.
[td_00982] ctx="行 2: [B1121]long[/B1121]" [B1121]long[/B1121]
[td_00983] ctx="列头: Member Name" [I1122]tv_nsec[/I1122]
[td_00984] ctx="列头: Description" Nanoseconds.
[p_00985] The [I1123]tv_nsec[/I1123] member is only valid if greater than or equal to zero, and less than the number of nanoseconds in a second (1000 million). The time interval described by this structure is ([I1124]tv_sec[/I1124] * 10[S1125][S1126]9[/S1126][/S1125] + [I1127]tv_nsec[/I1127]) nanoseconds.
[p_00986] A time value structure [B1128]itimerspec[/B1128] specifies an initial timer value and a repetition interval for use by the per-process timer functions. This structure includes at least the following members:
[td_00987] ctx="行 1: [B1129]struct timespec[/B1129]" [B1129]struct timespec[/B1129]
[td_00988] ctx="列头: Member Name" [I1130]it_interval[/I1130]
[td_00989] ctx="列头: Description" Timer period.
[td_00990] ctx="行 2: [B1131]struct timespec[/B1131]" [B1131]struct timespec[/B1131]
[td_00991] ctx="列头: Member Name" [I1132]it_value[/I1132]
[td_00992] ctx="列头: Description" Timer expiration.
[p_00993] If the value described by [I1133]it_value[/I1133] is non-zero, it indicates the time to or time of the next timer expiration (for relative and absolute timer values, respectively). If the value described by [I1134]it_value[/I1134] is zero, the timer shall be disarmed.
[p_00994] If the value described by [I1135]it_interval[/I1135] is non-zero, it specifies an interval which shall be used in reloading the timer when it expires; that is, a periodic timer is specified. If the value described by [I1136]it_interval[/I1136] is zero, the timer is disarmed after its next expiration; that is, a one-shot timer is specified.
[h5_00995] [A1137][/A1137]Timer Event Notification Control Block
[p_00996] Per-process timers may be created that notify the process of timer expirations by queuing a realtime extended signal. The [B1138]sigevent[/B1138] structure, defined in the Base Definitions volume of POSIX.1-2024, [A1139][I1140]&lt;signal.h&gt;[/I1140][/A1139], is used in creating such a timer. The [B1141]sigevent[/B1141] structure contains the signal number and an application-specific data value which shall be used when notifying the calling process of timer expiration events.
[h5_00997] [A1142][/A1142]Manifest Constants
[p_00998] The following constants are defined in the Base Definitions volume of POSIX.1-2024, [A1143][I1144]&lt;time.h&gt;[/I1144][/A1143]:
[dt_00999] CLOCK_REALTIME
[dd_01000] The identifier for the system-wide realtime clock.
[dt_01001] TIMER_ABSTIME
[dd_01002] Flag indicating time is absolute with respect to the clock associated with a timer.
[dt_01003] CLOCK_MONOTONIC
[dd_01004] The identifier for the system-wide monotonic clock, which is defined as a clock whose value cannot be set via [A1145][I1146]clock_settime[/I1146]()[/A1145] and which cannot have backward clock jumps. The maximum possible clock jump is implementation-defined.
[p_01005] The maximum allowable resolution for CLOCK_REALTIME and CLOCK_MONOTONIC clocks and all time services based on these clocks is represented by {_POSIX_CLOCKRES_MIN} and shall be defined as 20 ms (1/50 of a second). Implementations may support smaller values of resolution for these clocks to provide finer granularity time bases. The actual resolution supported by an implementation for a specific clock is obtained using the [A1147][I1148]clock_getres[/I1148]()[/A1147] function. If the actual resolution supported for a time service based on one of these clocks differs from the resolution supported for that clock, the implementation shall document this difference.
[p_01006] The minimum allowable maximum value for CLOCK_REALTIME and CLOCK_MONOTONIC clocks and all absolute time services based on them is the same as that defined by the ISO&nbsp;C standard for the [B1149]time_t[/B1149] type. If the maximum value supported by a time service based on one of these clocks differs from the maximum value supported by that clock, the implementation shall document this difference.
