[h4_01193] [A1605][/A1605]2.10.16 Use of Options
[p_01194] There are a number of socket options which either specialize the behavior of a socket or provide useful information. These options may be set at different protocol levels and are always present at the uppermost &quot;socket&quot; level.
[p_01195] Socket options are manipulated by two functions, [A1606][I1607]getsockopt[/I1607]()[/A1606] and [A1608][I1609]setsockopt[/I1609]()[/A1608]. These functions allow an application program to customize the behavior and characteristics of a socket to provide the desired effect.
[p_01196] All of the options usable with [A1610][I1611]setsockopt[/I1611]()[/A1610] have defaults. For each option where a default value is listed as implementation-defined, the implementation also controls whether a socket created by [A1612][I1613]accept[/I1613]()[/A1612] or [A1614][I1615]accept4[/I1615]()[/A1614] starts with the option reset to the original default value, or inherited as the value previously customized on the original listening socket. The type and meaning of these values is defined by the protocol level to which they apply. Instead of using the default values, an application program may choose to customize one or more of the options. However, in the bulk of cases, the default values are sufficient for the application.
[p_01197] Some of the options are used to enable or disable certain behavior within the protocol modules (for example, turn on debugging) while others may be used to set protocol-specific information (for example, IP time-to-live on all the application's outgoing packets). As each of the options is introduced, its effect on the underlying protocol modules is described.
