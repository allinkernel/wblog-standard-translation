[h3_01461] [A1903][/A1903]2.12 Status Information
[p_01462] Status information is data associated with a process detailing a change in the state of the process. It shall consist of:
[li_01463] The state the process transitioned into ([I1904]stopped[/I1904], [I1905]continued[/I1905], or [I1906]terminated[/I1906])
[li_01464] The information necessary to populate the [B1907]siginfo_t[/B1907] structure provided by [A1908][I1909]waitid[/I1909]()[/A1908]
[li_01465] If the new state is [I1910]terminated[/I1910]:  The low-order 8 bits of the status argument that the process passed to [A1911][I1912]_Exit[/I1912]()[/A1911], [A1913][I1914]_exit[/I1914]()[/A1913], or [A1915][I1916]exit[/I1916]()[/A1915], or the low-order 8 bits of the value the process returned from [I1917]main[/I1917]() Note that these 8 bits are part of the complete value that is used to set the [I1918]si_status[/I1918] member of the [B1919]siginfo_t[/B1919] structure provided by [A1920][I1921]waitid[/I1921]()[/A1920]  Whether the process terminated due to the receipt of a signal that was not caught and, if so, the number of the signal that caused the termination of the process
[li_01466] If the new state is [I1922]stopped[/I1922]:  The number of the signal that caused the process to stop
[p_01467] A process might not have any status information (such as immediately after a process has started).
[p_01468] Status information for a process shall be generated (made available to the parent process) when the process stops, continues, or terminates except in the following case:
[li_01469] If the parent process sets the action for the SIGCHLD signal to SIG_IGN, or if the parent sets the SA_NOCLDWAIT flag for the SIGCHLD signal action, process termination shall not generate new status information but shall cause any existing status information for the process to be discarded.
[p_01470] If new status information is generated, and the process already had status information, the existing status information shall be discarded and replaced with the new status information.
[p_01471] Only the process' parent process can obtain the process' status information. The parent obtains a child's status information by calling [A1923][I1924]wait[/I1924]()[/A1923], [A1925][I1926]waitid[/I1926]()[/A1925], or [A1927][I1928]waitpid[/I1928]()[/A1927]. Except when [A1929][I1930]waitid[/I1930]()[/A1929] is called with the WNOWAIT flag set in the [I1931]options[/I1931] argument, the status information obtained by a wait function shall be consumed (discarded) by that wait function; no two calls to [A1932][I1933]wait[/I1933]()[/A1932], [A1934][I1935]waitid[/I1935]()[/A1934] (without WNOWAIT), or [A1936][I1937]waitpid[/I1937]()[/A1936] shall obtain the same status information.
[p_01472] When status information becomes available to the parent process and more than one thread in the parent process is waiting for the status information (blocked in a call to [A1938][I1939]wait[/I1939]()[/A1938], [A1940][I1941]waitid[/I1941]()[/A1940], or [A1942][I1943]waitpid[/I1943]()[/A1942] with arguments that would match the status information):
[li_01473] If none of the matching threads is in a call to [A1944][I1945]waitid[/I1945]()[/A1944] with the WNOWAIT flag set in the [I1946]options[/I1946] argument, the thread that obtains the status information is unspecified.
[li_01474] Otherwise (at least one of the matching threads is in a call to [A1947][I1948]waitid[/I1948]()[/A1947] with the WNOWAIT flag set), the matching thread or threads that obtain the status information is unspecified except that at least one of the matching threads shall obtain the status information and at most one of the matching threads that are not calling [A1949][I1950]waitid[/I1950]()[/A1949] with the WNOWAIT flag set shall obtain it.
