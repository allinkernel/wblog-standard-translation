XSH 函数：rmdir()

名称 (NAME)

rmdir — 移除目录

提要 (SYNOPSIS)

#include <unistd.h>

int rmdir(const char *path);

说明 (DESCRIPTION)

rmdir() 函数应移除名称由 path 给出的目录。只有当该目录是空目录时，才应移除该目录。

如果该目录是根目录或任何进程的当前工作目录，则函数是成功，还是应失败并将 errno 设置为 [EBUSY]，是未指定的。

如果 path 命名一个符号链接，则 rmdir() 应失败并将 errno 设置为 [ENOTDIR]。

如果 path 参数引用一个最终组件是 dot 或 dot-dot 的路径，rmdir() 应失败。

如果目录的链接计数变为 0 且没有进程打开该目录，则目录占用的空间应被释放，并且该目录应不再可访问。如果移除最后一个链接时有一个或多个进程打开该目录，则 dot 和 dot-dot 项（如果存在）应在 rmdir() 返回之前被移除，并且不得在目录中创建新项，但在对该目录的所有引用被关闭之前，不应移除该目录。

如果该目录不是空目录，rmdir() 应失败并将 errno 设置为 [EEXIST] 或 [ENOTEMPTY]。

成功完成后，rmdir() 应将父目录的最后数据修改和最后文件状态更改时间戳标记为需要更新。

返回值 (RETURN VALUE)

成功完成后，rmdir() 函数应返回 0。否则，应返回 -1，并设置 errno 以指示错误。如果返回 -1，则所命名的目录不应被更改。

错误 (ERRORS)

在以下情况下，rmdir() 函数应失败：

[EACCES]
路径前缀的某个组件被拒绝搜索权限，或者要移除的目录的父目录被拒绝写权限。
[EBUSY]
要移除的目录当前正被系统或某个进程使用，并且实现认为这是一个错误。
[EEXIST] 或 [ENOTEMPTY]
path 参数命名的目录不是空目录，或者存在指向该目录的、除 dot 或 dot-dot 中的单个项以外的硬链接。
[EINVAL]
path 参数包含一个是 dot 的最后一个组件。
[EIO]
发生了物理 I/O 错误。
[ELOOP]
在解析 path 参数期间遇到的符号链接中存在循环。
[ENAMETOOLONG]
路径名的某个组件的长度长于 {NAME_MAX}。
[ENOENT]
path 的某个组件没有命名一个现有文件，或者 path 参数命名一个不存在的目录或指向空字符串。
[ENOTDIR]
path 的某个组件命名了一个既不是目录也不是指向目录的符号链接的现有文件。
[EPERM] 或 [EACCES]
[XSI] 包含 path 参数所引用的文件的目录上设置了 S_ISVTX 标志，并且进程不满足 XBD 4.5 目录保护 中规定的条件。
[EROFS]
要移除的目录项位于只读文件系统上。

在以下情况下，rmdir() 函数可以失败：

[ELOOP]
在解析 path 参数期间遇到的符号链接超过 {SYMLOOP_MAX} 个。
[ENAMETOOLONG]
路径名的长度超过 {PATH_MAX}，或者符号链接的路径名解析产生的中间结果的长度超过 {PATH_MAX}。

示例 (EXAMPLES)

移除目录 (Removing a Directory)

以下示例展示如何移除名为 /home/cnd/mod1 的目录。

#include <unistd.h>
 
int status;
...
status = rmdir("/home/cnd/mod1");

应用程序使用 (APPLICATION USAGE)

无。

原理 (RATIONALE)

rmdir() 和 rename() 函数起源于 4.2 BSD，它们对要移除的目录不存在或 new 已存在的情况使用 [ENOTEMPTY]。当 1984 年 /usr/group 标准发布时，它改用 [EEXIST]。当这些函数被 System V 采纳时，1984 年 /usr/group 标准被用作参考。因此，若干现有应用程序和实现支持/使用这两种形式，并且无法就任一值达成一致。所有实现都被要求在 <errno.h> 中同时提供具有不同值的 [EEXIST] 和 [ENOTEMPTY]，以便应用程序可以在 C 语言 case 语句中使用这两个值。

删除 pathname/dot 的含义不清楚，因为要移除的父目录中的文件（目录）的名称不清楚，特别是在存在指向目录的多个链接的情况下。

POSIX.1-1990 标准对存在指向被移除目录的多个硬链接时 rmdir() 的行为保持沉默。将 errno 设置为 [EEXIST] 或 [ENOTEMPTY] 的要求澄清了这种情况下的行为。

如果进程的当前工作目录正在被移除，那宜是被允许的错误。

几乎所有现有实现都检测 [ENOTEMPTY] 或 dot-dot 的情况。2.3 错误编号 中关于返回任何可能的错误之一的文本允许该行为继续。如果在解析 path 参数期间遇到的符号链接超过 {SYMLOOP_MAX} 个，可以返回 [ELOOP] 错误。
