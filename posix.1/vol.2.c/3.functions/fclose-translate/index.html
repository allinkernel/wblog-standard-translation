XSH 函数：fclose()

[h4_00001] 名称 (NAME)

[blockquote_00002] fclose — 关闭流 (close a stream)

[h4_00003] 提要 (SYNOPSIS)

[p_00004] #include <stdio.h>

int fclose(FILE *stream);

[h4_00005] 说明 (DESCRIPTION)

[CX] The functionality described on this reference page is aligned with the ISO C standard. Any conflict between the requirements described here and the ISO C standard is unintentional. This volume of POSIX.1-2024 defers to the ISO C standard.

[p_00006] fclose() 函数应使 stream 指向的流被刷新，并使关联的文件被关闭。流的任何未写入的缓冲数据应被写入文件；任何未读取的缓冲数据应被丢弃。无论调用是否成功，流都应与文件解除关联，并且由 setbuf() 或 setvbuf() 函数设置的任何缓冲区都应与该流解除关联。如果关联的缓冲区是自动分配的，则应释放它。

[p_00007] [CX] 如果文件尚未位于 EOF，且该文件是能够寻位的文件，则如果该流是底层文件描述的活动句柄，底层打开文件描述的文件偏移量应被设置为该流的文件位置。

[p_00008] 如果该流是可写的，并且仍有尚未写入文件的缓冲数据，则 fclose() 函数应标记更新底层文件的上次数据修改和上次文件状态更改时间戳。fclose() 函数应对与 stream 指向的流关联的文件描述符执行等效于 close() 的操作。

[p_00009] 在调用 fclose() 之后，任何对 stream 的使用都会导致未定义行为。

[h4_00010] 返回值 (RETURN VALUE)

[p_00011] 成功完成后，fclose() 应返回 0；否则，应返回 EOF [CX] 并设置 errno 以指示错误。

[h4_00012] 错误 (ERRORS)

[p_00013] 在以下情况下，fclose() 函数应失败：

[dt_00014] [EAGAIN]
[dd_00015] [CX] 为 stream 底层的文件描述符设置了 O_NONBLOCK 标志，并且线程将在写操作中被延迟。
[dt_00016] [EBADF]
[dd_00017] [CX] 流底层的文件描述符无效。
[dt_00018] [EFBIG]
[dd_00019] [CX] 试图写入超过最大文件大小的文件。
[dt_00020] [EFBIG]
[dd_00021] [CX] 试图写入超过进程文件大小限制的文件。 [XSI] 还应为该线程生成 SIGXFSZ 信号。
[dt_00022] [EFBIG]
[dd_00023] [CX] 该文件是普通文件，并且试图在或超出与相应流关联的偏移量最大值处写入。
[dt_00024] [EINTR]
[dd_00025] [CX] fclose() 函数被信号中断。
[dt_00026] [EIO]
[dd_00027] [CX] 进程是试图向其控制终端写入的后台进程组的成员，设置了 TOSTOP，调用线程未阻塞 SIGTTOU，进程未忽略 SIGTTOU，并且该进程的进程组是孤儿进程组。在实现定义的条件下也可以返回此错误。
[dt_00028] [ENOMEM]
[dd_00029] [CX] 底层流是由 open_memstream() 或 open_wmemstream() 创建的，且可用内存不足。
[dt_00030] [ENOSPC]
[dd_00031] [CX] 包含该文件的设备上或 fmemopen() 函数使用的缓冲区中没有剩余可用空间。
[dt_00032] [EPIPE]
[dd_00033] [CX] 试图写入没有任何进程为读取而打开的管道或 FIFO。还应向该线程发送 SIGPIPE 信号。

[p_00034] 在以下情况下，fclose() 函数可以失败：

[dt_00035] [ENXIO]
[dd_00036] [CX] 向不存在的设备发出了请求，或请求超出了设备的能力范围。

[h4_00039] 应用程序用法 (APPLICATION USAGE)

[p_00040] 由于在调用 fclose() 之后任何对 stream 的使用都会导致未定义行为，因此除了在进程终止之前（见 XBD 3.287 进程终止）之外，fclose() 不应在 stdin、stdout 或 stderr 上使用，以避免在这些流所依赖的其他标准接口中触发未定义行为。如果应用程序注册了任何 atexit() 处理器，则此类对 fclose() 的调用不应在最后一个处理器即将结束时之前发生。一旦用 fclose() 关闭了 stdin、stdout 或 stderr，就没有重新打开这些流中的任何一个的标准方法。

[p_00041] 使用 freopen() 更改 stdin、stdout 或 stderr 而不是关闭它们，可以避免稍后应用程序中文件意外地被打开为特殊文件描述符 STDIN_FILENO、STDOUT_FILENO 或 STDERR_FILENO 之一的危险。
