XSH 函数：lstat()

名称 (NAME)

fstatat、lstat、stat — 获取文件状态 (get file status)

摘要 (SYNOPSIS)

[OH] #include <fcntl.h>
#include <sys/stat.h>

int fstatat(int fd, const char *restrict path,
struct stat *restrict buf, int flag);
int lstat(const char *restrict path, struct stat *restrict buf);
int stat(const char *restrict path, struct stat *restrict buf);

说明 (DESCRIPTION)

stat() 函数应获取关于指定文件的信息，并将其写入 buf 参数所指向的区域。path 参数指向一个命名文件的路径名。不需要指定文件的读、写或执行权限。提供附加或替代文件访问控制机制的实现可以在实现定义的条件下使 stat() 失败。特别是，系统可以否认 path 指定的文件的存在。

如果指定的文件是符号链接，stat() 函数应使用符号链接的内容继续路径名解析，并且如果结果文件存在，应返回与该结果文件相关的信息。

buf 参数是指向 stat 结构的指针，如 <sys/stat.h> 头中所定义，关于文件的信息被放入该结构中。

stat() 函数应在写入 stat 结构之前更新任何与时间相关的字段（如 XBD 4.12 文件时间更新 中所述）。

[SHM] 如果指定的文件是共享内存对象，实现应在 buf 参数所指向的 stat 结构中更新 st_uid、st_gid、st_size 和 st_mode 字段，并且只有 S_IRUSR、S_IWUSR、S_IRGRP、S_IWGRP、S_IROTH 和 S_IWOTH 文件权限位需要有效。实现可以更新其他字段和标志。

[TYM] 如果指定的文件是类型化内存对象，实现应在 buf 参数所指向的 stat 结构中更新 st_uid、st_gid、st_size 和 st_mode 字段，并且只有 S_IRUSR、S_IWUSR、S_IRGRP、S_IWGRP、S_IROTH 和 S_IWOTH 文件权限位需要有效。实现可以更新其他字段和标志。

对于本卷 POSIX.1-2024 中定义的所有其他文件类型，结构成员 st_mode、st_ino、st_dev、st_uid、st_gid、st_atim、st_ctim 和 st_mtim 应具有有意义的值，并且成员 st_nlink 的值应被设置为指向该文件的硬链接数。

lstat() 函数应等同于 stat()，但当 path 指代符号链接时除外。在这种情况下，lstat() 应返回关于该链接的信息，而 stat() 应返回关于该链接所引用的文件的信息。

对于符号链接，st_mode 成员在与文件类型宏一起使用时，应包含有意义的信息。st_mode 中的文件模式位是未指定的。结构成员 st_ino、st_dev、st_uid、st_gid、st_atim、st_ctim 和 st_mtim 应具有有意义的值，并且 st_nlink 成员的值应被设置为指向该符号链接的硬链接数。st_size 成员的值应被设置为符号链接中包含的路径名的长度，不包括任何终止的空字节。

fstatat() 函数应等同于 stat() 或 lstat() 函数，具体取决于 flag 的值（见下文），但在 path 指定相对路径的情况下除外。在这种情况下，状态应从相对于与文件描述符 fd 关联的目录的文件中获取，而不是相对于当前工作目录。如果与文件描述符关联的打开文件描述的访问模式不是 O_SEARCH，函数应使用该文件描述符所基于目录的当前权限检查是否允许目录搜索。如果访问模式是 O_SEARCH，函数不应执行该检查。

flag 的值由以下列表中的标志按位包含式 OR 构成，这些标志定义于 <fcntl.h>：

AT_SYMLINK_NOFOLLOW
如果 path 命名一个符号链接，则返回该符号链接的状态。

如果在 fd 参数中向 fstatat() 传递特殊值 AT_FDCWD，则应使用当前工作目录，并且行为应分别与调用 stat() 或 lstat() 相同，具体取决于 flag 中是否设置了 AT_SYMLINK_NOFOLLOW 位。

返回值 (RETURN VALUE)

成功完成后，这些函数应返回 0。否则，这些函数应返回 -1 并设置 errno 以指示错误。

错误 (ERRORS)

如果满足以下条件，这些函数应失败：

[EACCES]
路径前缀的某个组件被拒绝搜索权限。
[EIO]
从文件系统读取时发生了错误。
[ELOOP]
在解析 path 参数期间遇到的符号链接中存在循环。
[ENAMETOOLONG]
路径名的某个组件的长度长于 {NAME_MAX}。
[ENOENT]
path 的某个组件没有命名存在的文件，或者 path 是空字符串。
[ENOTDIR]
路径前缀的某个组件命名的现有文件既不是目录也不是指向目录的符号链接，或者 path 参数包含至少一个非-<slash> 字符并以一个或多个尾随 <slash> 字符结尾，且最后一个路径名组件命名的现有文件既不是目录也不是指向目录的符号链接。
[EOVERFLOW]
以字节为单位的文件大小、分配给文件的块数或文件序列号无法在 buf 所指向的结构中被正确表示。

如果满足以下条件，fstatat() 函数应失败：

[EACCES]
与 fd 关联的打开文件描述的访问模式不是 O_SEARCH，且 fd 所基于目录的权限不允许目录搜索。
[EBADF]
path 参数没有指定绝对路径，且 fd 参数既不是 AT_FDCWD，也不是为读取或搜索而打开的有效文件描述符。
[ENOTDIR]
path 参数不是绝对路径，且 fd 是与非目录文件关联的文件描述符。

如果满足以下条件，这些函数可以失败：

[ELOOP]
在解析 path 参数期间遇到的符号链接超过 {SYMLOOP_MAX} 个。
[ENAMETOOLONG]
路径名的长度超过 {PATH_MAX}，或者符号链接的路径名解析产生了长度超过 {PATH_MAX} 的中间结果。
[EOVERFLOW]
要存储的值将使 stat 结构的成员之一溢出。

如果满足以下条件，fstatat() 函数可以失败：

[EINVAL]
flag 参数的值无效。

示例 (EXAMPLES)

获取文件状态信息 (Obtaining File Status Information)

以下示例展示了如何获取名为 /home/cnd/mod1 的文件的状态信息。为 stat 结构定义了结构变量 buffer。

#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>
 
struct stat buffer;
int         status;
...
status = stat("/home/cnd/mod1", &buffer);
获取目录信息 (Getting Directory Information)

以下示例片段获取目录中每个条目的状态信息。对 stat() 函数的调用将文件信息存储在 statbuf 所指向的 stat 结构中。stat() 调用之后的行将 stat 结构中的字段格式化以呈现给程序的用户。

#include <sys/types.h>
#include <sys/stat.h>
#include <dirent.h>
#include <pwd.h>
#include <grp.h>
#include <time.h>
#include <locale.h>
#include <langinfo.h>
#include <stdio.h>
#include <stdint.h>
 
struct dirent  *dp;
struct stat     statbuf;
struct passwd  *pwd;
struct group   *grp;
struct tm      *tm;
char            datestring[256];
...
/* Loop through directory entries. */
while ((dp = readdir(dir)) != NULL) {
 
    /* Get entry's information. */
    if (stat(dp->d_name, &statbuf) == -1)
        continue;
 
    /* Print out type, permissions, and number of links. */
    printf("%10.10s", mode_string(statbuf.st_mode));
    printf(" %4ju", (uintmax_t)statbuf.st_nlink);
 
    /* Print out owner's name if it is found using getpwuid(). */
    if ((pwd = getpwuid(statbuf.st_uid)) != NULL)
        printf(" %-8.8s", pwd->pw_name);
    else
        printf(" %-8ju", (uintmax_t)statbuf.st_uid);
 
    /* Print out group name if it is found using getgrgid(). */
    if ((grp = getgrgid(statbuf.st_gid)) != NULL)
        printf(" %-8.8s", grp->gr_name);
    else
        printf(" %-8ju", (uintmax_t)statbuf.st_gid);
 
    /* Print size of file. */
    printf(" %9jd", (intmax_t)statbuf.st_size);
 
    tm = localtime(&statbuf.st_mtime);
 
    /* Get localized date string. */
    strftime(datestring, sizeof(datestring), nl_langinfo(D_T_FMT), tm);
 
    printf(" %s %s\n", datestring, dp->d_name);
}
获取符号链接状态信息 (Obtaining Symbolic Link Status Information)

以下示例展示了如何获取名为 /modules/pass1 的符号链接的状态信息。为 stat 结构定义了结构变量 buffer。如果 path 参数指定了符号链接所指向的文件的路径名（/home/cnd/mod1），则调用该函数的结果将与调用 stat() 函数返回的结果相同。

#include <sys/stat.h>
 
struct stat buffer;
int status;
...
status = lstat("/modules/pass1", &buffer);

应用程序用法 (APPLICATION USAGE)

无。

理由 (RATIONALE)

描述 "附加或替代文件访问控制机制" 的段落旨在允许一种安全实现：其标签不支配文件标签的进程无法执行 stat() 函数。这与读权限无关；标签支配文件标签的进程不需要读权限。支持向上写操作（write-up）的实现即使拥有为写入而打开的有效文件描述符，也可能使 fstat() 函数调用失败。

fstatat() 函数的目的是在不受竞争条件影响的情况下获取当前工作目录以外的目录中的文件的状态。文件的路径的任何部分都可能在调用 stat() 的同时被更改，导致未指定的行为。通过为目标目录打开文件描述符并使用 fstatat() 函数，可以保证返回状态的文件位于相对于所需目录的位置。

变更历史 (CHANGE HISTORY)

第 6 版 (Issue 6)

在 SYNOPSIS（摘要）中，<sys/types.h> 头的可选包含已被移除。

对 POSIX 实现的以下新要求源自与单一 UNIX 规范（Single UNIX Specification）的一致性：

  • 包含 <sys/types.h> 的要求已被移除。虽然 <sys/types.h> 对先前 POSIX 规范的符合性实现是必需的，但它对 UNIX 应用程序不是必需的。

  • 添加了 [EIO] 强制性错误条件。

  • 添加了 [ELOOP] 强制性错误条件。

  • 添加了 [EOVERFLOW] 强制性错误条件。此更改是为了支持大文件。

  • 添加了 [ENAMETOOLONG] 和第二个 [EOVERFLOW] 可选错误条件。

进行了以下更改，以与 IEEE P1003.1a 草案标准保持一致：

  • 添加了关于符号链接处理的细节。

  • 添加了 [ELOOP] 可选错误条件。

规范文本已更新，以避免对应用程序要求使用 "must" 一词。

为与 ISO/IEC 9899:1999 标准保持一致，restrict 关键字被添加到 stat() 原型中。

第 7 版 (Issue 7)

应用了 Austin Group 解释 1003.1-2001 #143。

应用了 XSH-SD5-ERN-161，更新了 DESCRIPTION（说明）以澄清 st_nlink 适用于哪些文件类型。

从开放集团技术标准（The Open Group Technical Standard）2006 年扩展 API 集第 2 部分添加了 fstatat() 函数。

进行了与细粒度时间戳支持相关的更改。

lstat() 函数现在被要求在所有 stat 结构字段中为符号链接返回有意义的数据，但 st_mode 的权限位除外。

进行了更改以允许目录为搜索而打开。

[ENOTDIR] 错误条件被澄清为涵盖路径名的最后一个组件存在但不是目录或指向目录的符号链接的情况。

应用了 POSIX.1-2008 技术勘误 1 的 XSH/TC1-2008/0198 [461]、XSH/TC1-2008/0199 [324]、XSH/TC1-2008/0200 [278]、XSH/TC1-2008/0201 [278] 和 XSH/TC1-2008/0202 [291]。
