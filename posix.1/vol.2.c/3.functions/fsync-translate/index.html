XSH 函数：fsync()

名称 (NAME)

fsync — 同步对文件的更改 (synchronize changes to a file)

摘要 (SYNOPSIS)

[FSC] #include <unistd.h>

int fsync(int fildes);

说明 (DESCRIPTION)

fsync() 函数应请求将 fildes 命名的打开文件描述符的所有数据传输到 fildes 所描述的文件关联的存储设备。传输的性质是实现定义的。在系统完成该动作或检测到错误之前，fsync() 函数不应返回。

[SIO] 如果定义了 _POSIX_SYNCHRONIZED_IO，fsync() 函数应强制与文件描述符 fildes 指示的文件关联的所有当前排队的 I/O 操作进入同步 I/O 完成状态。所有 I/O 操作应按照为同步 I/O 文件完整性完成所定义的方式完成。

返回值 (RETURN VALUE)

成功完成后，fsync() 应返回 0。否则，应返回 -1 并设置 errno 以指示错误。如果 fsync() 函数失败，则不保证未完成的 I/O 操作已经完成。

错误 (ERRORS)

如果满足以下条件，fsync() 函数应失败：

[EBADF]
fildes 参数不是有效的描述符。
[EINTR]
fsync() 函数被信号中断。
[EINVAL]
fildes 参数不指代可以执行此操作的文件。
[EIO]
从文件系统读取或向文件系统写入时发生了 I/O 错误。

如果任何排队的 I/O 操作失败，fsync() 应返回为 read() 和 write() 定义的错误条件。

示例 (EXAMPLES)

应用程序用法 (APPLICATION USAGE)

要求对文件的修改在继续之前完成的程序宜使用 fsync() 函数；例如，包含简单事务设施的程序可能会使用它来确保事务引起的对一个或多个文件的所有修改都被记录下来。

修改目录的应用程序（例如，通过在目录中创建文件）可以在该目录上调用 fsync()，以确保目录的条目和文件属性被同步。对大多数应用程序而言，同步目录的条目宜无必要（参见 XBD 4.11 文件系统缓存）。

理由 (RATIONALE)

fsync() 函数旨在强制从缓冲区高速缓存进行数据的物理写入，并确保在系统崩溃或其他故障之后，截至 fsync() 调用时的所有数据都被记录在磁盘上。由于 "缓冲区高速缓存"、"系统崩溃"、"物理写入" 和 "非易失性存储" 的概念不在此处定义，措辞不得不更加抽象。

如果未定义 _POSIX_SYNCHRONIZED_IO，措辞在很大程度上依赖符合性文档来告知用户可以从系统期望什么。明确意图是允许空实现。这在系统在任何情况下都无法保证非易失性存储，或系统高度容错且不需要该功能的情况下可以是有效的。在这两个极端之间的中间地带，fsync() 可能实际导致数据被写入在断电时安全的地方，也可能不会。符合性文档宜至少说明存在一种配置（以及如何获得该配置），在该配置下，对于用户可以选择用于关键数据的至少某些文件，这一点可以得到保证。并不要求提供详尽的清单，而是要提供足够的信息，以便如果需要保存关键数据，用户可以确定如何配置系统以允许将数据写入非易失性存储。

可以合理地断言，fsync() 的关键方面在测试套件中测试是不合理的。这并不会使该函数的价值降低，只是使其更难测试。正式的符合性测试在测试此条件时可能宜强制系统崩溃（断电关机），但需要以这样的方式进行：除非正在制作结果的正式记录，自动化测试不要求这样做。省略对 fsync() 的测试也并非不合理，允许将其视为实现质量问题。

变更历史 (CHANGE HISTORY)

首次发布于第 3 版。

第 5 版 (Issue 5)

与 POSIX 实时扩展中的 fsync() 保持一致。具体来说，DESCRIPTION（说明）和 RETURN VALUE（返回值）部分被大大扩展，并且 ERRORS（错误）部分已更新，以表明 fsync() 可以返回为 read() 和 write() 定义的错误条件。

第 6 版 (Issue 6)

此函数被标记为文件同步（File Synchronization）选项的一部分。

对 POSIX 实现的以下新要求源自与单一 UNIX 规范（Single UNIX Specification）的一致性：

  • 添加了 [EINVAL] 和 [EIO] 强制性错误条件。

应用了 IEEE Std 1003.1-2001/Cor 2-2004 的条目 XSH/TC2/D6/44，对 DESCRIPTION（说明）进行了编辑性改写。不打算改变含义。

第 8 版 (Issue 8)

应用了 Austin Group 缺陷 672，更改了 APPLICATION USAGE（应用程序用法）部分。
