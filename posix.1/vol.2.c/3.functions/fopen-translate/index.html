XSH 函数：fopen()

[h4_00001] 名称 (NAME)

[blockquote_00002] fopen — 打开流 (open a stream)

[h4_00003] 提要 (SYNOPSIS)

[p_00004] #include <stdio.h>

FILE *fopen(const char *restrict pathname, const char *restrict mode);

[h4_00005] 说明 (DESCRIPTION)

[CX] Except for the "exclusive access" requirement (see below), the functionality described on this reference page is aligned with the ISO C standard. Any other conflict between the requirements described here and the ISO C standard is unintentional. This volume of POSIX.1-2024 defers to the ISO C standard for all fopen() functionality except in relation to "exclusive access".

[p_00006] fopen() 函数应打开其路径名为 pathname 所指向的字符串的文件，并将一个流与它关联。

[p_00007] mode 参数指向一个字符串。如果字符串中任何字符出现不止一次，则行为未指定。如果字符串以下列字符之一开头，则文件应以所指示的模式打开。否则，行为未定义。

[dt_00008] 'r'
[dd_00009] 为读取而打开文件。
[dt_00010] 'w'
[dd_00011] 截断为零长度或创建文件用于写入。
[dt_00012] 'a'
[dd_00013] 追加；在文件末尾打开或创建文件用于写入。

[p_00014] 字符串的其余部分可以包含下列任何字符，[CX] 以任意顺序， 并进一步影响文件的打开方式：

[dt_00015] 'b'
[dd_00016] [CX] 该字符应无任何作用，但为符合 ISO C 标准而允许。
[dt_00017] 'e'
[dd_00018] [CX] 底层文件描述符应原子地设置 FD_CLOEXEC 标志。
[dt_00019] 'x'
[dd_00020] 如果 mode 的第一个字符是 'w' [CX] 或 'a'， 那么如果文件已经存在或无法创建，则函数应失败；如果文件不存在且可以创建，则应以 [CX] 实现定义的 独占（也称为非共享）访问形式创建，[CX] 前提是底层文件系统支持，并且所得文件权限与没有 'x' 修饰符时的权限相同。如果 mode 的第一个字符是 'r'，则效果为实现定义的。 注： ISO C 标准要求独占访问"达到底层文件系统支持独占访问的程度"，但未定义它对此的含义。从表面意义理解——即系统必须在文件系统层面做它们所能做的一切，以排除他人的访问——这将要求 POSIX.1 系统以阻止其他用户和组访问的方式设置文件权限。因此，本卷 POSIX.1-2024 在"独占访问"要求方面不遵从 ISO C 标准。
[dt_00021] '+'
[dd_00022] 文件应以便于更新（既可读又可写）的方式打开，而不只是只读或只写。

[p_00023] 以读取模式（'r' 作为 mode 参数的第一个字符）打开文件时，如果文件不存在或无法读取，则应失败。

[p_00024] 以追加模式（'a' 作为 mode 参数的第一个字符）打开文件，应使所有后续对文件的写入都被强制到当时的当前文件末尾，无论中间是否有对 fseek() 的调用。

[p_00025] 当以更新模式（mode 参数中的 '+'）打开文件时，可以在关联的流上执行输入和输出。但是，应用程序应确保：输出之后不直接跟输入，除非中间调用了 fflush() 或文件定位函数（fseek()、fsetpos() 或 rewind()）；输入之后不直接跟输出，除非中间调用了文件定位函数，除非输入操作遇到文件末尾。

[p_00026] 打开时，当且仅当可以确定流不指向交互式设备时，流才被完全缓冲。流的错误和文件末尾指示符应被清除。

[p_00027] [CX] 如果 mode 中的第一个字符是 'w' 或 'a'，且文件先前不存在，则成功完成后，fopen() 应标记更新文件的上次数据访问、上次数据修改和上次文件状态更改时间戳，以及父目录的上次文件状态更改和上次数据修改时间戳。

[p_00028] 如果 mode 中的第一个字符是 'w' 或 'a'，且文件先前不存在，则 fopen() 函数应创建文件，如同它调用 open() 函数时使用了适合从 pathname 解释出的 path 参数的值、如下指定的 oflag 参数的值，以及第三个参数的 S_IRUSR | S_IWUSR | S_IRGRP | S_IWGRP | S_IROTH | S_IWOTH 值。

[p_00029] 如果 mode 中的第一个字符是 'w'，且文件先前已存在，则成功完成后，fopen() 应标记更新文件的上次数据修改和上次文件状态更改时间戳。

[p_00030] 成功调用 fopen() 函数后，应清除流的方向，[XSI] 应清除编码规则， 并且关联的 mbstate_t 对象应被设置为描述初始转换状态。

[p_00031] [CX] 与打开的流关联的文件描述符应如同通过使用以下标志调用 open() 一样被分配和打开：

[p_00050] 当且仅当指定了 'e' mode 字符串字符时，O_CLOEXEC 标志应被 OR 进上表中指定的初始 open() 标志。

[p_00051] 当且仅当 'x' mode 字符串字符与 'w' 或 'a' 一起指定时，O_EXCL 标志应被 OR 进上表中指定的初始 open() 标志。

[p_00052] 如果 mode 包含 'x'，并且底层文件系统支持通过使用特定于实现的标志调用 open() 来启用的独占访问（见上文），则行为应如同这些标志也被包含一样。

[p_00053] 当使用本标准指定的 mode 字符串时，实现应表现得如同没有其他标志被传给 open() 一样。

[h4_00054] 返回值 (RETURN VALUE)

[p_00055] 成功完成后，fopen() 应返回指向控制该流的对象的指针。否则，应返回空指针，[CX] 并应设置 errno 以指示错误。

[h4_00056] 错误 (ERRORS)

[p_00057] 在以下情况下，fopen() 函数应失败：

[dt_00058] [EACCES]
[dd_00059] [CX] 路径前缀的某个组件上拒绝搜索权限，或文件存在且拒绝 mode 指定的权限，或文件不存在且拒绝要创建的文件的父目录的写权限。
[dt_00060] [EEXIST]
[dd_00061] [CX] mode 参数以 w 或 a 开头并包含 x，但文件已经存在。
[dt_00062] [EILSEQ]
[dd_00063] [CX] mode 参数以 w 或 a 开头，文件先前不存在，且最后一个路径名组件不是可移植文件名，无法在目标目录中创建。
[dt_00064] [EINTR]
[dd_00065] [CX] 在 fopen() 期间捕获到一个信号。
[dt_00066] [EISDIR]
[dd_00067] [CX] 指定的文件是目录，且 mode 要求写访问权限。
[dt_00068] [ELOOP]
[dd_00069] [CX] 在解析 pathname 参数期间遇到的符号链接中存在循环。
[dt_00070] [EMFILE]
[dd_00071] [CX] 进程可用的所有文件描述符当前都已打开。
[dt_00072] [EMFILE]
[dd_00073] [CX] 调用进程中当前打开了 {STREAM_MAX} 个流。
[dt_00074] [ENAMETOOLONG]
[dd_00075] [CX] 路径名的长度超过 {PATH_MAX}，或符号链接的路径名解析产生了长度超过 {PATH_MAX} 的中间结果。
[dt_00076] [ENFILE]
[dd_00077] [CX] 系统中当前打开的文件数已达到允许的最大数量。
[dt_00078] [ENOENT]
[dd_00079] [CX] mode 字符串以 'r' 开头，且 pathname 的某个组件未命名现有文件；或 mode 以 'w' 或 'a' 开头，且 pathname 的路径前缀的某个组件未命名现有文件；或 pathname 是空字符串。
[dt_00080] [ENOENT] 或 [ENOTDIR]
[dd_00081] [CX] pathname 参数包含至少一个非 <slash> 字符，并以一个或多个尾部 <slash> 字符结尾。如果去掉尾部 <slash> 字符的 pathname 会命名一个现有文件，则不应发生 [ENOENT] 错误。
[dt_00082] [ENOSPC]
[dd_00083] [CX] 将包含新文件的目录或文件系统无法扩展，文件不存在，且该文件本应被创建。
[dt_00084] [ENOTDIR]
[dd_00085] [CX] 路径前缀的某个组件命名了一个既不是目录也不是指向目录的符号链接的现有文件，或者 pathname 参数包含至少一个非 <slash> 字符并以一个或多个尾部 <slash> 字符结尾，且最后一个路径名组件命名了一个既不是目录也不是指向目录的符号链接的现有文件。
[dt_00086] [ENXIO]
[dd_00087] [CX] 指定的文件是字符特殊文件或块特殊文件，且与该特殊文件关联的设备不存在。
[dt_00088] [EOVERFLOW]
[dd_00089] [CX] 指定的文件是普通文件，且文件的大小无法在 off_t 类型的对象中正确表示。
[dt_00090] [EROFS]
[dd_00091] [CX] 指定的文件位于只读文件系统上，且 mode 要求写访问权限。

[p_00092] 在以下情况下，fopen() 函数可以失败：

[dt_00093] [EINVAL]
[dd_00094] [CX] mode 参数的值无效。
[dt_00095] [ELOOP]
[dd_00096] [CX] 在解析 pathname 参数期间遇到的符号链接超过 {SYMLOOP_MAX} 个。
[dt_00097] [EMFILE]
[dd_00098] [CX] 调用进程中当前打开了 {FOPEN_MAX} 个流。
[dt_00099] [ENAMETOOLONG]
[dd_00100] [CX] 路径名某个组件的长度超过 {NAME_MAX}。
[dt_00101] [ENOMEM]
[dd_00102] [CX] 可用存储空间不足。
[dt_00103] [ETXTBSY]
[dd_00104] [CX] 该文件是正在执行的纯过程（共享文本）文件，且 mode 要求写访问权限。

[h4_00108] 应用程序用法 (APPLICATION USAGE)

[p_00109] 如果应用程序需要以文件已存在则失败的方式创建文件，并且要么要求它不拥有对文件的独占访问权、要么不需要独占访问权，则它宜使用带 O_CREAT 和 O_EXCL 标志的 open()，而不是在模式中使用 'x' 的 fopen()。如果需要，随后可以通过对 open() 返回的文件描述符调用 fdopen() 来创建流。

[h4_00110] 理由 (RATIONALE)

[p_00111] 'e' 模式字符作为避免多线程应用程序中数据竞争的一种便利而提供。没有它，在另一个线程用 fopen() 创建文件描述符、然后用 fileno() 和 fcntl() 设置 FD_CLOEXEC 标志之间的窗口内，文件描述符会泄漏到由一个线程创建的子进程中。也可以通过使用带 O_CLOEXEC 的 open() 后跟 fdopen() 来避免竞争，但是，对于 freopen() 函数没有安全的替代方案，而且一致性要求 'e' 修饰符应标准化用于所有接受 mode 字符串的函数。

[p_00112] ISO C 标准只识别 mode 字符串中某些位置的 '+'、'b' 和 'x' 字符，将其他安排留作未指定，并且只允许在以 'w' 开头的 mode 字符串中出现 'x'。本标准特别要求 mode 字符串中除第一个字符外的所有字符都支持以任意顺序识别。因此，"wxe" 和 "wex" 行为相同，而虽然 "wx+" 在 ISO C 标准中未指定，本标准要求它具有与 "w+x" 相同的行为。本标准还要求 'x' 对以 'a' 开头的 mode 字符串有效，并且对以 'r' 开头的 mode 字符串具有实现定义的行为。因此，虽然如果在没有 O_CREAT 的情况下指定 O_EXCL，open() 具有未定义行为，但 fopen() 并非如此。

[p_00113] 当 mode 中有 'x' 时，ISO C 标准要求在底层系统支持独占访问的程度上以独占访问方式创建文件。虽然 POSIX.1 未指定启用独占访问的任何方法，但它允许存在一个或多个启用它的实现特定标志。注意，如果要创建文件，它们应是文件创建标志，而不是文件访问模式标志（即包含在 O_ACCMODE 中的那些）或文件状态标志，这样它们就不会影响 fcntl() 以 F_GETFL 返回的值。在具有此类标志的实现上，如果对它们的支持依赖于文件系统，并且在使用 fopen() 在不支持它的文件系统上创建文件时请求独占访问，那么如果这些标志会导致 fopen() 失败，则必须不使用这些标志。

[p_00114] 一些实现支持强制文件锁，作为启用对文件的独占访问的一种手段。锁按正常方式设置，但不是仅仅阻止他人设置冲突的锁，而是阻止他人以与锁冲突的方式访问文件被锁部分的内容。然而，除非实现有一种在创建文件时设置整个文件写锁的方法，否则这不满足 ISO C 标准中文件"以底层系统支持独占访问的程度被创建为独占访问"的要求。（让 fopen() 创建文件并在文件上设置锁作为两个单独的操作不是一回事，而且会引入竞争条件，即另一个进程可以在两个操作之间打开文件并向其写入（或设置锁）。）然而，在所有支持强制文件锁的实现上，都不鼓励使用它；因此，建议支持强制文件锁的实现不要添加创建带有整文件独占锁集的文件的手段，这样就不要求 fopen() 启用强制文件锁以符合 ISO C 标准。具有创建带有整文件独占锁集的文件的手段的实现，将需要提供一种根据调用进程是在 POSIX.1 一致环境中还是在 ISO C 一致环境中执行来改变 fopen() 行为的方法。

[p_00115] 模式 "rx" 的典型实现定义行为是忽略 'x'，但标准开发者不希望强制规定这种行为。例如，实现可以允许共享读访问；也就是说，不允许以这种方式打开的文件再被打开用于写入。

[p_00116] 鼓励实现让 fopen() 和 freopen() 在 mode 以 'w' 或 'a' 开头、文件先前不存在、且 pathname 的最后一个组件包含任何具有 <newline> 字符编码值的字节时报告 [EILSEQ] 错误。
