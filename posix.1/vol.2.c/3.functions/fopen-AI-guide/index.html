XSH 函数导读：fopen()

0. 总览

fopen() 打开路径名为 pathname 的文件，并将一个流与它关联，返回指向该流对象的指针；失败时返回空指针并设置 errno。头文件为 <stdio.h>。原型关键点：两个参数均带 restrict 限定——FILE *fopen(const char *restrict pathname, const char *restrict mode)，调用方须保证两个字符串在生命周期内不被修改。

1. 机制

mode 的第一个字符决定基本模式：'r' 读取、'w' 截断或创建、'a' 追加（所有后续写入都被强制到当时的文件末尾，即使中间调用了 fseek()）。其余字符可任意顺序出现：'b' 无任何作用（仅为符合 ISO C 而允许）；'e' 使底层文件描述符原子地设置 FD_CLOEXEC；'x' 与 'w'/'a' 组合时，若文件已存在则失败，并以独占方式创建；'+' 使文件便于更新（可读可写）。底层通过 open() 实现：如 'w' 映射 O_WRONLY|O_CREAT|O_TRUNC，'a' 映射 O_WRONLY|O_CREAT|O_APPEND，仅当指定 'e'/'x' 时才 OR 进 O_CLOEXEC/O_EXCL。打开成功后流的方向、编码规则被清除，mbstate_t 置为初始转换状态；当且仅当能确定流不指向交互式设备时才完全缓冲，错误与文件末尾指示符被清除。

2. 易错点

  • mode 中任何字符出现不止一次则行为未指定；不以 'r'/'w'/'a' 开头则行为未定义，返回值也未必可靠。
  • 'x' 只对以 'w' 或 'a' 开头的模式有意义；对 'r' 开头的模式效果是实现定义的，不要依赖。
  • 更新模式（'+'）下，输出之后不能直接跟输入，除非中间调用 fflush() 或文件定位函数；输入之后也不能直接跟输出，除非中间定位或输入遇到文件末尾。
  • 追加模式下 fseek() 到文件中间再写，数据仍会落到文件末尾。
  • 若需要“文件已存在则创建失败”且不要求独占访问，规范建议改用带 O_CREAT|O_EXCL 的 open()，再用 fdopen() 建流。
  • 不要忘记检查返回值：失败时返回空指针，可能伴随 EACCES、ENOENT、EMFILE、EISDIR 等错误。

3. 示例

#include <stdio.h>

int main(void)
{
    FILE *fp = fopen("note.txt", "wxe"); /* 已存在则失败；fd 带 FD_CLOEXEC */
    if (fp == NULL) {
        perror("fopen");
        return 1;
    }
    fputs("hello\n", fp);
    fclose(fp);
    return 0;
}
