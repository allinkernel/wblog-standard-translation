XSH 函数导读：read()

0. 总览

read() 从与打开的文件描述符关联的文件中读取数据到用户缓冲区。所属头文件为 <unistd.h>。原型关键点：ssize_t read(int fildes, void *buf, size_t nbyte); —— 成功返回实际读取的字节数（非负），失败返回 -1 并设置 errno；返回值绝不应大于 nbyte。本页还包含预读变体 pread()，它从指定 offset 读取而不改变文件偏移。

1. 机制

在可寻址文件（如普通文件）上，读取从与 fildes 关联的文件偏移处开始，偏移按实际读取的字节数递增；在终端等不可寻址文件上，总是从当前位置读取，且偏移值未定义。返回短读数（小于 nbyte）是合法且常见的情况：文件剩余字节不足、被信号中断、或管道/FIFO/特殊文件立即可供读取的字节较少（如终端按行返回）。nbyte 为零时，read() 应返回 0 且无其他结果（错误检测可先行）。成功读取（nbyte 大于 0）时，最后数据访问时间戳被标记为需要更新。从管道或 FIFO 读取：无写者时返回 0 表示文件结尾；有写者但数据为空时，设置 O_NONBLOCK 则返回 -1/[EAGAIN]，否则阻塞。pread() 在无法寻址的文件上应失败，普通文件上 offset 为负返回 [EINVAL] 且偏移保持不变。

2. 易错点

不要假设一次读满 nbyte：短读是正常语义，调用者应循环读取直到凑够所需字节或遇到 0/[EAGAIN]，而非把短读当错误。读空管道无写者返回 0，容易被误判为"读到数据"；写者存在但无数据时非阻塞读返回 [EAGAIN]，两者务必区分。nbyte 大于 {SSIZE_MAX} 时结果实现定义，超大读取应分块。未写入的洞（lseek 越过后再读）返回 0 值字节。信号中断语义：读任何数据之前被中断返回 -1/[EINTR]；已读部分数据后被中断则返回已读字节数。常见错误还有 [EBADF]（描述符未以读方式打开）、[EISDIR]（目录上读取，应改用 readdir()）、[EOVERFLOW]（起始位置越过偏移最大值）、后台进程组读控制终端的 [EIO]。

3. 示例

#include <unistd.h>

char buf[4096];
ssize_t n;
int fd; /* 已以 O_RDONLY 打开的普通文件 */

/* 循环读取直到文件结尾，正确处理短读 */
while ((n = read(fd, buf, sizeof buf)) > 0) {
    /* 处理 buf 中的 n 个字节 */
}
if (n == -1) {
    /* 处理错误（如 EINTR、EAGAIN） */
}
