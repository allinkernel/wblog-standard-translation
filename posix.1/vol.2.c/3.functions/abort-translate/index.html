XSH 函数：abort()

名称 (NAME)

abort — 产生异常进程中止 (generate an abnormal process abort)

概要 (SYNOPSIS)

#include <stdlib.h>

_Noreturn void abort(void);

说明 (DESCRIPTION)

[CX] The functionality described on this reference page is aligned with the ISO C standard. Any conflict between the requirements described here and the ISO C standard is unintentional. This volume of POSIX.1-2024 defers to the ISO C standard.

abort() 函数应导致异常进程终止发生，除非它产生的 SIGABRT 信号被捕获并且信号处理器不返回。

[CX] 异常终止处理应包括为 SIGABRT 定义的默认动作，并且可以包括对所有打开的流实施 fclose() 的尝试。

SIGABRT 信号应发送给调用 [CX] 线程 ，如同通过使用参数 SIGABRT 的 raise() 发送一样。[CX] 如果此信号没有终止进程（例如，如果信号被捕获并且处理器返回），abort() 可以将 SIGABRT 的处置更改为 SIG_DFL 并（以相同的方式）再次发送该信号。如果发送第二个信号并且它没有终止进程，则行为是未指定的，但 abort() 调用不应返回。

[CX] 由 abort() 提供给 wait()、waitid() 或 waitpid() 的状态应是因 SIGABRT 信号而终止的进程的状态。 abort() 函数应覆盖对 SIGABRT 信号的阻塞或忽略。

返回值 (RETURN VALUE)

abort() 函数不应返回。

错误 (ERRORS)

未定义任何错误。

The following sections are informative.

示例 (EXAMPLES)

无。

应用程序用法 (APPLICATION USAGE)

捕获信号旨在为应用程序开发者提供可移植的中止处理的手段，不受任何实现提供的函数的可能干扰。

原理 (RATIONALE)

历史上，abort() 已通过调用其他信号操作函数（如 raise()、sigaction() 和 pthread_sigmask()）实现。这意味着它的操作可能受其他线程中的并发动作影响。例如，如果 abort() 试图通过调用 sigaction() 将 SIGABRT 的处置更改为 SIG_DFL 然后调用 raise() 来终止进程，另一个线程可能在这两次调用之间更改处置，导致进程不被终止。如果发生这种情况，唯一的要求是 abort() 不返回。实现可以循环调用这些函数（理论上可以无限期执行），或者可以通过调用 _exit() 来终止进程（这将确保终止但导致错误的等待状态）。为避免这些问题，鼓励实现以使其操作不受其他线程中的并发动作影响的方式实现 abort()。例如，它可以首先暂停所有其他线程的执行，或者它可以使用 "如同按信号终止" 的系统调用终止进程，而不是通过再次触发（第二个）SIGABRT。

ISO/IEC 9899:1999 标准要求（当前标准仍然要求）abort() 函数是异步信号安全的。由于 POSIX.1-2024 遵从 ISO C 标准，这要求将 DESCRIPTION 从 "应包括 fclose() 的效果" 更改为 "可以包括实施 fclose() 的尝试"。

修订后的措辞允许一些向后兼容性并避免潜在的死锁情况。

应用了 The Open Group Base 决议 bwg2002-003，从 DESCRIPTION 中移除了以下 XSI 阴影标记的段落：

"在符合 XSI 的系统上，此外异常终止处理应包括 fclose() 对消息目录描述符的效果。"

移除该段落有几个原因：

  • 在异常进程终止之前，不需要对打开的消息目录执行特殊处理。

  • 特别提及 abort() 包括 fclose() 对打开流的效果的主要原因是刷新在流上排队的输出。此上下文中的消息目录是只读的，因此不需要被刷新。

  • fclose() 对消息目录描述符的效果是未指定的。消息目录描述符被允许但不需要使用文件描述符实现，但 POSIX.1-2024 中没有提到消息目录描述符使用 fclose() 所预期的标准 I/O 流 FILE 对象。

未来方向 (FUTURE DIRECTIONS)

本标准的未来版本可以要求 abort() 以使其操作不受其他线程中的并发动作影响的方式实现。
