XSH 函数：read()

名称

pread, read — 从文件读取

概要

#include <unistd.h>

ssize_t pread(int fildes, void *buf, size_t nbyte, off_t offset);
ssize_t read(int fildes, void *buf, size_t nbyte);

说明

read() 函数应尝试从与打开的文件描述符 fildes 关联的文件中读取 nbyte 个字节，读入由 buf 指向的缓冲区。在同一管道、FIFO 或终端设备上进行多个并发读取的行为未指定。

在采取下面描述的任何动作之前，如果 nbyte 为零，read() 函数可以检测并返回如下所述的错误。在没有错误的情况下，或者如果没有执行错误检测，read() 函数应返回零且没有其他结果。

在支持寻址（例如普通文件）的文件上，read() 应从文件中由与 fildes 关联的文件偏移所给定的位置开始。文件偏移应按实际读取的字节数递增。

不支持寻址的文件——例如终端——总是从当前位置读取。与此类文件关联的文件偏移的值未定义。

不应发生越过当前文件结尾的数据传输。如果起始位置在文件结尾处或之后，则应返回 0。如果该文件引用的是设备特殊文件，则后续 read() 请求的结果是实现定义的。

如果 nbyte 的值大于 {SSIZE_MAX}，则结果实现定义。

当尝试从空的管道或 FIFO 读取时：

  • 如果没有进程将该管道打开用于写入，read() 应返回 0 以表示文件结尾。

  • 如果某个进程将该管道打开用于写入且设置了 O_NONBLOCK，read() 应返回 -1 并将 errno 设置为 [EAGAIN]。

  • 如果某个进程将该管道打开用于写入且 O_NONBLOCK 被清除，read() 应阻塞调用线程，直到写入了一些数据或所有曾将该管道打开用于写入的进程都关闭了该管道。

当尝试读取一个支持非阻塞读取且当前没有可用数据的文件（管道或 FIFO 除外）时：

  • 如果设置了 O_NONBLOCK，read() 应返回 -1 并将 errno 设置为 [EAGAIN]。

  • 如果 O_NONBLOCK 被清除，read() 应阻塞调用线程，直到有一些数据可用。

  • 如果有一些数据可用，则使用 O_NONBLOCK 标志没有效果。

read() 函数读取先前写入文件的数据。如果文件结尾之前的普通文件的任何部分尚未被写入，read() 应返回值为 0 的字节。例如，lseek() 允许将文件偏移设置到文件中现有数据结尾之后。如果稍后在此位置写入数据，则在先前数据结尾与新写入数据之间的间隙中的后续读取应返回值为 0 的字节，直到数据被写入该间隙。

在成功完成时，当 nbyte 大于 0 时，read() 应将文件的最后数据访问时间戳标记为需要更新，并应返回读取的字节数。该数字绝不应大于 nbyte。如果文件中剩余的字节数少于 nbyte、read() 请求被信号中断、或者该文件是管道或 FIFO 或特殊文件且立即可供读取的字节少于 nbyte，则返回的值可以小于 nbyte。例如，从与终端关联的文件进行 read() 可以返回一行已键入的数据。

如果 read() 在读取任何数据之前被信号中断，它应返回 -1，并将 errno 设置为 [EINTR]。

如果 read() 在成功读取了一些数据之后被信号中断，它应返回读取的字节数。

对于普通文件，不应发生越过与 fildes 关联的打开文件描述中确立的偏移最大值的数据传输。

如果 fildes 引用的是套接字，read() 应等同于不设置任何标志的 recv()。

[SIO] 如果已设置 O_DSYNC 和 O_RSYNC 位，则该文件描述符上的读 I/O 操作应按照同步 I/O 数据完整性完成所定义的方式完成。如果已设置 O_SYNC 和 O_RSYNC 位，则该文件描述符上的读 I/O 操作应按照同步 I/O 文件完整性完成所定义的方式完成。

[SHM] 如果 fildes 引用的是共享内存对象，则 read() 函数的结果未指定。

[TYM] 如果 fildes 引用的是类型化内存对象，则 read() 函数的结果未指定。

pread() 函数应等同于 read()，不同之处在于它应从文件中的给定位置读取而不改变文件偏移。pread() 的前三个参数与 read() 相同，另外增加了第四个参数 offset 用于指定文件内的期望位置。尝试在无法寻址的文件上执行 pread() 应导致错误。

返回值

成功完成后，这些函数应返回一个表示实际读取的字节数的非负整数。否则，这些函数应返回 -1 并设置 errno 以指明错误。

错误

在以下情况下，这些函数应失败：

[EAGAIN]
该文件既不是管道、也不是 FIFO、也不是套接字，为该文件描述符设置了 O_NONBLOCK 标志，且该线程将在读取操作中被延迟。
[EBADF]
fildes 参数不是为读取而打开的有效文件描述符。
[EINTR]
读取操作因收到信号而终止，且没有传输任何数据。
[EIO]
该进程是试图从其控制终端读取的后台进程组的成员，并且要么调用线程正在阻塞 SIGTTIN、要么该进程正在忽略 SIGTTIN、要么该进程的进程组是孤儿进程组。此错误也可以因实现定义的原因而产生。
[EISDIR]
[XSI] fildes 参数引用的是目录，且实现不允许使用 read() 或 pread() 读取该目录。应改用 readdir() 函数。
[EOVERFLOW]
该文件是普通文件，nbyte 大于 0，起始位置在文件结尾之前，且起始位置大于或等于与 fildes 关联的打开文件描述中确立的偏移最大值。

在以下情况下，pread() 函数应失败：

[EINVAL]
该文件是普通文件或块特殊文件，且 offset 参数为负数。文件偏移应保持不变。
[ESPIPE]
该文件无法寻址。

在以下情况下，read() 函数应失败：

[EAGAIN]
该文件是管道或 FIFO，为该文件描述符设置了 O_NONBLOCK 标志，且该线程将在读取操作中被延迟。
[EAGAIN] 或 [EWOULDBLOCK]
该文件是套接字，为该文件描述符设置了 O_NONBLOCK 标志，且该线程将在读取操作中被延迟。
[ECONNRESET]
尝试在套接字上进行读取，且连接被其对端强制关闭。
[ENOTCONN]
尝试在未连接的套接字上进行读取。
[ETIMEDOUT]
尝试在套接字上进行读取，且发生了传输超时。

在以下情况下，这些函数可以失败：

[EIO]
发生了物理 I/O 错误。
[ENOBUFS]
系统中可用于执行该操作的资源不足。
[ENOMEM]
可用于满足该请求的内存不足。
[ENXIO]
对不存在的设备发出了请求，或者该请求超出了设备的能力范围。
The following sections are informative.

示例

将数据读入缓冲区

下面的示例将数据从与文件描述符 fd 关联的文件读入由 buf 指向的缓冲区。

#include <sys/types.h>
#include <unistd.h>
...
char buf[20];
size_t nbytes;
ssize_t bytes_read;
int fd;
...
nbytes = sizeof(buf);
bytes_read = read(fd, buf, nbytes);
...

应用程序使用

不使用。

理由

POSIX.1-2024 本卷不规定返回错误后文件偏移的值；情况太多。对于编程错误，如 [EBADF]，由于不涉及文件，该概念没有意义。对于立即检测到的错误，如 [EAGAIN]，偏移显然不应改变。然而，在中断或硬件错误之后，更新后的值将非常有用，并且是许多实现的行为。

注意，读取零字节的 read() 不修改最后数据访问时间戳。请求多于零字节但返回零的 read() 被要求修改最后数据访问时间戳。

允许但不需要实现为读取零字节的 read() 请求执行错误检查。

输入和输出

使用大字节计数的 I/O 一直存在问题。诸如 lread() 和 lwrite()（使用并返回 long）之类的想法曾经被考虑过。当前的解决方案是在 ISO C 标准函数 read() 和 write() 上使用抽象类型。可以声明抽象类型以便现有函数可以工作，但也可以声明抽象类型以便在将来的实现中可以表示更大的类型。可以推定，任何限制 size_t 最大范围的约束也把可移植的 I/O 请求限制在相同的范围内。POSIX.1-2024 本卷还通过要求限制字节计数以便带符号的返回值保持有意义，进一步限制了该范围。由于返回类型也是（带符号的）抽象类型，实现可以将字节计数定义为大于 int 所能容纳的值。

标准制定者考虑过对管道或 FIFO 增加原子性要求，但认识到由于管道和 FIFO 的性质，无法保证 {PIPE_BUF} 或任何其他有助于应用程序可移植性的大小的读取的原子性。

POSIX.1-2024 本卷要求当 nbyte 为零时，read() 或 write() 不采取任何动作。这并不旨在优先于错误检测（如无效的缓冲区指针或文件描述符）。这与 POSIX.1-2024 本卷的其余部分一致，但这里的措辞可能被误读为要求在检测任何其他错误之前检测零的情况。值零应被视为正确的值，其语义是空操作。

I/O 旨在对普通文件、管道和 FIFO 是原子的。原子意味着来自单个操作、一开始就一起的所有字节最终一起结束，不会被其他 I/O 操作穿插。众所周知，终端不具备这一属性，并且终端被明确地（并且隐含地永久地）排除在外，使得该行为未指定。其他设备类型的行为也保持未指定，但该措辞旨在暗示将来的标准可能会选择规定原子性（或不规定）。

曾有人建议向 read() 和 write() 增加格式参数，以处理异构文件系统和基础硬件类型之间的网络化传输。OSI 表示层服务的支持可能需要这样的设施。然而，已确定这应与类似的 C 语言设施对应，而这超出了 POSIX.1-2024 本卷的范围。该概念已被建议给 ISO C 标准的制定者，供他们考虑作为未来工作的可能领域。

在 4.3 BSD 中，在传输任何数据之前被信号中断的 read() 或 write() 默认不返回 [EINTR] 错误，而是被重新启动。在 4.2 BSD、4.3 BSD 和第八版中，有一个附加函数 select()，其目的是暂停，直到在指定的文件描述符上检测到指定的活动（要读取的数据、要写入的空间等）。在为这些系统编写的应用程序中，常见做法是在希望 I/O 因信号而中断的情况下（如键盘输入），在 read() 之前使用 select()。

哪些文件或文件类型可被中断的问题被认为是实现设计问题。这通常主要受硬件和可靠性问题的影响。

没有对在"不可恢复错误"之后采取的动作的引用。描述硬件错误情况下发生什么被认为超出了 POSIX.1-2024 本卷的范围。

本标准的早期版本在中断的处理方面允许两种截然不同的行为。为了尽量减少由此产生的混乱，决定 POSIX.1-2024 应只支持这些行为中的一种。源自 AT&T 的系统的历史实践是，当所请求的数据传输了一部分但不是全部后被中断时，read() 和 write() 返回 -1 并将 errno 设置为 [EINTR]。然而，美国商务部的 FIPS 151-1 和 FIPS 151-2 要求历史上的 BSD 行为，即 read() 和 write() 返回中断前实际传输的字节数。如果传输了任何数据却返回 -1，则在可寻址设备上很难从错误中恢复，在不可寻址设备上则不可能恢复。大多数新实现支持这种行为。POSIX.1-2024 要求的行为是返回传输的字节数。

POSIX.1-2024 不规定对 read() 进行缓冲的实现何时实际将数据移入用户提供的缓冲区，因此实现可以选择在最晚可能的时刻这样做。因此，较早到达的中断可能不会导致 read() 返回部分字节计数，而是返回 -1 并将 errno 设置为 [EINTR]。

还考虑过将先前两个选项结合起来，在返回短计数的同时将 errno 设置为 [EINTR]。然而，不仅没有实现这一点的现有实践，而且这与"当设置了 errno 时，负责的函数应返回 -1"的想法相矛盾。

POSIX.1-2024 本卷有意不规定与管道、FIFO 和套接字相关的除 [ESPIPE] 之外的任何 pread() 错误。

第 5 版

更新了说明部分，以与 POSIX 实时扩展和 POSIX 线程扩展保持一致。

第 6 版

更新了说明和错误部分，以便对 STREAMS 的引用被标记为 XSI STREAMS 选项组的一部分。

以下对 POSIX 实现的新要求源自与单一 UNIX 规范的一致性：

  • 说明现在规定，如果 read() 在成功读取了一些数据之后被信号中断，它返回读取的字节数。在第 3 版中，read() 是返回读取的字节数、还是返回 -1 并将 errno 设置为 [EINTR] 是可选的。这是一项 FIPS 要求。

  • 在说明中，增加了文本以指明对于普通文件，不会发生越过与 fildes 关联的打开文件描述中确立的偏移最大值的数据传输。此更改是为了支持大文件。

  • 增加 [EOVERFLOW] 强制错误情况。

  • 增加 [ENXIO] 可选错误情况。

在说明中增加了引用套接字的文本。

为与 IEEE P1003.1a 草案标准保持一致，做了以下更改：

  • 阐明了读取零字节的效果。

更新了说明部分，通过规定 read() 对类型化内存对象的结果未指定，以与 IEEE Std 1003.1j-2000 保持一致。

增加了新的理由部分以解释输入和输出操作的原子性要求。

为套接字上的操作增加以下错误情况：[EAGAIN]、[ECONNRESET]、[ENOTCONN] 和 [ETIMEDOUT]。

[EIO] 错误变为可选的。

为套接字上的操作增加以下错误情况：[ENOBUFS] 和 [ENOMEM]。

readv() 函数被拆分到单独的参考页中。

应用 IEEE Std 1003.1-2001/Cor 2-2004 项目 XSH/TC2/D6/108，将错误部分中的 [EAGAIN] 错误从"进程将被延迟"更新为"线程将被延迟"。

应用 IEEE Std 1003.1-2001/Cor 2-2004 项目 XSH/TC2/D6/109，在理由部分做了编辑性更正。
