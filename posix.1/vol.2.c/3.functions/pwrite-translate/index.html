XSH 函数：pwrite()

名称

pwrite, write — 在文件上写入

概要

#include <unistd.h>

ssize_t pwrite(int fildes, const void *buf, size_t nbyte,
off_t offset);
ssize_t write(int fildes, const void *buf, size_t nbyte);

说明

write() 函数应尝试从由 buf 指向的缓冲区写入 nbyte 字节到与打开文件描述符 fildes 关联的文件。

在采取下面描述的任何动作之前，并且如果 nbyte 为零且该文件是普通文件，write() 函数可以按如下所述检测并返回错误。在没有错误的情况下，或者如果未执行错误检测，write() 函数应返回零且没有其他结果。如果 nbyte 为零且该文件不是普通文件，结果未指定。

在普通文件或其他能够寻址（seeking）的文件上，数据的实际写入应从与 fildes 关联的文件偏移所指示的文件位置开始进行。在 write() 成功返回之前，文件偏移应按实际写入的字节数递增。在普通文件上，如果最后写入的字节的位置大于或等于文件的长度，文件长度应被设置为该位置加一。

在无法寻址的文件上，写入应总是从当前位置开始。与这种设备关联的文件偏移的值是未定义的。

如果文件状态标志的 O_APPEND 标志被设置，文件偏移应在每次写入之前被设置为文件末尾，并且在更改文件偏移与写操作之间不应发生介入的文件修改操作。

如果 write() 请求写入的字节数多于可容纳的空间（例如，进程的文件大小限制或介质的物理末尾），则只应写入可容纳的那么多字节。例如，假设在达到限制之前文件中还有 20 字节的空间。写入 512 字节将返回 20。下一次写入非零字节数将给出失败返回（如下所述除外）。

如果该请求将导致文件大小超过进程的软文件大小限制，并且没有任何字节的空间可写，该请求应失败 [XSI] 且实现应为该线程生成 SIGXFSZ 信号。

如果 write() 在写入任何数据之前被信号中断，它应返回 -1 且 errno 设为 [EINTR]。

如果 write() 在成功写入了一些数据之后被信号中断，它应返回写入的字节数。

如果 nbyte 的值大于 {SSIZE_MAX}，结果为实现定义的。

在向普通文件的 write() 成功返回之后：

  • 从该次写入修改的每个字节位置进行的任何成功的 read() 应返回该 write() 为该位置指定的数据，直到这些字节位置再次被修改。

  • 随后对该文件中同一字节位置的任何成功 write() 应覆盖该文件数据。


对管道或 FIFO 的写请求应以与普通文件相同的方式处理，但有以下例外：

  • 管道或 FIFO 没有关联的文件偏移，因此每个写请求应追加到管道或 FIFO 的末尾。

  • 对 {PIPE_BUF} 字节或更少的写请求不应与在同一管道或 FIFO 上执行写操作的其他线程的数据交错。大于 {PIPE_BUF} 字节的写入可以在任意边界上与其它线程的写操作交错，无论文件状态标志的 O_NONBLOCK 标志是否被设置。

  • 如果 O_NONBLOCK 标志清除，写请求可以使线程阻塞，但在正常完成时它应返回 nbyte。

  • 如果 O_NONBLOCK 标志被设置，write() 请求应按以下方式以不同方式处理：

    • write() 函数不应阻塞线程。

    • 对 {PIPE_BUF} 或更少字节的写请求应具有以下效果：如果管道或 FIFO 中有足够的可用空间，write() 应传输所有数据并返回请求的字节数。否则，write() 应不传输任何数据并返回 -1 且 errno 设为 [EAGAIN]。

    • 对多于 {PIPE_BUF} 字节的写请求应导致以下情况之一：

      • 当至少一个字节可以被写入时，传输其能传输的并返回写入的字节数。当先前写入管道或 FIFO 的所有数据都被读取时，它应传输至少 {PIPE_BUF} 字节。

      • 当没有数据可以被写入时，不传输任何数据，并返回 -1 且 errno 设为 [EAGAIN]。

当尝试写入一个支持非阻塞写入且无法立即接受数据的文件描述符（管道或 FIFO 除外）时：

  • 如果 O_NONBLOCK 标志清除，write() 应阻塞调用线程，直到数据可以被接受。

  • 如果 O_NONBLOCK 标志被设置，write() 不应阻塞线程。如果可以在不阻塞线程的情况下写入一些数据，write() 应写入其能写入的并返回写入的字节数。否则，它应返回 -1 并将 errno 设为 [EAGAIN]。

成功完成时，当 nbyte 大于 0，write() 应将文件的最后数据修改和最后文件状态更改时间戳标记为更新，并且如果该文件是普通文件，文件模式的 S_ISUID 和 S_ISGID 位可以被清除。

对于普通文件，不应发生越过与 fildes 关联的打开文件描述中建立的偏移最大值的数据传输。

如果 fildes 引用套接字，write() 应等同于未设置标志的 send()。

[SIO] 如果已设置 O_DSYNC 位，文件描述符上的写 I/O 操作应按照同步 I/O 数据完整性完成所定义的方式完成。

如果已设置 O_SYNC 位，文件描述符上的写 I/O 操作应按照同步 I/O 文件完整性完成所定义的方式完成。

[SHM] 如果 fildes 引用共享内存对象，write() 函数的结果是未指定的。

[TYM] 如果 fildes 引用类型化内存对象，write() 函数的结果是未指定的。

pwrite() 函数应等同于 write()，不同之处在于它写入给定位置并且不更改文件偏移（无论是否设置 O_APPEND）。pwrite() 的前三个参数与 write() 相同，另外增加了第四个参数 offset，用于指定文件内的期望位置。尝试在无法寻址的文件上执行 pwrite() 应导致错误。

返回值

成功完成时，这些函数应返回实际写入与 fildes 关联的文件中的字节数。此数字绝不应大于 nbyte。否则，应返回 -1 并将 errno 设为指示错误。

错误

如果以下情况，这些函数应失败：

[EAGAIN]
该文件既不是管道，也不是 FIFO，也不是套接字，为该文件描述符设置了 O_NONBLOCK 标志，并且该线程将在 write() 操作中被延迟。
[EBADF]
fildes 参数不是打开用于写入的有效文件描述符。
[EFBIG]
尝试写入一个超过实现定义的最大文件大小的文件，并且没有任何字节的空间可写。
[EFBIG]
尝试写入一个超过进程文件大小限制的文件，并且没有任何字节的空间可写。[XSI] 还应为该线程生成 SIGXFSZ 信号。
[EFBIG]
该文件是普通文件，nbyte 大于 0，且起始位置大于或等于与 fildes 关联的打开文件描述中建立的偏移最大值。
[EINTR]
写操作因收到信号而终止，且未传输任何数据。
[EIO]
该进程是尝试写入其控制终端的后台进程组的成员，TOSTOP 被设置，调用线程未阻塞 SIGTTOU，该进程未忽略 SIGTTOU，且该进程的进程组是孤立的。此错误也可以在实现定义的条件下返回。
[ENOSPC]
包含该文件的设备上没有剩余可用空间。

如果以下情况，pwrite() 函数应失败：

[EINVAL]
该文件是普通文件或块特殊文件，且 offset 参数为负值。文件偏移应保持不变。
[ESPIPE]
该文件无法寻址。

如果以下情况，write() 函数应失败：

[EAGAIN]
该文件是管道或 FIFO，为该文件描述符设置了 O_NONBLOCK 标志，并且该线程将在写操作中被延迟。
[EAGAIN] 或 [EWOULDBLOCK]
该文件是套接字，为该文件描述符设置了 O_NONBLOCK 标志，并且该线程将在写操作中被延迟。
[ECONNRESET]
对未连接的套接字尝试了写入。
[EPIPE]
尝试向未被任何进程打开用于读取的管道或 FIFO 写入，或者该管道或 FIFO 只有一端打开。还应向该线程发送 SIGPIPE 信号。
[EPIPE]
对已关闭写入的套接字或不再连接的套接字尝试了写入。在后一种情况下，如果该套接字是 SOCK_STREAM 类型，还应向该线程发送 SIGPIPE 信号。

如果以下情况，这些函数可以失败：

[EIO]
发生了物理 I/O 错误。
[ENOBUFS]
系统中可用于执行该操作的资源不足。
[ENXIO]
对不存在的设备提出了请求，或者该请求超出了设备的能力范围。

如果以下情况，write() 函数可以失败：

[EACCES]
对套接字尝试了写入，且调用进程没有适当的权限。
[ENETDOWN]
对套接字尝试了写入，且用于到达目的地的本地网络接口已关闭。
[ENETUNREACH]
对套接字尝试了写入，且不存在到达网络的路径。
The following sections are informative.

示例

从缓冲区写入 (Writing from a Buffer)

下面的示例将数据从由 buf 指向的缓冲区写入与文件描述符 fd 关联的文件。

#include <sys/types.h>
#include <string.h>
...
char buf[20];
size_t nbytes;
ssize_t bytes_written;
int fd;
...
strcpy(buf, "This is a test\n");
nbytes = strlen(buf);
 
bytes_written = write(fd, buf, nbytes);
...

应用程序用法 (APPLICATION USAGE)

无。

理由 (RATIONALE)

另请参见 read() 中的 RATIONALE 部分。

尝试写入管道或 FIFO 具有几个主要特征：

  • 原子/非原子：如果一次操作中写入的全部量不与任何其他线程的数据交错，则写入是原子的。当有多个写入者向单个读取者发送数据时，这很有用。应用程序需要知道多大的写请求可以被期望原子地执行。这个最大值被称为 {PIPE_BUF}。本卷 POSIX.1-2024 未说明超过 {PIPE_BUF} 字节的写请求是否原子，但要求 {PIPE_BUF} 或更少字节的写入应是原子的。

  • 阻塞/立即：阻塞仅在 O_NONBLOCK 清除时才可能。如果有足够的空间可以立即写入所有请求的数据，实现应这样做。否则，调用线程可以阻塞；即暂停，直到有足够的空间可供写入。管道或 FIFO 的有效大小（一次操作中不阻塞即可写入的最大量）可以动态变化，取决于实现，因此不可能为其指定固定值。

  • 完整/部分/延迟：一个写请求：

    int fildes;
size_t nbyte;
ssize_t ret;
char *buf;
 
ret = write(fildes, buf, nbyte);

    可以返回：

    完整 (Complete)
    ret=nbyte
    部分 (Partial)
    ret<nbyte

    如果 nbyte<={PIPE_BUF}，这绝不应发生。如果确实发生（nbyte>{PIPE_BUF}），本卷 POSIX.1-2024 不保证原子性，即使 ret<={PIPE_BUF}，因为原子性是根据 请求的量而不是 写入的量来保证的。

    延迟 (Deferred):
    ret=-1, errno=[EAGAIN]

    此错误指示稍后的请求可以成功。它不指示它 应 成功，即使 nbyte<={PIPE_BUF}，因为如果没有进程从管道或 FIFO 读取，写入永远不会成功。应用程序可以有效地统计 [EAGAIN] 由 nbyte>{PIPE_BUF} 的特定值引起的次数，并可能在以后用较小的值进行写入，前提是管道或 FIFO 的有效大小可能已经减小。

    部分和延迟的写入仅在设置了 O_NONBLOCK 时才可能。

这些属性的关系如下表所示：

如果 O_NONBLOCK 标志清除，如果立即可写入的量少于请求的量，写请求应阻塞。如果该标志被设置（由 fcntl()），写请求绝不应阻塞。

当 O_NONBLOCK 被设置时，部分写入没有例外。除了写入空管道或 FIFO 之外，本卷 POSIX.1-2024 未具体指定何时执行部分写入，因为那将需要指定实现的内部细节。每个应用程序都应准备好处理当 O_NONBLOCK 被设置且请求的量大于 {PIPE_BUF} 时的部分写入，正如每个应用程序都应准备好处理其他种类的文件描述符上的部分写入一样。

强制在可以写入任何字节时至少写入一个字节的意图是，确保如果管道或 FIFO 中有任何空间，每次写入都会取得进展。如果管道或 FIFO 为空，必须写入 {PIPE_BUF} 字节；如果不是，则至少必须取得一些进展。

在本卷 POSIX.1-2024 要求返回 -1 并将 errno 设为 [EAGAIN] 的地方，大多数历史实现返回零（在设置了 O_NDELAY 标志的情况下，O_NDELAY 是 O_NONBLOCK 的历史前身，但其本身不在本卷 POSIX.1-2024 中）。选择本卷 POSIX.1-2024 中的错误指示是为了使应用程序能够将这些情况与文件末尾区分开。虽然 write() 不能接收文件末尾的指示，但 read() 可以，并且这两个函数具有相似的返回值。此外，一些现有系统（例如 Eighth Edition）允许写入零字节表示读取者应得到文件末尾指示；对于这些系统，write() 返回零表示成功写入了一个文件末尾指示。

允许但并非要求实现为写入零字节的 write() 请求执行错误检查。

曾考虑过 {PIPE_MAX} 限制的概念（指示可以在一次操作中写入管道或 FIFO 的最大字节数），但被否决了，因为该概念将不必要地限制应用程序写入。

另请参见 read() 中关于 O_NONBLOCK 的讨论。

写入可以相对于其他读取和写入被串行化。如果可以（以任何方式）证明对文件数据的 read() 发生在对该数据的 write() 之后，它必须反映该 write()，即使这些调用由不同的线程进行。对同一文件位置的多个写操作也有类似的要求。这需要保证数据从 write() 调用传播到后续的 read() 调用。该要求对于网络文件系统特别重要，因为某些缓存方案违反这些语义。

注意，这是以 read() 和 write() 的术语来指定的。XSI 扩展 readv() 和 writev() 也遵守这些语义。一个不遵循这些串行化要求的新"高性能"写入类似物也将被此措辞所允许。本卷 POSIX.1-2024 对应用程序级缓存（如 stdio 所做的）的任何影响也保持沉默。

本卷 POSIX.1-2024 未指定返回错误后文件偏移的值；情况太多。[EBADF] 之类的编程错误，由于不涉及文件，该概念毫无意义。对于立即检测到的错误，如 [EAGAIN]，指针显然不应改变。然而，在中断或硬件错误之后，更新后的值将非常有用，并且是许多实现的行为。

本卷 POSIX.1-2024 未指定多个线程对普通文件的并发写入行为，除非每次写入是原子的（参见 2.9.7 线程与文件操作的交互 (Thread Interactions with File Operations)）。应用程序应使用某种形式的并发控制。

本卷 POSIX.1-2024 有意不指定除 [ESPIPE] 之外与管道、FIFO 和套接字相关的任何 pwrite() 错误。
