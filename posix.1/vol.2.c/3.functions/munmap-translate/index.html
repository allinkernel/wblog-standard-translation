XSH 函数：munmap()

名称 (NAME)

munmap — 解除内存页的映射

摘要 (SYNOPSIS)

#include <sys/mman.h>

int munmap(void *addr, size_t len);

说明 (DESCRIPTION)

munmap() 函数应移除从 addr 开始、长度为 len 字节的进程地址空间任何部分所在的那些整页上的任何映射。对这些页的进一步引用应导致向进程产生 SIGSEGV 信号。若指定地址范围内没有映射，则 munmap() 没有效果。

实现可以要求 addr 是 sysconf() 返回的页大小的倍数。

若要移除的映射是私有的，则应丢弃在此地址范围内所做的任何修改。

[ML|MLR] 与此地址范围相关联的任何内存锁（参见 mlock() 和 mlockall()）应被移除，如同通过适当的 munlock() 调用一样。

[TYM] 若从类型化内存对象移除的映射使内存池的相应地址范围除通过可分配映射（即，以 POSIX_TYPED_MEM_MAP_ALLOCATABLE 标志打开的类型化内存对象的映射）外，系统内任何进程都无法访问，则该内存池范围应被释放，并且可以变得可用于满足未来的类型化内存分配请求。

从以 POSIX_TYPED_MEM_MAP_ALLOCATABLE 标志打开的类型化内存对象移除的映射不应以任何方式影响该类型化内存可供分配。

若该映射不是通过调用 mmap() 建立的，则此函数的行为未指定。

返回值 (RETURN VALUE)

成功完成时，munmap() 应返回 0；否则，它应返回 -1 并设置 errno 以指示错误。

错误 (ERRORS)

munmap() 函数在以下情况下应失败：

[EINVAL]
范围 [addr,addr+len) 内的地址超出进程地址空间的有效范围。
[EINVAL]
len 参数为 0。

munmap() 函数在以下情况下可以失败：

[EINVAL]
addr 参数不是 sysconf() 返回的页大小的倍数。
The following sections are informative.

示例 (EXAMPLES)

无。

应用程序使用 (APPLICATION USAGE)

无。

原理 (RATIONALE)

munmap() 函数与 SVR4 对应，正如 mmap() 函数一样。

应用程序可能已对包含共享内存的区域应用了进程内存锁定。若发生这种情况，munmap() 调用会忽略这些锁，并在必要时使这些锁被移除。

大多数实现要求 addr 是 sysconf() 返回的页大小的倍数。

更改历史 (CHANGE HISTORY)

首次发布于第 4 版第 2 修订版。

第 5 版 (Issue 5)

从 X/OPEN UNIX 扩展移至 BASE。

与 POSIX 实时扩展中的 munmap() 对齐，如下所示：

  • DESCRIPTION 被广泛改写。

  • 不再允许产生 SIGBUS 错误。

第 6 版 (Issue 6)

munmap() 函数被标记为内存映射文件和共享内存对象（Memory Mapped Files and Shared Memory Objects）选项的一部分。

以下对 POSIX 实现的新要求源自与单一 UNIX 规范（Single UNIX Specification）的对齐：

  • 更新了 DESCRIPTION，说明实现要求 addr 是页大小的倍数。

  • 增加了 [EINVAL] 错误条件。

为与 IEEE Std 1003.1j-2000 对齐而进行了以下更改：

  • 在 DESCRIPTION 中增加了类型化内存对象的语义。

  • 在 SEE ALSO 部分中增加了 posix_typed_mem_open() 函数。

应用了 IEEE Std 1003.1-2001/Cor 1-2002 的条目 XSH/TC1/D6/36，将 SYNOPSIS 中的边缘代码从 MF|SHM 改为 MC3（表示 MF|SHM|TYM 的记号）。

第 7 版 (Issue 7)

应用了 Austin Group 解释 1003.1-2001 #078，澄清了页对齐要求。

munmap() 函数从内存映射文件选项移至 Base。
