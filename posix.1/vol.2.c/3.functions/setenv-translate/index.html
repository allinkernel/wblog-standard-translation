XSH 函数：setenv()

名称 (NAME)

setenv — 添加或更改环境变量

提要 (SYNOPSIS)

[CX] #include <stdlib.h>

int setenv(const char *envname, const char *envval, int overwrite);

说明 (DESCRIPTION)

setenv() 函数应更新或添加调用进程环境中的一个变量。envname 参数指向一个包含要添加或更改的环境变量名称的字符串。环境变量应被设置为 envval 所指向的值。如果 envname 指向的字符串包含 '=' 字符，则函数应失败。如果 envname 命名的环境变量已存在且 overwrite 的值为非零，则函数应返回成功并且环境应被更新。如果 envname 命名的环境变量已存在且 overwrite 的值为零，则函数应返回成功并且环境应保持不变。

setenv() 函数应更新 environ 所指向的指针列表。

由 envname 和 envval 描述的字符串由本函数复制。

setenv() 函数不必是线程安全的。

返回值 (RETURN VALUE)

成功完成后，应返回零。否则，应返回 -1，设置 errno 以指示错误，并且环境应保持不变。

错误 (ERRORS)

在以下情况下，setenv() 函数应失败：

[EINVAL]
envname 参数指向一个空字符串，或指向一个包含 '=' 字符的字符串。
[ENOMEM]
没有足够的内存可用于将变量或其值添加到环境中。

示例 (EXAMPLES)

无。

应用程序使用 (APPLICATION USAGE)

参见 exec() 了解多线程应用程序中更改环境的限制。

原理 (RATIONALE)

如果 setenv() 更改外部变量 environ，可能会出现未预料的结果。特别是，如果 main() 的可选 envp 参数存在，它不会被更改，因此可能指向环境的过时副本（environ 的任何其他副本也是如此）。然而，除了上述限制之外，标准开发者意图必须支持通过 environ 指针遍历环境的传统方法。

人们决定本版本宜要求 setenv()，因为它解决了一项缺失的功能，并且不会给实现者带来重大负担。

关于是要求 System V putenv() 函数还是 BSD setenv() 函数作为强制性函数，存在相当大的争论。选择 setenv() 函数是因为它允许 unsetenv() 函数的实现删除环境变量，而无需指定额外的接口。putenv() 函数作为 XSI 选项的一部分可用。

标准开发者曾考虑要求 setenv() 在对其调用会导致超过 {ARG_MAX} 时指示错误。该要求被否决，因为该条件可能是暂时的，应用程序最终会减小环境的大小。最终的成败取决于调用 exec 时的大小，exec 会返回此错误条件的指示。

另请参见 getenv() 中的 RATIONALE 节。
