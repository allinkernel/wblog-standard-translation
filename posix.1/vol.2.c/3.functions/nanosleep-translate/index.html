XSH 函数：nanosleep()

名称 (NAME)

nanosleep — 高分辨率睡眠

概要 (SYNOPSIS)

[CX] #include <time.h>

int nanosleep(const struct timespec *rqtp, struct timespec *rmtp);

说明 (DESCRIPTION)

nanosleep() 函数应使当前线程挂起执行，直到 rqtp 参数指定的时间间隔经过，或直到信号被传递给调用线程且其动作是调用信号捕获函数或终止进程。挂起时间可能比请求的时间长，因为参数值被向上舍入到睡眠分辨率的整数倍，或因为系统调度其他活动。但是，除了被信号中断的情况外，挂起时间不应少于 rqtp 指定的时间，如系统时钟 CLOCK_REALTIME 所测量。

使用 nanosleep() 函数对任何信号的动作或阻塞没有影响。

返回值 (RETURN VALUE)

如果 nanosleep() 函数因请求的时间已过而返回，则其返回值应为零。

如果 nanosleep() 函数因被信号中断而返回，则它应返回 -1 并设置 errno 以指示中断。如果 rmtp 参数非 NULL，则更新它所引用的 timespec 结构以包含间隔中剩余的时间量（请求的时间减去实际睡眠的时间）。rqtp 和 rmtp 参数可以指向同一个对象。如果 rmtp 参数为 NULL，则不返回剩余时间。

如果 nanosleep() 失败，则它应返回 -1 并设置 errno 以指示错误。

错误 (ERRORS)

在以下情况下，nanosleep() 函数应失败：

[EINTR]
nanosleep() 函数被信号中断。
[EINVAL]
rqtp 参数指定的纳秒值小于零或大于或等于 1000 百万。

原理说明 (RATIONALE)

为了轮询不可中断函数的状态，挂起线程执行一段时间间隔是很常见的。通过为 sleep() 提供更精细分辨率的简单扩展，可以满足大量实际需求。

在 POSIX.1-1990 标准和 SVR4 中，可以实现这样的例程，但唤醒频率受 alarm() 和 sleep() 函数分辨率的限制。在 4.3 BSD 中，可以编写不使用静态存储且不保留任何系统设施的此类例程。虽然可以使用其余的 timer_*() 函数编写具有与 sleep() 类似功能的函数，但这样的函数需要使用信号并保留某个信号编号。本卷 POSIX.1-2024 要求 nanosleep() 不干扰信号功能。

nanosleep() 函数应在成功时返回 0，在失败或被中断时返回 -1。后一种情况与 sleep() 不同。这样做是因为剩余时间通过参数结构指针 rmtp 返回，而不是作为返回值。
