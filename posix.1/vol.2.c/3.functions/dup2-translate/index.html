XSH 函数：dup2()

名称 (NAME)

dup、dup2、dup3 — 复制一个打开的文件描述符 (duplicate an open file descriptor)

摘要 (SYNOPSIS)

#include <unistd.h>

int dup(int fildes);
int dup2(int fildes, int fildes2);
int dup3(int fildes, int fildes2, int flag);

说明 (DESCRIPTION)

dup() 函数为 fcntl() 使用 F_DUPFD 命令提供的服务提供了一种替代接口。调用 dup(fildes) 应等同于：

fcntl(fildes, F_DUPFD, 0);

dup2() 函数应使文件描述符 fildes2 指向与文件描述符 fildes 相同的打开文件描述并共享任何锁，并应返回 fildes2。如果 fildes2 已经是一个有效的打开文件描述符，则应首先将其关闭，除非 fildes 等于 fildes2，在这种情况下 dup2() 应返回 fildes2 而不关闭它。如果关闭操作未能关闭 fildes2，dup2() 应返回 -1，而不改变 fildes2 所指向的打开文件描述。如果 fildes 不是有效的文件描述符，dup2() 应返回 -1 且不应关闭 fildes2。如果 fildes2 小于 0 或大于或等于 {OPEN_MAX}，dup2() 应返回 -1 并将 errno 设置为 [EBADF]。

成功完成后，如果 fildes 不等于 fildes2，则与 fildes2 关联的 FD_CLOEXEC 和 FD_CLOFORK 标志应被清除。如果 fildes 等于 fildes2，则与 fildes2 关联的 FD_CLOEXEC 和 FD_CLOFORK 标志不应被更改。

dup3() 函数应等同于 dup2() 函数，不同之处在于，如果 fildes 等于 fildes2 则应是一个错误，且 fildes2 文件描述符上 FD_CLOEXEC 和 FD_CLOFORK 的状态应完全由 flag 参数决定，该参数可以由以下列表中的标志按位包含式 OR 构成：

O_CLOEXEC
在 fildes2 上原子地设置 FD_CLOEXEC 标志。
O_CLOFORK
在 fildes2 上原子地设置 FD_CLOFORK 标志。

[TYM] 如果 fildes 指代一个类型化内存对象，则 dup2() 或 dup3() 函数的结果是未指定的。

返回值 (RETURN VALUE)

成功完成后，应返回一个非负整数，即文件描述符；否则，应返回 -1 并设置 errno 以指示错误。

错误 (ERRORS)

如果满足以下条件，dup() 函数应失败：

[EBADF]
fildes 参数不是有效的打开文件描述符。
[EMFILE]
进程可用的所有文件描述符当前都已打开。

如果满足以下条件，dup2() 和 dup3() 函数应失败：

[EBADF]
fildes 参数不是有效的打开文件描述符，或者参数 fildes2 为负或大于或等于 {OPEN_MAX}。
[EINTR]
函数被信号中断。

如果满足以下条件，dup3() 函数应失败：

[EINVAL]
fildes 和 fildes2 参数相等。

如果满足以下条件，dup2() 和 dup3() 函数可以失败：

[EIO]
在尝试关闭 fildes2 时发生了 I/O 错误。

如果满足以下条件，dup3() 函数可以失败：

[EINVAL]
flag 参数的值无效。

示例 (EXAMPLES)

将标准输出重定向到文件 (Redirecting Standard Output to a File)

以下示例关闭当前进程的标准输出，将标准输出重新分配为指向 pfd 引用的文件，并关闭原始文件描述符以进行清理。

#include <unistd.h>
...
int pfd;
...
close(1);
dup(pfd);
close(pfd);
...
重定向错误消息 (Redirecting Error Messages)

以下示例将消息从 stderr 重定向到 stdout。

#include <unistd.h>
...
dup2(1, 2);
...

应用程序用法 (APPLICATION USAGE)

实现可以使用必须被继承到子进程中的文件描述符，以使子进程保持符合性，例如用于消息目录或跟踪目的。因此，使用任意整数作为 fildes2 调用 dup2() 的应用程序有产生不符合行为的风险，dup2() 只能可移植地用于覆盖应用程序通过显式操作获得的文件描述符值，或用于与标准文件流对应的三个文件描述符。为了避免将意外文件描述符泄漏到子进程或已执行程序中的竞争条件，应用程序宜考虑在打开所有文件描述符时设置 FD_CLOFORK 或 FD_CLOEXEC 标志，或同时设置两个标志，除非该文件描述符分别打算被子进程或已执行程序继承。

理由 (RATIONALE)

dup() 函数是多余的。它的服务也由 fcntl() 函数提供。它被包含在本卷 POSIX.1-2024 中主要是出于历史原因，因为许多现有应用程序使用它。另一方面，dup2() 函数提供了独特的服务，因为没有其他接口能够原子地替换现有的文件描述符。

dup2() 函数没有被标记为过时，因为它提供了由 fcntl() 以类型不安全版本提供的功能的类型安全版本。它被用于 POSIX Ada 绑定。

dup2() 函数不打算在临界区中用作同步机制。

在 [EBADF] 的描述中，fildes 超出范围的情况已由 fildes 无效的给定情况涵盖。fildes 和 fildes2 的描述不同，因为与 fildes2 相关的无效性只有一种，即它是否超出范围；也就是说，在进行 dup2() 调用时 fildes2 是否指向打开的文件并不重要。

带 O_CLOEXEC 和 O_CLOFORK 标志的 dup3() 函数对于避免多线程应用程序中的数据竞争是必要的。如果没有 O_CLOFORK，在一个线程用 dup2() 创建文件描述符然后使用 fcntl() 设置 FD_CLOFORK 标志之间的窗口期内，文件描述符会泄漏到另一个线程创建的子进程中。如果没有 O_CLOEXEC，如果 FD_CLOEXEC 没有被原子地设置，被子进程有意继承的文件描述符会同样泄漏到已执行的程序中。在使用 dup() 时避免相同竞争的对应安全做法是使用 fcntl() 函数的 F_DUPFD_CLOFORK 或 F_DUPFD_CLOEXEC 动作。
