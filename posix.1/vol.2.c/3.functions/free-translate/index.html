XSH 函数：free()

名称 (NAME)

free — 释放已分配的内存

摘要 (SYNOPSIS)

#include <stdlib.h>

void free(void *ptr);

说明 (DESCRIPTION)

[CX] The functionality described on this reference page is aligned with the ISO C standard. Any conflict between the requirements described here and the ISO C standard is unintentional. This volume of POSIX.1-2024 defers to the ISO C standard.

free() 函数应使 ptr 所指向的空间被释放；即，使其可供进一步分配。若 ptr 是空指针，则不应发生任何操作。否则，若该参数与先前由 aligned_alloc()、calloc()、malloc()、 [ADV] posix_memalign()、 realloc()、 [CX] reallocarray() 或 POSIX.1-2024 中按 malloc() 的方式分配内存的函数返回的指针不匹配， 或者该空间已通过调用 free()、[CX] reallocarray()、 或 realloc() 被释放，则行为未定义。

对指向已释放空间的指针的任何使用都会导致未定义行为。

[CX] 若 ptr 是空指针，或是先前按 malloc() 的方式返回且尚未被释放的指针，则 free() 函数不应修改 errno。

为确定数据竞争是否存在，free() 应表现得如同只访问了通过其参数可访问的内存位置，而不访问其他静态存储期存储。但该函数可以明显地修改其释放的存储。分配或释放特定内存区域的 aligned_alloc()、calloc()、free()、malloc()、[ADV] posix_memalign()、 [CX] reallocarray()、 以及 realloc() 调用应按单一全序发生（参见 XBD 4.15.1 内存排序），并且每次此类释放调用应与此顺序中的下一次分配（若有）同步。

返回值 (RETURN VALUE)

free() 函数不应返回值。

错误 (ERRORS)

未定义错误。

The following sections are informative.

示例 (EXAMPLES)

无。

应用程序使用 (APPLICATION USAGE)

现在不再要求实现支持包含 <malloc.h>。

由于 free() 函数对有效指针不修改 errno，因此在清理代码中使用它是安全的，不会破坏先前的错误，例如在以下示例代码中：

// buf was obtained by malloc(buflen)
    ret = write(fd, buf, buflen);
    if (ret < 0) {
        free(buf);
        return ret;
    }

但是，本标准的早期版本不要求这样做，并且同一示例必须写成：

// buf was obtained by malloc(buflen)
    ret = write(fd, buf, buflen);
    if (ret < 0) {
        int save = errno;
        free(buf);
        errno = save;
        return ret;
    }

更改历史 (CHANGE HISTORY)

首次发布于第 1 版。源自 SVID 第 1 版。

第 6 版 (Issue 6)

删除了对 valloc() 函数的引用。

第 7 版 (Issue 7)

更新了 DESCRIPTION，以澄清如果返回的指针不是由按 malloc() 的方式分配内存的函数返回的，则行为未定义。

第 8 版 (Issue 8)

应用了 Austin Group 缺陷 385，增加了一项要求：当传入指向可释放对象的指针时，free() 不修改 errno。

应用了 Austin Group 缺陷 1218，增加了 reallocarray()。

应用了 Austin Group 缺陷 1302，使此函数与 ISO/IEC 9899:2018 标准对齐。
