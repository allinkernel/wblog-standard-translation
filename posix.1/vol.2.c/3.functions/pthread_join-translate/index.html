XSH 函数：pthread_join()

名称 (NAME)

pthread_join — 等待线程终止 (wait for thread termination)

简介 (SYNOPSIS)

#include <pthread.h>

int pthread_join(pthread_t thread, void **value_ptr);

描述 (DESCRIPTION)

pthread_join() 函数应挂起调用线程的执行，直到目标 thread 终止，除非目标 thread 已经终止。从一次成功的、带有非 NULL value_ptr 参数的 pthread_join() 调用返回时，终止线程传递给 pthread_exit() 的值应在 value_ptr 所引用的位置中可用。当 pthread_join() 成功返回时，目标线程已终止。对指定同一目标线程的 pthread_join() 的多次同时调用的结果未定义。如果调用 pthread_join() 的线程被取消，则目标线程不应被分离。

僵尸线程是否计入 {PTHREAD_THREADS_MAX} 未指定。

如果 pthread_join() 的 thread 参数所指定的值未指向可汇合的（joinable）线程，则行为未定义。

如果 pthread_join() 的 thread 参数所指定的值指向调用线程，则行为未定义。

如果 thread 指向一个使用 thrd_create() 创建、并且通过从其启动例程返回而终止或已经终止的线程，则 pthread_join() 的行为未定义。如果 thread 指向一个通过调用 thrd_exit() 终止或已经终止的线程，则 pthread_join() 的行为未定义。

返回值 (RETURN VALUE)

如果成功，pthread_join() 函数应返回零；否则，应返回错误号以指示错误。

错误 (ERRORS)

pthread_join() 函数在以下情况下可以失败：

[EDEADLK]
检测到死锁。

pthread_join() 函数不应返回 [EINTR] 错误码。

The following sections are informative.

示例 (EXAMPLES)

以下是线程创建和删除的示例：

typedef struct {
    int *ar;
    long n;
} subarray;
 
void *
incer(void *arg)
{
    long i;
 
    for (i = 0; i < ((subarray *)arg)->n; i++)
        ((subarray *)arg)->ar[i]++;
}
 
int main(void)
{
    int        ar[1000000];
    pthread_t  th1, th2;
    subarray   sb1, sb2;
 
    sb1.ar = &ar[0];
    sb1.n  = 500000;
    (void) pthread_create(&th1, NULL, incer, &sb1);
 
    sb2.ar = &ar[500000];
    sb2.n  = 500000;
    (void) pthread_create(&th2, NULL, incer, &sb2);
 
    (void) pthread_join(th1, NULL);
    (void) pthread_join(th2, NULL);
    return 0;
}

应用用法 (APPLICATION USAGE)

无。

理由 (RATIONALE)

pthread_join() 函数是一种已被证明在多线程应用程序中有用的便利设施。诚然，如果未提供此函数，程序员可以通过将额外状态作为 start_routine() 参数的一部分传入来模拟它。终止线程将设置一个标志以指示终止，并广播一个作为该状态一部分的条件；进行汇合的线程将等待该条件变量。虽然这种技术允许线程等待更复杂的条件（例如，等待多个线程终止），但等待单个线程终止被认为具有广泛的用途。此外，包含 pthread_join() 函数丝毫不会妨碍程序员编写此类复杂的等待。因此，尽管它不是原语，但将 pthread_join() 纳入本卷 POSIX.1-2024 被认为是有价值的。

pthread_join() 函数提供了一种简单机制，允许应用程序等待线程终止。在线程终止后，应用程序可以选择清理该线程所使用的资源。例如，在 pthread_join() 返回后，任何由应用程序提供的栈存储都可以被回收。

对于每个以 detachstate 属性设置为 PTHREAD_CREATE_JOINABLE 创建的线程，最终都应调用 pthread_join() 或 pthread_detach() 函数，以便可以回收与该线程关联的存储。

由于以下原因，pthread_join() 与取消之间的交互是良好定义的：

  • 与所有其他非 async-cancel-safe 函数一样，pthread_join() 函数只能在延迟可取消类型下调用。

  • 在禁用可取消状态下不能发生取消。

因此，只需考虑默认可取消状态。如规定所述，pthread_join() 调用要么被取消，要么成功，但不会两者兼有。区别对应用程序是显而易见的，因为要么运行取消处理程序，要么 pthread_join() 返回。由于 pthread_join() 是在延迟可取消状态下调用的，因此不存在竞争条件。

如果实现检测到 pthread_join() 的 thread 参数所指定的值未指向可汇合的线程，则建议该函数应失败并报告 [EINVAL] 错误。

如果实现检测到 pthread_join() 的 thread 参数所指定的值指向调用线程，则建议该函数应失败并报告 [EDEADLK] 错误。

如果实现检测到在线程 ID 的生命周期结束后使用它，则建议该函数应失败并报告 [ESRCH] 错误。

pthread_join() 函数不能用于获取使用 thrd_create() 创建并通过从其启动例程返回而终止的线程的退出状态，也不能用于获取通过调用 thrd_exit() 终止的线程的退出状态，因为此类线程具有 int 退出状态，而不是 pthread_join() 通过其 value_ptr 参数返回的 void *。

变更历史 (CHANGE HISTORY)

首次在 Issue 5 中发布。为与 POSIX 线程扩展保持一致而纳入。

第 6 版 (Issue 6)

pthread_join() 函数被标记为 Threads 选项的一部分。

应用了 IEEE Std 1003.1-2001/Cor 2-2004 的条目 XSH/TC2/D6/97，更新了 ERRORS 部分，使 [EINVAL] 错误变为可选，并从中删除了 "the implementation has detected" 字样。

第 7 版 (Issue 7)

pthread_join() 函数从 Threads 选项移至 Base。

应用了 Austin Group Interpretation 1003.1-2001 #142，移除了 [ESRCH] 错误条件。

删除了针对非可汇合线程的 [EINVAL] 错误；此情况导致未定义行为。

删除了针对调用线程的 [EDEADLK] 错误；此情况导致未定义行为。

第 8 版 (Issue 8)

应用了 Austin Group Defect 792，将 "已退出但仍未被汇合的线程" 改为 "僵尸线程"。

应用了 Austin Group Defect 1302，更新了本页以说明 <threads.h> 接口的增加。
