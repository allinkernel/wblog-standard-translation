XSH 函数：pthread_key_create()

名称 (NAME)

pthread_key_create — 线程特定数据键创建 (thread-specific data key creation)

简介 (SYNOPSIS)

#include <pthread.h>

int pthread_key_create(pthread_key_t *key, void (*destructor)(void*));

描述 (DESCRIPTION)

pthread_key_create() 函数应创建一个对进程中所有线程可见的线程特定数据键。由 pthread_key_create() 提供的键值是不透明对象，用于定位线程特定数据。虽然不同的线程可以使用相同的键值，但由 pthread_setspecific() 绑定到键上的值是按线程维护的，并在调用线程的整个生命周期内持续存在。

在创建键时，值 NULL 应与所有活动线程中的新键相关联。在创建线程时，值 NULL 应与新线程中所有已定义的键相关联。

每个键值可以关联一个可选的析构函数。在线程退出时，如果某个键值具有非 NULL 的析构函数指针，并且该线程具有与该键关联的非 NULL 值，则将该键的值设置为 NULL，然后以先前关联的值作为其唯一参数调用所指向的函数。如果线程退出时存在多个析构函数，则析构函数的调用顺序未指定。

如果在为所有具有关联析构函数的非 NULL 值调用完所有析构函数之后，仍然存在一些具有关联析构函数的非 NULL 值，则重复该过程。如果在针对未处理的非 NULL 值进行了至少 {PTHREAD_DESTRUCTOR_ITERATIONS} 次析构函数调用迭代之后，仍然存在一些具有关联析构函数的非 NULL 值，实现可以停止调用析构函数，也可以继续调用析构函数，直到不存在具有关联析构函数的非 NULL 值，即使这可能导致无限循环。

返回值 (RETURN VALUE)

如果成功，pthread_key_create() 函数应将新创建的键值存储到 *key，并应返回零。否则，应返回错误号以指示错误。

错误 (ERRORS)

pthread_key_create() 函数在以下情况下应失败：

[EAGAIN]
系统缺少创建另一个线程特定数据键所需的资源，或者已超过系统对每个进程键总数 {PTHREAD_KEYS_MAX} 施加的限制。
[ENOMEM]
没有足够的内存来创建该键。

pthread_key_create() 函数不应返回 [EINTR] 错误码。

The following sections are informative.

示例 (EXAMPLES)

以下示例演示了一个函数，该函数在第一次被调用时初始化线程特定数据键，并将线程特定对象与每个调用线程相关联，在必要时初始化该对象。

static pthread_key_t key;
static pthread_once_t key_once = PTHREAD_ONCE_INIT;
 
static void
make_key()
{
    (void) pthread_key_create(&key, NULL);
}
 
func()
{
    void *ptr;
 
    (void) pthread_once(&key_once, make_key);
    if ((ptr = pthread_getspecific(key)) == NULL) {
        ptr = malloc(OBJECT_SIZE);
        ...
        (void) pthread_setspecific(key, ptr);
    }
    ...
}

注意，必须先初始化该键，然后才能使用 pthread_getspecific() 或 pthread_setspecific()。对 pthread_key_create() 的调用可以显式地在模块初始化例程中进行，也可以像本示例中那样由对模块的第一次调用隐式完成。在键初始化之前使用该键的任何尝试都是编程错误，这使得下面的代码不正确。

static pthread_key_t key;
 
func()
{
    void *ptr;
 
   /* KEY NOT INITIALIZED!!!  THIS WILL NOT WORK!!! */
    if ((ptr = pthread_getspecific(key)) == NULL &&
        pthread_setspecific(key, NULL) != 0) {
        pthread_key_create(&key, NULL);
        ...
    }
}

应用用法 (APPLICATION USAGE)

无。

理由 (RATIONALE)

析构函数 (Destructor Functions)

通常，代表特定线程绑定到键上的值是指向代表调用线程动态分配的存储的指针。使用 pthread_key_create() 指定的析构函数旨在在线程退出时释放此存储。线程取消清理处理程序不能用于此目的，因为线程特定数据可能在取消清理处理程序操作的词法作用域之外持续存在。

如果在线程的生命周期内需要更新与键关联的值，则可能需要在绑定新值之前释放与旧值关联的存储。虽然 pthread_setspecific() 函数可以自动完成此操作，但该特性的需求频率不足以证明增加的复杂性是合理的。相反，程序员负责释放过时的存储：

old = pthread_getspecific(key);
new = allocate();
destructor(old);
pthread_setspecific(key, new);
注：
如果启用异步取消运行，上述示例可能会泄漏存储。如果在 get 与 set 之间没有取消点，则在默认取消状态下不会出现此类问题。

不存在析构函数安全（destructor-safe）函数的概念。如果应用程序不从信号处理程序中调用 pthread_exit()，或者它在调用 async-unsafe 函数时阻塞了任何其处理程序可能调用 pthread_exit() 的信号，则所有函数都可以安全地从析构函数中调用。

非幂等数据键创建 (Non-Idempotent Data Key Creation)

曾有人要求使 pthread_key_create() 相对于给定的 key 地址参数具有幂等性。这将允许应用程序针对给定的 key 地址多次调用 pthread_key_create()，并保证只会创建一个键。这样做将要求键值预先初始化（可能是在编译时）为已知的空值，并要求基于 key 参数的地址和内容执行隐式互斥，以保证恰好创建一个键。

遗憾的是，隐式互斥不会仅限于 pthread_key_create()。在许多实现上，pthread_getspecific() 和 pthread_setspecific() 也必须执行隐式互斥，以防止使用未完整存储或尚不可见的键值。这可能会显著增加重要操作的成本，尤其是 pthread_getspecific()。

因此，这一提议被否决。pthread_key_create() 函数不执行任何隐式同步。确保在使用键之前每个键恰好被调用一次是程序员的责任。已经可以使用几种直接的机制来实现这一点，包括调用显式的模块初始化函数、使用互斥量以及使用 pthread_once()。这不会给程序员带来显著负担，不会引入可能令人困惑的 ad hoc 隐式同步机制，并且可能使常用的线程特定数据操作更高效。
