XSH 函数导读：fwrite()

0. 总览

fwrite() 做二进制输出：从 ptr 指向的数组中，将至多 nitems 个大小为 size 字节的元素写入流。头文件为 <stdio.h>。原型关键点：size_t fwrite(const void *restrict ptr, size_t size, size_t nitems, FILE *restrict stream)——返回成功写入的元素数，只有遇到写入错误时才小于 nitems。

1. 机制

规范把写入描述为“对每个对象调用 fputc() 函数 size 次”，从恰好覆盖该对象的 unsigned char 数组中按顺序取值；流的文件位置指示符按成功写入的字节数前进，出错时其值未指定。若 size 或 nitems 为 0，则返回 0 且流的状态保持不变；否则发生写入错误时设置流的错误指示符并设置 errno。POSIX 还要求：文件的上次数据修改和上次文件状态更改时间戳应在 fwrite() 成功执行与下一次 fflush()/fclose() 成功完成、或调用 exit()/abort() 之间被标记更新。

2. 易错点

  • 返回值是元素数而非字节数：fwrite(buf, 100, 2, fp) 返回 2 表示两个 100 字节元素全部写入，返回 1 表示只写成一个；按字节写应写成 fwrite(buf, 1, n, fp)，这样返回值直接等于字节数。
  • 返回 0 不一定是“什么都没写”，规范对部分写入的错误场景不保证位置指示符，数据状态可能不可靠。
  • 写满缓冲前数据不一定落盘：时间戳在 fflush()/fclose() 前未必更新，且真正写盘要靠 fflush() 或 fclose()——程序崩溃可能丢失缓冲中的数据。
  • 与 fread() 对称的移植性问题：元素长度与字节顺序（大小端）因机器而异，fwrite() 产生的文件是应用程序相关的，跨平台/跨程序读取可能失败。
  • 写入错误后流被标记错误，继续写入通常不再有效，应先处理 ferror()/errno。

3. 示例

#include <stdio.h>

int main(void)
{
    FILE *fp = fopen("data.bin", "wb");
    char buf[100] = "payload";
    size_t n;

    if (fp == NULL) {
        perror("fopen");
        return 1;
    }
    n = fwrite(buf, 1, sizeof(buf), fp); /* 按字节写，返回值即字节数 */
    if (n != sizeof(buf)) {
        perror("fwrite");
        fclose(fp);
        return 1;
    }
    if (fclose(fp) == EOF) {             /* 把缓冲真正落盘并检查 */
        perror("fclose");
        return 1;
    }
    return 0;
}
