XSH 函数：pread()

名称

pread, read — 从文件读取

概要

#include <unistd.h>

ssize_t pread(int fildes, void *buf, size_t nbyte, off_t offset);
ssize_t read(int fildes, void *buf, size_t nbyte);

说明

read() 函数应尝试从与打开文件描述符 fildes 关联的文件中读取 nbyte 字节到由 buf 指向的缓冲区中。在同一管道、FIFO 或终端设备上多次并发读取的行为是未指定的。

在采取下面描述的任何动作之前，并且如果 nbyte 为零，read() 函数可以按如下所述检测并返回错误。在没有错误的情况下，或者如果未执行错误检测，read() 函数应返回零且没有其他结果。

在支持寻址（seeking）的文件（例如普通文件）上，read() 应从由与 fildes 关联的文件偏移给定的文件位置开始。文件偏移应按实际读取的字节数递增。

不支持寻址的文件——例如终端——总是从当前位置读取。与这种文件关联的文件偏移的值是未定义的。

不应发生越过当前文件末尾的数据传输。如果起始位置在文件末尾处或之后，应返回 0。如果该文件引用设备特殊文件，后续 read() 请求的结果是实现定义的。

如果 nbyte 的值大于 {SSIZE_MAX}，结果为实现定义的。

当尝试从空管道或 FIFO 读取时：

  • 如果没有进程将管道打开用于写入，read() 应返回 0 以表示文件末尾。

  • 如果某个进程将管道打开用于写入且设置了 O_NONBLOCK，read() 应返回 -1 并将 errno 设为 [EAGAIN]。

  • 如果某个进程将管道打开用于写入且 O_NONBLOCK 清除，read() 应阻塞调用线程，直到写入了一些数据或所有将管道打开用于写入的进程都关闭了管道。

当尝试读取一个支持非阻塞读取且当前没有可用数据的文件（管道或 FIFO 除外）时：

  • 如果设置了 O_NONBLOCK，read() 应返回 -1 并将 errno 设为 [EAGAIN]。

  • 如果 O_NONBLOCK 清除，read() 应阻塞调用线程，直到一些数据变为可用。

  • 如果有一些数据可用，使用 O_NONBLOCK 标志没有效果。

read() 函数读取先前写入文件的数据。如果普通文件中文件末尾之前的任何部分尚未被写入，read() 应返回值为 0 的字节。例如，lseek() 允许文件偏移被设置到文件中现有数据的末尾之外。如果稍后在此位置写入数据，那么在数据被写入间隙之前，先前数据末尾与新写入数据之间的间隙中的后续读取应返回值为 0 的字节。

成功完成时，当 nbyte 大于 0，read() 应将文件的最后数据访问时间戳标记为更新，并应返回读取的字节数。此数字绝不应大于 nbyte。如果文件中剩余的字节数小于 nbyte，如果 read() 请求被信号中断，或者如果该文件是管道、FIFO 或特殊文件且立即可用于读取的字节少于 nbyte，则返回的值可以小于 nbyte。例如，从与终端关联的文件进行 read() 可以返回一行键入的数据。

如果 read() 在读取任何数据之前被信号中断，它应返回 -1 且 errno 设为 [EINTR]。

如果 read() 在成功读取了一些数据之后被信号中断，它应返回读取的字节数。

对于普通文件，不应发生越过与 fildes 关联的打开文件描述中建立的偏移最大值的数据传输。

如果 fildes 引用套接字，read() 应等同于未设置标志的 recv()。

[SIO] 如果已设置 O_DSYNC 和 O_RSYNC 位，文件描述符上的读 I/O 操作应按照同步 I/O 数据完整性完成所定义的方式完成。如果已设置 O_SYNC 和 O_RSYNC 位，文件描述符上的读 I/O 操作应按照同步 I/O 文件完整性完成所定义的方式完成。

[SHM] 如果 fildes 引用共享内存对象，read() 函数的结果是未指定的。

[TYM] 如果 fildes 引用类型化内存对象，read() 函数的结果是未指定的。

pread() 函数应等同于 read()，不同之处在于它应从文件中给定的位置读取而不更改文件偏移。pread() 的前三个参数与 read() 相同，另外增加了第四个参数 offset，用于指定文件内的期望位置。尝试在无法寻址的文件上执行 pread() 应导致错误。

返回值

成功完成时，这些函数应返回一个非负整数，指示实际读取的字节数。否则，这些函数应返回 -1 并将 errno 设为指示错误。

错误

如果以下情况，这些函数应失败：

[EAGAIN]
该文件既不是管道，也不是 FIFO，也不是套接字，为该文件描述符设置了 O_NONBLOCK 标志，并且该线程将在读操作中被延迟。
[EBADF]
fildes 参数不是打开用于读取的有效文件描述符。
[EINTR]
读操作因收到信号而终止，且未传输任何数据。
[EIO]
该进程是尝试从其控制终端读取的后台进程组的成员，并且要么调用线程正在阻塞 SIGTTIN，要么该进程正在忽略 SIGTTIN，要么该进程的进程组是孤立的。此错误也可以因实现定义的原因而产生。
[EISDIR]
[XSI] fildes 参数引用目录，且实现不允许使用 read() 或 pread() 读取该目录。应改用 readdir() 函数。
[EOVERFLOW]
该文件是普通文件，nbyte 大于 0，起始位置在文件末尾之前，且起始位置大于或等于与 fildes 关联的打开文件描述中建立的偏移最大值。

如果以下情况，pread() 函数应失败：

[EINVAL]
该文件是普通文件或块特殊文件，且 offset 参数为负值。文件偏移应保持不变。
[ESPIPE]
该文件无法寻址。

如果以下情况，read() 函数应失败：

[EAGAIN]
该文件是管道或 FIFO，为该文件描述符设置了 O_NONBLOCK 标志，并且该线程将在读操作中被延迟。
[EAGAIN] 或 [EWOULDBLOCK]
该文件是套接字，为该文件描述符设置了 O_NONBLOCK 标志，并且该线程将在读操作中被延迟。
[ECONNRESET]
对套接字尝试了读取，且连接被其对端强制关闭。
[ENOTCONN]
对未连接的套接字尝试了读取。
[ETIMEDOUT]
对套接字尝试了读取，且发生了传输超时。

如果以下情况，这些函数可以失败：

[EIO]
发生了物理 I/O 错误。
[ENOBUFS]
系统中可用于执行该操作的资源不足。
[ENOMEM]
可用于满足该请求的内存不足。
[ENXIO]
对不存在的设备提出了请求，或者该请求超出了设备的能力范围。

示例

将数据读入缓冲区 (Reading Data into a Buffer)

下面的示例从与文件描述符 fd 关联的文件中读取数据到由 buf 指向的缓冲区。

#include <sys/types.h>
#include <unistd.h>
...
char buf[20];
size_t nbytes;
ssize_t bytes_read;
int fd;
...
nbytes = sizeof(buf);
bytes_read = read(fd, buf, nbytes);
...

应用程序用法 (APPLICATION USAGE)

无。

理由 (RATIONALE)

本卷 POSIX.1-2024 未指定返回错误后文件偏移的值；情况太多。[EBADF] 之类的编程错误，由于不涉及文件，该概念毫无意义。对于立即检测到的错误，如 [EAGAIN]，偏移显然不应改变。然而，在中断或硬件错误之后，更新后的值将非常有用，并且是许多实现的行为。

注意，读取零字节的 read() 不修改最后数据访问时间戳。请求多于零字节但返回零的 read() 被要求修改最后数据访问时间戳。

允许但并非要求实现为读取零字节的 read() 请求执行错误检查。

输入和输出 (Input and Output)

使用大字节计数的 I/O 一直存在问题。诸如 lread() 和 lwrite()（使用并返回 long）的想法曾经被考虑过。当前的解决方案是在 ISO C 标准函数 read() 和 write() 上使用抽象类型。可以声明抽象类型以使现有函数正常工作，但也可以声明为在未来的实现中可以表示更大的类型。可以推定，无论什么约束限制了 size_t 的最大范围，也同样将可移植的 I/O 请求限制在同一范围内。本卷 POSIX.1-2024 还通过要求限制字节计数以使有符号返回值保持有意义，进一步限制了范围。由于返回类型也是（有符号）抽象类型，实现可以将字节计数定义为大于 int 所能容纳的值。

标准制定者曾考虑为管道或 FIFO 添加原子性要求，但认识到由于管道和 FIFO 的性质，无法保证对 {PIPE_BUF} 或任何其他有助于应用程序可移植性的大小的读取具有原子性。

本卷 POSIX.1-2024 要求当 nbyte 为零时，read() 或 write() 不采取任何动作。这并非意在优先于错误检测（如无效的缓冲区指针或文件描述符）。这与本卷 POSIX.1-2024 的其余部分一致，但这里的措辞可能被误读为要求在检测任何其他错误之前检测零的情况。值零应被视为一个正确的值，其语义是空操作。

I/O 意在对于普通文件、管道和 FIFO 是原子的。原子意味着来自单个操作的所有字节一同开始也一同结束，不会被其他 I/O 操作穿插。众所周知，终端不具备这一属性，并且终端被明确地（且隐含地永久）排除在外，使该行为成为未指定。其他设备类型的行为也留作未指定，但该措辞意在暗示未来的标准可能会选择规定原子性（或不规定）。

曾有人建议向 read() 和 write() 添加格式参数，以处理异构文件系统和基础硬件类型之间的网络传输。OSI 表示层服务的支持可能需要这样的设施。然而，已确定这应与类似的 C 语言设施相对应，而这超出了本卷 POSIX.1-2024 的范围。该概念已被建议给 ISO C 标准的制定者，供其考虑作为未来工作的可能领域。

在 4.3 BSD 中，在传输任何数据之前被信号中断的 read() 或 write() 默认不返回 [EINTR] 错误，而是被重启。在 4.2 BSD、4.3 BSD 和 Eighth Edition 中，还有一个额外的函数 select()，其目的是暂停，直到在指定的文件描述符上检测到指定的活动（要读取的数据、要写入的空间等）。在为那些系统编写的应用程序中，常见做法是在 read() 之前使用 select()，用于希望因信号而中断 I/O 的情况（如键盘输入）。

哪些文件或文件类型可被中断的问题被视为实现设计问题。这通常主要受硬件和可靠性问题的影响。

没有提及在"不可恢复错误"之后采取的动作。描述硬件错误情况下发生什么被认为超出了本卷 POSIX.1-2024 的范围。

本标准的早期版本在中断处理方面允许两种非常不同的行为。为了尽量减少由此产生的困惑，决定 POSIX.1-2024 应只支持这些行为中的一种。AT&T 衍生系统上的历史做法是，当所请求的数据传输了一部分但并非全部后发生中断时，read() 和 write() 返回 -1 并将 errno 设为 [EINTR]。然而，美国商务部 FIPS 151-1 和 FIPS 151-2 要求历史上的 BSD 行为，即 read() 和 write() 返回中断前实际传输的字节数。如果在传输了任何数据时返回 -1，则在可寻址的设备上难以从该错误中恢复，在不可寻址的设备上则不可能恢复。大多数新实现支持这种行为。POSIX.1-2024 要求的行为是返回已传输的字节数。

POSIX.1-2024 未指定对 read() 进行缓冲的实现实际何时将数据移入用户提供的缓冲区，因此实现可以选择在最晚的可能时刻这样做。因此，较早到达的中断可能不会导致 read() 返回部分字节计数，而是返回 -1 并将 errno 设为 [EINTR]。

还考虑过将先前两个选项结合起来，在返回短计数时将 errno 设为 [EINTR]。然而，不仅没有实现这一点的现有实践，而且这与当设置 errno 时，负责的函数应返回 -1 的想法相矛盾。

本卷 POSIX.1-2024 有意不指定除 [ESPIPE] 之外与管道、FIFO 和套接字相关的任何 pread() 错误。
