XSH 函数：mkdir()

名称 (NAME)

mkdir、mkdirat — 创建目录

提要 (SYNOPSIS)

#include <sys/stat.h>

int mkdir(const char *path, mode_t mode);

[OH] #include <fcntl.h>

int mkdirat(int fd, const char *path, mode_t mode);

说明 (DESCRIPTION)

mkdir() 函数应创建一个名为 path 的新目录。新目录的文件权限位 [XSI] 和 S_ISVTX 位 应由 mode 初始化。mode 参数的文件权限位应被进程的文件创建掩码修改。

当 mode 中除文件权限位 [XSI] 和 S_ISVTX 以外的位被设置时，这些附加位的含义是实现定义的。

目录的用户 ID 应被设置为进程的有效用户 ID。目录的组 ID 应被设置为父目录的组 ID 或进程的有效组 ID。实现应提供一种将目录的组 ID 初始化为父目录的组 ID 的方式。实现可以（但不必）提供一种实现定义的方式，将目录的组 ID 初始化为调用进程的有效组 ID。

新创建的目录应是空目录。

如果 path 命名一个符号链接，mkdir() 应失败并将 errno 设置为 [EEXIST]。

成功完成后，mkdir() 应将目录的最后数据访问、最后数据修改和最后文件状态更改时间戳标记为需要更新。此外，包含新项的目录的最后数据修改和最后文件状态更改时间戳应被标记为需要更新。

mkdirat() 函数应与 mkdir() 函数等价，但 path 指定相对路径的情况除外。在这种情况下，新创建的目录是相对于与文件描述符 fd 相关联的目录创建的，而不是相对于当前工作目录。如果与文件描述符相关联的打开文件描述的访问模式不是 O_SEARCH，则函数应使用文件描述符底层目录的当前权限检查是否允许目录搜索。如果访问模式是 O_SEARCH，则函数不应执行该检查。

如果在 fd 参数中向 mkdirat() 传入特殊值 AT_FDCWD，则应使用当前工作目录，并且行为应与调用 mkdir() 相同。

返回值 (RETURN VALUE)

成功完成后，这些函数应返回 0。否则，这些函数应返回 -1 并设置 errno 以指示错误。如果返回 -1，则不应创建任何目录。

错误 (ERRORS)

在以下情况下，这些函数应失败：

[EACCES]
路径前缀的某个组件被拒绝搜索权限，或者要创建的目录的父目录被拒绝写权限。
[EEXIST]
所命名的文件已存在。
[EILSEQ]
path 的最后一个路径名组件不是可移植文件名，并且无法在目标目录中创建。
[ELOOP]
在解析 path 参数期间遇到的符号链接中存在循环。
[EMLINK]
父目录的链接计数将超过 {LINK_MAX}。
[ENAMETOOLONG]
路径名的某个组件的长度长于 {NAME_MAX}。
[ENOENT]
path 的路径前缀的某个组件没有命名一个现有文件，或者 path 是空字符串。
[ENOSPC]
文件系统没有足够的空间来容纳新目录的内容或扩展新目录的父目录。
[ENOTDIR]
路径前缀的某个组件命名了一个既不是目录也不是指向目录的符号链接的现有文件。
[EROFS]
父目录位于只读文件系统上。

此外，在以下情况下，mkdirat() 函数应失败：

[EACCES]
与 fd 相关联的打开文件描述的访问模式不是 O_SEARCH，并且 fd 底层目录的权限不允许目录搜索。
[EBADF]
path 参数没有指定绝对路径，并且 fd 参数既不是 AT_FDCWD，也不是为读或搜索而打开的有效文件描述符。
[ENOTDIR]
path 参数不是绝对路径，并且 fd 是与非目录文件相关联的文件描述符。

在以下情况下，这些函数可以失败：

[ELOOP]
在解析 path 参数期间遇到的符号链接超过 {SYMLOOP_MAX} 个。
[ENAMETOOLONG]
路径名的长度超过 {PATH_MAX}，或者符号链接的路径名解析产生的中间结果的长度超过 {PATH_MAX}。

原理 (RATIONALE)

mkdir() 函数起源于 4.2 BSD，并在 Release 3.0 中被添加到 System V。

4.3 BSD 检测 [ENAMETOOLONG]。

POSIX.1-1990 标准要求新创建目录的组 ID 被设置为父目录的组 ID 或创建进程的有效组 ID。FIPS 151-2 要求实现提供一种将组 ID 设置为所在目录的组 ID 的方式，但不禁止实现同时支持将组 ID 设置为创建进程的有效组 ID 的方式。符合规范的应用程序不应假定将使用哪个组 ID。如果这很重要，应用程序可以在目录创建后使用 chown() 设置组 ID，或者确定实现在什么条件下会设置所需的组 ID。

mkdirat() 函数的目的是在不暴露于竞争条件的情况下在当前工作目录以外的目录中创建目录。文件的路径的任何部分都可能在与 mkdir() 调用并行的情况下被更改，导致未指定的行为。通过为目标目录打开文件描述符并使用 mkdirat() 函数，可以保证新创建的目录位于相对于所需目录的位置。

鼓励实现让 mkdir() 和 mkdirat() 在 path 的最后一个组件包含任何具有 <newline> 字符编码值的字节时报告 [EILSEQ] 错误。

变更历史 (CHANGE HISTORY)

在 Issue 3 中首次发布。为与 POSIX.1-1988 标准保持一致而纳入。

第 6 版 (Issue 6)

在 SYNOPSIS 中，移除了 <sys/types.h> 头文件的可选包含。

以下对 POSIX 实现的新要求源于与 Single UNIX Specification 的一致性：

  • 包含 <sys/types.h> 的要求已被移除。虽然 <sys/types.h> 是先前 POSIX 规范的符合实现所要求的，但 UNIX 应用程序并不要求它。

  • 添加了 [ELOOP] 强制错误条件。

  • 添加了第二个 [ENAMETOOLONG] 作为可选错误条件。

为与 IEEE P1003.1a 草案标准保持一致，进行了以下更改：

  • 添加了 [ELOOP] 可选错误条件。

进行了与细粒度时间戳支持相关的更改。

应用了 POSIX.1-2008 技术勘误 1（Technical Corrigendum 1）：XSH/TC1-2008/0375 [461]、XSH/TC1-2008/0376 [324]、XSH/TC1-2008/0377 [277]、XSH/TC1-2008/0378 [278] 和 XSH/TC1-2008/0379 [278]。
