XSH 函数：recv()

名称 (NAME)

recv — 从已连接的套接字接收消息 (recv — receive a message from a connected socket)

摘要 (SYNOPSIS)

#include <sys/socket.h>

ssize_t recv(int socket, void *buffer, size_t length, int flags);

说明 (DESCRIPTION)

recv() 函数应从连接模式或无连接模式的套接字接收消息。它通常与已连接的套接字一起使用，因为它不允许应用程序检索接收到的数据的源地址。

recv() 函数接受以下参数：

socket
指定套接字文件描述符。
buffer
指向应存储消息的缓冲区。
length
指定由 buffer 参数指向的缓冲区的长度（以字节为单位）。
flags
指定消息接收的类型。此参数的值通过对以下值中的零个或多个进行逻辑或构成： MSG_PEEK 窥视传入的消息。数据被视为未读，下一次 recv() 或类似函数仍应返回此数据。MSG_OOB 请求带外数据。带外数据的重要性和语义是特定于协议的。MSG_WAITALL 在 SOCK_STREAM 套接字上，此标志请求函数阻塞，直到可以返回全部数量的数据。如果套接字是基于消息的套接字、捕获到信号、连接被终止、指定了 MSG_PEEK，或者套接字有挂起的错误，则函数可以返回较少量的数据。

recv() 函数应返回写入由 buffer 参数指向的缓冲区的消息的长度。对于基于消息的套接字（如 SOCK_DGRAM 和 SOCK_SEQPACKET），整个消息应在一次操作中读取。如果消息太长而无法放入所提供的缓冲区，并且 flags 参数中未设置 MSG_PEEK，则多余字节应被丢弃。对于基于流的套接字（如 SOCK_STREAM），消息边界应被忽略。在这种情况下，数据一变得可用就应返回给用户，并且不应丢弃任何数据。

如果未设置 MSG_WAITALL 标志，则只应返回到第一条消息末尾为止的数据。

如果套接字处没有可用的消息，并且未在套接字的文件描述符上设置 O_NONBLOCK，则 recv() 应阻塞，直到消息到达或发生超时（参见 2.10.16 选项的使用 中的 SO_RCVTIMEO）。如果套接字处没有可用的消息，并且在套接字的文件描述符上设置了 O_NONBLOCK，则 recv() 应失败并将 errno 设置为 [EAGAIN] 或 [EWOULDBLOCK]。

返回值 (RETURN VALUE)

成功完成后，recv() 应返回消息的长度（以字节为单位）。如果没有可接收的消息并且对端已执行有序关闭，则 recv() 应返回 0。否则，应返回 -1，并设置 errno 以指示错误。

错误 (ERRORS)

在以下情况下，recv() 函数应失败：

[EAGAIN] 或 [EWOULDBLOCK]
套接字的文件描述符被标记为 O_NONBLOCK，且没有等待接收的数据；或设置了 MSG_OOB 且没有可用的带外数据，并且要么套接字的文件描述符被标记为 O_NONBLOCK，要么套接字不支持阻塞以等待带外数据。另请参见 2.10.16 选项的使用 中的 SO_RCVTIMEO。
[EBADF]
socket 参数不是有效的文件描述符。
[ECONNRESET]
连接被对端强制关闭。
[EINTR]
在任何数据可用之前，recv() 函数被一个已捕获的信号中断。
[EINVAL]
设置了 MSG_OOB 标志，且没有可用的带外数据。
[ENOTCONN]
在未连接的连接模式套接字上尝试进行接收。
[ENOTSOCK]
socket 参数不引用套接字。
[EOPNOTSUPP]
此套接字类型或协议不支持指定的标志。
[ETIMEDOUT]
连接在建立连接期间超时，或由于活动连接上的传输超时而超时。

在以下情况下，recv() 函数可以失败：

[EIO]
在读取或写入文件系统时发生 I/O 错误。
[ENOBUFS]
系统中可用于执行该操作的资源不足。
[ENOMEM]
可用于满足请求的内存不足。
The following sections are informative.

示例 (EXAMPLES)

无。

应用程序使用 (APPLICATION USAGE)

recv() 函数等效于 address 和 address_len 参数为空指针的 recvfrom()，并且如果 socket 参数引用的是套接字且 flags 参数为 0，则等效于 read()。

select() 和 poll() 函数可用于确定何时有数据可接收。
