XSH 函数导读：pread()

0. 总览

pread() 从文件中给定的位置读取数据，且不改变文件偏移，是与 read() 等价的定位读变体。所属头文件为 <unistd.h>。原型关键点：ssize_t pread(int fildes, void *buf, size_t nbyte, off_t offset); —— 前三个参数与 read() 相同，第四个参数 offset 指定文件内的期望位置；成功返回实际读取的字节数，失败返回 -1 并设置 errno。

1. 机制

除"从给定位置读取且不改变文件偏移"外，pread() 完全等同于 read()：读取从 offset 处开始，不应发生越过文件末尾的数据传输，起始位置在文件末尾处或之后时返回 0；返回的字节数绝不应大于 nbyte，短读（剩余字节不足、被信号中断、或管道/FIFO/特殊文件立即可供读取的字节较少）是合法结果；nbyte 为零时返回 0 且无其他结果；读任何数据前被信号中断返回 -1/[EINTR]，已读部分数据后被中断则返回已读字节数；成功读取（nbyte 大于 0）时最后数据访问时间戳被标记为需要更新。与 read() 不同，pread() 的语义不依赖也不修改当前文件偏移，因此多线程可以安全地对同一描述符并发做"定位读取"而无需 lseek+read 的组合——后者在并发下不是原子的。尝试在无法寻址的文件（如管道、FIFO、终端）上调用 pread() 应导致错误（[ESPIPE]）。

2. 易错点

offset 为负且文件是普通文件或块特殊文件时返回 [EINVAL]，且文件偏移应保持不变。规范有意不规定管道、FIFO 和套接字上除 [ESPIPE] 之外的 pread() 错误——在这些文件上不要依赖其他错误码。与 read() 相同的坑依然存在：不要假设一次读满 nbyte；读取未写入的洞（lseek 或大 offset 越过数据末尾）返回 0 值字节；nbyte 大于 {SSIZE_MAX} 结果实现定义。注意 pread() 成功读取（nbyte 大于 0）同样会更新最后数据访问时间戳。描述符必须以读方式打开（否则 [EBADF]），目录上读取可能返回 [EISDIR]（XSI）。

3. 示例

#include <unistd.h>

char buf[512];
ssize_t n;
int fd; /* 已以 O_RDONLY 打开的普通文件 */

/* 从偏移 1024 处读取，不影响文件偏移，可安全用于多线程 */
n = pread(fd, buf, sizeof buf, 1024);
if (n == -1) {
    /* 处理错误（如 ESPIPE、EINVAL、EINTR） */
} else if (n == 0) {
    /* offset 处已无数据（在文件末尾或之后） */
}
