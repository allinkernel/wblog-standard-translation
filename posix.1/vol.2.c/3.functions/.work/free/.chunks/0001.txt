[h4_00001] [A1][/A1]NAME
[blockquote_00002] free — free allocated memory
[h4_00003] [A2][/A2]SYNOPSIS
[p_00004] [CODE3]
[h4_00005] [A4][/A4]DESCRIPTION
[p_00006] The [I5]free[/I5]() function shall cause the space pointed to by [I6]ptr[/I6] to be deallocated; that is, made available for further allocation. If [I7]ptr[/I7] is a null pointer, no action shall occur. Otherwise, if the argument does not match a pointer earlier returned by [A8][I9]aligned_alloc[/I9]()[/A8], [A10][I11]calloc[/I11]()[/A10], [A12][I13]malloc[/I13]()[/A12],  [S14][[A15]ADV[/A15]][/S14] [IMG16] [A17][I18]posix_memalign[/I18]()[/A17], [IMG19] [A20][I21]realloc[/I21]()[/A20],  [S22][[A23]CX[/A23]][/S22] [IMG24] [A25][I26]reallocarray[/I26]()[/A25], or a function in POSIX.1-2024 that allocates memory as if by [A27][I28]malloc[/I28]()[/A27], [IMG29] or if the space has been deallocated by a call to [I30]free[/I30](), [S31][[A32]CX[/A32]][/S31] [IMG33] [A34][I35]reallocarray[/I35]()[/A34], [IMG36] or [A37][I38]realloc[/I38]()[/A37], the behavior is undefined.
[p_00007] Any use of a pointer that refers to freed space results in undefined behavior.
[p_00008] [S39][[A40]CX[/A40]][/S39] [IMG41] The [I42]free[/I42]() function shall not modify [I43]errno[/I43] if [I44]ptr[/I44] is a null pointer or a pointer previously returned as if by [A45][I46]malloc[/I46]()[/A45] and not yet deallocated. [IMG47]
[p_00009] For purposes of determining the existence of a data race, [I48]free[/I48]() shall behave as though it accessed only memory locations accessible through its argument and not other static duration storage. The function may, however, visibly modify the storage that it deallocates. Calls to [A49][I50]aligned_alloc[/I50]()[/A49], [A51][I52]calloc[/I52]()[/A51], [I53]free[/I53](), [A54][I55]malloc[/I55]()[/A54], [S56][[A57]ADV[/A57]][/S56] [IMG58] [A59][I60]posix_memalign[/I60]()[/A59], [IMG61]  [S62][[A63]CX[/A63]][/S62] [IMG64] [A65][I66]reallocarray[/I66]()[/A65], [IMG67] and [A68][I69]realloc[/I69]()[/A68] that allocate or deallocate a particular region of memory shall occur in a single total order (see XBD [A70][I71]4.15.1 Memory Ordering[/I71][/A70]), and each such deallocation call shall synchronize with the next allocation (if any) in this order.
[h4_00010] [A72][/A72]RETURN VALUE
[p_00011] The [I73]free[/I73]() function shall not return a value.
[h4_00012] [A74][/A74]ERRORS
[p_00013] No errors are defined.
