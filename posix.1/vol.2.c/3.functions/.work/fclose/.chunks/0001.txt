[h4_00001] [A1][/A1]NAME
[blockquote_00002] fclose — close a stream
[h4_00003] [A2][/A2]SYNOPSIS
[p_00004] [CODE3]
[h4_00005] [A4][/A4]DESCRIPTION
[p_00006] The [I5]fclose[/I5]() function shall cause the stream pointed to by [I6]stream[/I6] to be flushed and the associated file to be closed. Any unwritten buffered data for the stream shall be written to the file; any unread buffered data shall be discarded. Whether or not the call succeeds, the stream shall be disassociated from the file and any buffer set by the [A7][I8]setbuf[/I8]()[/A7] or [A9][I10]setvbuf[/I10]()[/A9] function shall be disassociated from the stream. If the associated buffer was automatically allocated, it shall be deallocated.
[p_00007] [S11][[A12]CX[/A12]][/S11] [IMG13] If the file is not already at EOF, and the file is one capable of seeking, the file offset of the underlying open file description shall be set to the file position of the stream if the stream is the active handle to the underlying file description.
[p_00008] The [I14]fclose[/I14]() function shall mark for update the last data modification and last file status change timestamps of the underlying file, if the stream was writable, and if buffered data remains that has not yet been written to the file. The [I15]fclose[/I15]() function shall perform the equivalent of a [A16][I17]close[/I17]()[/A16] on the file descriptor that is associated with the stream pointed to by [I18]stream[/I18]. [IMG19]
[p_00009] After the call to [I20]fclose[/I20](), any use of [I21]stream[/I21] results in undefined behavior.
[h4_00010] [A22][/A22]RETURN VALUE
[p_00011] Upon successful completion, [I23]fclose[/I23]() shall return 0; otherwise, it shall return EOF [S24][[A25]CX[/A25]][/S24] [IMG26] &nbsp;and set [I27]errno[/I27] to indicate the error. [IMG28]
[h4_00012] [A29][/A29]ERRORS
[p_00013] The [I30]fclose[/I30]() function shall fail if:
[dt_00014] [EAGAIN]
[dd_00015] [S31][[A32]CX[/A32]][/S31] [IMG33] The O_NONBLOCK flag is set for the file descriptor underlying [I34]stream[/I34] and the thread would be delayed in the write operation. [IMG35]
[dt_00016] [EBADF]
[dd_00017] [S36][[A37]CX[/A37]][/S36] [IMG38] The file descriptor underlying stream is not valid. [IMG39]
[dt_00018] [EFBIG]
[dd_00019] [S40][[A41]CX[/A41]][/S40] [IMG42] An attempt was made to write a file that exceeds the maximum file size. [IMG43]
[dt_00020] [EFBIG]
[dd_00021] [S44][[A45]CX[/A45]][/S44] [IMG46] An attempt was made to write a file that exceeds the file size limit of the process.  [IMG47] [S48][[A49]XSI[/A49]][/S48] [IMG50] A SIGXFSZ signal shall also be generated for the thread. [IMG51]
[dt_00022] [EFBIG]
[dd_00023] [S52][[A53]CX[/A53]][/S52] [IMG54] The file is a regular file and an attempt was made to write at or beyond the offset maximum associated with the corresponding stream. [IMG55]
[dt_00024] [EINTR]
[dd_00025] [S56][[A57]CX[/A57]][/S56] [IMG58] The [I59]fclose[/I59]() function was interrupted by a signal. [IMG60]
[dt_00026] [EIO]
[dd_00027] [S61][[A62]CX[/A62]][/S61] [IMG63] The process is a member of a background process group attempting to write to its controlling terminal, TOSTOP is set, the calling thread is not blocking SIGTTOU, the process is not ignoring SIGTTOU, and the process group of the process is orphaned. This error may also be returned under implementation-defined conditions. [IMG64]
[dt_00028] [ENOMEM]
[dd_00029] [S65][[A66]CX[/A66]][/S65] [IMG67] The underlying stream was created by [A68][I69]open_memstream[/I69]()[/A68] or [A70][I71]open_wmemstream[/I71]()[/A70] and insufficient memory is available. [IMG72]
[dt_00030] [ENOSPC]
[dd_00031] [S73][[A74]CX[/A74]][/S73] [IMG75] There was no free space remaining on the device containing the file or in the buffer used by the [A76][I77]fmemopen[/I77]()[/A76] function. [IMG78]
[dt_00032] [EPIPE]
[dd_00033] [S79][[A80]CX[/A80]][/S79] [IMG81] An attempt is made to write to a pipe or FIFO that is not open for reading by any process. A SIGPIPE signal shall also be sent to the thread. [IMG82]
[p_00034] The [I83]fclose[/I83]() function may fail if:
[dt_00035] [ENXIO]
[dd_00036] [S84][[A85]CX[/A85]][/S84] [IMG86] A request was made of a nonexistent device, or the request was outside the capabilities of the device. [IMG87]
[h4_00037] [A88][/A88]EXAMPLES
[p_00038] None.
[h4_00039] [A89][/A89]APPLICATION USAGE
[p_00040] Since after the call to [I90]fclose[/I90]() any use of [I91]stream[/I91] results in undefined behavior, [I92]fclose[/I92]() should not be used on [I93]stdin[/I93], [I94]stdout[/I94], or [I95]stderr[/I95] except immediately before process termination (see XBD [A96][I97]3.287 Process Termination[/I97][/A96]), so as to avoid triggering undefined behavior in other standard interfaces that rely on these streams. If there are any [A98][I99]atexit[/I99]()[/A98] handlers registered by the application, such a call to [I100]fclose[/I100]() should not occur until the last handler is finishing. Once [I101]fclose[/I101]() has been used to close [I102]stdin[/I102], [I103]stdout[/I103], or [I104]stderr[/I104], there is no standard way to reopen any of these streams.
[p_00041] Use of [A105][I106]freopen[/I106]()[/A105] to change [I107]stdin[/I107], [I108]stdout[/I108], or [I109]stderr[/I109] instead of closing them avoids the danger of a file unexpectedly being opened as one of the special file descriptors STDIN_FILENO, STDOUT_FILENO, or STDERR_FILENO at a later time in the application.
