[h4_00001] [A1][/A1]NAME
[blockquote_00002] rename, renameat — rename file
[h4_00003] [A2][/A2]SYNOPSIS
[p_00004] [CODE3]
[h4_00005] [A4][/A4]DESCRIPTION
[p_00006] For [I5]rename[/I5](): [S6][[A7]CX[/A7]][/S6] [IMG8] &nbsp;The functionality described on this reference page is aligned with the ISO&nbsp;C standard. Any conflict between the requirements described here and the ISO&nbsp;C standard is unintentional. This volume of POSIX.1-2024 defers to the ISO&nbsp;C standard. [IMG9]
[p_00007] The [I10]rename[/I10]() function shall change the name of a file. The [I11]old[/I11] argument points to the pathname of the file to be renamed. The [I12]new[/I12] argument points to the new pathname of the file. [S13][[A14]CX[/A14]][/S13] [IMG15] &nbsp;If the [I16]new[/I16] argument does not resolve to an existing directory entry for a file of type directory and the [I17]new[/I17] argument contains at least one non-&lt;slash&gt; character and ends with one or more trailing &lt;slash&gt; characters after all symbolic links have been processed, [I18]rename[/I18]() shall fail.
[p_00008] If either the [I19]old[/I19] or [I20]new[/I20] argument names a symbolic link, [I21]rename[/I21]() shall operate on the symbolic link itself, and shall not resolve the last component of the argument. If the [I22]old[/I22] argument and the [I23]new[/I23] argument resolve to either the same existing directory entry or different directory entries for the same existing file, [I24]rename[/I24]() shall return successfully and perform no other action.
[p_00009] If the [I25]old[/I25] argument names a file that is not a directory and the [I26]new[/I26] argument names a directory, or [I27]old[/I27] names a directory and [I28]new[/I28] names a file that is not a directory, or [I29]new[/I29] names a directory that is not empty, [I30]rename[/I30]() shall fail. Otherwise, if the directory entry named by [I31]new[/I31] exists, it shall be removed and [I32]old[/I32] renamed to [I33]new[/I33]. In this case, a directory entry named [I34]new[/I34] shall remain visible to other threads throughout the renaming operation and refer either to the file referred to by [I35]new[/I35] or [I36]old[/I36] before the operation began.
[p_00010] If either [I37]pathname[/I37] argument refers to a path whose final component is either dot or dot-dot, [I38]rename[/I38]() shall fail.
[p_00011] If the [I39]old[/I39] argument points to a pathname of a symbolic link, the symbolic link shall be renamed. If the [I40]new[/I40] argument points to a pathname of a symbolic link, the symbolic link shall be removed.
[p_00012] The [I41]old[/I41] pathname shall not name an ancestor directory of the [I42]new[/I42] pathname. Write access permission is required for the directory containing [I43]old[/I43] and the directory containing [I44]new[/I44]. If the [I45]old[/I45] argument points to the pathname of a directory, write access permission may be required for the directory named by [I46]old[/I46], and, if it exists, the directory named by [I47]new[/I47].
[p_00013] If the [I48]new[/I48] argument names an existing file and the file's link count becomes 0 when it is removed and no process has the file open, the space occupied by the file shall be freed and the file shall no longer be accessible. If one or more processes have the file open when the last link is removed, the link shall be removed before [I49]rename[/I49]() returns, but the removal of the file contents shall be postponed until all references to the file are closed.
[p_00014] Upon successful completion, [I50]rename[/I50]() shall mark for update the last data modification and last file status change timestamps of the parent directory of each file.
[p_00015] If the [I51]rename[/I51]() function fails for any reason other than [EIO], any file named by [I52]new[/I52] shall be unaffected.
[p_00016] The [I53]renameat[/I53]() function shall be equivalent to the [I54]rename[/I54]() function except in the case where either [I55]old[/I55] or [I56]new[/I56] specifies a relative path. If [I57]old[/I57] is a relative path, the file to be renamed is located relative to the directory associated with the file descriptor [I58]oldfd[/I58] instead of the current working directory. If [I59]new[/I59] is a relative path, the same happens only relative to the directory associated with [I60]newfd[/I60]. If the access mode of the open file description associated with the file descriptor is not O_SEARCH, the function shall check whether directory searches are permitted using the current permissions of the directory underlying the file descriptor. If the access mode is O_SEARCH, the function shall not perform the check.
[p_00017] If [I61]renameat[/I61]() is passed the special value AT_FDCWD in the [I62]oldfd[/I62] or [I63]newfd[/I63] parameter, the current working directory shall be used in the determination of the file for the respective [I64]path[/I64] parameter. [IMG65]
[h4_00018] [A66][/A66]RETURN VALUE
[p_00019] Upon successful completion, the [I67]rename[/I67]() function shall return 0. Otherwise, it shall return -1, [S68][[A69]CX[/A69]][/S68] [IMG70] [I71]errno[/I71] shall be set to indicate the error, [IMG72] &nbsp;and neither the file named by [I73]old[/I73] nor the file named by [I74]new[/I74] shall be changed or created.
[p_00020] [S75][[A76]CX[/A76]][/S75] [IMG77] Upon successful completion, the [I78]renameat[/I78]() function shall return 0. Otherwise, it shall return -1 and set [I79]errno[/I79] to indicate the error. [IMG80]
[h4_00021] [A81][/A81]ERRORS
[p_00022] The [I82]rename[/I82]() [S83][[A84]CX[/A84]][/S83] [IMG85] &nbsp;and [I86]renameat[/I86]() [IMG87] &nbsp;functions shall fail if:
[dt_00023] [EACCES]
[dd_00024] [S88][[A89]CX[/A89]][/S88] [IMG90] A component of either path prefix denies search permission; or one of the directories containing [I91]old[/I91] or [I92]new[/I92] denies write permissions; or, write permission is required and is denied for a directory pointed to by the [I93]old[/I93] or [I94]new[/I94] arguments. [IMG95]
[dt_00025] [EBUSY]
[dd_00026] [S96][[A97]CX[/A97]][/S96] [IMG98] The directory named by [I99]old[/I99] or [I100]new[/I100] is currently in use by the system or another process, and the implementation considers this an error. [IMG101]
[dt_00027] [EEXIST]&nbsp;or&nbsp;[ENOTEMPTY]
[dd_00028] [S102][[A103]CX[/A103]][/S102] [IMG104]  The [I105]new[/I105] argument names a directory that is not empty. [IMG106]
[dt_00029] [EILSEQ]
[dd_00030] [S107][[A108]CX[/A108]][/S107] [IMG109] The last pathname component of the new pathname is not a portable filename, and cannot be created in the target directory. [IMG110]
[dt_00031] [EINVAL]
[dd_00032] [S111][[A112]CX[/A112]][/S111] [IMG113] The [I114]old[/I114] pathname names an ancestor directory of the [I115]new[/I115] pathname, or either pathname argument contains a final component that is dot or dot-dot. [IMG116]
[dt_00033] [EIO]
[dd_00034] [S117][[A118]CX[/A118]][/S117] [IMG119] A physical I/O error has occurred. [IMG120]
[dt_00035] [EISDIR]
[dd_00036] [S121][[A122]CX[/A122]][/S121] [IMG123] The [I124]new[/I124] argument points to a directory and the [I125]old[/I125] argument points to a file that is not a directory. [IMG126]
[dt_00037] [ELOOP]
[dd_00038] [S127][[A128]CX[/A128]][/S127] [IMG129] A loop exists in symbolic links encountered during resolution of the [I130]old[/I130] or [I131]new[/I131] argument. [IMG132]
[dt_00039] [EMLINK]
[dd_00040] [S133][[A134]CX[/A134]][/S133] [IMG135] The file named by [I136]old[/I136] is a directory, and the link count of the parent directory of [I137]new[/I137] would exceed {LINK_MAX}. [IMG138]
[dt_00041] [ENAMETOOLONG]
[dd_00042] [S139][[A140]CX[/A140]][/S139] [IMG141]  The length of a component of a pathname is longer than {NAME_MAX}. [IMG142]
[dt_00043] [ENOENT]
[dd_00044] [S143][[A144]CX[/A144]][/S143] [IMG145] The [I146]old[/I146] argument does not name an existing file, a component of the path prefix of [I147]new[/I147] does not exist, or either [I148]old[/I148] or [I149]new[/I149] points to an empty string. [IMG150]
[dt_00045] [ENOSPC]
[dd_00046] [S151][[A152]CX[/A152]][/S151] [IMG153] The directory that would contain [I154]new[/I154] cannot be extended. [IMG155]
[dt_00047] [ENOTDIR]
[dd_00048] [S156][[A157]CX[/A157]][/S156] [IMG158] A component of either path prefix names an existing file that is neither a directory nor a symbolic link to a directory; or the [I159]old[/I159] argument names a directory and the [I160]new[/I160] argument names a non-directory file; or the [I161]old[/I161] argument contains at least one non-&lt;slash&gt; character and ends with one or more trailing &lt;slash&gt; characters and the last pathname component names an existing file that is neither a directory nor a symbolic link to a directory; or the [I162]old[/I162] argument names an existing non-directory file and the [I163]new[/I163] argument names a nonexistent file, contains at least one non-&lt;slash&gt; character, and ends with one or more trailing &lt;slash&gt; characters; or the [I164]new[/I164] argument names an existing non-directory file, contains at least one non-&lt;slash&gt; character, and ends with one or more trailing &lt;slash&gt; characters. [IMG165]
[dt_00049] [EPERM] or [EACCES]
[dd_00050] [S166][[A167]XSI[/A167]][/S166] [IMG168]  The S_ISVTX flag is set on the directory containing the file referred to by [I169]old[/I169] and the process does not satisfy the criteria specified in XBD [A170][I171]4.5 Directory Protection[/I171][/A170] with respect to [I172]old[/I172]; or [I173]new[/I173] refers to an existing file, the S_ISVTX flag is set on the directory containing this file, and the process does not satisfy the criteria specified in XBD [A174][I175]4.5 Directory Protection[/I175][/A174] with respect to this file. [IMG176]
[dt_00051] [EROFS]
[dd_00052] [S177][[A178]CX[/A178]][/S177] [IMG179] The requested operation requires writing in a directory on a read-only file system. [IMG180]
[dt_00053] [EXDEV]
[dd_00054] [S181][[A182]CX[/A182]][/S181] [IMG183] The file named by [I184]old[/I184] and the directory in which the directory entry named by [I185]new[/I185] is to be created or replaced are on different file systems and the implementation does not support hard links between file systems. [IMG186]
[p_00055] [S187][[A188]CX[/A188]][/S187] [IMG189] In addition, the [I190]renameat[/I190]() function shall fail if:
[dt_00056] [EACCES]
[dd_00057] The access mode of the open file description associated with [I191]oldfd[/I191] or [I192]newfd[/I192] is not O_SEARCH and the permissions of the directory underlying [I193]oldfd[/I193] or [I194]newfd[/I194], respectively, do not permit directory searches.
[dt_00058] [EBADF]
[dd_00059] The [I195]old[/I195] argument does not specify an absolute path and the [I196]oldfd[/I196] argument is neither AT_FDCWD nor a valid file descriptor open for reading or searching, or the [I197]new[/I197] argument does not specify an absolute path and the [I198]newfd[/I198] argument is neither AT_FDCWD nor a valid file descriptor open for reading or searching.
[dt_00060] [ENOTDIR]
[dd_00061] The [I199]old[/I199] or [I200]new[/I200] argument is not an absolute path and [I201]oldfd[/I201] or [I202]newfd[/I202], respectively, is a file descriptor associated with a non-directory file.
[p_00062] The [I203]rename[/I203]() [S204][[A205]CX[/A205]][/S204] [IMG206] &nbsp;and [I207]renameat[/I207]() [IMG208] &nbsp;functions may fail if:
[dt_00063] [ELOOP]
[dd_00064] [S209][[A210]CX[/A210]][/S209] [IMG211] More than {SYMLOOP_MAX} symbolic links were encountered during resolution of the [I212]old[/I212] or [I213]new[/I213] argument. [IMG214]
[dt_00065] [ENAMETOOLONG]
[dd_00066] [S215][[A216]CX[/A216]][/S215] [IMG217]  The length of a pathname exceeds {PATH_MAX}, or pathname resolution of a symbolic link produced an intermediate result with a length that exceeds {PATH_MAX}. [IMG218]
[dt_00067] [ETXTBSY]
[dd_00068] [S219][[A220]CX[/A220]][/S219] [IMG221] The file named by [I222]new[/I222] exists and is the last directory entry to a pure procedure (shared text) file that is being executed. [IMG223]

[h4_00072] [A228][/A228]APPLICATION USAGE
[p_00073] Some implementations mark for update the last file status change timestamp of renamed files and some do not. Applications which make use of the last file status change timestamp may behave differently with respect to renamed files unless they are designed to allow for either behavior.
[h4_00074] [A229][/A229]RATIONALE
[p_00075] This [I230]rename[/I230]() function is equivalent for regular files to that defined by the ISO&nbsp;C standard. Its inclusion here expands that definition to include actions on directories and specifies behavior when the [I231]new[/I231] parameter names a file that already exists. That specification requires that the action of the function be atomic.
[p_00076] One of the reasons for introducing this function was to have a means of renaming directories while permitting implementations to prohibit the use of [A232][I233]link[/I233]()[/A232] and [A234][I235]unlink[/I235]()[/A234] with directories, thus constraining links to directories to those made by [A236][I237]mkdir[/I237]()[/A236].
[p_00077] The specification that if [I238]old[/I238] and [I239]new[/I239] refer to the same file is intended to guarantee that:
[p_00078] does not remove the file.
[p_00079] Renaming dot or dot-dot is prohibited in order to prevent cyclical file system paths.
[p_00080] See also the descriptions of [ENOTEMPTY] and [ENAMETOOLONG] in [A240][I241]rmdir[/I241]()[/A240] and [EBUSY] in [A242][I243]unlink[/I243]()[/A242]. For a discussion of [EXDEV], see [A244][I245]link[/I245]()[/A244].
[p_00081] The purpose of the [I246]renameat[/I246]() function is to rename files in directories other than the current working directory without exposure to race conditions. Any part of the path of a file could be changed in parallel to a call to [I247]rename[/I247](), resulting in unspecified behavior. By opening file descriptors for the source and target directories and using the [I248]renameat[/I248]() function it can be guaranteed that that renamed file is located correctly and the resulting file is in the desired directory.
[p_00082] Implementations are encouraged to have [I249]rename[/I249]() and [I250]renameat[/I250]() report an [EILSEQ] error if the file named by [I251]new[/I251] does not already exist and the last component of that pathname contains any bytes that have the encoded value of a &lt;newline&gt; character.
