[h4_00001] [A1][/A1]NAME
[blockquote_00002] malloc — a memory allocator
[h4_00003] [A2][/A2]SYNOPSIS
[p_00004] [CODE3]
[h4_00005] [A4][/A4]DESCRIPTION
[p_00006] The [I5]malloc[/I5]() function shall allocate unused space for an object whose size in bytes is specified by [I6]size[/I6] and whose value is unspecified.
[p_00007] The order and contiguity of storage allocated by successive calls to [I7]malloc[/I7]() is unspecified. The pointer returned if the allocation succeeds shall be suitably aligned so that it may be assigned to a pointer to any type of object with a fundamental alignment requirement and then used to access such an object in the space allocated (until the space is explicitly freed or reallocated). Each such allocation shall yield a pointer to an object disjoint from any other object. The pointer returned points to the start (lowest byte address) of the allocated space. If the space cannot be allocated, a null pointer shall be returned. If the size of the space requested is 0, the behavior is implementation-defined: either a null pointer shall be returned, or the behavior shall be as if the size were some non-zero value, except that the behavior is undefined if the returned pointer is used to access an object.
[p_00008] For purposes of determining the existence of a data race, [I8]malloc[/I8]() shall behave as though it accessed only memory locations accessible through its argument and not other static duration storage. The function may, however, visibly modify the storage that it allocates. Calls to [A9][I10]aligned_alloc[/I10]()[/A9], [A11][I12]calloc[/I12]()[/A11], [A13][I14]free[/I14]()[/A13], [I15]malloc[/I15](), [S16][[A17]ADV[/A17]][/S16] [IMG18] &nbsp;[A19][I20]posix_memalign[/I20]()[/A19], [IMG21]  [S22][[A23]CX[/A23]][/S22] [IMG24] [A25][I26]reallocarray[/I26]()[/A25], [IMG27] &nbsp;and [A28][I29]realloc[/I29]()[/A28] that allocate or deallocate a particular region of memory shall occur in a single total order (see [A30][I31]4.15.1 Memory Ordering[/I31][/A30]), and each such deallocation call shall synchronize with the next allocation (if any) in this order.
[h4_00009] [A32][/A32]RETURN VALUE
[p_00010] Upon successful completion, [I33]malloc[/I33]() shall return a pointer to the allocated space; if [I34]size[/I34] is 0, the application shall ensure that the pointer is not used to access an object.
[p_00011] Otherwise, it shall return a null pointer [S35][[A36]CX[/A36]][/S35] [IMG37] &nbsp;and set [I38]errno[/I38] to indicate the error. [IMG39]
[h4_00012] [A40][/A40]ERRORS
[p_00013] The [I41]malloc[/I41]() function shall fail if:
[dt_00014] [ENOMEM]
[dd_00015] [S42][[A43]CX[/A43]][/S42] [IMG44] Insufficient storage space is available. [IMG45]
[p_00016] The [I46]malloc[/I46]() function may fail if:
[dt_00017] [EINVAL]
[dd_00018] [S47][[A48]CX[/A48]][/S47] [IMG49] [I50]size[/I50] is 0 and the implementation does not support 0 sized allocations. [IMG51]
[h4_00019] [A52][/A52]EXAMPLES
[p_00020] None.
[h4_00021] [A53][/A53]APPLICATION USAGE
[p_00022] None.
[h4_00023] [A54][/A54]RATIONALE
[p_00024] Some implementations set [I55]errno[/I55] to [EAGAIN] to signal memory allocation failures that might succeed if retried and [ENOMEM] for failures that are unlikely to ever succeed, for example due to configured limits. [A56][I57]2.3 Error Numbers[/I57][/A56] permits this behavior; when multiple error conditions are simultaneously true there is no precedence between them.
