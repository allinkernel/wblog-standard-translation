[h4_00001] [A1][/A1]NAME
[blockquote_00002] pwrite, write — write on a file
[h4_00003] [A2][/A2]SYNOPSIS
[p_00004] [CODE3]
[h4_00005] [A4][/A4]DESCRIPTION
[p_00006] The [I5]write[/I5]() function shall attempt to write [I6]nbyte[/I6] bytes from the buffer pointed to by [I7]buf[/I7] to the file associated with the open file descriptor, [I8]fildes[/I8].
[p_00007] Before any action described below is taken, and if [I9]nbyte[/I9] is zero and the file is a regular file, the [I10]write[/I10]() function may detect and return errors as described below. In the absence of errors, or if error detection is not performed, the [I11]write[/I11]() function shall return zero and have no other results. If [I12]nbyte[/I12] is zero and the file is not a regular file, the results are unspecified.
[p_00008] On a regular file or other file capable of seeking, the actual writing of data shall proceed from the position in the file indicated by the file offset associated with [I13]fildes[/I13]. Before successful return from [I14]write[/I14](), the file offset shall be incremented by the number of bytes actually written. On a regular file, if the position of the last byte written is greater than or equal to the length of the file, the length of the file shall be set to this position plus one.
[p_00009] On a file not capable of seeking, writing shall always take place starting at the current position. The value of a file offset associated with such a device is undefined.
[p_00010] If the O_APPEND flag of the file status flags is set, the file offset shall be set to the end of the file prior to each write and no intervening file modification operation shall occur between changing the file offset and the write operation.
[p_00011] If a [I15]write[/I15]() requests that more bytes be written than there is room for (for example, the file size limit of the process or the physical end of a medium), only as many bytes as there is room for shall be written. For example, suppose there is space for 20 bytes more in a file before reaching a limit. A write of 512 bytes will return 20. The next write of a non-zero number of bytes would give a failure return (except as noted below).
[p_00012] If the request would cause the file size to exceed the soft file size limit for the process and there is no room for any bytes to be written, the request shall fail [S16][[A17]XSI[/A17]][/S16] [IMG18] &nbsp;and the implementation shall generate a SIGXFSZ signal for the thread. [IMG19]
[p_00013] If [I20]write[/I20]() is interrupted by a signal before it writes any data, it shall return -1 with [I21]errno[/I21] set to [EINTR].
[p_00014] If [I22]write[/I22]() is interrupted by a signal after it successfully writes some data, it shall return the number of bytes written.
[p_00015] If the value of [I23]nbyte[/I23] is greater than {SSIZE_MAX}, the result is implementation-defined.
[p_00016] After a [I24]write[/I24]() to a regular file has successfully returned:
[p_00017] Any successful [A25][I26]read[/I26]()[/A25] from each byte position in the file that was modified by that write shall return the data specified by the [I27]write[/I27]() for that position until such byte positions are again modified.
[p_00018] Any subsequent successful [I28]write[/I28]() to the same byte position in the file shall overwrite that file data.
[p_00019] Write requests to a pipe or FIFO shall be handled in the same way as a regular file with the following exceptions:
[p_00020] There is no file offset associated with a pipe or FIFO, hence each write request shall append to the end of the pipe or FIFO.
[p_00021] Write requests of {PIPE_BUF} bytes or less shall not be interleaved with data from other threads performing write operations on the same pipe or FIFO. Writes of greater than {PIPE_BUF} bytes may have data interleaved, on arbitrary boundaries, with write operations by other threads, whether or not the O_NONBLOCK flag of the file status flags is set.
[p_00022] If the O_NONBLOCK flag is clear, a write request may cause the thread to block, but on normal completion it shall return [I29]nbyte[/I29].
[p_00023] If the O_NONBLOCK flag is set, [I30]write[/I30]() requests shall be handled differently, in the following ways:
[p_00024] The [I31]write[/I31]() function shall not block the thread.
[p_00025] A write request for {PIPE_BUF} or fewer bytes shall have the following effect: if there is sufficient space available in the pipe or FIFO, [I32]write[/I32]() shall transfer all the data and return the number of bytes requested. Otherwise, [I33]write[/I33]() shall transfer no data and return -1 with [I34]errno[/I34] set to [EAGAIN].
[p_00026] A write request for more than {PIPE_BUF} bytes shall cause one of the following:
[p_00027] When at least one byte can be written, transfer what it can and return the number of bytes written. When all data previously written to the pipe or FIFO is read, it shall transfer at least {PIPE_BUF} bytes.
[p_00028] When no data can be written, transfer no data, and return -1 with [I35]errno[/I35] set to [EAGAIN].
[p_00029] When attempting to write to a file descriptor (other than a pipe or FIFO) that supports non-blocking writes and cannot accept the data immediately:
[p_00030] If the O_NONBLOCK flag is clear, [I36]write[/I36]() shall block the calling thread until the data can be accepted.
[p_00031] If the O_NONBLOCK flag is set, [I37]write[/I37]() shall not block the thread. If some data can be written without blocking the thread, [I38]write[/I38]() shall write what it can and return the number of bytes written. Otherwise, it shall return -1 and set [I39]errno[/I39] to [EAGAIN].
[p_00032] Upon successful completion, where [I40]nbyte[/I40] is greater than 0, [I41]write[/I41]() shall mark for update the last data modification and last file status change timestamps of the file, and if the file is a regular file, the S_ISUID and S_ISGID bits of the file mode may be cleared.
[p_00033] For regular files, no data transfer shall occur past the offset maximum established in the open file description associated with [I42]fildes[/I42].
[p_00034] If [I43]fildes[/I43] refers to a socket, [I44]write[/I44]() shall be equivalent to [A45][I46]send[/I46]()[/A45] with no flags set.
[p_00035] [S47][[A48]SIO[/A48]][/S47] [IMG49] If the O_DSYNC bit has been set, write I/O operations on the file descriptor shall complete as defined by synchronized I/O data integrity completion.
[p_00036] If the O_SYNC bit has been set, write I/O operations on the file descriptor shall complete as defined by synchronized I/O file integrity completion. [IMG50]
[p_00037] [S51][[A52]SHM[/A52]][/S51] [IMG53] If [I54]fildes[/I54] refers to a shared memory object, the result of the [I55]write[/I55]() function is unspecified. [IMG56]
[p_00038] [S57][[A58]TYM[/A58]][/S57] [IMG59] If [I60]fildes[/I60] refers to a typed memory object, the result of the [I61]write[/I61]() function is unspecified. [IMG62]
[p_00039] The [I63]pwrite[/I63]() function shall be equivalent to [I64]write[/I64](), except that it writes into a given position and does not change the file offset (regardless of whether O_APPEND is set). The first three arguments to [I65]pwrite[/I65]() are the same as [I66]write[/I66]() with the addition of a fourth argument [I67]offset[/I67] for the desired position inside the file. An attempt to perform a [I68]pwrite[/I68]() on a file that is incapable of seeking shall result in an error.
[h4_00040] [A69][/A69]RETURN VALUE
[p_00041] Upon successful completion, these functions shall return the number of bytes actually written to the file associated with [I70]fildes[/I70]. This number shall never be greater than [I71]nbyte[/I71]. Otherwise, -1 shall be returned and [I72]errno[/I72] set to indicate the error.
[h4_00042] [A73][/A73]ERRORS
[p_00043] These functions shall fail if:
[dt_00044] [EAGAIN]
[dd_00045] The file is neither a pipe, nor a FIFO, nor a socket, the O_NONBLOCK flag is set for the file descriptor, and the thread would be delayed in the [I74]write[/I74]() operation.
[dt_00046] [EBADF]
[dd_00047] The [I75]fildes[/I75] argument is not a valid file descriptor open for writing.
[dt_00048] [EFBIG]
[dd_00049] An attempt was made to write a file that exceeds the implementation-defined maximum file size and there was no room for any bytes to be written.
[dt_00050] [EFBIG]
[dd_00051] An attempt was made to write a file that exceeds the file size limit of the process, and there was no room for any bytes to be written. [S76][[A77]XSI[/A77]][/S76] [IMG78] &nbsp;A SIGXFSZ signal shall also be generated for the thread. [IMG79]
[dt_00052] [EFBIG]
[dd_00053] The file is a regular file, [I80]nbyte[/I80] is greater than 0, and the starting position is greater than or equal to the offset maximum established in the open file description associated with [I81]fildes[/I81].
[dt_00054] [EINTR]
[dd_00055] The write operation was terminated due to the receipt of a signal, and no data was transferred.
[dt_00056] [EIO]
[dd_00057] The process is a member of a background process group attempting to write to its controlling terminal, TOSTOP is set, the calling thread is not blocking SIGTTOU, the process is not ignoring SIGTTOU, and the process group of the process is orphaned. This error may also be returned under implementation-defined conditions.
[dt_00058] [ENOSPC]
[dd_00059] There was no free space remaining on the device containing the file.
[p_00060] The [I82]pwrite[/I82]() function shall fail if:
[dt_00061] [EINVAL]
[dd_00062] The file is a regular file or block special file, and the [I83]offset[/I83] argument is negative. The file offset shall remain unchanged.
[dt_00063] [ESPIPE]
[dd_00064] The file is incapable of seeking.
[p_00065] The [I84]write[/I84]() function shall fail if:
[dt_00066] [EAGAIN]
[dd_00067] The file is a pipe or FIFO, the O_NONBLOCK flag is set for the file descriptor, and the thread would be delayed in the write operation.
[dt_00068] [EAGAIN] or [EWOULDBLOCK]
[dd_00069] The file is a socket, the O_NONBLOCK flag is set for the file descriptor, and the thread would be delayed in the write operation.
[dt_00070] [ECONNRESET]
[dd_00071] A write was attempted on a socket that is not connected.
[dt_00072] [EPIPE]
[dd_00073] An attempt is made to write to a pipe or FIFO that is not open for reading by any process, or that only has one end open. A SIGPIPE signal shall also be sent to the thread.
[dt_00074] [EPIPE]
[dd_00075] A write was attempted on a socket that is shut down for writing, or is no longer connected. In the latter case, if the socket is of type SOCK_STREAM, a SIGPIPE signal shall also be sent to the thread.
[p_00076] These functions may fail if:
[dt_00077] [EIO]
[dd_00078] A physical I/O error has occurred.
[dt_00079] [ENOBUFS]
[dd_00080] Insufficient resources were available in the system to perform the operation.
[dt_00081] [ENXIO]
[dd_00082] A request was made of a nonexistent device, or the request was outside the capabilities of the device.
[p_00083] The [I85]write[/I85]() function may fail if:
[dt_00084] [EACCES]
[dd_00085] A write was attempted on a socket and the calling process does not have appropriate privileges.
[dt_00086] [ENETDOWN]
[dd_00087] A write was attempted on a socket and the local network interface used to reach the destination is down.
[dt_00088] [ENETUNREACH]
[dd_00089] A write was attempted on a socket and no route to the network is present.

[h4_00095] [A91][/A91]RATIONALE
[p_00096] See also the RATIONALE section in [A92][I93]read[/I93]()[/A92].
[p_00097] An attempt to write to a pipe or FIFO has several major characteristics:
[p_00098] [I94]Atomic/non-atomic[/I94]: A write is atomic if the whole amount written in one operation is not interleaved with data from any other thread. This is useful when there are multiple writers sending data to a single reader. Applications need to know how large a write request can be expected to be performed atomically. This maximum is called {PIPE_BUF}. This volume of POSIX.1-2024 does not say whether write requests for more than {PIPE_BUF} bytes are atomic, but requires that writes of {PIPE_BUF} or fewer bytes shall be atomic.
[p_00099] [I95]Blocking/immediate[/I95]: Blocking is only possible with O_NONBLOCK clear. If there is enough space for all the data requested to be written immediately, the implementation should do so. Otherwise, the calling thread may block; that is, pause until enough space is available for writing. The effective size of a pipe or FIFO (the maximum amount that can be written in one operation without blocking) may vary dynamically, depending on the implementation, so it is not possible to specify a fixed value for it.
[p_00100] [I96]Complete/partial/deferred[/I96]: A write request:
[p_00101] may return:
[dt_00102] Complete
[dd_00103] [I97]ret[/I97]=[I98]nbyte[/I98]
[dt_00104] Partial
[p_00105] This shall never happen if [I99]nbyte[/I99]&lt;={PIPE_BUF}. If it does happen (with [I100]nbyte[/I100]&gt;{PIPE_BUF}), this volume of POSIX.1-2024 does not guarantee atomicity, even if [I101]ret[/I101]&lt;={PIPE_BUF}, because atomicity is guaranteed according to the amount [I102]requested[/I102], not the amount [I103]written[/I103].
[dt_00106] Deferred:
[p_00107] This error indicates that a later request may succeed. It does not indicate that it [I104]shall[/I104] succeed, even if [I105]nbyte[/I105]&lt;={PIPE_BUF}, because if no process reads from the pipe or FIFO, the write never succeeds. An application could usefully count the number of times [EAGAIN] is caused by a particular value of [I106]nbyte[/I106]&gt;{PIPE_BUF} and perhaps do later writes with a smaller value, on the assumption that the effective size of the pipe or FIFO may have decreased.
[p_00108] Partial and deferred writes are only possible with O_NONBLOCK set.

[p_00135] There is no exception regarding partial writes when O_NONBLOCK is set. With the exception of writing to an empty pipe or FIFO, this volume of POSIX.1-2024 does not specify exactly when a partial write is performed since that would require specifying internal details of the implementation. Every application should be prepared to handle partial writes when O_NONBLOCK is set and the requested amount is greater than {PIPE_BUF}, just as every application should be prepared to handle partial writes on other kinds of file descriptors.
[p_00136] The intent of forcing writing at least one byte if any can be written is to assure that each write makes progress if there is any room in the pipe or FIFO. If the pipe or FIFO is empty, {PIPE_BUF} bytes must be written; if not, at least some progress must have been made.
[p_00137] Where this volume of POSIX.1-2024 requires -1 to be returned and [I130]errno[/I130] set to [EAGAIN], most historical implementations return zero (with the O_NDELAY flag set, which is the historical predecessor of O_NONBLOCK, but is not itself in this volume of POSIX.1-2024). The error indications in this volume of POSIX.1-2024 were chosen so that an application can distinguish these cases from end-of-file. While [I131]write[/I131]() cannot receive an indication of end-of-file, [A132][I133]read[/I133]()[/A132] can, and the two functions have similar return values. Also, some existing systems (for example, Eighth Edition) permit a write of zero bytes to mean that the reader should get an end-of-file indication; for those systems, a return value of zero from [I134]write[/I134]() indicates a successful write of an end-of-file indication.
[p_00138] Implementations are allowed, but not required, to perform error checking for [I135]write[/I135]() requests of zero bytes.
[p_00139] The concept of a {PIPE_MAX} limit (indicating the maximum number of bytes that can be written to a pipe or FIFO in a single operation) was considered, but rejected, because this concept would unnecessarily limit application writing.
[p_00140] See also the discussion of O_NONBLOCK in [A136][I137]read[/I137]()[/A136].
[p_00141] Writes can be serialized with respect to other reads and writes. If a [A138][I139]read[/I139]()[/A138] of file data can be proven (by any means) to occur after a [I140]write[/I140]() of the data, it must reflect that [I141]write[/I141](), even if the calls are made by different threads. A similar requirement applies to multiple write operations to the same file position. This is needed to guarantee the propagation of data from [I142]write[/I142]() calls to subsequent [A143][I144]read[/I144]()[/A143] calls. This requirement is particularly significant for networked file systems, where some caching schemes violate these semantics.
[p_00142] Note that this is specified in terms of [A145][I146]read[/I146]()[/A145] and [I147]write[/I147](). The XSI extensions [A148][I149]readv[/I149]()[/A148] and [A150][I151]writev[/I151]()[/A150] also obey these semantics. A new &quot;high-performance&quot; write analog that did not follow these serialization requirements would also be permitted by this wording. This volume of POSIX.1-2024 is also silent about any effects of application-level caching (such as that done by [I152]stdio[/I152]).
[p_00143] This volume of POSIX.1-2024 does not specify the value of the file offset after an error is returned; there are too many cases. For programming errors, such as [EBADF], the concept is meaningless since no file is involved. For errors that are detected immediately, such as [EAGAIN], clearly the pointer should not change. After an interrupt or hardware error, however, an updated value would be very useful and is the behavior of many implementations.
[p_00144] This volume of POSIX.1-2024 does not specify the behavior of concurrent writes to a regular file from multiple threads, except that each write is atomic (see [A153][I154]2.9.7 Thread Interactions with File Operations[/I154][/A153]). Applications should use some form of concurrency control.
[p_00145] This volume of POSIX.1-2024 intentionally does not specify any [I155]pwrite[/I155]() errors related to pipes, FIFOs, and sockets other than [ESPIPE].
