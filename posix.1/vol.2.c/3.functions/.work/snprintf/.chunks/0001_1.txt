[h4_00001] [A1][/A1]NAME
[blockquote_00002] asprintf, dprintf, fprintf, printf, snprintf, sprintf — print formatted output
[h4_00003] [A2][/A2]SYNOPSIS
[p_00004] [CODE3]
[h4_00005] [A4][/A4]DESCRIPTION
[p_00006] The [I5]fprintf[/I5]() function shall place output on the named output [I6]stream[/I6]. The [I7]printf[/I7]() function shall place output on the standard output stream [I8]stdout[/I8]. The [I9]sprintf[/I9]() function shall place output followed by the null byte, [CODE10], in consecutive bytes starting at *[I11]s[/I11]; it is the user's responsibility to ensure that enough space is available.
[p_00007] [S12][[A13]CX[/A13]][/S12] [IMG14] The [I15]asprintf[/I15]() function shall be equivalent to [I16]sprintf[/I16](), except that the output string shall be written to dynamically allocated memory, allocated as if by a call to [A17][I18]malloc[/I18]()[/A17], of sufficient length to hold the resulting string, including a terminating null byte. If the call to [I19]asprintf[/I19]() is successful, the address of this dynamically allocated string shall be stored in the location referenced by [I20]ptr[/I20].
[p_00008] The [I21]dprintf[/I21]() function shall be equivalent to the [I22]fprintf[/I22]() function, except that [I23]dprintf[/I23]() shall write output to the file associated with the file descriptor specified by the [I24]fildes[/I24] argument rather than place output on a stream. [IMG25]
[p_00009] The [I26]snprintf[/I26]() function shall be equivalent to [I27]sprintf[/I27](), with the addition of the [I28]n[/I28] argument which limits the number of bytes written to the buffer referred to by [I29]s[/I29]. If [I30]n[/I30] is zero, nothing shall be written and [I31]s[/I31] may be a null pointer. Otherwise, output bytes beyond the [I32]n[/I32]-1st shall be discarded instead of being written to the array, and a null byte is written at the end of the bytes actually written into the array.
[p_00010] If copying takes place between objects that overlap as a result of a call to [I33]sprintf[/I33]() or [I34]snprintf[/I34](), the results are undefined.
[p_00011] Each of these functions converts, formats, and prints its arguments under control of the [I35]format[/I35]. The application shall ensure that the format is a character string, beginning and ending in its initial shift state, if any. The format is composed of zero or more directives: [I36]ordinary characters[/I36], which are simply copied to the output stream, and [I37]conversion specifications[/I37], each of which shall result in the fetching of zero or more arguments. The results are undefined if there are insufficient arguments for the format. If the format is exhausted while arguments remain, the excess arguments shall be evaluated but are otherwise ignored.
[p_00012] [S38][[A39]CX[/A39]][/S38] [IMG40] Conversions can be applied to the [I41]n[/I41]th argument after the [I42]format[/I42] in the argument list, rather than to the next unused argument. In this case, the conversion specifier character [CODE43] (see below) is replaced by the sequence [CODE44][I45]n[/I45][CODE46], where [I47]n[/I47] is a decimal integer in the range [1,{NL_ARGMAX}], giving the position of the argument in the argument list. This feature provides for the definition of format strings that select arguments in an order appropriate to specific languages (see the EXAMPLES section).
[p_00013] The [I48]format[/I48] can contain either numbered argument conversion specifications (that is, those introduced by [CODE49][I50]n[/I50][CODE51] and optionally containing the [CODE52][I53]m[/I53][CODE54] forms of field width and precision), or unnumbered argument conversion specifications (that is, those introduced by the [CODE55] character and optionally containing the [CODE56] form of field width and precision), but not both. The only exception to this is that [CODE57] can be mixed with the [CODE58][I59]n[/I59][CODE60] form. The results of mixing numbered and unnumbered argument specifications in a format string are undefined. When numbered argument specifications are used, specifying the [I61]N[/I61]th argument requires that all the leading arguments, from the first to the ([I62]N-1[/I62])th, are specified in the format string.
[p_00014] In format strings containing the [CODE63][I64]n[/I64][CODE65] form of conversion specification, numbered arguments in the argument list can be referenced from the format string as many times as required. [IMG66]
[p_00015] In format strings containing the [CODE67] form of conversion specification, each conversion specification uses the first unused argument in the argument list.
[p_00016] [S68][[A69]CX[/A69]][/S68] [IMG70] All forms of the [I71]fprintf[/I71]() functions allow for the insertion of a language-dependent radix character in the output string. The radix character is defined in the current locale (category [I72]LC_NUMERIC ).[/I72] In the POSIX locale, or in a locale where the radix character is not defined, the radix character shall default to a &lt;period&gt; ([CODE73]). [IMG74]

[p_00020] An optional [I97]precision[/I97] that gives the minimum number of digits to appear for the [CODE98], [CODE99], [CODE100], [CODE101], [CODE102], and [CODE103] conversion specifiers; the number of digits to appear after the radix character for the [CODE104], [CODE105], [CODE106], [CODE107], [CODE108], and [CODE109] conversion specifiers; the maximum number of significant digits for the [CODE110] and [CODE111] conversion specifiers; or the maximum number of bytes to be printed from a string in the [CODE112] [S113][[A114]XSI[/A114]][/S113] [IMG115] &nbsp;and [CODE116] [IMG117] &nbsp;conversion specifiers. [p_00022] A [I130]conversion specifier[/I130] character that indicates the type of conversion to be applied.
