[h4_00001] [A1][/A1]NAME
[blockquote_00002] fread — binary input
[h4_00003] [A2][/A2]SYNOPSIS
[p_00004] [CODE3]
[h4_00005] [A4][/A4]DESCRIPTION
[p_00006] The [I5]fread[/I5]() function shall read into the array pointed to by [I6]ptr[/I6] up to [I7]nitems[/I7] elements whose size is specified by [I8]size[/I8] in bytes, from the stream pointed to by [I9]stream[/I9]. For each object, [I10]size[/I10] calls shall be made to the [A11][I12]fgetc[/I12]()[/A11] function and the results stored, in the order read, in an array of [B13]unsigned char[/B13] exactly overlaying the object. The file position indicator for the stream (if defined) shall be advanced by the number of bytes successfully read. If an error occurs, the resulting value of the file position indicator for the stream is unspecified. If a partial element is read, its value is unspecified.
[p_00007] [S14][[A15]CX[/A15]][/S14] [IMG16] The [I17]fread[/I17]() function may mark the last data access timestamp of the file associated with [I18]stream[/I18] for update. The last data access timestamp shall be marked for update by the first successful execution of [A19][I20]fgetc[/I20]()[/A19], [A21][I22]fgets[/I22]()[/A21], [I23]fread[/I23](), [A24][I25]fscanf[/I25]()[/A24], [A26][I27]getc[/I27]()[/A26], [A28][I29]getchar[/I29]()[/A28], [A30][I31]getdelim[/I31]()[/A30], [A32][I33]getline[/I33]()[/A32], or [A34][I35]scanf[/I35]()[/A34] using [I36]stream[/I36] that returns data not supplied by a prior call to [A37][I38]ungetc[/I38]()[/A37]. [IMG39]
[h4_00008] [A40][/A40]RETURN VALUE
[p_00009] The [I41]fread[/I41]() function shall return the number of elements successfully read, which shall be less than [I42]nitems[/I42] only if an error or end-of-file is encountered, or [I43]size[/I43] is zero. If [I44]size[/I44] or [I45]nitems[/I45] is 0, [I46]fread[/I46]() shall return 0 and the contents of the array and the state of the stream shall remain unchanged. Otherwise, if an error occurs, the error indicator for the stream shall be set, [S47][[A48]CX[/A48]][/S47] [IMG49] &nbsp;and [I50]errno[/I50] shall be set to indicate the error. [IMG51]
[h4_00010] [A52][/A52]ERRORS
[p_00011] Refer to [A53][I54]fgetc[/I54]()[/A53].
[h4_00012] [A55][/A55]EXAMPLES
[h5_00013] [A56][/A56]Reading from a Stream
[p_00014] The following example transfers a single 100-byte fixed length record from the [I57]fp[/I57] stream into the array pointed to by [I58]buf[/I58].
[p_00015] If a read error occurs, [I59]elements_read[/I59] will be zero but the number of bytes read from the stream could be anything from zero to [I60]sizeof[/I60]([I61]buf[/I61])-1.
[p_00016] The following example reads multiple single-byte elements from the [I62]fp[/I62] stream into the array pointed to by [I63]buf[/I63].
[p_00017] If a read error occurs, [I64]bytes_read[/I64] will contain the number of bytes read from the stream.
[h4_00018] [A65][/A65]APPLICATION USAGE
[p_00019] The [A66][I67]ferror[/I67]()[/A66] or [A68][I69]feof[/I69]()[/A68] functions must be used to distinguish between an error condition and an end-of-file condition.
[p_00020] Because of possible differences in element length and byte ordering, files written using [A70][I71]fwrite[/I71]()[/A70] are application-dependent, and possibly cannot be read using [I72]fread[/I72]() by a different application or by the same application on a different processor.
