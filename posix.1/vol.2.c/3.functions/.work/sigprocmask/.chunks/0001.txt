[blockquote_00002] pthread_sigmask, sigprocmask — examine and change blocked signals
[h4_00003] [A2][/A2]SYNOPSIS
[blockquote_00004] [CODE3] [CODE4]
[h4_00005] [A5][/A5]DESCRIPTION
[p_00006] The [I6]pthread_sigmask[/I6]() function shall examine or change (or both) the calling thread's signal mask.
[p_00007] If the argument [I7]set[/I7] is not a null pointer, it points to a set of signals to be used to change the currently blocked set.
[p_00008] The argument [I8]how[/I8] indicates the way in which the set is changed, and the application shall ensure it consists of one of the following values:
[dt_00009] SIG_BLOCK
[dd_00010] The resulting set shall be the union of the current set and the signal set pointed to by [I9]set[/I9].
[dt_00011] SIG_SETMASK
[dd_00012] The resulting set shall be the signal set pointed to by [I10]set[/I10].
[dt_00013] SIG_UNBLOCK
[dd_00014] The resulting set shall be the intersection of the current set and the complement of the signal set pointed to by [I11]set[/I11].
[p_00015] If the argument [I12]oset[/I12] is not a null pointer, the previous mask shall be stored in the location pointed to by [I13]oset[/I13]. If [I14]set[/I14] is a null pointer, the value of the argument [I15]how[/I15] is not significant and the thread's signal mask shall be unchanged; thus the call can be used to enquire about currently blocked signals.
[p_00016] If the argument [I16]set[/I16] is not a null pointer, after [I17]pthread_sigmask[/I17]() changes the currently blocked set of signals it shall determine whether there are any pending unblocked signals; if there are any, then at least one of those signals shall be delivered before the call to [I18]pthread_sigmask[/I18]() returns.
[p_00017] It is not possible to block those signals which cannot be ignored. This shall be enforced by the system without causing an error to be indicated.
[p_00018] If any of the SIGFPE, SIGILL, SIGSEGV, or SIGBUS signals are generated while they are blocked, the result is undefined, unless the signal was generated by the action of another process, or by one of the functions [A19][I20]kill[/I20]()[/A19], [A21][I22]pthread_kill[/I22]()[/A21], [A23][I24]raise[/I24]()[/A23], or [A25][I26]sigqueue[/I26]()[/A25].
[p_00019] If [I27]pthread_sigmask[/I27]() fails, the thread's signal mask shall not be changed.
[p_00020] The [I28]sigprocmask[/I28]() function shall be equivalent to [I29]pthread_sigmask[/I29](), except that its behavior is unspecified if called from a multi-threaded process, and on error it returns -1 and sets [I30]errno[/I30] to the error number instead of returning the error number directly.
[h4_00021] [A31][/A31]RETURN VALUE
[p_00022] Upon successful completion, [I32]pthread_sigmask[/I32]() shall return 0; otherwise, it shall return the corresponding error number.
[p_00023] Upon successful completion, [I33]sigprocmask[/I33]() shall return 0; otherwise, -1 shall be returned and [I34]errno[/I34] shall be set to indicate the error.
[h4_00024] [A35][/A35]ERRORS
[p_00025] These functions shall fail if:
[dt_00026] [EINVAL]
[dd_00027] The [I36]set[/I36] argument is not a null pointer and the value of the [I37]how[/I37] argument is not equal to one of the defined values.
[p_00028] These functions shall not return an error code of [EINTR].

[h4_00032] [A41][/A41]APPLICATION USAGE
[p_00033] Although [I42]pthread_sigmask[/I42]() has to deliver at least one of any pending unblocked signals that exist after it has changed the currently blocked set of signals, there is no requirement that the delivered signal(s) include any that were unblocked by the change. If one or more signals that were already unblocked become pending (see [A43][I44]2.4.1 Signal Generation and Delivery[/I44][/A43]) during the period the [I45]pthread_sigmask[/I45]() call is executing, the signal(s) delivered before the call returns might include only those signals.
[h4_00034] [A46][/A46]RATIONALE
[p_00035] When a thread's signal mask is changed in a signal-catching function that is installed by [A47][I48]sigaction[/I48]()[/A47], the restoration of the signal mask on return from the signal-catching function overrides that change (see [A49][I50]sigaction[/I50]()[/A49]). If the signal-catching function was installed with [A51][I52]signal[/I52]()[/A51], it is unspecified whether this occurs.
[p_00036] See [A53][I54]kill[/I54]()[/A53] for a discussion of the requirement on delivery of signals.
