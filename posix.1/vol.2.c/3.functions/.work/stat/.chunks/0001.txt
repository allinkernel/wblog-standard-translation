[h4_00001] [A1][/A1]NAME
[blockquote_00002] fstatat, lstat, stat — get file status
[h4_00003] [A2][/A2]SYNOPSIS
[p_00004] [CODE3]
[h4_00005] [A4][/A4]DESCRIPTION
[p_00006] The [I5]stat[/I5]() function shall obtain information about the named file and write it to the area pointed to by the [I6]buf[/I6] argument. The [I7]path[/I7] argument points to a pathname naming a file. Read, write, or execute permission of the named file is not required. An implementation that provides additional or alternate file access control mechanisms may, under implementation-defined conditions, cause [I8]stat[/I8]() to fail. In particular, the system may deny the existence of the file specified by [I9]path[/I9].
[p_00007] If the named file is a symbolic link, the [I10]stat[/I10]() function shall continue pathname resolution using the contents of the symbolic link, and shall return information pertaining to the resulting file if the file exists.
[p_00008] The [I11]buf[/I11] argument is a pointer to a [B12]stat[/B12] structure, as defined in the [A13][I14]&lt;sys/stat.h&gt;[/I14][/A13] header, into which information is placed concerning the file.
[p_00009] The [I15]stat[/I15]() function shall update any time-related fields (as described in XBD [A16][I17]4.12 File Times Update[/I17][/A16]), before writing into the [B18]stat[/B18] structure.
[p_00010] [S19][[A20]SHM[/A20]][/S19] [IMG21] If the named file is a shared memory object, the implementation shall update in the [B22]stat[/B22] structure pointed to by the [I23]buf[/I23] argument the [I24]st_uid[/I24], [I25]st_gid[/I25], [I26]st_size[/I26], and [I27]st_mode[/I27] fields, and only the S_IRUSR, S_IWUSR, S_IRGRP, S_IWGRP, S_IROTH, and S_IWOTH file permission bits need be valid. The implementation may update other fields and flags. [IMG28]
[p_00011] [S29][[A30]TYM[/A30]][/S29] [IMG31] If the named file is a typed memory object, the implementation shall update in the [B32]stat[/B32] structure pointed to by the [I33]buf[/I33] argument the [I34]st_uid[/I34], [I35]st_gid[/I35], [I36]st_size[/I36], and [I37]st_mode[/I37] fields, and only the S_IRUSR, S_IWUSR, S_IRGRP, S_IWGRP, S_IROTH, and S_IWOTH file permission bits need be valid. The implementation may update other fields and flags. [IMG38]
[p_00012] For all other file types defined in this volume of POSIX.1-2024, the structure members [I39]st_mode[/I39], [I40]st_ino[/I40], [I41]st_dev[/I41], [I42]st_uid[/I42], [I43]st_gid[/I43], [I44]st_atim[/I44], [I45]st_ctim[/I45], and [I46]st_mtim[/I46] shall have meaningful values and the value of the member [I47]st_nlink[/I47] shall be set to the number of hard links to the file.
[p_00013] The [I48]lstat[/I48]() function shall be equivalent to [I49]stat[/I49](), except when [I50]path[/I50] refers to a symbolic link. In that case [I51]lstat[/I51]() shall return information about the link, while [I52]stat[/I52]() shall return information about the file the link references.
[p_00014] For symbolic links, the [I53]st_mode[/I53] member shall contain meaningful information when used with the file type macros. The file mode bits in [I54]st_mode[/I54] are unspecified. The structure members [I55]st_ino[/I55], [I56]st_dev[/I56], [I57]st_uid[/I57], [I58]st_gid[/I58], [I59]st_atim[/I59], [I60]st_ctim[/I60], and [I61]st_mtim[/I61] shall have meaningful values and the value of the [I62]st_nlink[/I62] member shall be set to the number of hard links to the symbolic link. The value of the [I63]st_size[/I63] member shall be set to the length of the pathname contained in the symbolic link not including any terminating null byte.
[p_00015] The [I64]fstatat[/I64]() function shall be equivalent to the [I65]stat[/I65]() or [I66]lstat[/I66]() function, depending on the value of [I67]flag[/I67] (see below), except in the case where [I68]path[/I68] specifies a relative path. In this case the status shall be retrieved from a file relative to the directory associated with the file descriptor [I69]fd[/I69] instead of the current working directory. If the access mode of the open file description associated with the file descriptor is not O_SEARCH, the function shall check whether directory searches are permitted using the current permissions of the directory underlying the file descriptor. If the access mode is O_SEARCH, the function shall not perform the check.
[p_00016] Values for [I70]flag[/I70] are constructed by a bitwise-inclusive OR of flags from the following list, defined in [A71][I72]&lt;fcntl.h&gt;[/I72][/A71]:
[dt_00017] AT_SYMLINK_NOFOLLOW
[dd_00018] If [I73]path[/I73] names a symbolic link, the status of the symbolic link is returned.
[p_00019] If [I74]fstatat[/I74]() is passed the special value AT_FDCWD in the [I75]fd[/I75] parameter, the current working directory shall be used and the behavior shall be identical to a call to [I76]stat[/I76]() or [I77]lstat[/I77]() respectively, depending on whether or not the AT_SYMLINK_NOFOLLOW bit is set in [I78]flag[/I78].
[h4_00020] [A79][/A79]RETURN VALUE
[p_00021] Upon successful completion, these functions shall return 0. Otherwise, these functions shall return -1 and set [I80]errno[/I80] to indicate the error.
[h4_00022] [A81][/A81]ERRORS
[p_00023] These functions shall fail if:
[dt_00024] [EACCES]
[dd_00025] Search permission is denied for a component of the path prefix.
[dt_00026] [EIO]
[dd_00027] An error occurred while reading from the file system.
[dt_00028] [ELOOP]
[dd_00029] A loop exists in symbolic links encountered during resolution of the [I82]path[/I82] argument.
[dt_00030] [ENAMETOOLONG]
[dd_00031] The length of a component of a pathname is longer than {NAME_MAX}.
[dt_00032] [ENOENT]
[dd_00033] A component of [I83]path[/I83] does not name an existing file or [I84]path[/I84] is an empty string.
[dt_00034] [ENOTDIR]
[dd_00035] A component of the path prefix names an existing file that is neither a directory nor a symbolic link to a directory, or the [I85]path[/I85] argument contains at least one non-&lt;slash&gt; character and ends with one or more trailing &lt;slash&gt; characters and the last pathname component names an existing file that is neither a directory nor a symbolic link to a directory.
[dt_00036] [EOVERFLOW]
[dd_00037] The file size in bytes or the number of blocks allocated to the file or the file serial number cannot be represented correctly in the structure pointed to by [I86]buf[/I86].
[p_00038] The [I87]fstatat[/I87]() function shall fail if:
[dt_00039] [EACCES]
[dd_00040] The access mode of the open file description associated with [I88]fd[/I88] is not O_SEARCH and the permissions of the directory underlying [I89]fd[/I89] do not permit directory searches.
[dt_00041] [EBADF]
[dd_00042] The [I90]path[/I90] argument does not specify an absolute path and the [I91]fd[/I91] argument is neither AT_FDCWD nor a valid file descriptor open for reading or searching.
[dt_00043] [ENOTDIR]
[dd_00044] The [I92]path[/I92] argument is not an absolute path and [I93]fd[/I93] is a file descriptor associated with a non-directory file.
[p_00045] These functions may fail if:
[dt_00046] [ELOOP]
[dd_00047] More than {SYMLOOP_MAX} symbolic links were encountered during resolution of the [I94]path[/I94] argument.
[dt_00048] [ENAMETOOLONG]
[dd_00049] The length of a pathname exceeds {PATH_MAX}, or pathname resolution of a symbolic link produced an intermediate result with a length that exceeds {PATH_MAX}.
[dt_00050] [EOVERFLOW]
[dd_00051] A value to be stored would overflow one of the members of the [B95]stat[/B95] structure.
[p_00052] The [I96]fstatat[/I96]() function may fail if:
[dt_00053] [EINVAL]
[dd_00054] The value of the [I97]flag[/I97] argument is not valid.

[h4_00062] [A116][/A116]APPLICATION USAGE
[p_00063] None.
[h4_00064] [A117][/A117]RATIONALE
[p_00065] The intent of the paragraph describing &quot;additional or alternate file access control mechanisms&quot; is to allow a secure implementation where a process with a label that does not dominate the file's label cannot perform a [I118]stat[/I118]() function. This is not related to read permission; a process with a label that dominates the file's label does not need read permission. An implementation that supports write-up operations could fail [A119][I120]fstat[/I120]()[/A119] function calls even though it has a valid file descriptor open for writing.
[p_00066] The purpose of the [I121]fstatat[/I121]() function is to obtain the status of files in directories other than the current working directory without exposure to race conditions. Any part of the path of a file could be changed in parallel to a call to [I122]stat[/I122](), resulting in unspecified behavior. By opening a file descriptor for the target directory and using the [I123]fstatat[/I123]() function it can be guaranteed that the file for which status is returned is located relative to the desired directory.
