[h4_00001] [A1][/A1]NAME
[blockquote_00002] ftruncate — truncate a file to a specified length
[h4_00003] [A2][/A2]SYNOPSIS
[p_00004] [CODE3]
[h4_00005] [A4][/A4]DESCRIPTION
[p_00006] If [I5]fildes[/I5] is not a valid file descriptor open for writing, the [I6]ftruncate[/I6]() function shall fail.
[p_00007] If [I7]fildes[/I7] refers to a regular file, the [I8]ftruncate[/I8]() function shall cause the size of the file to be truncated to [I9]length[/I9]. If the size of the file previously exceeded [I10]length[/I10], the extra data shall no longer be available to reads on the file. If the file previously was smaller than this size, [I11]ftruncate[/I11]() shall increase the size of the file. If the file size is increased, the extended area shall appear as if it were zero-filled. The value of the seek pointer shall not be modified by a call to [I12]ftruncate[/I12]().
[p_00008] Upon successful completion, if [I13]fildes[/I13] refers to a regular file, [I14]ftruncate[/I14]() shall mark for update the last data modification and last file status change timestamps of the file and the S_ISUID and S_ISGID bits of the file mode may be cleared. If the [I15]ftruncate[/I15]() function is unsuccessful, the file is unaffected.
[p_00009] If the request would cause the file size to exceed the soft file size limit for the process, the request shall fail [S16][[A17]XSI[/A17]][/S16] [IMG18] &nbsp;and the implementation shall generate a SIGXFSZ signal for the thread. [IMG19]
[p_00010] If [I20]fildes[/I20] is a file descriptor open for writing and refers to a file that is neither a regular file nor a shared memory object, the result is unspecified.
[p_00011] [S21][[A22]SHM[/A22]][/S21] [IMG23] If [I24]fildes[/I24] refers to a shared memory object, [I25]ftruncate[/I25]() shall set the size of the shared memory object to [I26]length[/I26]. [IMG27]
[p_00012] If the effect of [I28]ftruncate[/I28]() is to decrease the size of a memory mapped file [S29][[A30]SHM[/A30]][/S29] [IMG31] &nbsp;or a shared memory object [IMG32] &nbsp;and whole pages beyond the new end were previously mapped, then the whole pages beyond the new end shall be discarded.
[p_00013] References to discarded pages shall result in the generation of a SIGBUS signal.
[p_00014] If the effect of [I33]ftruncate[/I33]() is to increase the size of a memory object, it is unspecified whether the contents of any mapped pages between the old end-of-file and the new are flushed to the underlying object.
[h4_00015] [A34][/A34]RETURN VALUE
[p_00016] Upon successful completion, [I35]ftruncate[/I35]() shall return 0; otherwise, -1 shall be returned and [I36]errno[/I36] set to indicate the error.
[h4_00017] [A37][/A37]ERRORS
[p_00018] The [I38]ftruncate[/I38]() function shall fail if:
[dt_00019] [EBADF] or [EINVAL]
[dd_00020] The [I39]fildes[/I39] argument is not a file descriptor open for writing.
[dt_00021] [EFBIG] or [EINVAL]
[dd_00022] The [I40]length[/I40] argument is greater than the maximum file size.
[dt_00023] [EFBIG]
[dd_00024] The [I41]length[/I41] argument exceeds the file size limit of the process. [S42][[A43]XSI[/A43]][/S42] [IMG44] &nbsp;A SIGXFSZ signal shall also be generated for the thread. [IMG45]
[dt_00025] [EFBIG]
[dd_00026] The file is a regular file and [I46]length[/I46] is greater than the offset maximum established in the open file description associated with [I47]fildes[/I47].
[dt_00027] [EINTR]
[dd_00028] A signal was caught during execution.
[dt_00029] [EINVAL]
[dd_00030] The [I48]length[/I48] argument is less than 0 or the [I49]fildes[/I49] argument refers to a file on which this operation is not possible (for example, a pipe, FIFO or socket).
[dt_00031] [EIO]
[dd_00032] An I/O error occurred while reading from or writing to a file system.

[h4_00044] [A61][/A61]CHANGE HISTORY
[p_00045] First released in Issue 4, Version 2.
[h4_00046] [A62][/A62]Issue 5
[p_00047] Moved from X/OPEN UNIX extension to BASE and aligned with [I63]ftruncate[/I63]() in the POSIX Realtime Extension. Specifically, the DESCRIPTION is extensively reworded and [EROFS] is added to the list of mandatory errors that can be returned by [I64]ftruncate[/I64]().
[p_00048] Large File Summit extensions are added.
[h4_00049] [A65][/A65]Issue 6
[p_00050] The [A66][I67]truncate[/I67]()[/A66] function is split out into a separate reference page.
[p_00051] The following new requirements on POSIX implementations derive from alignment with the Single UNIX Specification:
[p_00052] The DESCRIPTION is changed to indicate that if the file size is changed, and if the file is a regular file, the S_ISUID and S_ISGID bits in the file mode may be cleared.
[p_00053] The following changes were made to align with the IEEE&nbsp;P1003.1a draft standard:
[p_00054] The DESCRIPTION text is updated.
[p_00055] XSI-conformant systems are required to increase the size of the file if the file was previously smaller than the size requested.
[h4_00056] [A68][/A68]Issue 7
[p_00057] Austin Group Interpretation 1003.1-2001 #056 is applied, revising the ERRORS section (although the [EINVAL] &quot;may fail&quot; error was subsequently removed during review of the XSI option).
[p_00058] Functionality relating to the Memory Protection and Memory Mapped Files options is moved to the Base.
[p_00059] The DESCRIPTION is updated so that a call to [I69]ftruncate[/I69]() when the file is smaller than the size requested will increase the size of the file. Previously, non-XSI-conforming implementations were allowed to increase the size of the file or fail.
[p_00060] Changes are made related to support for finegrained timestamps.
[h4_00061] [A70][/A70]Issue 8
[p_00062] Austin Group Defect 308 is applied, clarifying the handling of [EFBIG] errors.
[p_00063] Austin Group Defect 1169 is applied, removing a redundant statement that [I71]ftruncate[/I71]() fails if [I72]fildes[/I72] refers to a directory.
[p_00064] Austin Group Defect 1381 is applied, adding a second condition to the [EINVAL] error and rearranging the ERRORS section into alphabetical order.
[p_00065] Austin Group Defect 1669 is applied, removing XSI shading from part of the [EFBIG] error relating to the file size limit for the process.
