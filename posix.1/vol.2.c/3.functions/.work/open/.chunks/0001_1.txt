# start_index 1
[h4_00001] [A1][/A1]NAME
[blockquote_00002] open, openat — open file
[h4_00003] [A2][/A2]SYNOPSIS
[p_00004] [CODE3]
[h4_00005] [A4][/A4]DESCRIPTION
[p_00006] The [I5]open[/I5]() function shall establish the connection between a file and a file descriptor. It shall create an open file description that refers to a file and a file descriptor that refers to that open file description. The file descriptor is used by other I/O functions to refer to that file. The [I6]path[/I6] argument points to a pathname naming the file.
[p_00007] The [I7]open[/I7]() function shall return a file descriptor for the named file, allocated as described in [A8][I9]2.6 File Descriptor Allocation[/I9][/A8]. The open file description is new, and therefore the file descriptor shall not share it with any other process in the system. The FD_CLOEXEC file descriptor flag associated with the new file descriptor shall be cleared unless the O_CLOEXEC flag is set in [I10]oflag[/I10]. The FD_CLOFORK file descriptor flag associated with the new file descriptor shall be cleared unless the O_CLOFORK flag is set in [I11]oflag[/I11].
[p_00008] The file offset used to mark the current position within the file shall be set to the beginning of the file.
[p_00009] The file status flags and file access modes of the open file description shall be set according to the value of [I12]oflag[/I12].
[p_00010] Values for [I13]oflag[/I13] are constructed by a bitwise-inclusive OR of flags from the following list, defined in [A14][I15]&lt;fcntl.h&gt;[/I15][/A14]. Applications shall specify exactly one of the first five values (file access modes) below in the value of [I16]oflag[/I16]:
[dt_00011] O_EXEC
[dd_00012] Open for execute only (non-directory files). If [I17]path[/I17] names a directory and O_EXEC is not the same value as O_SEARCH, [I18]open[/I18]() shall fail.
[dt_00013] O_RDONLY
[dd_00014] Open for reading only.
[dt_00015] O_RDWR
[dd_00016] Open for reading and writing. If [I19]path[/I19] names a FIFO, and the implementation does not support opening a FIFO for simultaneous read and write, then [I20]open[/I20]() shall fail.
[dt_00017] O_SEARCH
[dd_00018] Open directory for search only. If [I21]path[/I21] names a non-directory file and O_SEARCH is not the same value as O_EXEC, [I22]open[/I22]() shall fail.
[dt_00019] O_WRONLY
[dd_00020] Open for writing only.
[p_00021] Any combination of the following may be used:
[dt_00022] O_APPEND
[dd_00023] If set, the file offset shall be set to the end of the file prior to each write.
[dt_00024] O_CLOEXEC
[dd_00025] If set, the FD_CLOEXEC flag for the new file descriptor shall be set.
[dt_00026] O_CLOFORK
[dd_00027] If set, the FD_CLOFORK flag for the new file descriptor shall be set.
[dt_00028] O_CREAT
[dd_00029] If the file exists, this flag has no effect except as noted under O_EXCL below. Otherwise, if O_DIRECTORY is not set the file shall be created as a regular file; the user ID of the file shall be set to the effective user ID of the process; the group ID of the file shall be set to the group ID of the file's parent directory or to the effective group ID of the process; and the access permission bits (see [A23][I24]&lt;sys/stat.h&gt;[/I24][/A23]) of the file mode shall be set to the value of the argument following the [I25]oflag[/I25] argument taken as type [B26]mode_t[/B26] modified as follows: a bitwise AND is performed on the file-mode bits and the corresponding bits in the complement of the process' file mode creation mask. Thus, all bits in the file mode whose corresponding bit in the file mode creation mask is set are cleared. When bits other than the file permission bits are set, the effect is unspecified. The argument following the [I27]oflag[/I27] argument does not affect whether the file is open for reading, writing, or for both. Implementations shall provide a way to initialize the file's group ID to the group ID of the parent directory. Implementations may, but need not, provide an implementation-defined way to initialize the file's group ID to the effective group ID of the calling process.
[dt_00030] O_DIRECTORY
[dd_00031] If [I28]path[/I28] resolves to a non-directory file, fail and set [I29]errno[/I29] to [ENOTDIR].
[dt_00032] O_DSYNC
[dd_00033] [S30][[A31]SIO[/A31]][/S30] [IMG32] Write I/O operations on the file descriptor shall complete as defined by synchronized I/O data integrity completion. [IMG33]
[dt_00034] O_EXCL
[dd_00035] If O_CREAT and O_EXCL are set, [I34]open[/I34]() shall fail if the file exists. The check for the existence of the file and the creation of the file if it does not exist shall be atomic with respect to other threads executing [I35]open[/I35]() naming the same filename in the same directory with O_EXCL and O_CREAT set. If O_EXCL and O_CREAT are set, and [I36]path[/I36] names a symbolic link, [I37]open[/I37]() shall fail and set [I38]errno[/I38] to [EEXIST], regardless of the contents of the symbolic link. If O_EXCL is set and O_CREAT is not set, the result is undefined.
[dt_00036] O_NOCTTY
[dd_00037] If set and [I39]path[/I39] identifies a terminal device, [I40]open[/I40]() shall not cause the terminal device to become the controlling terminal for the process. If [I41]path[/I41] does not identify a terminal device, O_NOCTTY shall be ignored.
[dt_00038] O_NOFOLLOW
[dd_00039] If [I42]path[/I42] names a symbolic link, fail and set [I43]errno[/I43] to [ELOOP].
[dt_00040] O_NONBLOCK
[p_00041] If O_NONBLOCK is set, an [I44]open[/I44]() for reading-only shall return without delay. An [I45]open[/I45]() for writing-only shall return an error if no process currently has the file open for reading.
[p_00042] If O_NONBLOCK is clear, an [I46]open[/I46]() for reading-only shall block the calling thread until a thread opens the file for writing. An [I47]open[/I47]() for writing-only shall block the calling thread until a thread opens the file for reading.
[p_00043] When opening a block special or character special file that supports non-blocking opens:
[p_00044] If O_NONBLOCK is set, the [I48]open[/I48]() function shall return without blocking for the device to be ready or available. Subsequent behavior of the device is device-specific.
[p_00045] If O_NONBLOCK is clear, the [I49]open[/I49]() function shall block the calling thread until the device is ready or available before returning.
[p_00046] Otherwise, the O_NONBLOCK flag shall not cause an error, but it is unspecified whether the file status flags will include the O_NONBLOCK flag.
[dt_00047] O_RSYNC
[dd_00048] [S50][[A51]SIO[/A51]][/S50] [IMG52] Read I/O operations on the file descriptor shall complete at the same level of integrity as specified by the O_DSYNC and O_SYNC flags. If both O_DSYNC and O_RSYNC are set in [I53]oflag[/I53], all I/O operations on the file descriptor shall complete as defined by synchronized I/O data integrity completion. If both O_SYNC and O_RSYNC are set in flags, all I/O operations on the file descriptor shall complete as defined by synchronized I/O file integrity completion. [IMG54]
[dt_00049] O_SYNC
[p_00050] [S55][[A56]XSI[/A56]][/S55] [IMG57] The O_SYNC flag shall be supported for regular files, even if the Synchronized Input and Output option is not supported. [IMG58]
[dt_00051] O_TRUNC
[dd_00052] If the file exists and is a regular file, and the file is successfully opened O_RDWR or O_WRONLY, its length shall be truncated to 0, and the mode and owner shall be unchanged. It shall have no effect on FIFO special files or terminal device files. Its effect on other file types is implementation-defined. The result of using O_TRUNC without either O_RDWR or O_WRONLY is undefined.
[dt_00053] O_TTY_INIT
[dd_00054] If [I59]path[/I59] identifies a terminal device other than a pseudo-terminal, the device is not already open in any process, and either O_TTY_INIT is set in [I60]oflag[/I60] or O_TTY_INIT has the value zero, [I61]open[/I61]() shall set any non-standard [B62]termios[/B62] structure terminal parameters to a state that provides conforming behavior (see XBD [A63][I64]11.2 Parameters that Can be Set[/I64][/A63]) and initialize the [B65]winsize[/B65] structure associated with the terminal to appropriate default settings. It is unspecified whether O_TTY_INIT has any effect if the device is already open in any process. If [I66]path[/I66] identifies the subsidiary side of a pseudo-terminal that is not already open in any process, [I67]open[/I67]() shall set any non-standard [B68]termios[/B68] structure terminal parameters to a state that provides conforming behavior and initialize the [B69]winsize[/B69] structure associated with the terminal to appropriate default settings, regardless of whether O_TTY_INIT is set. If [I70]path[/I70] does not identify a terminal device, O_TTY_INIT shall be ignored.
[p_00055] If O_CREAT and O_DIRECTORY are set and the requested access mode is neither O_WRONLY nor O_RDWR, the result is unspecified.
[p_00056] If O_CREAT is set and the file did not previously exist, upon successful completion, [I71]open[/I71]() shall mark for update the last data access, last data modification, and last file status change timestamps of the file and the last data modification and last file status change timestamps of the parent directory.
[p_00057] If O_TRUNC is set and the file did previously exist, upon successful completion, [I72]open[/I72]() shall mark for update the last data modification and last file status change timestamps of the file.
[p_00058] [S73][[A74]SIO[/A74]][/S73] [IMG75] If both the O_SYNC and O_DSYNC flags are set, the effect is as if only the O_SYNC flag was set. [IMG76]
[p_00059] The application shall ensure that it specifies the O_TTY_INIT flag on the first open of a terminal device since system boot or since the device was closed by the process that last had it open. The application need not specify the O_TTY_INIT flag when opening pseudo-terminals. [S77][[A78]XSI[/A78]][/S77] [IMG79] &nbsp;If [I80]path[/I80] names the manager side of a pseudo-terminal device, then it is unspecified whether [I81]open[/I81]() locks the subsidiary side so that it cannot be opened. Conforming applications shall call [A82][I83]unlockpt[/I83]()[/A82] before opening the subsidiary side. [IMG84]
[p_00060] The largest value that can be represented correctly in an object of type [B85]off_t[/B85] shall be established as the offset maximum in the open file description.
[p_00061] The [I86]openat[/I86]() function shall be equivalent to the [I87]open[/I87]() function except in the case where [I88]path[/I88] specifies a relative path. In this case the file to be opened is determined relative to the directory associated with the file descriptor [I89]fd[/I89] instead of the current working directory. If the access mode of the open file description associated with the file descriptor is not O_SEARCH, the function shall check whether directory searches are permitted using the current permissions of the directory underlying the file descriptor. If the access mode is O_SEARCH, the function shall not perform the check.
[p_00062] The [I90]oflag[/I90] parameter and the optional fourth parameter correspond exactly to the parameters of [I91]open[/I91]().
[p_00063] If [I92]openat[/I92]() is passed the special value AT_FDCWD in the [I93]fd[/I93] parameter, the current working directory shall be used and the behavior shall be identical to a call to [I94]open[/I94]().
[h4_00064] [A95][/A95]RETURN VALUE
[p_00065] Upon successful completion, these functions shall open the file and return a non-negative integer representing the file descriptor. Otherwise, these functions shall return -1 and set [I96]errno[/I96] to indicate the error. If -1 is returned, no files shall be created or modified.
[h4_00066] [A97][/A97]ERRORS
[p_00067] These functions shall fail if:
[dt_00068] [EACCES]
[dd_00069] Search permission is denied on a component of the path prefix, or the file exists and the permissions specified by [I98]oflag[/I98] are denied, or the file does not exist and write permission is denied for the parent directory of the file to be created, or O_TRUNC is specified and write permission is denied.
[dt_00070] [EEXIST]
[dd_00071] O_CREAT and O_EXCL are set, and the named file exists.
[dt_00072] [EILSEQ]
[dd_00073] O_CREAT was specified, the file did not exist, and the last pathname component of [I99]path[/I99] is not a portable filename and cannot be created in the target directory.
[dt_00074] [EINTR]
[dd_00075] A signal was caught during [I100]open[/I100]().
[dt_00076] [EINVAL]
[dd_00077] The [I101]path[/I101] argument names a FIFO, O_RDWR was specified, and the implementation considers this an error; [S102][[A103]SIO[/A103]][/S102] [IMG104] &nbsp;or synchronized I/O flags were specified and the implementation does not support synchronized I/O for the file. [IMG105]
[dt_00078] [EISDIR]
[dd_00079] The named file is a directory and [I106]oflag[/I106] includes O_WRONLY or O_RDWR, or includes O_CREAT without O_DIRECTORY, or includes O_EXEC when O_EXEC is not the same value as O_SEARCH.
[dt_00080] [ELOOP]
[dd_00081] A loop exists in symbolic links encountered during resolution of the [I107]path[/I107] argument, or O_NOFOLLOW was specified and the [I108]path[/I108] argument names a symbolic link.
[dt_00082] [EMFILE]
[dd_00083] All file descriptors available to the process are currently open.
[dt_00084] [ENAMETOOLONG]
[dd_00085] The length of a component of a pathname is longer than {NAME_MAX}.
[dt_00086] [ENFILE]
[dd_00087] The maximum allowable number of files is currently open in the system.
[dt_00088] [ENOENT]
[dd_00089] O_CREAT is not set and a component of [I109]path[/I109] does not name an existing file, or O_CREAT is set and a component of the path prefix of [I110]path[/I110] does not name an existing file, or [I111]path[/I111] points to an empty string.
[dt_00090] [ENOENT] or [ENOTDIR]
[dd_00091] O_CREAT is set, and the [I112]path[/I112] argument contains at least one non-&lt;slash&gt; character and ends with one or more trailing &lt;slash&gt; characters. If [I113]path[/I113] without the trailing &lt;slash&gt; characters would name an existing file, an [ENOENT] error shall not occur.
[dt_00092] [ENOSPC]
[dd_00093] The directory or file system that would contain the new file cannot be expanded, the file does not exist, and O_CREAT is specified.
[dt_00094] [ENOTDIR]
[dd_00095] A component of the path prefix names an existing file that is neither a directory nor a symbolic link to a directory; or O_CREAT and O_EXCL are not specified, the [I114]path[/I114] argument contains at least one non-&lt;slash&gt; character and ends with one or more trailing &lt;slash&gt; characters, and the last pathname component names an existing file that is neither a directory nor a symbolic link to a directory; or O_DIRECTORY was specified and the [I115]path[/I115] argument names a non-directory file; or the [I116]path[/I116] argument names a non-directory file and O_SEARCH was specified when O_SEARCH is not the same value as O_EXEC.
[dt_00096] [ENXIO]
[dd_00097] O_NONBLOCK is set, the named file is a FIFO, O_WRONLY is set, and no process has the file open for reading.
[dt_00098] [ENXIO]
[dd_00099] The named file is a character special or block special file, and the device associated with this special file does not exist.
[dt_00100] [EOVERFLOW]
[dd_00101] The named file is a regular file and the size of the file cannot be represented correctly in an object of type [B117]off_t[/B117].
[dt_00102] [EROFS]
[dd_00103] The named file resides on a read-only file system and either O_WRONLY, O_RDWR, O_CREAT (if the file does not exist), or O_TRUNC is set in the [I118]oflag[/I118] argument.
[p_00104] The [I119]openat[/I119]() function shall fail if:
[dt_00105] [EACCES]
[dd_00106] The access mode of the open file description associated with [I120]fd[/I120] is not O_SEARCH and the permissions of the directory underlying [I121]fd[/I121] do not permit directory searches.
[dt_00107] [EBADF]
[dd_00108] The [I122]path[/I122] argument does not specify an absolute path and the [I123]fd[/I123] argument is neither AT_FDCWD nor a valid file descriptor open for reading or searching.
[dt_00109] [ENOTDIR]
[dd_00110] The [I124]path[/I124] argument is not an absolute path and [I125]fd[/I125] is a file descriptor associated with a non-directory file.
[p_00111] These functions may fail if:
[dt_00112] [EAGAIN]
[dd_00113] [S126][[A127]XSI[/A127]][/S126] [IMG128] The [I129]path[/I129] argument names the subsidiary side of a pseudo-terminal device that is locked. [IMG130]
[dt_00114] [EINVAL]
[dd_00115] The value of the [I131]oflag[/I131] argument is not valid.
[dt_00116] [ELOOP]
[dd_00117] More than {SYMLOOP_MAX} symbolic links were encountered during resolution of the [I132]path[/I132] argument.
[dt_00118] [ENAMETOOLONG]
[dd_00119] The length of a pathname exceeds {PATH_MAX}, or pathname resolution of a symbolic link produced an intermediate result with a length that exceeds {PATH_MAX}.
[dt_00120] [EOPNOTSUPP]
[dd_00121] The [I133]path[/I133] argument names a socket.
[dt_00122] [ETXTBSY]
[dd_00123] The file is a pure procedure (shared text) file that is being executed and [I134]oflag[/I134] is O_WRONLY or O_RDWR.

[h4_00132] [A144][/A144]APPLICATION USAGE
[p_00133] POSIX.1-2024 does not require that terminal parameters be automatically set to any state on first open, nor that they be reset after the last close. It is possible for a non-conforming application to leave a terminal device in a state where the next process to use that device finds it in a non-conforming state, but has no way of determining this. To ensure that the device is set to a conforming initial state, applications which perform a first open of a terminal (other than a pseudo-terminal) should do so using the O_TTY_INIT flag to set the parameters associated with the terminal to a conforming state.
[p_00134] Except as specified in this volume of POSIX.1-2024, the flags allowed in [I145]oflag[/I145] are not mutually-exclusive and any number of them may be used simultaneously. Not all combinations of flags make sense. For example, using O_SEARCH | O_CREAT will successfully open a pre-existing directory for searching, but if there is no existing file by that name, then it is unspecified whether a regular file will be created. Likewise, if a non-directory file descriptor is successfully returned, it is unspecified whether that descriptor will have execute permissions as if by O_EXEC (note that it is unspecified whether O_EXEC and O_SEARCH have the same value).
[p_00135] The O_CLOEXEC and O_CLOFORK flags of [I146]open[/I146]() are necessary to avoid a data race in multi-threaded applications. Without O_CLOFORK, a file descriptor is leaked into a child process created by one thread in the window between another thread creating a file descriptor with [I147]open[/I147]() and then using [A148][I149]fcntl[/I149]()[/A148] to set the FD_CLOFORK flag. Without O_CLOEXEC, a file descriptor intentionally inherited by child processes is similarly leaked into an executed program if FD_CLOEXEC is not set atomically.
[h4_00136] [A150][/A150]RATIONALE
[p_00137] Some implementations permit opening FIFOs with O_RDWR. Since FIFOs could be implemented in other ways, and since two file descriptors can be used to the same effect, an implementation is allowed to reject the use of O_RDWR on a FIFO.
[p_00138] See [A151][I152]getgroups[/I152]()[/A151] about the group of a newly created file.
[p_00139] The use of [I153]open[/I153]() to create a regular file is preferable to the use of [A154][I155]creat[/I155]()[/A154], because the latter is redundant and included only for historical reasons.
[p_00140] The use of the O_TRUNC flag on FIFOs and directories (pipes cannot be [I156]open[/I156]()-ed) must be permissible without unexpected side-effects (for example, [A157][I158]creat[/I158]()[/A157] on a FIFO must not remove data). Since terminal special files might have type-ahead data stored in the buffer, O_TRUNC should not affect their content, particularly if a program that normally opens a regular file should open the current controlling terminal instead. Other file types, particularly implementation-defined ones, are left implementation-defined.
[p_00141] POSIX.1-2024 permits [EACCES] to be returned for conditions other than those explicitly listed.
[p_00142] The O_NOCTTY flag was added to allow applications to avoid unintentionally acquiring a controlling terminal as a side-effect of opening a terminal file. This volume of POSIX.1-2024 does not specify how a controlling terminal is acquired, but it allows an implementation to provide this on [I159]open[/I159]() if the O_NOCTTY flag is not set and other conditions specified in XBD [A160][I161]11. General Terminal Interface[/I161][/A160] are met.
[p_00143] In historical implementations the value of O_RDONLY is zero. Because of that, it is not possible to detect the presence of O_RDONLY and another option. Future implementations should encode O_RDONLY and O_WRONLY as bit flags so that:
[p_00144] O_EXEC and O_SEARCH are specified as two of the five file access modes. Since O_EXEC does not apply to directories, and O_SEARCH only applies to directories, their values need not be distinct. Although this standard requires [I162]open[/I162]() to fail on an attempt to use O_EXEC on a directory, or O_SEARCH on a non-directory, this only applies in implementations where the two modes have distinct values. Since O_RDONLY has historically had the value zero, implementations are not able to distinguish between O_SEARCH and O_SEARCH | O_RDONLY, and similarly for O_EXEC.
[p_00145] In general, the [I163]open[/I163]() function follows the symbolic link if [I164]path[/I164] names a symbolic link. However, the [I165]open[/I165]() function, when called with O_CREAT and O_EXCL, is required to fail with [EEXIST] if [I166]path[/I166] names an existing symbolic link, even if the symbolic link refers to a nonexistent file. This behavior is required so that privileged applications can create a new file in a known location without the possibility that a symbolic link might cause the file to be created in a different location.
[p_00146] For example, a privileged application that must create a file with a predictable name in a user-writable directory, such as the user's home directory, could be compromised if the user creates a symbolic link with that name that refers to a nonexistent file in a system directory. If the user can influence the contents of a file, the user could compromise the system by creating a new system configuration or spool file that would then be interpreted by the system. The test for a symbolic link which refers to a nonexisting file must be atomic with the creation of a new file.
[p_00147] In addition, the [I167]open[/I167]() function refuses to open non-directories if the O_DIRECTORY flag is set. This avoids race conditions whereby a user might compromise the system by substituting a hard link to a sensitive file (e.g., a device or a FIFO) while a privileged application is running, where opening a file even for read access might have undesirable side-effects.
[p_00148] In addition, the [I168]open[/I168]() function does not follow symbolic links if the O_NOFOLLOW flag is set. This avoids race conditions whereby a user might compromise the system by substituting a symbolic link to a sensitive file (e.g., a device) while a privileged application is running, where opening a file even for read access might have undesirable side-effects.
[p_00149] The POSIX.1-1990 standard required that the group ID of a newly created file be set to the group ID of its parent directory or to the effective group ID of the creating process. FIPS 151-2 required that implementations provide a way to have the group ID be set to the group ID of the containing directory, but did not prohibit implementations also supporting a way to set the group ID to the effective group ID of the creating process. Conforming applications should not assume which group ID will be used. If it matters, an application can use [A169][I170]chown[/I170]()[/A169] to set the group ID after the file is created, or determine under what conditions the implementation will set the desired group ID.
[p_00150] The purpose of the [I171]openat[/I171]() function is to enable opening files in directories other than the current working directory without exposure to race conditions. Any part of the path of a file could be changed in parallel to a call to [I172]open[/I172](), resulting in unspecified behavior. By opening a file descriptor for the target directory and using the [I173]openat[/I173]() function it can be guaranteed that the opened file is located relative to the desired directory. Some implementations use the [I174]openat[/I174]() function for other purposes as well. In some cases, if the [I175]oflag[/I175] parameter has the O_XATTR bit set, the returned file descriptor provides access to extended attributes. This functionality is not standardized here.
