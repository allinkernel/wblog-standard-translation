[h4_00152] [A180][/A180]FUTURE DIRECTIONS
[p_00153] A future version of this standard may add an O_NOCLOBBER flag, specified as follows, for use by shells when the [I181]noclobber[/I181] option is set (see XRAT [A182][I183]C.2.7.2 Redirecting Output[/I183][/A182]):
[dt_00154] O_NOCLOBBER
[dd_00155] If O_CREAT and O_NOCLOBBER are set, [I184]open[/I184]() shall fail if the file exists and is either a regular file or a symbolic link that resolves to a regular file. The check for the existence and type of the file and the creation of the file if it does not exist shall be atomic with respect to other threads executing [I185]open[/I185]() naming the same filename in the same directory with O_NOCLOBBER and O_CREAT set or with O_EXCL and O_CREAT set. If O_NOCLOBBER and O_CREAT are set, and the file exists and is either a non-regular file or a symbolic link that resolves to a non-regular file, the file shall be opened as if neither flag was set. If O_NOCLOBBER and O_CREAT are set, and [I186]path[/I186] names a symbolic link that does not resolve to an existing file, an empty file shall be created such that [I187]path[/I187] resolves to the newly created file. If O_NOCLOBBER is set and O_CREAT is not set, the result is undefined.

[h4_00159] [A231][/A231]CHANGE HISTORY
[p_00160] First released in Issue 1. Derived from Issue 1 of the SVID.
[h4_00161] [A232][/A232]Issue 5
[p_00162] The DESCRIPTION is updated for alignment with the POSIX Realtime Extension and the POSIX Threads Extension.
[p_00163] Large File Summit extensions are added.
[h4_00164] [A233][/A233]Issue 6
[p_00165] In the SYNOPSIS, the optional include of the [A234][I235]&lt;sys/types.h&gt;[/I235][/A234] header is removed.
[p_00166] The following new requirements on POSIX implementations derive from alignment with the Single UNIX Specification:
[p_00167] The requirement to include [A236][I237]&lt;sys/types.h&gt;[/I237][/A236] has been removed. Although [A238][I239]&lt;sys/types.h&gt;[/I239][/A238] was required for conforming implementations of previous POSIX specifications, it was not required for UNIX applications.
[p_00168] In the DESCRIPTION, O_CREAT is amended to state that the group ID of the file is set to the group ID of the file's parent directory or to the effective group ID of the process. This is a FIPS requirement.
[p_00169] In the DESCRIPTION, text is added to indicate setting of the offset maximum in the open file description. This change is to support large files.
[p_00170] In the ERRORS section, the [EOVERFLOW] condition is added. This change is to support large files.
[p_00171] The [ENXIO] mandatory error condition is added.
[p_00172] The [EINVAL], [ENAMETOOLONG], and [ETXTBSY] optional error conditions are added.
[p_00173] The DESCRIPTION and ERRORS sections are updated so that items related to the optional XSI STREAMS Option Group are marked.
[p_00174] The following changes were made to align with the IEEE&nbsp;P1003.1a draft standard:
[p_00175] An explanation is added of the effect of the O_CREAT and O_EXCL flags when the path refers to a symbolic link.
[p_00176] The [ELOOP] optional error condition is added.
[p_00177] The normative text is updated to avoid use of the term &quot;must&quot; for application requirements.
[p_00178] The DESCRIPTION of O_EXCL is updated in response to IEEE PASC Interpretation 1003.1c #48.
