XSH 函数：rename()

名称 (NAME)

rename、renameat — 重命名文件

提要 (SYNOPSIS)

#include <stdio.h>

int rename(const char *old, const char *new);

[OH] #include <fcntl.h>

[CX] int renameat(int oldfd, const char *old, int newfd,
const char *new);

说明 (DESCRIPTION)

对于 rename()：[CX] 本参考页所述功能与 ISO C 标准一致。此处所述要求与 ISO C 标准之间的任何冲突均属无意。本卷 POSIX.1-2024 遵从 ISO C 标准。

rename() 函数应更改文件的名称。old 参数指向要重命名的文件的路径名。new 参数指向文件的新路径名。[CX] 如果在处理完所有符号链接后，new 参数没有解析到类型为目录的文件的现有目录项，并且 new 参数包含至少一个非 <slash> 字符并以一个或多个尾部 <slash> 字符结尾，则 rename() 应失败。

如果 old 或 new 参数中任一命名一个符号链接，rename() 应对该符号链接本身进行操作，并且不应解析该参数的最后一个组件。如果 old 参数和 new 参数解析到同一现有目录项，或解析到同一现有文件的不同目录项，则 rename() 应成功返回并且不执行其他操作。

如果 old 参数命名一个不是目录的文件且 new 参数命名一个目录，或者 old 命名一个目录且 new 命名一个不是目录的文件，或者 new 命名一个不是空目录的目录，则 rename() 应失败。否则，如果由 new 命名的目录项存在，则应移除它并将 old 重命名为 new。在这种情况下，名为 new 的目录项在整个重命名操作期间应保持对其他线程可见，并引用操作开始前由 new 或 old 引用的文件。

如果任一 pathname 参数引用一个最终组件是 dot 或 dot-dot 的路径，则 rename() 应失败。

如果 old 参数指向符号链接的路径名，则该符号链接应被重命名。如果 new 参数指向符号链接的路径名，则该符号链接应被移除。

old 路径名不应命名 new 路径名的祖先目录。包含 old 的目录和包含 new 的目录需要写访问权限。如果 old 参数指向目录的路径名，则对于由 old 命名的目录以及（如果存在）由 new 命名的目录，可以要求写访问权限。

如果 new 参数命名一个现有文件，且该文件被移除时其链接计数变为 0 并且没有进程打开该文件，则文件占用的空间应被释放，并且该文件应不再可访问。如果移除最后一个链接时有一个或多个进程打开该文件，则链接应在 rename() 返回之前被移除，但文件内容的移除应推迟到对该文件的所有引用都被关闭。

成功完成后，rename() 应将每个文件的父目录的最后数据修改和最后文件状态更改时间戳标记为需要更新。

如果 rename() 函数因 [EIO] 以外的任何原因失败，由 new 命名的任何文件应不受影响。

renameat() 函数应与 rename() 函数等价，但 old 或 new 中任一指定相对路径的情况除外。如果 old 是相对路径，则要重命名的文件是相对于与文件描述符 oldfd 相关联的目录确定的，而不是相对于当前工作目录。如果 new 是相对路径，则同样只是相对于与 newfd 相关联的目录。如果与文件描述符相关联的打开文件描述的访问模式不是 O_SEARCH，则函数应使用文件描述符底层目录的当前权限检查是否允许目录搜索。如果访问模式是 O_SEARCH，则函数不应执行该检查。

如果在 oldfd 或 newfd 参数中向 renameat() 传入特殊值 AT_FDCWD，则在确定相应 path 参数的文件时应使用当前工作目录。

返回值 (RETURN VALUE)

成功完成后，rename() 函数应返回 0。否则，它应返回 -1，[CX] 应设置 errno 以指示错误， 并且由 old 命名的文件和由 new 命名的文件都不应被更改或创建。

[CX] 成功完成后，renameat() 函数应返回 0。否则，它应返回 -1 并设置 errno 以指示错误。

错误 (ERRORS)

rename() [CX] 和 renameat() 函数在以下情况下应失败：

[EACCES]
[CX] 任一路径前缀的某个组件拒绝搜索权限；或者包含 old 或 new 的目录之一拒绝写权限；或者，old 或 new 参数所指向的目录需要写权限却被拒绝。
[EBUSY]
[CX] 由 old 或 new 命名的目录当前正被系统或另一进程使用，并且实现认为这是一个错误。
[EEXIST] 或 [ENOTEMPTY]
[CX] new 参数命名的目录不是空目录。
[EILSEQ]
[CX] 新路径名的最后一个路径名组件不是可移植文件名，并且无法在目标目录中创建。
[EINVAL]
[CX] old 路径名命名 new 路径名的祖先目录，或者任一路径名参数包含一个是 dot 或 dot-dot 的最终组件。
[EIO]
[CX] 发生了物理 I/O 错误。
[EISDIR]
[CX] new 参数指向一个目录，而 old 参数指向一个不是目录的文件。
[ELOOP]
[CX] 在解析 old 或 new 参数期间遇到的符号链接中存在循环。
[EMLINK]
[CX] 由 old 命名的文件是目录，并且 new 的父目录的链接计数将超过 {LINK_MAX}。
[ENAMETOOLONG]
[CX] 路径名的某个组件的长度长于 {NAME_MAX}。
[ENOENT]
[CX] old 参数没有命名一个现有文件，new 的路径前缀的某个组件不存在，或者 old 或 new 指向空字符串。
[ENOSPC]
[CX] 将包含 new 的目录无法被扩展。
[ENOTDIR]
[CX] 任一路径前缀的某个组件命名了一个既不是目录也不是指向目录的符号链接的现有文件；或者 old 参数命名一个目录且 new 参数命名一个非目录文件；或者 old 参数包含至少一个非 <slash> 字符并以一个或多个尾部 <slash> 字符结尾，且最后一个路径名组件命名了一个既不是目录也不是指向目录的符号链接的现有文件；或者 old 参数命名一个现有的非目录文件且 new 参数命名一个不存在的文件，包含至少一个非 <slash> 字符，并以一个或多个尾部 <slash> 字符结尾；或者 new 参数命名一个现有的非目录文件，包含至少一个非 <slash> 字符，并以一个或多个尾部 <slash> 字符结尾。
[EPERM] 或 [EACCES]
[XSI] 包含 old 所引用的文件的目录上设置了 S_ISVTX 标志，并且进程相对于 old 不满足 XBD 4.5 目录保护 中规定的条件；或者 new 引用一个现有文件，包含该文件的目录上设置了 S_ISVTX 标志，并且进程相对于该文件不满足 XBD 4.5 目录保护 中规定的条件。
[EROFS]
[CX] 请求的操作要求在只读文件系统上的目录中进行写。
[EXDEV]
[CX] 由 old 命名的文件与将在其中创建或替换由 new 命名的目录项的目录位于不同的文件系统上，并且实现不支持文件系统之间的硬链接。

[CX] 此外，在以下情况下，renameat() 函数应失败：

[EACCES]
与 oldfd 或 newfd 相关联的打开文件描述的访问模式不是 O_SEARCH，并且 oldfd 或 newfd（分别）底层目录的权限不允许目录搜索。
[EBADF]
old 参数没有指定绝对路径且 oldfd 参数既不是 AT_FDCWD 也不是为读或搜索而打开的有效文件描述符，或者 new 参数没有指定绝对路径且 newfd 参数既不是 AT_FDCWD 也不是为读或搜索而打开的有效文件描述符。
[ENOTDIR]
old 或 new 参数不是绝对路径，并且 oldfd 或 newfd（分别）是与非目录文件相关联的文件描述符。

rename() [CX] 和 renameat() 函数在以下情况下可以失败：

[ELOOP]
[CX] 在解析 old 或 new 参数期间遇到的符号链接超过 {SYMLOOP_MAX} 个。
[ENAMETOOLONG]
[CX] 路径名的长度超过 {PATH_MAX}，或者符号链接的路径名解析产生的中间结果的长度超过 {PATH_MAX}。
[ETXTBSY]
[CX] 由 new 命名的文件存在，并且是正在执行的纯过程（共享文本）文件的最后一个目录项。
The following sections are informative.

示例 (EXAMPLES)

重命名文件 (Renaming a File)

以下示例展示如何将名为 /home/cnd/mod1 的文件重命名为 /home/cnd/mod2。

#include <stdio.h>
 
int status;
...
status = rename("/home/cnd/mod1", "/home/cnd/mod2");

应用程序使用 (APPLICATION USAGE)

某些实现将重命名文件的最后文件状态更改时间戳标记为需要更新，而某些实现不这样做。使用最后文件状态更改时间戳的应用程序在涉及重命名文件时可能表现不同，除非它们被设计为允许任一行为。

原理 (RATIONALE)

此 rename() 函数对于普通文件与 ISO C 标准定义的那个等价。它在此处的纳入将该定义扩展为包括对目录的操作，并规定了 new 参数命名一个已存在的文件时的行为。该规定要求函数的作用是原子的。

引入此函数的原因之一是要有一种重命名目录的手段，同时允许实现禁止对目录使用 link() 和 unlink()，从而将对目录的链接限制为 mkdir() 创建的链接。

关于如果 old 和 new 引用同一文件的规范旨在保证：

rename("x", "x");

不移除该文件。

为阻止循环的文件系统路径，禁止重命名 dot 或 dot-dot。

另请参见 rmdir() 中 [ENOTEMPTY] 和 [ENAMETOOLONG] 的描述以及 unlink() 中 [EBUSY] 的描述。关于 [EXDEV] 的讨论，参见 link()。

renameat() 函数的目的是在不暴露于竞争条件的情况下重命名当前工作目录以外的目录中的文件。文件的路径的任何部分都可能在与 rename() 调用并行的情况下被更改，导致未指定的行为。通过为源目录和目标目录打开文件描述符并使用 renameat() 函数，可以保证被重命名的文件被正确定位，并且结果文件位于所需目录中。

鼓励实现让 rename() 和 renameat() 在由 new 命名的文件尚不存在且该路径名的最后一个组件包含任何具有 <newline> 字符编码值的字节时报告 [EILSEQ] 错误。
