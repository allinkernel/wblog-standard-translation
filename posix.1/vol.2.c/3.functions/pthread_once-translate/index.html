XSH 函数：pthread_once()

名称 (NAME)

pthread_once — 动态包初始化 (dynamic package initialization)

简介 (SYNOPSIS)

#include <pthread.h>

int pthread_once(pthread_once_t *once_control,
void (*init_routine)(void));
pthread_once_t once_control = PTHREAD_ONCE_INIT;

描述 (DESCRIPTION)

进程中任何线程以给定的 once_control 对 pthread_once() 的第一次调用，应调用不带参数的 init_routine。以相同的 once_control 对 pthread_once() 的后续调用不应调用 init_routine。从 pthread_once() 返回时，init_routine 应已完成。once_control 参数应确定相关的初始化例程是否已被调用。

pthread_once() 函数不是取消点。但是，如果 init_routine 是取消点并被取消，则对 once_control 的影响应如同从未调用过 pthread_once()。

如果对 init_routine 的调用因调用 longjmp() 或 siglongjmp() 而终止，则行为未定义。

常量 PTHREAD_ONCE_INIT 在 <pthread.h> 头文件中定义。

如果 once_control 具有自动存储期，或未由 PTHREAD_ONCE_INIT 初始化，则 pthread_once() 的行为未定义。

返回值 (RETURN VALUE)

成功完成后，pthread_once() 应返回零；否则，应返回错误号以指示错误。

错误 (ERRORS)

pthread_once() 函数不应返回 [EINTR] 错误码。

The following sections are informative.

示例 (EXAMPLES)

无。

应用用法 (APPLICATION USAGE)

如果 init_routine 以相同的 once_control 递归调用 pthread_once()，则该递归调用不会调用指定的 init_routine，因此指定的 init_routine 将无法完成，从而对 pthread_once() 的递归调用将不会返回。在 init_routine 中使用 longjmp() 或 siglongjmp() 跳转到 init_routine 之外的点，会阻止 init_routine 返回。

理由 (RATIONALE)

某些 C 库是为动态初始化而设计的。也就是说，库的全局初始化在库中的第一个过程被调用时执行。在单线程程序中，这通常使用一个静态变量来实现，在进入例程时检查该变量的值，如下所示：

static int random_is_initialized = 0;
extern void initialize_random(void);
 
int random_function()
{
    if (random_is_initialized == 0) {
        initialize_random();
        random_is_initialized = 1;
    }
    ... /* Operations performed after initialization. */
}

为了在多线程程序中保持相同的结构，需要一个新的原语。否则，库初始化必须通过在使用库之前显式调用库导出的初始化函数来完成。

对于多线程进程中的动态库初始化，如果使用初始化标志，则需要保护该标志免受同时调用该库的多个线程的修改。这可以通过使用互斥量（通过赋值 PTHREAD_MUTEX_INITIALIZER 初始化）来完成。然而，更好的解决方案是使用正是为此目的而设计的 pthread_once()，如下所示：

#include <pthread.h>
static pthread_once_t random_is_initialized = PTHREAD_ONCE_INIT;
extern void initialize_random(void);
 
int random_function()
{
    (void) pthread_once(&random_is_initialized, initialize_random);
    ... /* Operations performed after initialization. */
}

如果实现检测到 pthread_once() 的 once_control 参数所指定的值未指向由 PTHREAD_ONCE_INIT 初始化的 pthread_once_t 对象，则建议该函数应失败并报告 [EINVAL] 错误。

变更历史 (CHANGE HISTORY)

首次在 Issue 5 中发布。为与 POSIX 线程扩展保持一致而纳入。

第 6 版 (Issue 6)

pthread_once() 函数被标记为 Threads 选项的一部分。

增加了 [EINVAL] 错误作为 "可以失败" 情形，用于任一参数无效的情况。

第 7 版 (Issue 7)

pthread_once() 函数从 Threads 选项移至 Base。

删除了针对未初始化的 pthread_once_t 对象的 [EINVAL] 错误；此情况导致未定义行为。

应用了 POSIX.1-2008 技术勘误 2 的 XSH/TC2-2008/0284 [863]、XSH/TC2-2008/0285 [874]、XSH/TC2-2008/0286 [874] 和 XSH/TC2-2008/0287 [747]。

第 8 版 (Issue 8)

应用了 Austin Group Defect 1330，移除了过时的接口。
