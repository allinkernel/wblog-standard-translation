XSH 函数：getenv()

名称 (NAME)

getenv、secure_getenv — 获取环境变量的值

提要 (SYNOPSIS)

#include <stdlib.h>

char *getenv(const char *name);

[CX] char *secure_getenv(const char *name);

说明 (DESCRIPTION)

[CX] The functionality described on this reference page is aligned with the ISO C standard. Any conflict between the requirements described here and the ISO C standard is unintentional. This volume of POSIX.1-2024 defers to the ISO C standard.

getenv() 函数应在调用进程的环境中（参见 XBD 8. 环境变量）搜索环境变量 name（如果存在），并返回指向该环境变量的值的指针。如果找不到指定的环境变量，则应返回空指针。应用程序应确保不修改由 getenv() 函数所指向的字符串，[CX] 除非它是先前通过向 environ 赋新值 [XSI] 或使用 putenv() 放入环境的可修改对象的一部分。

[CX] 由 getenv() 返回的指针应指向 environ 所指向的环境数据内的一个字符串。

注：
此要求是对 ISO C 标准的扩展，该标准允许 getenv() 将数据复制到内部缓冲区。

secure_getenv() 函数应与 getenv() 等价，不同之处在于：如果调用进程不满足以下所有安全条件，则应返回空指针：

  1. 调用进程的有效用户 ID 和真实用户 ID 在程序启动期间相等。

  2. 调用进程的有效组 ID 和真实组 ID 在程序启动期间相等。

  3. 额外的实现定义的安全条件。

返回值 (RETURN VALUE)

成功完成后，getenv() 应返回一个指向包含指定 name 的值的字符串的指针。如果在调用进程的环境中找不到指定的 name，则应返回空指针。

[CX] 成功完成后，secure_getenv() 应返回一个指向包含指定 name 的值的字符串的指针。如果在调用进程的环境中找不到指定的 name，或者调用进程不满足 DESCRIPTION 中列出的安全条件，则应返回空指针。

错误 (ERRORS)

未定义任何错误。

The following sections are informative.

示例 (EXAMPLES)

获取环境变量的值 (Getting the Value of an Environment Variable)

以下示例获取 HOME 环境变量的值。

#include <stdlib.h>
...
const char *name = "HOME";
char *value;
 
value = getenv(name);

应用程序使用 (APPLICATION USAGE)

无。

原理 (RATIONALE)

clearenv() 函数曾被考虑但被否决。putenv() 函数现在已被纳入，以与 Single UNIX Specification 保持一致。

本标准的某些早期版本不要求 getenv() 是线程安全的，因为它被允许返回指向内部缓冲区的值。然而，ISO C 标准允许的这种行为不再被 POSIX.1 允许。POSIX.1 要求环境数据可通过 environ[] 获得，因此 getenv() 没有理由不能返回指向实际数据的指针而不是副本。因此，getenv() 现在被要求是线程安全的（除非另一线程修改环境）。

符合规范的应用程序被要求不直接修改 environ 所指向的指针，而只能使用 setenv()、unsetenv() 和 putenv() 函数，或对 environ 本身的赋值，来操作进程环境。此约束允许实现妥善管理其分配的内存。这使得实现能够在调用 unsetenv() 时释放其为存储在 environ 中的字符串（也许还有指向它们的指针）分配的任何空间。C 运行时启动过程（即调用 main() 并可能初始化 environ 的过程）也可以初始化一个标志，表明环境尚未被复制到分配的内存中，或者单独的表尚未被初始化。如果应用程序通过向 environ 赋新值切换到全新的环境，这可以被 getenv()、setenv()、unsetenv() 或 putenv() 检测到，实现可以在此时基于新环境重新初始化。（这可能包括将环境字符串复制到新数组中并将 environ 赋为指向它。）

事实上，为了 getenv() 的更高性能，不提供 putenv() 的实现还可以在可被更快搜索的数据结构（如索引哈希表或二叉树）中维护环境的单独副本，并在调用 setenv() 或 unsetenv() 时同时更新该副本和 environ 处的线性列表。在确实提供 putenv() 的实现上，这样的副本可能仍然值得，但需要考虑到应用程序可以直接修改用 putenv() 添加的环境字符串的内容。例如，如果通过搜索副本找到的环境字符串是用 putenv() 添加的，实现就需要检查 environ 中的字符串是否仍然具有相同的名称（如果副本包含值，还要检查值），并且每当搜索副本没有产生匹配时，实现就需要搜索 environ 中每个用 putenv() 添加的环境字符串，以防其中任何一个改变了名称而现在匹配。因此，每次使用 putenv() 向环境添加内容都会降低拥有副本的速度优势。

getenv() 的性能对于拥有大量环境变量的应用程序可能很重要。通常，这样的应用程序将环境用作用户可配置参数的资源数据库。这些变量位于用户的 shell 环境中这一事实通常意味着任何其他使用环境变量的程序（如 ls，它试图使用 COLUMNS ), 或实际上几乎任何实用程序（LANG , LC_ALL , 等等）同样会因对变量进行线性搜索而变慢。

目前不要求实现维护单独的数据结构，甚至不要求实现管理其消耗的内存，因为人们认为这会减少不愿改变其历史实现的实现者之间的共识。
