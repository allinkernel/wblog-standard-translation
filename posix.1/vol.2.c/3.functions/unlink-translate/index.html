XSH 函数：unlink()

名称 (NAME)

unlink、unlinkat — 移除目录项

提要 (SYNOPSIS)

#include <unistd.h>

int unlink(const char *path);

[OH] #include <fcntl.h>

int unlinkat(int fd, const char *path, int flag);

说明 (DESCRIPTION)

unlink() 函数应移除由 path 命名的目录项，并应递减该目录项所引用的文件的链接计数。如果 path 命名一个符号链接，unlink() 应移除该符号链接，并且不应影响由该符号链接的内容命名的任何文件。

当文件的链接计数变为 0 且没有进程通过打开的文件描述符或内存映射（参见 mmap()）引用该文件时，文件占用的空间应被释放，并且该文件应不再可访问。如果移除最后一个链接时有一个或多个进程对文件有这样的引用，则链接应在 unlink() 返回之前被移除，但文件内容的移除应推迟到不再存在对该文件的此类引用时。当文件占用的空间已被释放时，文件的序列号（st_ino），从而文件身份（参见 XBD <sys/stat.h>），应变得可供重用。

path 参数不应命名目录，除非进程具有适当的特权并且实现支持对目录使用 unlink()。

成功完成后，unlink() 应将父目录的最后数据修改和最后文件状态更改时间戳标记为需要更新。此外，如果文件的链接计数不为 0，则应将文件的最后文件状态更改时间戳标记为需要更新。

unlinkat() 函数应与 unlink() 或 rmdir() 函数等价，但 path 指定相对路径的情况除外。在这种情况下，要移除的目录项是相对于与文件描述符 fd 相关联的目录确定的，而不是相对于当前工作目录。如果与文件描述符相关联的打开文件描述的访问模式不是 O_SEARCH，则函数应使用文件描述符底层目录的当前权限检查是否允许目录搜索。如果访问模式是 O_SEARCH，则函数不应执行该检查。

flag 的值由以下列表中的标志按位包含 OR 构成，这些标志定义在 <fcntl.h> 中：

AT_REMOVEDIR
将 fd 和 path 指定的目录项作为目录而非普通文件移除。

如果在 fd 参数中向 unlinkat() 传入特殊值 AT_FDCWD，则应使用当前工作目录，并且行为应分别与调用 unlink() 或 rmdir() 相同，具体取决于 flag 中是否设置了 AT_REMOVEDIR 位。

返回值 (RETURN VALUE)

成功完成后，这些函数应返回 0。否则，这些函数应返回 -1 并设置 errno 以指示错误。如果返回 -1，则所命名的文件不应被更改。

错误 (ERRORS)

在以下情况下，这些函数应失败并且不应 unlink 该文件：

[EACCES]
路径前缀的某个组件被拒绝搜索权限，或者包含要移除的目录项的目录被拒绝写权限。
[EBUSY]
由 path 参数命名的文件无法被 unlink，因为它正被系统或另一进程使用，并且实现认为这是一个错误。
[ELOOP]
在解析 path 参数期间遇到的符号链接中存在循环。
[ENAMETOOLONG]
路径名的某个组件的长度长于 {NAME_MAX}。
[ENOENT]
path 的某个组件没有命名一个现有文件，或者 path 是空字符串。
[ENOTDIR]
路径前缀的某个组件命名了一个既不是目录也不是指向目录的符号链接的现有文件，或者 path 参数包含至少一个非 <slash> 字符并以一个或多个尾部 <slash> 字符结尾，并且最后一个路径名组件命名了一个既不是目录也不是指向目录的符号链接的现有文件。
[EPERM] 或 [EACCES]
[XSI] 包含 path 参数所引用的文件的目录上设置了 S_ISVTX 标志，并且进程不满足 XBD 4.5 目录保护 中规定的条件。
[EROFS]
要 unlink 的目录项是只读文件系统的一部分。

在以下情况下，unlink() 函数应失败并且不应 unlink 该文件：

[EPERM]
由 path 命名的文件是目录，并且调用进程不具有适当的特权，或者实现禁止对目录使用 unlink()。

在以下情况下，unlinkat() 函数应失败并且不应 unlink 该文件：

[EACCES]
与 fd 相关联的打开文件描述的访问模式不是 O_SEARCH，并且 fd 底层目录的权限不允许目录搜索。
[EBADF]
path 参数没有指定绝对路径，并且 fd 参数既不是 AT_FDCWD，也不是为读或搜索而打开的有效文件描述符。
[ENOTDIR]
path 参数不是绝对路径，并且 fd 是与非目录文件相关联的文件描述符。
[EEXIST] 或 [ENOTEMPTY]
flag 参数设置了 AT_REMOVEDIR 位，并且 path 参数命名的目录不是空目录，或者存在指向该目录的、除 dot 或 dot-dot 中的单个项以外的硬链接。
[ENOTDIR]
flag 参数设置了 AT_REMOVEDIR 位，并且 path 没有命名目录。
[EPERM]
由 path 命名的文件是目录，flag 参数没有设置 AT_REMOVEDIR 位，并且调用进程不具有适当的特权，或者实现禁止对目录使用 unlink()。

在以下情况下，这些函数可以失败并且不 unlink 该文件：

[ELOOP]
在解析 path 参数期间遇到的符号链接超过 {SYMLOOP_MAX} 个。
[ENAMETOOLONG]
路径名的长度超过 {PATH_MAX}，或者符号链接的路径名解析产生的中间结果的长度超过 {PATH_MAX}。
[ETXTBSY]
要 unlink 的项是正在执行的纯过程（共享文本）文件的最后一个目录项。

在以下情况下，unlinkat() 函数可以失败并且不 unlink 该文件：

[EINVAL]
flag 参数的值无效。

示例 (EXAMPLES)

移除指向文件的链接 (Removing a Link to a File)

以下示例展示如何通过移除名为 /modules/pass1 的项来移除指向名为 /home/cnd/mod1 的文件的链接。

#include <unistd.h>
 
char *path = "/modules/pass1";
int   status;
...
status = unlink(path);
检查错误 (Checking for an Error)

以下示例片段创建一个名为 LOCKFILE 的临时口令锁文件（定义为 /etc/ptmp），并为其获取文件描述符。如果该文件无法为写而打开，则使用 unlink() 移除文件描述符与 LOCKFILE 之间的链接。

#include <sys/types.h>
#include <stdio.h>
#include <fcntl.h>
#include <errno.h>
#include <unistd.h>
#include <sys/stat.h>
 
#define LOCKFILE "/etc/ptmp"
 
int pfd;  /* Integer for file descriptor returned by open call. */
FILE *fpfd;  /* File pointer for use in putpwent(). */
...
/* Open password Lock file. If it exists, this is an error. */
if ((pfd = open(LOCKFILE, O_WRONLY| O_CREAT | O_EXCL, S_IRUSR
    | S_IWUSR | S_IRGRP | S_IROTH)) == -1)  {
    fprintf(stderr, "Cannot open /etc/ptmp. Try again later.\n");
    exit(1);
}
 
/* Lock file created; proceed with fdopen of lock file so that
   putpwent() can be used.
 */
if ((fpfd = fdopen(pfd, "w")) == NULL) {
    close(pfd);
    unlink(LOCKFILE);
    exit(1);
}
替换文件 (Replacing Files)

以下示例片段使用 unlink() 丢弃指向文件的链接，以便可以用文件的新版本替换它们。第一次调用在发生错误时移除指向 LOCKFILE 的链接。随后的调用移除指向 SAVEFILE 和 PASSWDFILE 的链接，以便可以创建新链接，然后在不再需要时移除指向 LOCKFILE 的链接。

#include <sys/types.h>
#include <stdio.h>
#include <fcntl.h>
#include <errno.h>
#include <unistd.h>
#include <sys/stat.h>
 
#define LOCKFILE "/etc/ptmp"
#define PASSWDFILE "/etc/passwd"
#define SAVEFILE "/etc/opasswd"
...
/* If no change was made, assume error and leave passwd unchanged. */
if (!valid_change) {
    fprintf(stderr, "Could not change password for user %s\n", user);
    unlink(LOCKFILE);
    exit(1);
}
 
/* Change permissions on new password file. */
chmod(LOCKFILE, S_IRUSR | S_IRGRP | S_IROTH);
 
/* Remove saved password file. */
unlink(SAVEFILE);
 
/* Save current password file. */
link(PASSWDFILE, SAVEFILE);
 
/* Remove current password file. */
unlink(PASSWDFILE);
 
/* Save new password file as current password file. */
link(LOCKFILE,PASSWDFILE);
 
/* Remove lock file. */
unlink(LOCKFILE);
 
exit(0);

应用程序使用 (APPLICATION USAGE)

应用程序宜使用 rmdir() 移除目录。

原理 (RATIONALE)

在许多历史实现中，由于 link() 中给出的原因（另请参见 rename()），unlink 目录被限制为超级用户。

[EBUSY] 在历史实现中的含义是 "mount point busy"（挂载点忙）。由于本卷 POSIX.1-2024 不涵盖挂载和卸载的系统管理概念，该错误的描述被更改为 "resource busy"（资源忙）。（当第二个进程试图打开独占使用的设备时，某些设备驱动程序使用此含义。）该措辞还旨在允许实现在目录是任何进程的根目录或当前工作目录时拒绝移除该目录。

标准开发者审查了 TR 24715-2006，并注意到符合 LSB 的实现可能在 unlink 目录时返回 [EISDIR] 而不是 [EPERM]。曾考虑通过将 [EPERM] 的要求更改为 [EPERM] 或 [EISDIR] 来允许这种行为，但决定反对，因为这会破坏现有的严格符合和符合的应用程序。为可移植到 POSIX.1-2024 和 LSB 两者而编写的应用程序应准备好处理任一错误码。

unlinkat() 函数的目的是移除当前工作目录以外的目录中的目录项，而不暴露于竞争条件。文件的路径的任何部分都可能在与 unlink() 调用并行的情况下被更改，导致未指定的行为。通过为目标目录打开文件描述符并使用 unlinkat() 函数，可以保证被移除的目录项位于相对于所需目录的位置。
