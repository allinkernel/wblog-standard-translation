XSH 函数导读：sigprocmask()

0. 总览

sigprocmask() 用于检查并更改调用线程的阻塞信号集合（信号掩码）。头文件为 <signal.h>。原型关键点：int sigprocmask(int how, const sigset_t *restrict set, sigset_t *restrict oset)——how 指定更改方式，set 为要应用的信号集（NULL 时仅查询，此时 how 被忽略），oset 接收旧的掩码。它与 pthread_sigmask() 基本等价，但若从多线程进程调用其行为未指定，且出错时返回 -1 并设置 errno 而非直接返回错误编号。

1. 机制

how 有三种取值：SIG_BLOCK（结果集 = 当前集 ∪ set，即"加入阻塞"）、SIG_SETMASK（结果集 = set，整体替换）、SIG_UNBLOCK（结果集 = 当前集 ∩ set 的补集，即"解除阻塞"）。oset 非空时返回之前的掩码。若 set 非空，更改之后若存在任何待决的未阻塞信号，则调用返回前应传递其中至少一个（但不保证包括本次解除阻塞的信号）。无法忽略的信号不能被阻塞，系统静默强制执行而不报错。失败时信号掩码不被更改；不应返回 [EINTR]。

2. 易错点

  • 多线程：多线程进程应使用 pthread_sigmask()；sigprocmask() 在该场景行为未指定。掩码是每线程的，新创建的线程继承创建者的掩码。
  • SIGFPE/SIGILL/SIGSEGV/SIGBUS 被阻塞：若这些同步信号在阻塞状态下被生成，除非由 kill()/pthread_kill()/raise()/sigqueue() 或另一进程产生，否则结果未定义——例如除零发生在阻塞 SIGFPE 期间即属未定义。
  • 处理程序内改掩码会被覆盖：由 sigaction() 安装的处理程序正常返回时恢复原掩码，会把处理程序内 pthread_sigmask() 的更改覆盖掉（signal() 安装时是否覆盖未指定）。
  • 错误处理差异：pthread_sigmask() 成功返回 0、失败直接返回错误编号；sigprocmask() 失败返回 -1 并置 errno。无效 how 值返回 [EINVAL]。
  • 阻塞与待决：阻塞期间到达的信号转为待决，解除阻塞时至少传递一个；做"先阻塞、后逐信号处理"的设计时（典型的是配合 sigwait()），注意调用返回前信号可能已被传递。

3. 示例

#include <pthread.h>
#include <signal.h>

int main(void) {
    sigset_t mask;
    sigemptyset(&mask);
    sigaddset(&mask, SIGINT);
    sigaddset(&mask, SIGTERM);
    /* 阻塞 SIGINT/SIGTERM，再由专用线程 sigwait() 处理 */
    if (pthread_sigmask(SIG_BLOCK, &mask, NULL) != 0) {
        return 1;
    }
    return 0;
}
