XSH 函数：socket()

名称 (NAME)

socket — 为通信创建端点 (socket — create an endpoint for communication)

摘要 (SYNOPSIS)

#include <sys/socket.h>

int socket(int domain, int type, int protocol);

说明 (DESCRIPTION)

socket() 函数应在通信域中创建一个未绑定的套接字，并返回一个文件描述符，该文件描述符可用于后续对套接字进行操作的函数调用。文件描述符的分配应如 2.6 文件描述符分配 所述。

socket() 函数接受以下参数：

domain
指定要在其中创建套接字的通信域。
type
指定要创建的套接字的类型。
protocol
指定要与套接字一起使用的特定协议。将 protocol 指定为 0 会使 socket() 使用适合所请求套接字类型的未指定默认协议。

domain 参数指定通信域中使用的地址族。系统支持的地址族是实现定义的。

可用于 domain 参数的符号常量在 <sys/socket.h> 头文件中定义。

type 参数指定套接字类型，该类型决定了通过套接字进行通信的语义。定义了以下套接字类型；实现可以指定额外的套接字类型：

SOCK_STREAM
提供有序、可靠、双向、连接模式的字节流，并且可以提供带外数据的传输机制。
SOCK_DGRAM
提供数据报，即无连接模式、不可靠的固定最大长度的消息。
SOCK_SEQPACKET
为记录提供有序、可靠、双向、连接模式的传输路径。一条记录可以使用一个或多个输出操作发送，并使用一个或多个输入操作接收，但单个操作绝不会传输超过一条记录的部分内容。记录边界通过 MSG_EOR 标志对接收方可见。

此外，type 参数可以包含以下列表中标志的按位或（bitwise-inclusive OR）：

SOCK_CLOEXEC
在新文件描述符上原子地设置 FD_CLOEXEC 标志。
SOCK_CLOFORK
在新文件描述符上原子地设置 FD_CLOFORK 标志。
SOCK_NONBLOCK
在新文件描述上设置 O_NONBLOCK 文件状态标志。

实现可以定义额外的标志。

如果 protocol 参数非零，则应指定该地址族支持的协议。如果 protocol 参数为零，则应使用该地址族和类型的默认协议。系统支持的协议是实现定义的。

进程可能需要拥有适当的权限才能使用 socket() 函数或创建某些套接字。

返回值 (RETURN VALUE)

成功完成后，socket() 应返回一个非负整数，即套接字文件描述符。否则，应返回 -1，并设置 errno 以指示错误。

错误 (ERRORS)

在以下情况下，socket() 函数应失败：

[EAFNOSUPPORT]
实现不支持指定的地址族。
[EMFILE]
进程可用的所有文件描述符当前都已打开。
[ENFILE]
系统中不再有可用的文件描述符。
[EPROTONOSUPPORT]
protocol 的值为非零，且该协议不被地址族支持，或该协议不被实现支持。
[EPROTOTYPE]
protocol 的值为非零，且该套接字类型不被协议支持。
[ESOCKTNOSUPPORT] [OB] 或 [EPROTONOSUPPORT] 或 [EPROTOTYPE] 该套接字类型不被地址族支持，或该套接字类型不被实现支持。

在以下情况下，socket() 函数可以失败：

[EACCES]
进程没有适当的权限。
[ENOBUFS]
系统中可用于执行该操作的资源不足。
[ENOMEM]
可用于满足请求的内存不足。
The following sections are informative.

示例 (EXAMPLES)

无。

应用程序使用 (APPLICATION USAGE)

特定地址族的文档指定了每个地址族支持哪些协议。特定协议的文档指定了每个协议支持哪些套接字类型。

应用程序可以通过尝试创建将 domain 设置为所讨论协议的套接字来确定某个地址族是否受支持。

理由 (RATIONALE)

在 type 参数（用于 socket()）中使用 SOCK_CLOEXEC 和 SOCK_CLOFORK 标志对于避免多线程应用程序中的数据竞争是必要的。没有 SOCK_CLOFORK，在一个线程调用 socket() 与另一个线程使用 fcntl() 设置 FD_CLOFORK 标志之间的窗口期内，文件描述符会泄漏到由一个线程创建的子进程中。没有 SOCK_CLOEXEC，如果 FD_CLOEXEC 不是原子设置的，则有意由子进程继承的文件描述符会同样泄漏到被执行的程序中。SOCK_NONBLOCK 标志是为了方便避免额外的 fcntl() 调用。

历史上，该标准未规定在套接字类型不受支持时应使用的 errno 值，并且各实现之间存在差异。一些实现复用了现有的标准 [EPROTONOSUPPORT] 或 [EPROTOTYPE] 值，而另一些实现则将 errno 设置为（当时）非标准的 [ESOCKTNOSUPPORT] 值。在本版本的标准中，这三个值都是允许的，但当未指定协议（即 protocol 的值为零）时，使用 [EPROTONOSUPPORT] 或 [EPROTOTYPE] 被认为具有误导性，因此这些替代项已被标记为过时。如果 protocol 非零，由于错误条件之间没有优先级，即使在针对 [ESOCKTNOSUPPORT] 条件的过时替代项被移除之后，这三个值仍将被允许。

未来方向 (FUTURE DIRECTIONS)

本标准的未来版本可能会禁止在套接字类型不受支持且 protocol 为零时将 errno 设置为 [EPROTONOSUPPORT] 或 [EPROTOTYPE]。
