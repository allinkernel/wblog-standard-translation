XSH 函数：lseek()

名称

lseek — 移动读/写文件偏移

概要

#include <unistd.h>

off_t lseek(int fildes, off_t offset, int whence);

说明

lseek() 函数应按如下方式设置与文件描述符 fildes, 关联的打开文件描述的文件偏移：

  • 如果 whence 为 SEEK_SET，文件偏移应被设置为 offset 字节。

  • 如果 whence 为 SEEK_CUR，文件偏移应被设置为其当前位置加上 offset。

  • 如果 whence 为 SEEK_END，文件偏移应被设置为文件大小加上 offset。

  • 如果 whence 为 SEEK_HOLE，文件偏移应被设置为洞内一个字节的最小位置且不小于 offset，除非如果 offset 落在不在洞内的最后一个字节之后，那么文件偏移可以改为被设置为文件大小。如果 offset 大于或等于文件大小，则应是错误。

  • 如果 whence 为 SEEK_DATA，文件偏移应被设置为不在洞内的一个字节的最小位置且不小于 offset。如果不存在这样的字节，则应是错误。

符号常量 SEEK_SET、SEEK_CUR、SEEK_END、SEEK_HOLE 和 SEEK_DATA 在 <unistd.h> 中定义。

洞是文件内一个连续的字节区域，其所有字节的值都为零。并非所有值为零的字节都需要属于洞；然而，所有可寻址（seekable）的文件应具有一个从文件当前大小开始的虚拟洞，无论该文件是否是稀疏的。

lseek() 在无法寻址的设备上的行为是实现定义的。与这种设备关联的文件偏移的值是未定义的。

lseek() 函数应允许文件偏移被设置到文件中现有数据末尾之外。如果稍后在此位置写入数据，那么在数据实际写入间隙之前，后续对间隙中数据的读取应返回值为 0 的字节。

lseek() 函数本身不应扩展文件的大小。

[SHM] 如果 fildes 引用共享内存对象，lseek() 函数的结果是未指定的。

[TYM] 如果 fildes 引用类型化内存对象，lseek() 函数的结果是未指定的。

返回值

成功完成时，应返回结果偏移（以距文件开头字节数计）。否则，应返回 -1，errno 应被设为指示错误，且文件偏移应保持不变。

错误

如果以下情况，lseek() 函数应失败：

[EBADF]
fildes 参数不是一个打开的文件描述符。
[EINVAL]
whence 参数不是一个合适的值，或者对于普通文件、块特殊文件或目录，结果文件偏移将为负值。
[ENXIO]
whence 参数为 SEEK_HOLE 或 SEEK_DATA，且 offset 大于或等于文件大小；或者 whence 参数为 SEEK_DATA 且偏移落在不在洞内的最后一个字节之后。
[EOVERFLOW]
结果文件偏移将是一个无法在 off_t 类型的对象中正确表示的值。
[ESPIPE]
fildes 参数与管道、FIFO 或套接字关联。

理由 (RATIONALE)

ISO C 标准包含函数 fgetpos() 和 fsetpos()，它们通过使用一种特殊的定位类型来处理非常大的文件。

虽然 lseek() 可以将文件偏移定位到文件末尾之外，但该函数本身不扩展文件的大小。虽然 POSIX.1-2024 中可以直接扩展文件大小的唯一函数是 write()、truncate() 和 ftruncate()，但若干最初源自 ISO C 标准的函数，如 fwrite()、fprintf() 等等，也可以做到（通过引起对 write() 的调用）。

会导致返回 [EINVAL] 的无效文件偏移可能既是实现定义的又是设备相关的（例如，内存可能很少有无效值）。在某些实现中，负文件偏移对于某些设备可能是有效的。

POSIX.1-1990 标准没有专门禁止 lseek() 返回负偏移。因此，要求应用程序在调用前清除 errno 并在返回时检查 errno，以确定返回值 (off_t)-1 是负偏移还是错误条件的指示。标准制定者不希望要求符合的应用程序采取这一行动，并选择要求当对于普通文件、块特殊文件或目录结果文件偏移将为负值时，errno 被设为 [EINVAL]。

并非所有文件系统都支持洞，即使支持稀疏文件的地方，也不要求所有连续的零字节块都被识别为洞。然而，由于要求所有文件具有从当前文件大小开始的虚拟洞，应用程序编写者可以使用 SEEK_HOLE 和 SEEK_DATA 来优化当已知一个字节块全为零时可以运行得更快的算法，因为非稀疏文件将正确地报告整个文件为单个非洞。对于这两个常量，一个简单的递归实现如下，然而，对于支持稀疏文件的文件系统，鼓励实现做得更好。

off_t lseek(int fildes, off_t offset, int whence)
{
    off_t cur, end;
    switch (whence)
    {
    case SEEK_HOLE:
    case SEEK_DATA:
        cur = lseek(fildes, 0, SEEK_CUR);
        if (cur < 0)
            return cur;
        end = lseek(fildes, 0, SEEK_END);
        if (end < 0)
            return end;
        if (offset < end)
            return whence == SEEK_HOLE ?
                end : lseek(fildes, offset, SEEK_SET);
        lseek(fildes, cur, SEEK_SET);
        errno = ENXIO;
        return -1;
    default:
        ... /* Existing implementation */
    }
}

注意，虽然上面看起来像用户空间代码，但 lseek() 不能通过用户空间中的递归调用实现，因为这不符合作业 2.9.7 线程与文件操作的交互 (Thread Interactions with File Operations) 中的原子性要求。
