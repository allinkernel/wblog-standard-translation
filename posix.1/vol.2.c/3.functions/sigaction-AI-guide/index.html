XSH 函数导读：sigaction()

0. 总览

sigaction() 用于检查并更改与特定信号关联的动作，是 POSIX 中安装信号处理程序的首选接口。头文件为 <signal.h>。原型关键点：int sigaction(int sig, const struct sigaction *restrict act, struct sigaction *restrict oact)——act 指定新动作（可为 NULL 仅查询），oact 接收旧动作（可为 NULL）。核心数据结构是 sigaction 结构，含 sa_handler、sa_sigaction（两者存储可重叠，不应同时使用）、sa_mask 与 sa_flags。

1. 机制

通过 sa_flags 控制行为：设置 SA_SIGINFO 时用三参数捕获函数 void func(int signo, siginfo_t *info, void *context)（info 说明信号原因与 si_value 等，context 可转换为 ucontext_t *），否则用一参数的 sa_handler。SA_RESTART 使被中断的可中断函数自动重启而非以 [EINTR] 失败；SA_RESETHAND 在进入处理程序时将处置重置为 SIG_DFL（SIGILL/SIGTRAP 例外）；SA_NODEFER 阻止把 sig 本身加入执行期间的掩码。执行期间的掩码 = 当前掩码 ∪ sa_mask ∪（默认含 sig 自身），正常返回后恢复。动作持续有效，直到再次 sigaction()、SA_RESETHAND 重置或调用 exec。成功返回 0；失败返回 -1、置 errno 且不安装任何新处理程序。

2. 易错点

  • 与 signal() 混用：同一进程中对同一信号混用二者，经 oact 读回的字段值未指定；库例程应始终使用 sigaction()。规范明确要求 sigaction() 能正确保存/恢复 signal() 建立的动作，反之不保证。
  • 处理程序内调用限制：只应调用异步信号安全函数；即使"安全"函数也可能改 errno，处理程序应保存并恢复 errno。longjmp()/siglongjmp() 不在安全列表内，用它离开处理程序必须显式恢复信号掩码。
  • SIGKILL/SIGSTOP：不可捕获/忽略，把它们加入掩码或设为 SIG_DFL 由系统静默强制或不报错（NULL act 查询必须成功）。
  • SA_RESETHAND 与 SA_NODEFER：实现可"如同也设置了 SA_NODEFER"，依赖重置语义时必须显式设置 SA_NODEFER 以保证可移植。
  • 并发 sigwait()：进程内同一信号并发使用 sigaction() 与 sigwait() 结果未指定；设置 SA_SIGINFO 时应用方不应同时动 sa_handler。

3. 示例

#include <signal.h>
#include <stdio.h>

static void handler(int signum) {
    /* 仅可调用异步信号安全函数 */
    (void)signum;
}

int main(void) {
    struct sigaction sa;
    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_RESTART; /* 被处理程序中断的调用自动重启 */
    if (sigaction(SIGINT, &sa, NULL) == -1) {
        perror("sigaction");
        return 1;
    }
    return 0;
}
