XSH 函数导读：fork()

0. 总览

fork() 创建新进程：子进程是调用进程（父进程）的精确副本。头文件为 <unistd.h>；原型为 pid_t fork(void)，另有 pid_t _Fork(void)。成功时向子进程返回 0、向父进程返回子进程的进程 ID；失败时向父进程返回 -1 并设置 errno。

1. 机制

fork() 复制进程映像：子进程获得唯一进程 ID，拥有父进程文件描述符自身的副本（设置了 FD_CLOFORK 的除外，其余与父进程引用同一个打开文件描述），继承打开的目录流、消息目录描述符与信号量，保留内存映射（MAP_PRIVATE 修改互不可见），但不继承父进程拥有的文件锁、待处理信号、闹钟与间隔定时器、每进程定时器及内存锁。子进程以单线程创建：若父进程是多线程，子进程只含调用线程与整个地址空间的副本，因此子进程在成功执行 exec 函数之前只应执行异步信号安全操作。fork() 之后父子进程应都能独立执行。_Fork() 与 fork() 等价，但不调用 pthread_atfork() 注册的 fork 处理器，且本身是异步信号安全的。

2. 易错点

经典坑是缓冲区双写：fork() 前写入 stdio 缓冲的数据被复制进子进程，父子各自冲刷会写出两份或出现交错；子进程里宜只做异步信号安全操作并尽快 exec。另一个是描述符泄漏：未设 FD_CLOFORK 或 FD_CLOEXEC 的描述符全部被子进程继承，可能被长期占用。多线程进程调用 fork() 时，其他线程持有的进程共享锁不会被子进程持有；非进程共享锁在子进程中对其执行任何操作都是未定义行为。还要记住 fork() 返回两次，漏判 pid==-1 会掩盖失败。

3. 示例

#include <unistd.h>
#include <sys/wait.h>

pid_t pid = fork();
if (pid == -1)
    return 1;               /* 失败：未创建子进程 */
if (pid == 0) {
    execl("/bin/ls", "ls", (char *)0);
    _exit(127);             /* exec 失败 */
}
waitpid(pid, NULL, 0);      /* 父进程等待子进程 */
