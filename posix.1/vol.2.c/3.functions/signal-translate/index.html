XSH 函数：signal()

名称 (NAME)

signal — 信号管理

概要 (SYNOPSIS)

#include <signal.h>

void (*signal(int sig, void (*func)(int)))(int);

说明 (DESCRIPTION)

[CX] The functionality described on this reference page is aligned with the ISO C standard. Any conflict between the requirements described here and the ISO C standard is unintentional. This volume of POSIX.1-2024 defers to the ISO C standard.

signal() 函数选择三种方式之一，用于随后处理信号编号 sig 的接收。如果 func 的值为 SIG_DFL，则应对该信号进行默认处理。如果 func 的值为 SIG_IGN，则应忽略该信号。否则，应用程序应确保 func 指向在该信号发生时将被调用的函数。因信号而调用此类函数，或（递归地）调用由该调用所调用的任何进一步函数（标准库中的函数除外），称为 "信号处理程序"。

当信号发生时，且 func 指向一个函数，是否执行以下内容的等效操作是实现定义的：

signal(sig, SIG_DFL);

被执行，或者实现阻止一组实现定义的信号（至少包括 sig）在当前信号处理完成之前发生。（如果 sig 的值为 SIGILL，实现可以另选定义不采取任何操作。）接下来执行以下内容的等效操作：

(*func)(sig);

被执行。如果该函数返回（若确实返回），且 sig 的值是 SIGFPE、SIGILL 或 SIGSEGV，或对应于计算异常的任何其他实现定义的值，则行为未定义。否则，程序应在被中断的点恢复执行。ISO C 标准对应用程序从信号处理程序中调用 raise() 施加了限制。[CX] 此限制不适用于 POSIX 应用程序，因为 POSIX.1-2024 要求 raise() 是异步信号安全的（参见 2.4.3 信号动作）。

[CX] 如果进程是多线程的， 或者进程是单线程的，并且信号处理程序的执行不是以下操作的结果：

  • 进程调用 abort()、raise()、[CX] kill()、pthread_kill() 或 sigqueue() 来产生一个未被阻塞的信号

  • [CX] 一个待决信号被解除阻塞并在解除阻塞的调用返回之前被传递

则在以下情况下行为未定义：

  • 信号处理程序引用任何对象 [CX] （除 errno 之外，具有静态或线程存储期且不是无锁原子对象，[CX] 并且不是不可修改对象（例如，字符串字面量、以 const 限定类型定义的对象以及映射为只读的内存中的对象） ），除非是通过向声明为 volatile sig_atomic_t 的对象赋值，[CX] 并且除非对该对象的先前修改（如果有）发生在信号处理程序被调用之前，且从信号处理程序返回发生在对该对象的下一次修改（如果有）之前。

  • 信号处理程序调用本标准中定义的任何函数 [CX] （2.4 信号概念 中列出的函数之一除外）。

在程序启动时，执行以下内容的等效操作：

signal(sig, SIG_IGN);

对某些信号执行，并执行以下内容的等效操作：

signal(sig, SIG_DFL);

对所有其他信号执行 [CX] （参见 exec）。

signal() 函数成功后不应更改 errno 的设置。

[CX] signal() 函数必须是线程安全的。（参见 2.9.1 线程安全。）

返回值 (RETURN VALUE)

如果请求可以得到满足，signal() 应返回针对指定信号 sig 的最近一次 signal() 调用的 func 值。否则，应返回 SIG_ERR，并在 errno 中存储一个正值。

错误 (ERRORS)

在以下情况下，signal() 函数应失败：

[EINVAL]
[CX] sig 参数不是有效的信号编号，或试图捕获无法捕获的信号或忽略无法忽略的信号。

在以下情况下，signal() 函数可以失败：

[EINVAL]
[CX] 试图将无法捕获或忽略（或两者兼有）的信号的动作设置为 SIG_DFL。

示例 (EXAMPLES)

无。

应用程序使用 (APPLICATION USAGE)

sigaction() 函数提供了更全面、更可靠的信号控制机制；新应用程序应使用 sigaction() 而不是 signal()。

原理说明 (RATIONALE)

ISO C 标准规定，在多线程程序中使用 signal() 会导致未定义行为。然而，POSIX.1 自线程被添加到 ISO C 标准之前就要求 signal() 是线程安全的。
