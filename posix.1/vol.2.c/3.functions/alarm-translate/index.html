XSH 函数：alarm()

名称 (NAME)

alarm — 调度一个报警信号

概要 (SYNOPSIS)

#include <unistd.h>

unsigned alarm(unsigned seconds);

说明 (DESCRIPTION)

alarm() 函数应使系统在 seconds 指定的实时秒数经过后为进程生成 SIGALRM 信号。处理器调度延迟可能阻止进程在信号一生成就处理它。

如果 seconds 为 0，则待决的报警请求（如果有）被取消。

报警请求不会堆叠；只能以这种方式调度一次 SIGALRM 生成。如果 SIGALRM 信号尚未生成，则该调用应导致重新调度生成 SIGALRM 信号的时间。

返回值 (RETURN VALUE)

如果存在一个时间尚未用完的先前 alarm() 请求，则 alarm() 应返回一个非零值，即到先前请求本应生成 SIGALRM 信号之前的秒数。否则，alarm() 应返回 0。

错误 (ERRORS)

alarm() 函数总是成功的，并且没有保留返回值来指示错误。

示例 (EXAMPLES)

应用程序使用 (APPLICATION USAGE)

fork() 函数清除子进程中的待决报警。由 exec 函数之一创建的新进程映像继承旧进程映像中到报警信号剩余的时间。

应用程序开发者应注意，seconds 参数的类型和 alarm() 的返回值是 unsigned。这意味着严格符合规范的 POSIX 系统接口应用程序不能传递大于 {UINT_MAX} 最小保证值的值（ISO C 标准将其设置为 65535），任何传递更大值的应用程序都在限制其可移植性。曾考虑过不同的类型，但历史实现（包括具有 16 位 int 类型的实现）始终使用 unsigned 或 int。

应用程序开发者应注意，当同一进程同时使用 alarm() 和 sleep() 函数时可能发生的交互。

原理说明 (RATIONALE)

许多历史实现（包括 Version 7 和 System V）允许报警提前最多一秒发生。其他实现允许报警提前最多半秒或一个时钟滴答发生，或者根本不允许提前发生。后者被认为最合适，因为它提供了最可预测的行为，尤其是因为信号总是可以因调度而无限期延迟。因此，应用程序可以选择 seconds 参数作为它们希望在信号之前经过的最短时间量。

此处和其他地方（sleep()、times()）的术语 "realtime" 旨在表示英语常用用法中的 "wall clock" 时间，与 "realtime operating systems" 无关。它与 虚拟时间 形成对比，如果只使用 time 一词，可能会被误解。

在一些实现中，包括 4.3 BSD，非常大的 seconds 参数值被静默向下舍入到实现特定的最大值。该最大值足够大（大约几个月），以至于效果不明显。

多线程应用程序中报警的生成有两个可能的选择：为调用线程生成或为进程生成。第一个选项不会特别有用，因为报警状态是按进程维护的，并且由最后一次调用 alarm() 建立的报警是唯一会处于活动状态的报警。

此外，允许为线程生成异步信号将给整个信号模型引入一个例外。这需要有令人信服的理由才能证明合理。
