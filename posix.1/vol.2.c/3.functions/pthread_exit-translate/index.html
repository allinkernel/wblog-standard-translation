XSH 函数：pthread_exit()

名称 (NAME)

pthread_exit — 线程终止 (thread termination)

简介 (SYNOPSIS)

#include <pthread.h>

_Noreturn void pthread_exit(void *value_ptr);

描述 (DESCRIPTION)

pthread_exit() 函数应终止调用线程，并使值 value_ptr 可供与终止线程的任何成功汇合（join）使用。任何已压入但尚未弹出的取消清理处理程序，都应按其压入的相反顺序弹出，然后执行。在所有取消清理处理程序执行完毕后，如果该线程有任何线程特定数据（无论是与键类型 tss_t 还是 pthread_key_t 相关联），都应以未指定的顺序调用适当的析构函数。线程终止不会释放任何应用程序可见的进程资源，包括但不限于互斥量和文件描述符，也不会执行任何进程级清理操作，包括但不限于调用可能存在的任何 atexit() 例程。

当一个不是使用 thrd_create() 创建、也不是最初调用 main() 的那个线程，从用于创建它的启动例程返回时，会隐式调用 pthread_exit()。该函数的返回值应作为线程的退出状态。

如果从因隐式或显式调用 pthread_exit() 而被调用的取消清理处理程序或析构函数中调用 pthread_exit()，则其行为未定义。

在线程终止后，访问该线程局部 (auto) 变量的结果未定义。因此，不应将退出线程局部变量的引用用作 pthread_exit() 的 value_ptr 参数值。

在最后一个线程终止后，进程应以退出状态 0 退出。其行为应如同实现在线程终止时以参数零调用了 exit()。

返回值 (RETURN VALUE)

pthread_exit() 函数不能返回到其调用者。

错误 (ERRORS)

未定义错误。

The following sections are informative.

示例 (EXAMPLES)

无。

应用用法 (APPLICATION USAGE)

不应从使用 thrd_create() 创建的线程中调用 pthread_exit()，因为它们的退出状态具有不同的类型（int 而不是 void *）。如果从初始线程调用 pthread_exit() 而它又不是最后一个终止的线程，则其他线程不应尝试使用 thrd_join() 获取其退出状态。

理由 (RATIONALE)

使用 pthread_create() 启动的线程终止的正常机制，是从启动它的 pthread_create() 调用中指定的例程返回。pthread_exit() 函数提供了线程无需从其启动例程返回即可终止的能力，从而提供了与 exit() 类似的函数。

无论线程终止的方法如何，任何已压入但尚未弹出的取消清理处理程序都会被执行，任何现有线程特定数据的析构函数也都会被执行。本卷 POSIX.1-2024 要求按顺序弹出并调用取消清理处理程序。在所有取消清理处理程序执行完毕后，对于线程中存在的每一项线程特定数据，都会以未指定的顺序调用线程特定数据析构函数。这种排序是必要的，因为取消清理处理程序可能依赖于线程特定数据。

由于状态的含义由应用程序决定（除非线程已被取消，在这种情况下它是 PTHREAD_CANCELED），实现无法知道什么是非法的状态值，这就是为什么不进行任何地址错误检查。
