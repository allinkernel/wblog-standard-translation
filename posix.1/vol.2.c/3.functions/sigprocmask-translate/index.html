XSH 函数：sigprocmask()

名称 (NAME)

pthread_sigmask, sigprocmask — 检查并更改阻塞的信号

概要 (SYNOPSIS)

[CX] #include <signal.h>

int pthread_sigmask(int how, const sigset_t *restrict set,
sigset_t *restrict oset);
int sigprocmask(int how, const sigset_t *restrict set,
sigset_t *restrict oset);

说明 (DESCRIPTION)

pthread_sigmask() 函数应检查或更改（或两者兼有）调用线程的信号掩码。

如果 set 参数不是空指针，则它指向一组用于更改当前阻塞集的信号。

how 参数指示更改该集的方式，应用程序应确保它由以下值之一组成：

SIG_BLOCK
结果集应是当前集与 set 指向的信号集的并集。
SIG_SETMASK
结果集应是 set 指向的信号集。
SIG_UNBLOCK
结果集应是当前集与 set 指向的信号集的补集的交集。

如果 oset 参数不是空指针，则先前的掩码应存储在 oset 指向的位置。如果 set 是空指针，则 how 参数的值无关紧要，线程的信号掩码应保持不变；因此，该调用可用于查询当前阻塞的信号。

如果 set 参数不是空指针，则在 pthread_sigmask() 更改当前阻塞的信号集之后，它应确定是否存在任何待决的未阻塞信号；如果存在，则在 pthread_sigmask() 调用返回之前，应传递这些信号中的至少一个。

不可能阻塞那些无法忽略的信号。系统应强制执行这一点而不指示错误。

如果在 SIGFPE、SIGILL、SIGSEGV 或 SIGBUS 信号被阻塞时生成其中任何一个，则结果是未定义的，除非该信号是由另一个进程的动作或由 kill()、pthread_kill()、raise() 或 sigqueue() 函数之一生成的。

如果 pthread_sigmask() 失败，则线程的信号掩码不应被更改。

sigprocmask() 函数应等同于 pthread_sigmask()，不同之处在于如果从多线程进程中调用，其行为是未指定的，并且在出错时返回 -1 并将 errno 设置为错误编号，而不是直接返回错误编号。

返回值 (RETURN VALUE)

成功完成后，pthread_sigmask() 应返回 0；否则，应返回相应的错误编号。

成功完成后，sigprocmask() 应返回 0；否则，应返回 -1，并设置 errno 以指示错误。

错误 (ERRORS)

在以下情况下，这些函数应失败：

[EINVAL]
set 参数不是空指针，并且 how 参数的值不等于定义的值之一。

这些函数不应返回 [EINTR] 错误代码。

示例 (EXAMPLES)

在多线程进程中发送信号 (Signaling in a Multi-Threaded Process)

此示例展示了使用 pthread_sigmask() 来处理多线程进程中的信号。它提供了一个相当通用的框架，可以很容易地改编/扩展。

#include <stdio.h>
#include <stdlib.h>
#include <pthread.h>
#include <signal.h>
#include <string.h>
#include <errno.h>
...
 
static sigset_t   signal_mask;  /* signals to block         */
 
int main (int argc, char *argv[])
{
    pthread_t  sig_thr_id;      /* signal handler thread ID */
    int        rc;              /* return code              */
 
    sigemptyset (&signal_mask);
    sigaddset (&signal_mask, SIGINT);
    sigaddset (&signal_mask, SIGTERM);
    rc = pthread_sigmask (SIG_BLOCK, &signal_mask, NULL);
    if (rc != 0) {
        /* handle error */
        ...
    }
    /* any newly created threads inherit the signal mask */
 
    rc = pthread_create (&sig_thr_id, NULL, signal_thread, NULL);
    if (rc != 0) {
        /* handle error */
        ...
    }
 
    /* APPLICATION CODE */
    ...
}
 
void *signal_thread (void *arg)
{
    int       sig_caught;    /* signal caught       */
    int       rc;            /* returned code       */
 
    rc = sigwait (&signal_mask, &sig_caught);
    if (rc != 0) {
        /* handle error */
    }
    switch (sig_caught)
    {
    case SIGINT:     /* process SIGINT  */
        ...
        break;
    case SIGTERM:    /* process SIGTERM */
        ...
        break;
    default:         /* should normally not happen */
        fprintf (stderr, "\nUnexpected signal %d\n", sig_caught);
        break;
    }
}

应用程序使用 (APPLICATION USAGE)

尽管 pthread_sigmask() 必须传递在它更改当前阻塞的信号集之后存在的任何待决未阻塞信号中的至少一个，但不要求传递的信号包括由该更改解除阻塞的任何信号。如果在 pthread_sigmask() 调用执行期间，一个或多个已经解除阻塞的信号变为待决（参见 2.4.1 信号的产生与传递），则调用返回之前传递的信号可能只包括这些信号。

原理说明 (RATIONALE)

当在由 sigaction() 安装的信号捕获函数中更改线程的信号掩码时，从信号捕获函数返回时恢复信号掩码会覆盖该更改（参见 sigaction()）。如果信号捕获函数是使用 signal() 安装的，则是否发生这种情况是未指定的。

关于信号传递要求的讨论，参见 kill()。
