XSH 函数导读：getenv()

0. 总览

getenv() 获取环境变量的值：在调用进程的环境中搜索名为 name 的环境变量，找到则返回指向其值的指针，找不到返回空指针。头文件为 <stdlib.h>。原型关键点：char *getenv(const char *name)——仅此一个参数，不设任何错误。

1. 机制

返回的指针指向 environ 所指向的环境数据内的一个字符串（这是对 ISO C 的扩展：ISO C 允许把数据复制到内部缓冲区，而 POSIX 要求直接指向真实数据）。因此 getenv() 被要求是线程安全的——除非另一线程正在修改环境。与它配套的 secure_getenv() 行为等价，但当调用进程不满足安全条件时返回空指针：有效用户 ID 与真实用户 ID 在程序启动期间不相等、有效组 ID 与真实组 ID 在程序启动期间不相等，或额外的实现定义的安全条件。这些函数未定义任何错误，也不设置 errno。

2. 易错点

  • 返回指针的修改限制：应用程序应确保不修改 getenv() 返回的字符串——除非它是先前通过向 environ 赋新值或使用 putenv() 放入环境的可修改对象的一部分。
  • 修改环境要用 setenv()/unsetenv()/putenv()（或对 environ 本身赋值），不要直接改动 environ 指向的字符串内容。
  • 返回值可能随后续环境操作失效：调用 setenv()/unsetenv()/putenv() 后，先前取得的指针可能指向已被释放或重排的数据，不应长期保存后使用。
  • 找不到变量与“值为空字符串”不同：返回空指针表示不存在；"" 表示存在但值为空。
  • 在安全敏感场景（如 setuid 程序、检查启动时环境）应使用 secure_getenv()，否则可能信任了被攻击者控制的环境变量。

3. 示例

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    const char *home = getenv("HOME");
    if (home == NULL) {
        puts("未设置 HOME");
        return 0;
    }
    printf("HOME=%s\n", home); /* 只读使用，不修改该字符串 */
    return 0;
}
