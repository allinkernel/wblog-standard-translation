XSH 函数：sleep()

名称 (NAME)

sleep — 挂起执行一段时间间隔

概要 (SYNOPSIS)

#include <unistd.h>

unsigned sleep(unsigned seconds);

说明 (DESCRIPTION)

sleep() 函数应使调用线程挂起执行，直到 seconds 参数指定的实时秒数经过，或直到信号被传递给调用线程且其动作是调用信号捕获函数或终止进程。由于系统调度其他活动，挂起时间可能比请求的时间长。

在单线程程序中，sleep() 可以使用 SIGALRM。在多线程程序中，sleep() 不应使用 SIGALRM，并且本 DESCRIPTION（说明）的其余部分不适用。

如果在 sleep() 执行期间为调用进程生成了 SIGALRM 信号，并且 SIGALRM 信号被忽略或阻塞而无法传递，则 sleep() 是否在 SIGALRM 信号被调度时返回是未指定的。如果该信号被阻塞，则它在 sleep() 返回后是保持待决还是被丢弃也是未指定的。

如果在 sleep() 执行期间为调用进程生成了 SIGALRM 信号（不是由先前调用 alarm() 所致），并且 SIGALRM 信号未被忽略或阻塞而无法传递，则该信号除了导致 sleep() 返回之外是否还有其他任何效果是未指定的。

如果信号捕获函数中断了 sleep()，并检查或更改了 SIGALRM 被调度生成的时间、与 SIGALRM 信号关联的动作，或 SIGALRM 信号是否被阻塞而无法传递，则结果是未指定的。

如果信号捕获函数中断了 sleep()，并调用 siglongjmp() 或 longjmp() 来恢复在 sleep() 调用之前保存的环境，则与 SIGALRM 信号关联的动作以及 SIGALRM 信号被调度生成的时间是未指定的。除非进程的信号掩码作为环境的一部分被恢复，否则 SIGALRM 信号是否被阻塞也是未指定的。

返回值 (RETURN VALUE)

如果 sleep() 因请求的时间已过而返回，则返回值应为 0。如果 sleep() 因信号传递而返回，则返回值应为 "未睡足" 的时间量（请求的时间减去实际睡眠的时间），以秒为单位。

错误 (ERRORS)

未定义任何错误。

原理说明 (RATIONALE)

sleep() 函数的实现有两种一般方法。一种是使用 alarm() 函数调度 SIGALRM 信号，然后挂起调用线程等待该信号。另一种是实现一个独立的设施。本卷 POSIX.1-2024 允许在单线程程序中使用任一方法，但简单的 alarm/挂起实现不适合多线程程序。

为了遵守本卷 POSIX.1-2024 中除明确描述外任何原语都不应更改进程属性的要求，使用 SIGALRM 的实现必须仔细考虑先前 alarm() 调用调度的任何 SIGALRM 信号、先前为 SIGALRM 建立的动作以及 SIGALRM 是否被阻塞。如果在 sleep() 通常会完成之前已调度了 SIGALRM，则 sleep() 必须缩短到该时间，并在 sleep() 返回之前生成 SIGALRM（可能通过直接调用信号捕获函数来模拟）。如果在 sleep() 通常会完成之后已调度了 SIGALRM，则必须在 sleep() 返回之前将其重新调度到同一时间。SIGALRM 的动作和阻塞必须被保存和恢复。

历史实现通常使用 alarm() 和 pause() 实现基于 SIGALRM 的版本。其中一种实现容易出现无限挂起，如 pause() 中所述。另一种此类实现使用 C 语言的 setjmp() 和 longjmp() 函数来避免该窗口。该实现引入了另一个问题：当 SIGALRM 信号中断用户为捕获另一个信号而安装的信号捕获函数时，longjmp() 会中止该信号捕获函数。基于 sigprocmask()、alarm() 和 sigsuspend() 的实现可以避免这些问题。

尽管采取了所有合理的谨慎措施，但两种类型的实现之间仍存在一些非常微妙但可检测且不可避免的差异。这些就是本卷 POSIX.1-2024 中提到的情况，即发生与 SIGALRM 相关的某些其他活动，并且结果被声明为未指定。所有这些情况都足够罕见，不会引起大多数应用程序的关注。

另请参见 alarm() 中对术语 实时 的讨论。

由于 sleep() 可以使用 alarm() 实现，因此在 alarm() 下关于报警提前发生的讨论也适用于 sleep()。

应用程序开发者应注意，seconds 参数的类型和 sleep() 的返回值是 unsigned。这意味着严格符合规范的 POSIX 系统接口应用程序不能传递大于 {UINT_MAX} 最小保证值的值（ISO C 标准将其设置为 65535），任何传递更大值的应用程序都在限制其可移植性。曾考虑过不同的类型，但历史实现（包括具有 16 位 int 类型的实现）始终使用 unsigned 或 int。

调度延迟可能导致进程在请求的时间之后很久才从 sleep() 函数返回。在这种情况下，返回值应设置为零，因为公式（请求的时间减去实际花费的时间）产生负数，而 sleep() 返回 unsigned。

未来方向 (FUTURE DIRECTIONS)

本标准的未来版本可能要求 sleep() 在所有程序中都不使用 SIGALRM，而不仅仅是在多线程程序中。
