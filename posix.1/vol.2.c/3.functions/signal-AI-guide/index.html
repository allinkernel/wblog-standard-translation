XSH 函数导读：signal()

0. 总览

signal() 用于设置信号编号 sig 的后续处理方式，是 POSIX 中信号管理最基础的接口。头文件为 <signal.h>。原型关键点是返回类型：void (*signal(int sig, void (*func)(int)))(int)——它接收一个信号编号和一个函数指针，返回上一次安装的处理函数指针（或 SIG_ERR），这个返回类型本身就是 C 里函数指针写法最绕的例子之一。本页功能与 ISO C 标准对齐，冲突时以 ISO C 为准。

1. 机制

func 有三种取值：SIG_DFL（默认处理）、SIG_IGN（忽略该信号），或者指向用户函数的指针。信号发生时，实现等价于执行 signal(sig, SIG_DFL);（或临时阻塞一组实现定义的信号）再调用 (*func)(sig)——因此 signal() 默认"一次性"：处理完一次后恢复默认动作，若想持续捕获需在处理器内重新安装。程序启动时，部分信号被设为 SIG_IGN，其余设为 SIG_DFL（参考 exec 的描述）。函数成功后不应改变 errno，且必须是线程安全的。

2. 易错点

  • 历史遗留语义：ISO C 允许实现选择"先重置为 SIG_DFL"或"阻塞期间"两种模型，导致 signal() 在不同系统上行为不一；新应用程序应改用 sigaction()，它提供更全面、可靠的信号控制。
  • 处理程序内访问对象受限：除 errno 外，处理程序引用静态或线程存储期的对象（除非是无锁原子对象或只读对象，且仅通过 volatile sig_atomic_t 赋值）属未定义行为；调用除异步信号安全函数之外的任何标准函数同样未定义。
  • 异常信号不可"返回"：若处理器返回，且 sig 是 SIGFPE、SIGILL、SIGSEGV 或任何对应计算异常的信号，行为未定义。
  • 多线程：除非信号由 abort/raise/kill/pthread_kill/sigqueue 产生或解除阻塞时被传递，否则处理程序访问上述对象属未定义行为。
  • 错误处理：无效信号编号或试图捕获/忽略不可捕获的信号返回 SIG_ERR 并置 errno 为正值（EINVAL）。

3. 示例

#include <signal.h>
#include <stdio.h>

static void handler(int sig) {
    /* 只允许写 volatile sig_atomic_t */
    (void)sig;
}

int main(void) {
    if (signal(SIGINT, handler) == SIG_ERR) {
        perror("signal");
        return 1;
    }
    return 0;
}
