XSH 函数：exit()

名称 (NAME)

exit — 终止进程 (terminate a process)

概要 (SYNOPSIS)

#include <stdlib.h>

void exit(int status);

说明 (DESCRIPTION)

[CX] The functionality described on this reference page is aligned with the ISO C standard. Any conflict between the requirements described here and the ISO C standard is unintentional. This volume of POSIX.1-2024 defers to the ISO C standard.

exit() 函数应导致正常进程终止发生。由 at_quick_exit() 函数注册的任何函数不应被调用。如果进程多次调用 exit() 函数，或者除了 exit() 函数之外还调用 quick_exit() 函数，则行为是未定义的。

status 的值可以是 0、EXIT_SUCCESS、EXIT_FAILURE、[CX] 或任何其他值，尽管只有最低有效的 8 位（即 status & 0377）应可从 wait() 和 waitpid() 获得；完整值应可从 waitid() 以及传递给 SIGCHLD 信号处理器的 siginfo_t 中获得。

exit() 函数应首先按注册的相反顺序调用由 atexit() 注册的所有函数，但某个函数在其被注册时已经被调用过的任何先前注册的函数之后被调用的情况除外。每个函数被调用的次数与其被注册的次数相同。如果在调用任何此类函数期间，进行了会终止对该注册函数的调用的 longjmp() 函数调用，则行为是未定义的。

如果由调用 atexit() 注册的函数未能返回，则其余注册的函数不应被调用，并且 exit() 处理的其余部分不应完成。

exit() 函数然后应刷新所有具有未写入缓冲数据的打开流。[CX] 对于作为其底层文件描述符的活动句柄、且文件尚未处于 EOF 且能够寻址的每个流，底层打开的文件描述的文件偏移量应被设置为该流的文件位置。对于每个打开的流，exit() 函数应对与该流关联的文件描述符执行等效的 close()。 最后，进程应被终止，[CX] 后果与 进程终止的后果() 中所述相同。

返回值 (RETURN VALUE)

exit() 函数不返回。

错误 (ERRORS)

未定义任何错误。

应用程序用法 (APPLICATION USAGE)

当具有未写入缓冲数据的流被 exit() 刷新时，调用进程无法发现 exit() 是否成功地将数据写入了底层文件描述符。因此，强烈建议应用程序在调用 exit() 或以指示未发生错误的 status 值从对 main() 的初始调用返回时，始终确保任何流中都没有未写入的缓冲数据。

例如，以下代码演示了在以状态 0 调用 exit() 之前确保 stdout 已经成功刷新的方法之一。如果刷新失败，则关闭 stdout 底层的文件描述符，以便 exit() 不会尝试重复失败的写操作。如果刷新成功，则使用 ferror() 执行最终检查，以确保在早期刷新操作期间（当时未处理）没有写错误。

int status = 0;
if (fflush(stdout) != 0) {
    perror("appname: standard output");
    close(fileno(stdout));
    status = 1;
}
else if (ferror(stdout)) {
    fputs("appname: write error on standard output\n", stderr);
    status = 1;
}
exit(status);
